## 学び

- **F# の `[<Literal>]` は decimal に使えない** — `let maxWeightKg = 30_000m` に `[<Literal>]` を付けると実行時に `InvalidProgramException`（型初期化子で失敗）。Literal はプリミティブ（int/string/bool 等）限定。通常の `let` にする
- **FsUnit の `should equal (Ok())` は unit を含む Result で誤判定する** — 「Expected: Equals Ok ()、Actual: Ok ()」と同値なのに失敗する。`match ... with | Ok () -> ()` のパターンマッチで検証する
- **既存 ADR の確認を計画時に怠ると番号衝突する** — `docs/adr/` を見ずに IT1 計画へ ADR 番号を振ったため 0001-0003 と衝突。設計ドキュメントレビューの指摘は「レビュー日時点」のもので、その後 docs が更新済みのことが多い（今回コンテキスト数・US トレーサビリティ・ADR 化は解消済みだった）。計画時は必ず現物（ADR ディレクトリ・design ドキュメント）を確認する
- **ナビ導線は「実際に辿る」テストを書く** — ログアウトの GET リンク → 404 は、POST ハンドラの単体テストだけでは検出できなかった。リンク要素の method/action と、そのメソッドでの実リクエストの両方を受け入れテストで検証する
- **集約の複数書き込みは着手時にトランザクション方針を決める** — Donald の `Db.exec` は autocommit のため、親子 INSERT を単に並べると部分永続化が起きる。`conn.BeginTransaction()` + `Db.setTransaction tx` + Commit/Rollback で原子化し、子失敗時に親も残らない原子性テストを DoD にする
- **F# entry-point の WebApplicationFactory は回避してよい** — F# の `[<EntryPoint>] let main` は WebApplicationFactory と相性が悪い。パイプライン構成を `configureServices`/`configureApp`/`webApp` に切り出し、`WebHostBuilder().ConfigureServices(...).Configure(...)` + `TestServer` で受け入れテストを組むと安定（`#nowarn "44"` で WebHostBuilder 非推奨を抑制）
- **NuGet の脆弱性警告（NU1903）は推移的パッケージを明示ピンで潰す** — Microsoft.Data.Sqlite 経由の `SQLitePCLRaw.lib.e_sqlite3` 2.1.11 が該当。`SQLitePCLRaw.bundle_e_sqlite3` 3.0.3 を明示参照で上書き。`Rfc2898DeriveBytes` のコンストラクタ非推奨は静的 `Rfc2898DeriveBytes.Pbkdf2` で解消
- **dotnet watch のブラウザ自動更新は「Development 環境 + Accept: text/html」で注入される** — `curl`（`Accept: */*`）では注入スクリプトが出ないため未動作に見える。実ブラウザ相当のヘッダで確認する。ポートをハードコードせず `ASPNETCORE_URLS` を尊重すると watch/launchSettings と両立する。F# はインプロセスホットリロード非対応で「再ビルド + 再起動」になる
- **バージョンは実在を確認してから指定** — Donald は 11.x が存在せず 10.1.0 が最新、Giraffe.ViewEngine は 1.4.0。`dotnet package search` で確認してから固定する
