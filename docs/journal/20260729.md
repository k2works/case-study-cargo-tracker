## 学び

- **不変条件は Presentation でなく集約で守る**。受入条件をコントローラだけに置くとクライアント値偽装で破れる。定義したのに未使用のドメインメソッド（`expectedArrivalTime`）は「不変条件の配線漏れ」のサイン。集約に検証を入れ、確定 POST は永続化済みの値で再解決する二層防御にする。
- **BC 独立の cross-context 読み取りは読み取り ACL に閉じる**。Booking が Routing の候補を得るのに、Routing ドメイン型を import せず Booking 側の Kysely reader + DTO で境界化。ただし共有 DB 直読は dependency-cruiser の import 検証をすり抜ける盲点。ADR に明記し契約テストを将来課題化する。
- **Try は計画のタスク・成功基準に落として初めて返済される**。「余力次第の繰越」にせず IT 内の 0SP 枠に具体化したことで T1〜T3・T5・T6 を消化できた。
- **pg-mem 統合テストは FK 参照先の seed を忘れやすい**。leg の location FK 違反は `seedLocations` 追加で解消。cargo は FK なしだったため既存テストは通っていた＝新テーブル追加時に顕在化する罠。
- **SonarQube はこの環境の CI にない**。TS take-1 の CI は Lint/Test と E2E の 2 ジョブのみ、ローカルも未設定。closing-iteration の SonarQube ゲートは実行できないので「CI 自動チェックで代替」と正直に記録する（ゲート PASS を偽らない）。
- **並列エージェントの二段活用が効いた**。開始準備の整合性検証 2 体、締めのレビュー 5 体、設計同期 3 体をそれぞれ並列化。指摘を受けてからその場で本体を修正する運用で、負債の持ち越しを抑えられた。
