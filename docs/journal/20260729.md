## 学び

- **受入基準に列挙された項目は 1 項目 = 1 spec アサートに落とす**。「担当者・日時・理由」の 3 点のうち日時を実装で落とした。列挙形の受入基準はチェックリスト化しないと項目が抜ける。→ Try T48。
- **文字列 include の受入テストは偽陽性を疑う**。`include("billing")` はロール名がナビ・パスに必ず現れるため、担当者記録が画面に無くても緑になる。監査値は「一意な実値」で検証する。lifecycle spec 側（`adjusted_by == "経理太郎"`）が正しい手本だった。
- **金額の符号・状態集合の意味・計算式を変える実装は ADR 要否を必ず判定する**。COMPENSATION 加算→減算は請求総額の符号が反転する構造相当の変更。実装は 1 行でも意思決定の記録は別途必要。→ Try T49。
- **Ruby の負数インデックス回り込みは silent なので境界を明示的に弾く**。`line_items[seq_number.to_i - 1]` は seq=0 で `[-1]`（末尾）を返し、`params[...].to_i` の欠損時 0 と組み合わさると末尾誤削除になる。`< 1` ガードと境界値 spec（0・-1・範囲外）で防ぐ。
- **ドメインの状態機械をビューで再判定しない**。取消可否を `payment_status == "PENDING" || "OVERDUE"` と直書きすると、自ら定めた DoD（述語判定）と矛盾する。`cancellable` フラグで集約の `unsettled?` に一本化。既存メモリ「集約状態の再導出禁止」と同型。
- **金額の符号反転は MoneyAmount の責務**。集約に `negate` を public 露出させず `MoneyAmount#subtract` に閉じる。VO の責務を集約に漏らさない。
- **SonarQube gulp タスクは TS ハードコードで落ちる**。`-Dsonar.sources=src` 固定のため、`apps/cargo-tracker` から `npx sonarqube-scanner` を直接実行して回避。スキャン前にフル RSpec でカバレッジ（coverage.json）を再生成しないと新規カバレッジが部分実行値に落ちてゲートが割れる（54.8% で一度 ERROR になった）。
- **CI トリガの確認**: backend-ci.yml は push が main ブランチのみ。作業ブランチでは `gh workflow run --ref` で手動 dispatch する。
