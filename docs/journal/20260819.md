# 2026-08-19 開発ジャーナル

イテレーション 1（US26 ログイン・US27 ログアウト・US31 アカウント保護・US02 荷主登録、9 SP）を、品質ゲートの実配線から始めてアウトサイドインで通し切った日。検査を先に置いたことで、実装中に 5 件の実欠陥が自動で見つかった。

## ハイライト

- **検査の土台を Day 1 に置いた**。ArchUnit の全サービス配布・未適用を落とすメタテスト・カバレッジ検証・CI・E2E 基盤。以降 11 IT の全ストーリーがこの上に乗る
- **公開経路の設計欠陥を破壊検証が検出**。`/api/v1/tracking/**` を公開すると追跡管理者専用の `/api/v1/tracking/manage` まで無認証で通っていた。公開経路を `/api/v1/public/` 配下に分離した
- **方言スモークが素通りする形の欠陥を発見**。`#{keyword} IS NULL` は prepare だけでは通り、実行時にしか落ちない。`getParameterMetaData()` まで確認するよう強化した
- **トークンの保管先を ADR-005 として決めた**。E2E で URL 直接遷移が落ちたことから、メモリのみでは業務が止まると分かった
- **マニュアルのキャプチャ自動生成が最初の利用者になった**。撮った画面を見て、未実装メニューが行き先のないリンクになっていることに気づいた

## 学び

- **検査は「入れたこと」でなく「働くこと」を確かめる**。今回 3 つの検査が空振りしていた。メタテストは up-to-date でスキップ、方言スモークは prepare だけで素通り、`~` は互換モードでも解釈されるため違反例にならない。いずれも破壊検証で初めて分かった
- **破壊検証の違反例そのものを疑う**。「赤にならない」ときは検査が壊れている場合と、違反例が違反になっていない場合がある。両方を切り分ける
- **公開経路は業務 API と接頭辞を共有しない**。同じ接頭辞でワイルドカードを開けると、後から生えた業務 API が黙って公開される。パスから公開範囲が読めるようにする
- **ADR の規則は依存の有無でなく振る舞いで検査する**。「JWT ライブラリに依存しない」だと発行者（authms）が例外になる。「検証 API を呼ばない」なら発行と検証を正しく分けられる
- **画面は撮ってみないと分からない**。未実装メニューが行き先のないリンクになっていたのは、キャプチャを見るまで誰も気づかなかった
- **設計に書いていない判断は ADR にする**。トークンの保管先は設計に記載がなく、E2E の失敗という形で判断を迫られた
