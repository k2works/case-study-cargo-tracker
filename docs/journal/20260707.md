## 学び

- **翻案は「技術マッピング表を先に固定してから並列化」する**。エージェントごとに判断させると DB・E2E ドライバ・認証方式が食い違う。それでも今回 SQLite/Selenium/Devise の翻案漏れが残ったので、翻案後は「旧スタック名の横断 grep」を機械的チェックとして必ず回す
- **ドキュメント間整合はレビューエージェントの複数視点が有効**。コンテキスト数の分裂はアーキテクト・PM・テスターがそれぞれ別の入口から同じ問題に到達した。単独レビューでは「自分の読んだ 1 ドキュメント内の整合」しか見えない
- **並列エージェントの大規模編集はマーカー駆動でリカバリ可能にする**。途中死したときに grep で適用済み/未適用を判定できる固有トークン（今回なら `ROUTE_REQUESTED`）を修正指示に含めておく
- **`rails new` をモノレポのサブディレクトリに作るときは `.git` の削除を忘れない**（`git add` が exit 128 で落ちる）
- **同一マシンで同系プロジェクトを並行する場合、DB ポートは最初からずらす**（5433 採用）。docker-compose と database.yml の両方をセットで変更する
- **lint-staged から Ruby ツールを呼ぶときは rbenv shims を PATH 先頭に足す**。Git hook のシェルは rbenv 初期化を通らないことがあり、システム Ruby（2.6）に落ちる
