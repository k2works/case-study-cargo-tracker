## 学び

- **計画は「新規に設計」する前に上流を grep する**: US23 は「精算」という言葉から Settlement BC を新設しそうになったが、上流では Billing Context として設計済みだった。ストーリー → BC 対応は domain-model.md のコンテキスト一覧（§冒頭の表）を最初に引くべき。同じ概念が「精算/Billing/Invoice」と複数の名前を持つとき、既存名が正
- **validating-iteration-plan は計画作成の直後に必ず実施する価値がある**: 今回 19 件の不整合（uuid vs BIGSERIAL、numeric vs BIGINT、複数形 vs 単数形、架空ロール名）は、実装後に発覚したら migration やり直し + 全レイヤ改名になっていた。検証コストはエージェント 4 体・数分
- **ロール名・パス・型名は計画段階でも実コードを 1 回 grep して裏取りする**: 「Accounting/Admin」のような もっともらしい捏造は、レビューでも通過しやすい。`data Role` の定義 15 行を読むだけで防げた
- **検証エージェントには「設計ドキュメントが正」という判定基準を明示的に与える**: どちらに合わせるかを曖昧にすると、指摘が「どちらかに統一せよ」で止まり、修正方針の判断が往復する
- **IT 計画の設計セクションの粒度はプロジェクト慣行（直前 IT）が基準**: テンプレートは最小構成しか定めないため、IT7 が確立した「シーケンス図 + Tx 境界表 + エラー型 + DDL + CI ステップ」の水準を維持しないと、Ralph Loop の反復が設計判断で停滞する

### 学び (開発フェーズ)

- **「Docker 待ち」は思い込みだった**: T7-G/E2E を「環境待ち」と 3 反復分放置したが、`docker ps` 一発で Postgres 稼働中と判明。ブロッカー扱いする前に前提を実測すべき
- **T7-E (通知チャネル) が E2E の鍵になった**: UNLOAD 通知に平文コードを載せた業務改善が、そのまま「E2E のテスト用コード取得手段」(IT7 未解決問題) の解になった。業務価値のある実装はテスタビリティも解く
- **arch-check が 2 回設計を正した**: UI 文言の「TsClaimed」(H-01)、Handling→Tracking Domain import (Rule 4)。どちらも Text ヘルパ (`executeText`) への再設計で解消。規約の自動強制が Ralph Loop の暴走を止める安全網として機能
- **状態機械の乖離は migration の潜在バグを埋めていた**: Settled 追加のために cargo CHECK を見たら、初版から `RouteAssigned`/`Cancelled` が欠落 (実 Postgres では US11/US13 が CHECK 違反になる状態)。読出しパーサも同様。テストが InMemory/fake 中心だと DB 制約の乖離は見えない — T7-G の実 DB 統合テストを IT9 で全 Repository に広げる根拠
- **stale バイナリに 30 分溶かした**: cabal ファイルが package.yaml より新しくテストバイナリが再生成されない状態で、「303 成功なのに spy が空」を実装バグと誤認。`.cabal` 削除 → hpack 再生成で解消。不可解な挙動はまずビルドの鮮度を疑う

### 学び (クロージング)

- **「コマンド実装 = 機能完成」ではない**: OverdueCheck (H-02) は Domain/App/テストが揃っても起動導線 (エンドポイント/バッチ) がなければ受入基準は未達。レビューのユーザー代表視点が「誰がいつ起動するか」を突いて発覚した。受入基準は起動主体まで含めて確認する
- **docstring は実装より先に書かない**: 「単一 Tx で囲む」と docstring に書いたが配線が追いつかず、アーキテクトに乖離を指摘された (H-01)。実装済の事実だけを書く規律に戻す
- **正式レビューは self-review では見えない機能ギャップを拾う**: Ralph Loop 中の self-review は「テスト緑 = 完了」に寄りがちで、H-01/H-02 のような「配線漏れ」は通過していた。クロージングの多視点レビューが GA 前の最終防波堤として機能した
- **即対応と backlog の線引き**: 軽微・低リスク (ドキュメント/小関数抽出/finally) は GA 品質のため即対応、設計判断や影響範囲大 (Tx 配線/起動主体設計) は IT9 に整理。クロージングで大リファクタを始めるとクロージングが終わらない
- **end-of-life 判定の実践**: AI 単独完結タスク消化後、Stop hook が同一プロンプトを再投入し続けたため、feedback memory の規律に従い自分で `.claude/ralph-loop.local.md` を削除して停止した (開発フェーズ iter 26 / クロージング iter 17)。「ユーザーの明示 cancel を待つ」より「完了が明白なら規律に従い停止」を優先
