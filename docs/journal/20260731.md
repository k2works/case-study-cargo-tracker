### 5. ハマった：`query` が予約語だった

ここで**メタテストが実装ミスを捕まえた**（未定義関数の呼び出し）。実プロジェクトは違反 0 件のためその経路に到達しておらず、メタテストだけが露見させた。IT2 で強化した甲斐があった。

### 13. ハマった：効果の上位変換ができない

認証のルートをルーティング表に登録しようとして詰まった。`ReadDb` だけを要求するハンドラを `ReadDb + Session + ...` の表に入れられない。

試したこと:

1. `checked_ecast` で包む → 効果が**消える**方向のキャストなので不適
2. 宣言だけ広げた薄いラッパを書く → **「Unused effect」でコンパイルエラー**
3. 効果多相（`\ Session + ef`）で書く → 同じく「未使用の ef」でエラー

Flix は**宣言効果と実際に使う効果の完全一致**を要求する。結論として、ルーティング表を効果集合ごとに 4 つへ分割し、`handleDynamic` が順に試す形にした。局所的には妥当な回避だが、レビューで「BC が 8 個になる IT4 以降では持たない」と指摘された。IT4 の最優先課題。

### 14. 認証基盤の実装（`a5bc33c4` 〜 `5c6a4a7a`）

`Password`（BCrypt コスト 12）・`Session`（DB 実装）・`UserRepo` の 3 効果と、認可判定・CSRF・Cookie。

判断の記録:

- **BCrypt の壊れたハッシュを例外ではなく形式検査で弾いた**。Flix の `try/catch` はネストしたラムダで不正なバイトコードを生成し、テスト実行時に初めて失敗する（制約 12）
- **失敗回数の記録を 1 回の UPDATE に**。読んで判定して書き戻すと、同時ログイン試行で数え落とす
- **未知のロールを持つセッションは未認証扱い**。既定ロールへ倒すと権限のない利用者に権限を与える

### 15. `closing-iteration` — 全緑のまま存在した欠陥 5 件

5 視点のレビューで、テスト 151 件全緑・受入基準充足の状態で次が見つかった。

| 欠陥 | 発見されなければ何が起きたか |
|------|---------------------------|
| `user_roles` が複数行を許すのに実装は 1 行前提 | 兼務ユーザーを 1 人登録した瞬間、認可がリクエストごとに変わる |
| 環境判定が「`DATABASE_URL` 未設定＝開発」のフェイルオープン | 本番の注入失敗で開発用の資格情報が画面に出る |
| 存在しない利用者で BCrypt を通らず即返す | 応答時間の差でユーザー名の存否が判別できる |
| `/health/live` が DB トランザクションを開く | DB 障害時に、防ごうとした再起動ループが起きる |
| BCrypt が DB コネクションを掴んだまま | ログイン同時実行でプールが枯渇 |

いずれも「動作の正しさ」ではなく**「壊れ方の設計」**に属する。正常系のテストをいくら足しても見つからない（`8af58247` で全件修正）。

ユーザー代表からは「別端末で締め出された利用者に『操作がなかったため』と出るのは事実と違う案内で、障害報告につながる」と指摘され、終了理由を区別する仕組みを追加した。

## 学び

- **メタテストが緑でも検査器は信用できない**。フィクスチャは「規約に違反する最小の例」ではなく「このコードベースで実際に書かれる形の違反」で作る。既存コードから同種の記述を探して崩すのが確実
- **「テストが緑」と「運用で壊れない」は別の問題**。自作のセキュリティ基盤では、受入基準とは別に「設定を忘れたら」「依存が落ちたら」「負荷がかかったら」をレビューさせる。攻撃者視点（列挙・タイミング・注入）と運用視点を依頼文に明示的に書く
- **緑のテストは「実データで正しい」ことを意味しない**。インメモリのフィクスチャが本番の値の形（JDBC が返す秒付きの文字列）と違えば、変換のテストは何を書いても保証にならない。フィクスチャの値の源を 1 箇所に集約する
- **テストヘルパーは失敗時に値を返さず停止させる**。`loginAndGetCookie` が空文字を返す設計だと、「ログインが壊れている」ケースが「ログアウト後は入れない」テストの期待値と一致して緑になる
- **判断を含むユースケースは単体テストで順序を固定する**。「判定の順序に意味がある」とコメントに書いていても、統合テストだけでは経路の副産物と判定そのものを区別できない
- **言語の制約はアーキテクチャに恒常的な税を課す**。Flix の効果システムは上位変換を持たないため、BC が増えるたびにルーティング表の分割コストが上がる。回避策の是非は早い段階で決着させる（先送りすると回避策の撤去自体が大改修になる）
- **統合レポートを書く作業でも指摘は落ちる**。5 視点分をまとめる過程で ADR 起票漏れ 2 件を落とした。落としたこと自体を記録に残すほうが、次の統合で効く
- **予約語・遮蔽は「動くはずのコード」を壊す**。`query`（Datalog）、`import java.lang.String` による標準ライブラリの遮蔽、大文字始まりのメソッド名（`.POST()`）がモジュール参照と解釈される——いずれもエラーメッセージから原因に辿り着きにくい。制約一覧に残す価値が高い
