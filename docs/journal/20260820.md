- **kind の全サービスが再起動ループに入った**。`startupProbe` を入れて解消

### 3. Docker Desktop の破損と復旧

クローズ作業中に Docker の API が 500 を返すようになり、Testcontainers・SonarQube・ドキュメントサイトのビルドがすべて止まった。`docker desktop restart` で復旧。

復旧後の一斉起動で 7 サービスが再起動ループに入った。Spring Boot の初期化（コンテキスト 42 秒 + Flyway 36 秒）が liveness の猶予を超え、正常に起動中のコンテナが殺されていた。

### 4. CI の確認

push 済みの HEAD で CI が **failure** のまま放置されていた。E2E の webServer が `npm run dev:mock`（削除済み）を呼んでいたのが原因。ローカルでは dev サーバーが起動済みで `reuseExistingServer` が効き、webServer の起動自体がスキップされていたため見えなかった。

## 学び

- **モックで完結した検証は「動く」ことを保証しない**。認証トークンの配線漏れは 137 ファイル・全テスト緑をすり抜けた。フロントの検証が MSW 越しで、ヘッダを誰も見ていなかった
- **時間で変わる振る舞いは可変 Clock でテストする**。固定 Clock では「15 分後にどうなるか」を通れず、ロック解除が名目だけになっていることに気づけなかった
- **修正のテストは二次欠陥も暴く**。「期限切れなら数え直す」を入れたら、今度は「期限だけ残って何度でも失敗できる」状態が現れた。1 つ直して 1 つ確かめるサイクルが効いた
- **`reuseExistingServer` はローカルの検査を無効化する**。dev サーバーが起動していると webServer の設定が使われず、CI でだけ落ちる
- **probe の猶予は実態に合わせる**。10 サービスの一斉起動は単体起動の何倍も遅い。`startupProbe` が無いと、正常に起動中のコンテナが殺されて負荷がさらに増える悪循環になる
- **品質ゲートは「設定があること」から確かめる**。スキャン対象が未定義でも `sonar-local:scan` はエラーにならず、既定の架空プロジェクトを見ていた
