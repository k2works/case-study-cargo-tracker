## 学び

- **ループ内で `gh` を呼ぶと stdin を消費してハングする**。`while read` の入力ファイルや端末 stdin を子プロセスの gh が食う。全 `gh` 呼び出しに `</dev/null` を付けると解決。単発では再現せずループで再現、という切り分けが鍵。
- **GraphQL の複数ミューテーションは件数上限（RESOURCE_LIMITS_EXCEEDED）**。125 更新（25 item × 5 フィールド）を 1 発で投げると途中で失敗。**5 item ごとにバッチ分割**で安定。
- **ランタイム設定バグは oneshot/CI テストを素通りする**。今回 4 件（①デフォルト DATABASE_URL が docker-compose の cargo/cargo と不一致、②tower-sessions の Cookie が既定 `Secure=true` で http ログインループ、③seed バイナリ追加で `cargo run -p` が曖昧化 → `default-run` 必須、④ローカル sqlx-cli が postgres ドライバ無し → 埋め込み MIGRATOR の migrate バイナリで回避）。**実起動 smoke テスト**を IT2 の Try に追加。tower oneshot は Cookie を手動転送するため Secure 属性を検出できない。
- **sqlx はランタイム `query`（非マクロ）ならビルド時 DB 不要**。オフラインビルドは成立し、`query!` マクロ + `.sqlx` 硬化は後回しにできる（task 1.7 の実質完了）。
- **設計ドキュメント内の「論理モデル vs テーブル定義」ドリフト**は、どちらを SSoT とするか明示注記で解消する。両方直すのではなく正典を宣言。
- **認可を文字列ロール比較でハンドラに手書きすると DRY・型安全・セキュリティの三重負債**。レビューで 4 視点が独立指摘 → 早期に extractor + `Vec<Role>` 型化すべき。文字列マジックはコンパイラが守れない。
- **型で不正状態を排除する設計はテスト空間を縮小する**（`ShipperKind::Corporate(CorporateProfile)`）。レビュー全視点が高評価した最大の資産。
- **mermaid の点線ラベルはピリオドで壊れる**（`-.Release 0.1.->`）。`-.->|"ラベル"|` 記法が安全。subgraph 識別子は ASCII 推奨。
- **background 実行はハングしやすい**（環境依存）。前景の小バッチ + `</dev/null` の方が確実だった。
