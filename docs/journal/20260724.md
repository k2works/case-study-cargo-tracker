## 学び

- **ツールチェーンのビルド Go バージョンに注意**: golangci-lint v1.64（go1.25 ビルド）は go1.26 プロジェクトで実行拒否。CI と揃えるには対象 Go で再ビルド（v2.12 を go1.26 で）。lint ツールは「対応言語バージョン」でなく「ビルド Go バージョン」で落ちる。
- **go-arch-lint は BC×レイヤーで両軸を強制する**。BC 単位だけだと同一 BC 内のレイヤー import を誤検出、レイヤー単位だけだと BC 独立を守れない。deepScan は手動 DI の合成ルート（main）で正当な注入を誤検出するため無効化し、import ベースの検証で担保する。
- **アーキテクチャテスト緑 ≠ 構造的健全**。共有 commonComponent（sqlcgen）に全 BC の生成コードを集約すると、go-arch-lint を無検出で通過しつつ BC 越境の型アクセスが可能になる「隠れた共有カーネル」。構造検証をすり抜ける負債はレビューの人間視点で拾う。
- **共有カーネル型は「同じ意味を全 BC で共有」が前提**。`ShipperId` が Shipper では UUID、Booking では shipper_code を運ぶと意味が二重化する。BC 間参照は業務識別子と決めたら型名も `ShipperCode` に正すべき（ADR 化）。
- **testcontainers のカスタム wait strategy は port 待ちを含めない**と `port "5432/tcp" not found` になる。postgres モジュールは `postgres.BasicWaitStrategies()` を使う。
- **SonarQube のパスワードハッシュはバージョンで変わる**。26.x は PBKDF2-SHA512（100010 反復・512bit・`iterations$base64` 形式 + salt 列 base64）。BCRYPT は検証されない。DB 直接リセット時は PBKDF2 形式で生成する。
- **`sqa_` 分析トークンは `/api/authentication/validate` で判定できない**（常に false 相当）。実スキャンが唯一の検証。`.env` のトークンは再発行しても手で貼り替えないと反映されない。admin ログインがあれば API（`/api/user_tokens/generate`）で発行して .env 更新するのが確実。
- **Bash で全角文字と変数展開を隣接させない**。`（PORT=$PORT）` のように全角括弧が `$PORT` に隣接すると変数名解決が壊れる。変数を含む echo は ASCII に。
- **Backend CI が feature ブランチで発火しない場合は `workflow_dispatch`**。`on: push: branches: [main]` のワークフローは `gh workflow run <wf> --ref <branch>` で手動起動して CI 緑を確認できる。
- **横断関心事（認証・認可）はスコープ外にしない**。ロール制御を実装するなら認証は前提。要件段階で各ストーリーに必要ロールを併記しておく（Try T7）。
