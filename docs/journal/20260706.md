## 学び

- **翻案は「対応表を先に固定してから並列化」**。技術マッピングを各エージェント任せにすると用語がぶれる。今回は最初の 1 メッセージで対応表を確定したことで 10 ドキュメントの一貫性が保てた
- **並列生成したドキュメント群は必ず横断レビューを挟む**。個々のエージェントは正しくても、enum 定義のようなドキュメント間の整合はレビューでしか検出できない（状態機械 3 種の不統一はまさにこれ）
- **sqlx の `query!` マクロはビルド時に DB か `.sqlx` キャッシュを要求する**。Dockerfile / CI に SQLX_OFFLINE 戦略を最初から織り込まないと「設計どおり作ると必ずビルド失敗」になる
- **macOS の BSD grep は BRE の `\|` 非対応**。ポータブルなフックスクリプトでは `grep -E` を使う
- **フック検証で `git stash` を使うと直前の未コミット変更（package.json 等）を巻き込む**。検証用の一時変更は `git checkout --` で戻すか、stash 後に `stash show --name-only` で内容を必ず確認する
- **バックグラウンドエージェントへの追加指示は SendMessage で**。同一ファイルを編集中のエージェントに後続タスクを渡せば、競合なく 1 パスで済む
- **PlantUML の状態名に「・」等の記号は使えない**。日本語ラベルは `state "表示名" as alias` でエイリアス化する。生成後の `plantuml -syntax` 一括検証をルーチンにする
