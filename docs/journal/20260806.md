## 学び

- **「〜しない」と書いたコメントは、それを強制する仕組みが無ければただの願望である。** 利用者シードの「本番では適用しない」は、`common/` に置いた時点で嘘になっていた。**宣言を見つけたらテストにする**のが唯一の対処
- **スキャナの緑を無条件に信じない。** Trivy も SonarQube も JIG も、初回は「安全である」ではなく「設定が間違っている」を意味していた。**何件検出したかを一度は目視する**。0 件が続くツールは、働いているかを疑う
- **並行性の欠陥は逐次のテストでは絶対に出ない。** 総当たり攻撃は逐次では来ないのに、ロックのテストは逐次でしか書いていなかった。安全装置は攻撃者の来かたで試す
- **時刻を注入する設計にしただけでは足りない。** 差し替えるテストを書いて初めて意味を持つ。`Clock` の注入は「テストできるようにした」ではなく「テストを書く前提を整えた」に過ぎない
- **MockMvc は forward 先を描画しない。** 403 画面のように forward で出す画面は、MockMvc だけでは中身を確認できない。実機（Playwright）での確認が要る
- **Spring Boot 4 は自動構成がモジュール分割されている。** 依存を入れただけでは有効にならず、しかも**静かに何も起きない**（Flyway が実行されない・Security フィルタが適用されない）。移行時はここを最初に疑う
- **`io.spring.dependency-management` の管理版は `resolutionStrategy.force` より強い。** BOM の版を上書きするには、プラグイン自身の `dependencyManagement.dependencies` を使う
- **CI の赤は一意にする。** `trivy-action` はバージョン解決の失敗と脆弱性の検出が同じ赤になり、どちらか分からなかった。公式イメージの直接実行に変えた
- **マニュアルを実装より先に書くと、「こうあるべき」が「こうなっている」として書かれる。** 存在しない解除機能とエラーメッセージを案内していた。**キャプチャ生成が通ることを記述の前提条件にする**（生成できない＝画面が無い）
- **ドキュメントの「向き」を間違えると、狙いと反対に働く。** ArchUnit の `ignoreDependency(依存元, 依存先)` を逆に書いた正典のサンプルは、「共有カーネルから他 BC への依存」を無視する設定だった。サンプルコードも実際に動かして確かめる

IT1 のクローズに続けて IT2（US04 貨物予約 / US32 荷主訂正、7SP）を計画から実装・クローズまで通した。**IT1 の裏テーマ「緑であることと働いていることは別」は、IT2 では「宣言と実態は別」になった。**

### ハイライト

- **ADR の「〜しない」を棚卸ししたら、9 件中 4 件は文章だけだった。** 破ってもビルドが緑になる状態を、依存検証タスクと ArchUnit ルールで塞いだ

- **共通マイグレーションに `setval` を書いてローカル起動が落ちた。** Testcontainers のテストは全緑のまま。ADR-003 が警告している方言差の、警戒していなかった側だった
- **SonarQube のセキュリティホットスポットを、権限が無いまま突き止めて直した。** 中身はメールアドレス正規表現の ReDoS だった

### 学び

- **「入口を作る」ことに気を取られて「開放してよいか」を確かめなかった。** IT1 の教訓（ロール別の作業入口の欠落）を強く意識した結果、逆側に倒れた。到達性の確認は「見せる」と「見せない」の両方向で行う。`non_functional.md` は ROLE_SHIPPER を「自社予約・追跡（Phase 2）」と明記していたので、正典を読めば分かった
- **安全装置を壊して確認する規律を、テストの側にも当てる必要があった。** ReDoS 対策を経過時間で守ろうとしたが、脆弱な実装に戻しても緑のまま通った。分岐の結果（どちらの検査で落ちたか）で判定する形に書き直して初めて赤になった。**赤にならないテストは何も守っていない**
- **方言差は「H2 で緑・本番で赤」だけではない。** 逆（本番で緑・ローカルで赤）も同じ頻度で起きる。しかも落ちるのが起動なので CI では気づけず、画面を触ろうとした瞬間に分かる。マイグレーションを足したら実際に起動する
- **テストデータの採番も本番と同じ経路を使う。** 自前の `MAX + 1` がシーケンスと衝突し、**原因でないテストが**UNIQUE 制約で落ちた。個別実行では緑、フル実行だけ赤という見えにくい症状になる
- **1 回のスキャンで品質ゲートは終わらない。** ReDoS を直したら S5998 と S2629 が新しく出た。5 回まわして PASS になった
- **権限が足りないときに「見えないから保留」にしない。** SonarQube の API が権限不足で読めなかったので、ローカルコンテナの DB を読み取りのみで参照して箇所を割り出した
