## 学び

- **tsx は NestJS の DI を壊す**: esbuild ベースのランナーは `emitDecoratorMetadata` 非対応。デコレータメタデータに依存する DI フレームワークでは SWC（`@swc-node/register` + `.swcrc` に `decoratorMetadata: true`）を使う。単体テストが通っても実行時 DI が undefined になる罠。
- **`npm ci` は lock ドリフトで CI だけ赤になる**: 多数の install/uninstall 後の lock はプラットフォーム別 optional 依存（@emnapi 等）が欠落しうる。macOS の `npm ci --dry-run` は通っても Linux CI で落ちる。依存変更後は `rm -rf node_modules package-lock.json && npm install` でクリーン再生成する。
- **`Number('')` は 0**: 空フォーム値を素朴に `Number()` すると 0 になり必須検証をすり抜ける。空文字は明示的に NaN/undefined へ変換してから検証する。
- **日付期限 vs 時刻付き到着の粒度不一致**（[[feedback_date-vs-timestamp-deadline]] 再発）: DATE 期限（00:00）とミリ秒 ETA を `getTime()` 比較すると当日着を誤って刈る。日付単位に丸めて比較し、境界テスト（当日着・時刻付き）を必須化する。
- **ReDoS は正規表現の量指定子の重なりで起きる**: `[^\s@]+@[^\s@]+\.[^\s@]{2,}` のような重なる量指定子は SonarQube が hotspot として検出。文字列走査ベースの線形検証に置換すれば hotspot 自体が消え、手動レビュー運用も不要になる。
- **SonarQube hotspot は分析トークンで操作できない**: hotspots API は 403。手動レビュー必須の hotspot が出たら UI か管理者権限が要る。根本修正できるものはコードで消すのが最も安い。
- **ValidationError パターンは BC 横断で統一する**: 利用者提示エラーと内部障害を型で区別（`*ValidationError`）しないと、入力ミスが「予期せぬエラー」としてログ・画面に漏れる。新 BC ごとに横展開を忘れやすい。
- **設計ドリフトは実装と同一クローズで是正する**（[[feedback_scope-change-canon-sync]]）: 他 take 由来の「実装済み」注記・IT4 予定カラムの前倒しは、実装と同じイテレーションで data-model/domain-model/ADR を同期させないと正典がずれる。
- **BC 独立性は arch ルールで機械化する**: ACL を「置く」だけでなく dependency-cruiser で `shared→contexts` 逆流や cross-context 直参照を禁止し、緑を DoD にする。BC が 1 つの早い段階でルールを入れるのが最も安い。
