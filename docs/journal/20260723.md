## 学び

- **ローカルの Lint 緑を CI 緑と混同しない**。ローカル toolchain が CI（`@stable`）より古いと、新しい clippy lint がすり抜けて CI だけ赤になる。自動チェックは「CI と同じツールチェーン」で回す。クローズ前に `gh run` で実結果を必ず見る。
- **`format!` の `&(...).to_uppercase()` は冗長参照**。所有 `String` を返すメソッドチェーンに `&` を付けると新 clippy が `-D warnings` で落とす。値を返すメソッドの前に `&` を付けない。
- **cargo の巨大インクリメンタルキャッシュは破損しうる**。`-p <crate>` は通るのに `--workspace` が同じクレートで幻のエラーを出す、という矛盾が出たら疑う。`cargo clean` で確定させる（部分 clean は連鎖するのでフル clean が速い）。
- **testid を用意しただけでは受入基準を担保しない**。UI 表示制御（出し分け・可視/不可視）が受入基準に含まれるなら、E2E で `toBeVisible/toBeHidden` を必須ケース化する。
- **「送信＝記録」系の通知テストは件数だけでなく宛先・本文までアサートする**。件数チェックは宛先ハードコードのような機能欠陥をすり抜ける（IT4-6 で 3 IT 連続で形を変えて露見）。
- **スキル運用の穴は、そのスキル自身を直して塞ぐ**。CI 確認の抜けは一度きりの修正で終わらせず、`closing-iteration` にステップとチェックリスト項目として組み込むことで再発を防ぐ。
