2. **経路確定後の権限エラー** — 経路設計者が確定すると `/bookings/{id}`（ROLE_SALES 限定）へリダイレクトし「権限がありません」。設計者自身の作業一覧 `/routing/requests?msg=routed` へ戻すよう修正。既存テストが**バグった挙動を固定化**していたため一緒に是正。
3. **追跡番号の確認場所なし** — 貨物追跡は番号入力のみで一覧が無く、確定時に自動発行される追跡番号を確認できなかった。`/tracking` に追跡一覧（ROLE_TRACKER）、予約詳細に追跡番号表示を追加。

## 学び

- **設計に書いてあっても実装に無ければ「無い」** — 経路設計ナビは ui_design に存在したのに navMenu から漏れていた。設計の正しさは実装到達を保証しない。ナビは navMenu 一元管理にして navbar/dashboard を同期させると穴が減る。
- **ロール横断の PRG リダイレクト先は遷移元ロールでアクセス可能か必ず確認** — 経路設計者→予約詳細（ROLE_SALES 限定）の権限エラーは、成功処理後の遷移先を疑わないと見つからない。
- **テストがバグを固定化していることがある** — 「予約詳細へリダイレクトする」という受入テストが、実は権限エラーになる誤挙動を保証していた。修正時はテストの前提も疑う。
- **外部ライブラリはビルドが通っても採用可否を推移的依存で判断する** — WireMock.Net はコンパイル可能だが高深刻度の脆弱性連鎖を持ち込む。契約固定は HttpListener で十分達成でき、依存を増やさない方が堅い。
- **「本番互換テスト用 postgres」を用意しても、書き込みを実際に流していなければ互換とは言えない** — 全 integration テストが SQLite で、postgres の書き込みは一度も実行されていなかった。ISO 文字列→timestamptz の暗黙キャスト不可は本番で初めて露呈する。アプリが時刻を文字列で一貫処理するなら、postgres 側も TEXT に寄せるのが整合的。
- **`IsDevelopment()` は拡張メソッドで Release publish 時に解決に失敗しうる** — ローカル Debug ビルドは通っても Docker の Release publish で FS0039 になった。`EnvironmentName = "Development"` の直接比較に置き換えて回避。
- **exit 139（SIGSEGV）でも真因は管理例外のことがある** — コンテナのアプリログ末尾に Npgsql の 42804 が出ていた。終了コードだけで判断せずログを読む。
- **不可逆・外部アクションは Ralph Loop でも自律実行しない** — DB スキーマ変更は AskUserQuestion、リリース tag は保留、GitHub 同期は明示指示待ち、と境界を保った。
