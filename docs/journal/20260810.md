# 2026-08-10 開発ジャーナル

v1.1.0 のリリースを締めたところから始め、リリース呼称の統一と Release 2.0 の計画づくりを経て、**IT13（US21 料金算出 / US22 法人割引）と IT14（US23 精算）を計画からクローズまで 2 本通した**。Billing Context が立ち上がり、引取が済んだ貨物の料金を算出して確定し、請求書を発行して入金を確認し、予約が「精算完了」になるまでが 1 本につながった。この日の裏テーマは「**書いたことと、していることは別**」だった。コメントが宣言した守りは実在せず、ADR が決めた不変条件は制約になっておらず、「例外にしない」という判断は「記録もしない」に滑っていた。

## ハイライト

**返済枠 8 タスク（10 件）を序盤で完済**してからストーリー本体に入った。C1（引取日）では、荷役の記録から数え直さず `cargo.claimed_at` に**作業日時**を永続化した（登録日ではない。現場は後から登録する）。C16（ダッシュボードの案内）では、ロールの名簿を `DashboardEntryRoles` に集約し、**画面の `sec:authorize` を読み出して名簿と突き合わせる検査**を足した。名簿から `BILLING` を外すと 2 本が赤になることを確認した。

### 9. `closing-iteration` — IT14 のクローズ

5 視点の並列レビューが**高 18 / 中 19 / 低 8 件**。うち 13 件を IT 内で返した。重いものから:

- **`settle` / `notifyIssued` の戻り値を捨てていた**（architect）。「例外にしない」は正しいが、そこから「何もしない」へ滑っていた。監査ログと画面に残す形に直した
- **期限のテストが CI の時間帯でだけ落ちる**（tester）。DB の `CURRENT_DATE`（UTC）で期限を作り、判定はアプリ（JST）で走っていた
- **ADR-018 の「1 請求書 1 入金」が DB 制約になっていない**（architect）。`LEFT JOIN payment` のため、重複行は**締めの二重計上**として現れる。V35 で `UNIQUE` にした
- **楽観的ロックが「働くこと」を確かめていない**（tester）。C13 の修正でロックを丸ごと外しても全テストが緑だった
- **入金額・入金日時・支払方法・参照番号が画面のどこにも出ない**（user-rep）。入力させた項目が読めないのは記録として成立していない
- **「利用者に見せる語は請求書に統一する」という規則を、規則を書いた本人が破っていた**（technical-writer）。同じ画面に「請求書詳細」と「精算書を発行」が同居していた

SonarQube は 11 件の Code Smell で一度 FAIL したが、いずれも機械的なもの（単一行のテキストブロック・`Month` 定数）で、直して **PASS** にした。CI も緑を確認した。

## 学び

- **「例外にしない」は「記録しない」を含まない。** 副次的な処理の失敗で主たる事実を巻き戻さないのは正しい判断だが、**そこから「だから何もしない」へ滑ると、失敗が誰にも見えなくなる**。戻り値を持つポートを呼んだら、その値を使っているかを実装時に確かめる。使っていないなら、記録するか、**同期である必要がない**のでイベントにするかを選ぶ
- **DB の `CURRENT_DATE` も「JVM 既定の now()」と同じ罠である。** Testcontainers の PostgreSQL は UTC。期限をそこで作ってアプリ（業務タイムゾーン）で判定すると、**日本時間 0〜9 時に走らせたときだけ落ちる**。テストは `LocalDate.now(clock)` で日付を作ってパラメータで渡す
- **ADR に「〜として使う」と書いたら、「どこが守るか」を同じ場所に書く。** DB 制約か、ドメインか、テストか、守らないか。3 イテレーション連続で「ADR の口約束」を後から見つけている
- **Javadoc に「〜はいる」「〜が起きる」と書いたら、その経路を 1 本テストで踏む。** 「連絡先が未登録の荷主はいる」と書いたが `shipper.email` は NOT NULL で**到達不能**だった。踏めない主張は書き換える
- **列挙を画面に書くと、足すたびに書き足し忘れる。** 名簿を 1 か所に集め、**画面と名簿を機械が突き合わせる**形にすると 3 回目が止まる。2 回起きた時点で、規律ではなく構造で止める
- **問い合わせ回数では判別できないものがある。** 「全件を引く」も「絞って引く」も 1 クエリなので、回数を数えるテストは緑のままだった。**何が返るか**で確かめる形に変えたら壊せた
- **同型の引数が隣接している record は、位置を取り違えてもコンパイルが通る。** 入金の 4 項目を `PaymentDetail` にまとめたら、循環的複雑度の指摘も同時に消えた。**検査が指した場所と、直すべき場所は一致する**
