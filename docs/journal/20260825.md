- **E2E が新しいガードの手前で止まり、以前からの守りを踏まなくなっていた**
- **マニュアルのキャプチャが実欠陥を写した。** 申告日時が生の ISO・UTC で出ており、

## その日の流れ

### 1. IT7 が置いた検査が、設計どおり赤になった

通関状態のイベントを足したところ、IT7 の「発行する種類は 1 つだけ」が赤になった。
**赤くなること自体が設計どおり**である——発行が増えたら気づく、という約束だった。

ただ直し方を考えて、**数ではなく名前で並べる形**にした。「1 つだけ」という数の検査は、
1 本足して 1 本消す入れ替えを見逃す。何を発行してよいかを名簿で持つほうが、次に足す人に
判断の材料を渡せる。

### 2. Phase 6 — 実環境で 1 本通す

kind へイメージを作り直して流した。まず気にしていたのは**交換機の引数**である。既存の
環境では宣言し直せず、1 つ食い違えばそのサービスは起動しない。Testcontainers では毎回
まっさらなので出ない。結果、3 サービスとも同じ引数で宣言できていた——検査を先に書いて
おいたのが効いた。

そこから先が本題だった。

**通関 → 引取の拒否 → 留置 → 未解決一覧**は通った。ただし私が最初に書いた assert が
間違っていた——公開追跡に「税関」の語が出ることを期待していたが、公開画面は**理由を
出さない設計**である。イベントは届いており、間違っていたのは検査のほうだった。
公開には「問題が発生した」まで、種別と理由は認証の内側、という形に直した。

**輸送中 → 申請 → 承認**は、承認待ちの一覧を取るところで 404 になった。Gateway に経路が
無かった。画面からは 404 に見え、サービス側は正しく動いている——**サービスのテストは
全部緑のまま**である。

同型を機械で見つけたくて、コントローラの宣言と Gateway の述語を突き合わせる検査を書いた。
最初の版は**プロファイルをまとめて集めていた**ので、片方から経路を消しても赤にならな
かった。プロファイルごとに見る形へ直したら、**本番プロファイルの欠落を 2 件**指した。
公開追跡が本番で 404 になる状態だった。

### 3. クローズ — 5 視点が動かなかった

`developing-review` の 5 エージェントを並列起動したが、**いずれも結果を返さずに終了**した。
再試行した 2 体も同じ。5 つの観点を自分で順に通す形に切り替えた。

IT7・IT8 では**複数視点が独立に指摘したものが最も重い欠陥**だった。その効果は今回
働いていない。報告書とふりかえりの両方に、そのことを書いた。

自分で通す過程で 2 件見つかった。ダッシュボードに**同じ行き先のリンクが 2 つ**並んで
いたこと（navbar には重複の検査があったが、ダッシュボードには無かった）と、
**`REQUEST_CANCELLATION` がモックにしか無い**ことである。後者は、画面が
`availableActions` を見てボタンを出す設計なので、**サーバが載せ忘れると画面には何も
出ないが API は 200 を返す**。実環境の受け入れテストも API 直叩きだったので通っていた。

### 4. 品質ゲート — 指摘の中に本物が混ざっていた

SonarQube が Bug 1・Code Smell 39 を出した。数だけ見ると些末に見えるが、読むと本物が
あった。

- **空リストに対する述語アサート**。列挙が読めていなければ `doesNotContain` は常に真に
  なる。追跡の状態に値を足しても緑のまま——IT8 で「並び順の外の値」が実バグを生んだ
  直後の箇所だった
- **宙に浮いた Javadoc が 4 件**。メソッドを動かしたときに説明が取り残され、別の
  メソッドの上に積み重なっていた。読む人は隣の説明を信じる
- **キューの引数を 4 か所で書き写していた**。上で書いたとおり、引数の食い違いはサービスを
  起動不能にする

その途中で、**型検査が何も見ていない**ことに気づいた。未定義の関数を呼ぶコードを
`tsc --noEmit` が素通りさせ、テストで初めて 9 件落ちた。緑を見て安心していた分、
検査が無いより危ない。

### 5. マニュアルのキャプチャが欠陥を写した

撮り直したキャプチャで、申告日時が `2027-09-03T00:00:00.000Z` と出ていた。実 API は
「2027-09-03 09:00」を返す。**モックだけが生のまま返していた**。画面のテストは日時の
形を見ていなかったので、食い違いに気づけない。

キャプチャは「実装と手引きを合わせるため」に撮っているが、**撮った絵を見ることで欠陥が
見つかる**こともある、という日だった。

## 学んだこと

1. **画面から踏むテストと、API を叩くテストは別のものを守る。** 応答の一覧に依存する
   画面は、載せ忘れを API のテストでは捕まえられない
2. **検査を書いたら、その場で壊す。** Gateway の検査も、名簿の検査も、最初の版は
   壊しても赤にならなかった。書いた直後に壊さなければ、そのまま置かれていた
3. **新しい検査コマンドは、一度壊して確かめる。** 何も見ていないコマンドを「緑」と
   読み違えると、検査が無い状態より危ない
4. **守りを 1 段足したら、後ろの守りが今も踏まれているか確かめる。** 通関ガードを足した
   ことで、「荷受人の確認」の検査が空振りになっていた
