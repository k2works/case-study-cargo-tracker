## Skill 実行の時系列

### 1. `opening-iteration` — IT3 の開始準備

計画作成時の突合で**前提の欠落を 3 件**見つけた。

| 見つけたもの | 内容 |
| :--- | :--- |
| 港マスタが空 | `carrier_movement` は `location` への外部キーを持つため、**航海を 1 件も登録できない** |
| `voyage` にカラムが無い | 船名・運送会社・取扱貨物種別。IT2 の `cargo` と同じ型の欠落 |
| `domain-model.md` に要素が無い | `VesselName` / `CarrierName` / `RoutingCargoType` |

あわせて US06 の「通知が送信される」が ADR-006 により実体を持たないことを確認し、「経路割り当て待ち一覧に現れる」へ受入基準を修正した。**通知の実体が無いまま「送信される」と書き続けると、永遠に満たせない受入基準が残る。**

`release_plan.md` の SP 合計が 2 件ずれていたのもここで見つけた（US32・US34 を足したときに合計を更新していなかった）。

### 2. `orchestrating-development` — 実装

**返済枠から着手した。** ページ送り・バッジ色分け・荷主検索モーダル・キャンセル確認。IT2 の Try「返済枠を最初から時間で確保する」に従った。

途中で**日本時間 0〜9 時に当日着の予約が拒否される**バグを掘り当てた。アプリの時計が `Clock.systemUTC()` で、UTC ではまだ前日だったためである。たまたま日付をまたいだ時刻に作業していてテストが落ちた。

**正典のずれも 1 件。** `ui_design.md` の付録は「全 enum の日本語ラベルの正典」と宣言しているのに、実装は 3 件（仮受付 / 配達完了 / 精算済）が食い違っていた。**実装に合わせて正典を書き換えると、正典が正典でなくなる。** 宣言された正典に、実装・受入基準・マニュアル・要件定義を揃えた。

ドメインは中盤の規律どおり画面より先に固めた。`Schedule` の連結制約（区間 n の到着港 = 区間 n+1 の出発港）と時系列制約（着く前に次の船は出ない）は、**どちらも 1 行で完結せず行をまたぐため DB の CHECK 制約では守れない**。検証を外すと 4 件落ちることを実測してから採用した。

### 3. 方言差 3 回目 — 仕組みにする

キャプチャを撮ろうとして航路一覧が 500 になった。**`LATERAL` を H2 が解釈できない。** Testcontainers のテストは全部緑のままだった。

IT2 から数えて 3 回目である。

| 書いたもの | 症状 |
| :--- | :--- |
| `setval`（共通マイグレーション） | ローカル起動が Flyway で止まる |
| `INTERVAL 'N days'`（動作確認用データ） | 同上 |
| `LATERAL`（航路一覧のクエリ） | 画面が 500 |

ADR-003 は「H2 で緑だが本番で落ちる」方向だけを警戒していたが、**逆方向も同じ頻度で起きる**。人の注意に頼るのをやめ、全クエリサービスを H2 上で実行して「解釈できるか」だけを見る `H2DialectSmokeTest` を置いた。ADR-003 にも規律として追記した。

### 4. `closing-iteration` — CI が赤だった

クローズのステップ 2.5（CI 確認）で赤を見つけた。**ローカルは緑だった。**

原因は、**直したはずの不具合（UTC で業務日付を判断する）と同じ取り違えを、テストの側でしていた**こと。ローカル（JST）では一致するため見えず、CI（UTC）でだけ 1 日ずれた。しかも**同じ形が 4 ファイルに残っていた**。1 か所直して満足し、他を探さなかった。

Trivy も HIGH 2 件を検出していた。Checkstyle の推移的依存である。**ビルドツール自身の依存もスキャンの対象**であり、アプリの実行時に載らなくても CI のビルド環境で実行されるコードである。

### 5. レビューで行き止まりを見つけた

**経路割り当て待ち一覧から予約の内容を確認できなかった。** 一覧には出発地・目的地しか出ておらず、寸法や品名は見えない。経路設計者は一覧を見た後、何もできない状態だった。

IT2 の教訓（ロールへの開放を確かめる）は守れていたが、**「開いた画面から次に何ができるか」は別の観点**である。正典が定める残り日数の色分け（3 日以内は赤、7 日以内は橙）も実装していなかった。**画面遷移図は計画に載せたが、画面の中の要素表を突き合わせていなかった。**

予約詳細を経路設計者にも開放した（GET のみ。操作は営業担当者のまま）。**読むことと変えることは別である。**

## 学び

- **同じ型の失敗が 2 回続いたら、その場で仕組みにする。** 方言差は 3 回目でようやくスモークテストにした。1 回目の時点で「同じ型が続く」と読めたはずである
- **修正した層の「鏡像」を探す。** ある層の取り違えを直したら、`grep` で同じ形が他に無いか確認する。今回は `LocalDate.now()` が 4 ファイルに残っていた
- **クローズ前に CI と同じ条件で 1 度回す**（`TZ=UTC ./gradlew test`）。ローカルと CI の環境差は、環境差そのものを再現しないと見えない
- **ロール別の到達性と、画面から先への到達性は別の観点である。** 「開けるか」を確かめても「開いた先で何ができるか」は確かめたことにならない
- **正典が「自分が正典である」と宣言しているなら、実装をそちらに合わせる。** 実装に合わせて正典を書き換えると、正典が正典でなくなる
- **ビルドツール自身の依存も攻撃面である。** 本番に載らないことは、無視してよい理由にならない
- **業務日付は利用者の暦の上の概念である。** サーバの標準時で判断すると、時差の分だけ「当日」を拒否する時間帯ができる。日中しか動かさなければ一生気づかない
