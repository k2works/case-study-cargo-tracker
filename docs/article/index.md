# 記事

同一の題材（国際貨物輸送管理システム = Cargo Tracker）を素材にした 2 つの記事シリーズです。

いずれも DDD・ヘキサゴナルアーキテクチャ・CQRS によるモジュラーモノリスを、XP のイテレーション単位で追います。「何を作ったか」ではなく **各イテレーションで何を判断し、何を間違え、どう直したか** を記録することを主眼にしています。

## シリーズ一覧

| シリーズ | 軸 | 言語 | 章数 | 主題 |
| :--- | :--- | :--- | ---: | :--- |

| [関数型ドメインモデリング](functional-domain-modeling/index.md) | F#（IT1〜IT8） | 1 言語 | 11 | 業務ルールをどこまで型に埋め込めるか |

### モノリスアーキテクチャ実装比較

Java（Spring Boot）実装の 10 イテレーションを骨格に、各章末で他 9 言語（C# / F# / Scala / Haskell / Flix / Rust / Go / Ruby / TypeScript）が同じユーザーストーリーをどう実装したかを比較します。

型システム・エコシステム・境界の防御手段の違いが、同じ要件に対してどう表れるかを横断的に扱います。

> [シリーズを読む](monolith-architecture/index.md)

### 関数型ドメインモデリング

F#（Giraffe）実装の 8 イテレーションを追い、**不正な状態を表現不可能にする**という設計手法が実際の業務システムでどこまで通用するかを検証します。

スマートコンストラクタ、和型による条件付き必須の排除、状態がデータを持つ状態機械、Railway Oriented Programming の 4 技法が中心です。手法が届かなかった領域も同じ比重で扱います。

> [シリーズを読む](functional-domain-modeling/index.md)

## 読む順序

- **多言語比較から入る** — 設計判断の幅を先に把握したい場合は [モノリスアーキテクチャ実装比較](monolith-architecture/index.md) から。第 1 章で全体像、第 12 章で総括が読めます
- **関数型設計から入る** — 型による設計に関心がある場合は [関数型ドメインモデリング](functional-domain-modeling/index.md) から。第 1 章に技法がまとまっています
- **両方を突き合わせる** — 2 系列は相互に参照しています。同じ要件（貨物種別の条件付き必須、状態遷移、金額計算）を両シリーズで比較すると差が鮮明になります

## 参照元ソース

## 要件

各章が扱うユーザーストーリー（US01〜US23）と受入基準は、[要件](../requirements/index.md) を参照してください。記事側では要件の全文を再掲せず、イテレーションごとに対象ストーリーの ID と要点だけを示しています。

| ドキュメント | 内容 |
| :--- | :--- |
| [要件定義書](../requirements/requirements_definition.md) | システム価値・外部環境・境界・内部構造（RDRA 2.0） |
| [ビジネスユースケース](../requirements/business_usecase.md) | 業務視点のユースケース |
| [システムユースケース](../requirements/system_usecase.md) | システム視点のユースケース |
| [ユーザーストーリー](../requirements/user_story.md) | 各ストーリーの本文と受入条件（US01〜US27） |

10 実装はいずれもこの要件を正典としており、**ストーリー ID が共通であることが言語横断比較の接続点**になっています。イテレーション数は言語ごとに 7〜12 と異なりますが、同じ US を軸に突き合わせられるのはこのためです。

両シリーズが扱うのは US01〜US23 です。認証・航海マスタ管理にあたる US24 以降は、実装ごとに採否と割り当てイテレーションが分かれるため、比較の軸には含めていません（F# シリーズでは US24・US25 を IT3 の対象として扱います）。
