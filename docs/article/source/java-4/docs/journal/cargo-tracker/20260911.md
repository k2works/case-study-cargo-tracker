# 2026-09-11 IT13 の開発とクローズ

## この日やったこと

IT13（US21 輸送料金を算出する・US22 法人割引を適用する）の開発フェーズとクローズを通しました。
billingms を新しい BC として立て、引取完了から請求の算出・調整までを繋ぎました。

## 判断の記録

### 検査を足したのに、その検査は 1 度も走っていなかった

この IT でいちばん重い欠陥です。時限式の赤（受入フィクスチャの固定日付）を防ぐ規約テストを
3 本足したのですが、同じ変更で `shared/build.gradle.kts` に書いた入力宣言のパスを間違えました。

```kotlin
inputs.dir(rootProject.file("../../frontend/src"))  // 実在しない
```

存在しないディレクトリを入力に宣言すると、`:shared:test` はタスクの構成時点で落ちます。
つまり **shared のテストが 1 本も走らない**。ビルドは確かに赤かったのですが、私はその赤を
同時に進めていたカバレッジ作業のせいだと決めつけ、パスを見ていませんでした。

直した瞬間、その規約テストは計画書に書かれた 2 つの実在しないクラス名を見つけました。
本来こうなるはずだったものが、丸一日遅れて起きたわけです。

ふりかえりの Try に 2 つ落としました。**「検査を足した変更では、その検査を 1 度赤にする」**と
**「赤の理由を推測しない」**。後者は特に、同時に 2 つの作業を走らせているときに効きます。

### IT12 の「この版に手立てが無い」は誤りだった

IT12 のふりかえりで、死信キューの系列を貨物ごとに割る手段が Axon 5 には無い、と記録していました。
今回改めて当たると `@SequencingPolicy(type = PropertySequencingPolicy.class, parameters = "...")` で
できました。

記録を消さず、ADR-0014 に決定 4 と但し書きを足す形にしました。誤った結論も、いつ・なぜそう
判断したかが残っていないと、次に同じ調査をする人が「前に無理と言われた」で止まります。
そして新しい振る舞いは `anotherCargoIsNotParkedByAPoisonEvent` で固定しました。

### 請求 ID がカラムに入らず、投影だけが静かに死んだ

`INV-` + UUID で 40 文字。集約は受け取り、イベントも流れ、投影の INSERT だけが `VARCHAR(36)` に
入らず死信に落ちました。単体テストは全部緑です。見つかったのは画面から踏んだときでした。

**層ごとの検査は自分の層しか見ない**——この教訓は何度目かですが、今回は「集約が受け付けた値が
投影のスキーマに収まるか」という、層の**あいだ**にある制約でした。`INV-yyyyMMdd-8hex` に直し、
長さそのものを見る回帰テストを置きました。

### 料率を bookingms に写さなかった

US08・US09・US12 の「費用」に関する受入基準を、この IT の料率で満たせないかと考えました。
できますが、料率表が 2 か所になります。ADR-0016（料率は設定に置く）の決定 1 と真っ向から
ぶつかるので、見送りました。あの受入基準は見積（US01, IT14）の担当です。

同じ理屈で「請求を手動で開始する API」も作りませんでした。あれば便利ですが、引取から請求への
連鎖が止まっていることを隠してしまいます。

## 詰まったこと

- **2 つのサービスが 1 つの JVM に載ると `application.yml` は片方しか読まれない**。契約の往復テストが
  起動できず、料率が null になりました。`billing-rates.yml` に切り出して `spring.config.import` で
  取り込む形に。
- **調整の明細がリプレイで増える**。`MAX(line_seq)+1` は冪等ではありません。`source_event_id` を
  足して部分一意インデックスと `ON CONFLICT DO NOTHING` で塞ぎました。追記専用の行はリプレイで
  増える——これも繰り返し出てくる形です。
- **`until ! pgrep -f "gulp k8s:images"` が永久に回る**。ループ自身のコマンドラインが `pgrep` に
  一致していました。
- **ビルド中にソースを触った**のを 2 度やり、そのたびに止めて回し直しました。

## 学び

レビューを**クローズの最初**に起動する運用（IT12 の Try）は今回も効きました。5 視点すべてが
3〜6 分で返り、64 件・うち高が 18 件。高は全部クローズ前に直せました。12 件は IT14 へ渡して
あります（確認証跡・再算出の入口・調整の取り消し——この 3 つは US23 の発行より前に要ります）。

今回の 3 つの主要な欠陥（走らない規約テスト・カラム長・調整の重複）はどれも、
**「緑である」ことと「守っている」ことが別物**という同じ形をしています。前者は緑ですらなかった
（赤を読み違えた）という点で、いちばん質が悪いものでした。
