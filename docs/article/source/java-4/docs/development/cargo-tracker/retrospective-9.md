**本 IT で handlingms が動き出しました。** 新設 BC が 1 つ、契約イベントが 2 本、投影が 3 つ、画面が 2 つ増え、荷役から貨物状態と予約へ連鎖する経路ができました。

同時に、**このプロジェクトで最も多くの実欠陥が見つかった IT** でもあります。着手前の検証で 3 件、クローズのレビューで 10 件、フルビルドと実クラスタで 4 件。**すべて緑のテストの下にありました。**

## Keep（続けること）

### K1: 並列レビューが自分では見えない欠陥を 10 件出した

5 視点が 10 分以内に全数返着し、**高 10 件すべてがクローズ前に直りました**。うち **5 件は複数の視点が独立に同じ場所を指しました**。

| 欠陥 | 指摘した視点 |
| :--- | :--- |
| 冪等キーが再送のたびに変わる（押し直すと二重記録） | user・writer・tester |
| 取り消しが画面から実演できない（`voidHandling` が参照 0 件） | user・writer・tester |
| 作業日時が入力できず US15 §3 が未達 | user・writer・tester |
| 最後でない荷役の取り消しで貨物状態が巻き戻る | programmer・architect |
| ADR の検査名が実在しない・正典の図が旧イベント名 | architect・writer |

**1 本だけなら「気になる」で終わったものが、3 本が同じ場所を指すと「直すべきもの」に変わります。** これがレビューを 5 本並べる価値でした。

### K2: 着手前の検証が「実装不能な正典」を 1 件止めた

IT8 のふりかえり Try T5（正典の元イベントが購読できるか着手前に `grep` する）が効き、`cargo_snapshot` の元イベント `TrackingNumberIssuedEvent` が **bookingms の内部イベントで handlingms から購読できない**ことを着手前に見つけました。ADR-0012 で決め直し、実装は詰まらずに進みました。

### K3: 「壊して赤を見る」を 5 回実施した

ダッシュボードの導線・反応ハンドラの引数（`finalPort` と `offRoute` の入れ替え）・冪等キー・`AdrHasChecksTest`・`TransportStatus` の規約。**とくに反応ハンドラは、入れ替えても全テストが緑**でした——検査を足したうえで壊して確かめなければ、空振りに気づけませんでした。

## Problem（問題だったこと）

### P1: 「文書に書いた保証」が 7 件、実装を伴っていなかった

高 10 件のうち 7 件がこの型です。

- 「再送しても同じ鍵になる」——**4 か所**（画面のコメント・`api.ts` の javadoc・集約の javadoc・マニュアル）が書いていたのに、`mutationFn` の中で毎回採番していた
- 「これは警告ではなく拒否」（不変条件 4）——`requiresCustomsClearance` は本番コードから 1 度も呼ばれていなかった
- 「重複登録の 5 分規則は集約が守る」——**集約では守れない**（1 作業 1 集約なので他の作業を知らない）
- ADR-0012 決定 4 の検査名——クラスもメソッドも存在しなかった
- マニュアルの「履歴から取り消します」「過去の日時は入れられます」——どちらも画面に無かった

**自分が書いた保証ほど疑いにくい。** 書いた時点では本当にそうするつもりで、書いたことで満たした気になります。

### P2: 受入基準を 1 項目ずつ表にしていなかった

計画の成功基準に**書いてあったのに**やりませんでした。tester のレビューが表を作って初めて **US15 §3（作業日時）の未達**が見つかりました。自分で作っていれば実装中に気づけたはずです。

### P3: 値を足したあと、全層を読み直していなかった

これも成功基準にありました。読み直していれば、**取り消しの配線漏れ**（api.ts にあるのに画面が呼ばない）と**作業日時の未送信**（サーバは受けられるのに画面が送らない）は自分で見つかりました。

### P4: フルビルドと実クラスタでしか出ない欠陥が 4 件

| 欠陥 | どこでだけ赤になるか |
| :--- | :--- |
| 適用済みマイグレーション V004 への追記（checksum 不一致） | **実クラスタだけ**。CI は新しい DB に当てるので緑 |
| `TransportStatus` の `IllegalArgumentException`（規約テスト） | **フルビルドだけ**。shared の規約テストはモジュール単位では走らない |
| `TrackingQueryHandler` の `Instant.now()`（ArchUnit） | 同上 |
| 予約一覧の上限で新規予約が見えない | **実クラスタだけ**。テストデータが少ないと起きない |

**モジュール単位のテストは自分の層しか見ません。**

### P5: クラスタ E2E を US ごとに回さず終盤に集めた

IT8 の Try T2 が守れていない **2 回目**です。US15 が 1 本の IT だったことも理由ですが、T7（S50）を終えた時点で 1 度回していれば、取り消しと作業日時の欠落は**レビューを待たずに**見つかりました。

### P6: レビュー結果が 5 本中 4 本、長さ制限で切れて届いた

続きを個別に求める往復が発生しました。最初から出力の形を指定していれば避けられました。
