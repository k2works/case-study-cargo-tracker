# イテレーション 8 ふりかえり

| 項目 | 内容 |
| :--- | :--- |
| イテレーション | IT8（Release 1.0 追跡と荷役・中盤） |
| 対象 | US18 追跡情報を照会する（5）・US17 貨物状態を手動更新する（3） |

| 実績 SP | **8**（達成率 100%。8 回連続） |

**本 IT で貨物が外から「見える」ようになりました。** 認証を通らない経路を初めて作り、追跡番号の形式・レート制限・情報の出し分けという「認証が無い前提の守り」を一式そろえました。

## Keep（続けること）

### K1: 着手前の検証が US18 の前提そのものを止めた

自己検証で**追跡番号が正典違反**（`TRK-` + 英数 10 桁のはずが `T-2026-000001` の連番）だと分かりました。US18 の照会は認証不要なので、連番のまま公開すれば 1 つ知れば前後がすべて読めます。**実装ではなく実データで裏を取った**のが効きました——クラスタに `-000001`・`-000005`・`-000007` が並んでいました。

さらに**検証エージェント 2 本が遅れて返着**し、高 4 件・中 5 件が入っていました。特に「**総当たり対策の 429 が実体を持たない**」（gatewayms に実装 0 件）は、括弧書きのまま実装されずに終わるところでした。IT7 のクローズでは「返らない」と判断して自己レビューで確定させましたが、**待つ価値がありました**。

### K2: 「壊して赤を見る」を 3 回実施した

- 例外発生中の手動更新を許すように守りを外す → 該当テストだけが赤
- 認証ストアの保存先を `localStorage` にする → 該当テストが赤
- 荷主の差し込み行を消す → 該当テストが赤

**書いた保証を赤で固定する**が習慣として定着してきました。

### K3: 配線の検査を層ごとに足した

`@MessageIdentifier` の解決（`TrackingStatusUpdateIT`）とレート制限フィルタの登録（`PublicTrackingRateLimitWiringIT`）は、**どちらも単体テストでは判別できません**。層が全部緑でも配線は未検査、という IT7 の教訓を先回りして潰せました。

### K4: 引き継ぎ枠を Day 1 で返す形が 4 回続けて機能した

H.1〜H.3 を Day 1 に消化し、本体（US18・US17）に食い込みませんでした。

## Problem（問題だったこと）

### P1: 正典が実装不能な指定をしていた（2 件目）

`data-model.md` は `shipper_cargo_snapshot` の元イベントを `TrackingNumberIssuedEvent`（契約）と書いていましたが、**これは bookingms の内部イベントで `shared/contract` に無く、trackingms からは購読できません**。IT7 の「投影の元イベントがその BC から購読できるか確かめる」と同じ形が再発しました。

着手前の検証で気づけたのは「契約ではない」ことまでで、**表そのものが要らない**（`tracking_summary.shipper_id` と同じ情報になる）と分かったのは実装中でした。

### P2: `SELECT *` が列順マッピングで壊れた

注釈ベースの MyBatis マッパーで `SELECT *` を record に割り当てると、名前ではなく**列の順**で決まります。`ALTER TABLE` で足した列は末尾に来るので、record の途中に項目を足した瞬間に全部ずれました。**落ち方が原因を指しません**——「TIMESTAMPTZ の列に `evt-1` が入らない」という無関係な例外になりました。

### P3: SonarQube をクローズで初めて回した（IT7 と同じ）

計画の成功基準に「US ごとに 1 度回す」と書いていたのに、**クローズで初めて回して 4 件をまとめて直しました**。IT7 でも同じことを書いて同じように守れていません。**書いただけで守られない約束**の典型です。

### P4: クラスタ E2E を 1 度しか回さなかった

「Day 9 に 1 度、クローズ前にもう 1 度」と決めていましたが、実装の終盤に 1 度だけでした。早く回していれば、**荷主が上限を超えると予約が取れない欠陥**をもっと早く見つけられました。

### P5: 検査の足場が環境で壊れた（Node 25）

`authStore.test.ts` が `localStorage.getItem is not a function` で落ちました。**Node 25 が `localStorage` を組み込みで持つ**ようになり、Vitest が jsdom のものに差し替えないため、空の器が残っていました。実装は正しく、壊れていたのは足場です。原因の特定に 40 分ほどかかりました。

### P6: クラスタのイメージ入れ替えが途中で止まっていた

`k8s:load` が中断し、frontend・billingms・www が 4 時間前のイメージのままでした。**古いバンドルに対して E2E を回して 3 件が赤**になり、原因の切り分けに時間を使いました。「同一タグのイメージは作り直す」の教訓を持っていたのに、**作り直したあと載ったことを確かめていませんでした**。
