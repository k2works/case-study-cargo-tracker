## Keep

### Try T3 を 3 回目でようやく守った

IT8・IT9 は「クラスタ E2E を終盤にまとめる」形で 2 回続けて守れませんでした。IT10 は
**計画の段階で T2e・T6e という独立したタスク行を立て**、US を閉じる前に実際に回しました。

守れた理由は「気をつける」ではなく**タスク行にしたこと**です。計画の検証（`validating-design`）が
「Try T3 は『タスク行に立てた』と書いてあるが、実際には T10 が終盤にまとめている」と指摘し、
着手前に直せました。

そして **T2e が実際に 2 件の欠陥を出しました**——投影の書き手漏れと、予約／輸送の
`DELIVERED` の呼び名重複。どちらも層ごとの検査では出ません。

### 着手前の検証が正典側の欠落を 5 件見つけた

`validating-iteration-plan` と `validating-design` が、実装を始める前に
**`ShipperNotifiedEvent` の再利用が実装不能**（bookingms の内部イベントで trackingms から
発行も購読もできない）ことを見つけました。IT8 で `TrackingNumberIssuedEvent` に対して
起きたのと同じ形で、**2 度目は着手前に止められました**。

正典側の欠落は注 N1〜N5 として計画に明記し、当該 IT で反映しました。

### 並列レビューが 2 分で返り、出力の形が崩れなかった

Try T7（依頼文で出力の形を指定）が効きました。IT9 は 5 通中 4 通が途中で切れて追加の
やり取りが必要でしたが、**IT10 は 5 通とも「高と中だけ・1 件 1 行の表・3000 字以内」で
返り、切れたものはありません**。

### レビューの高 12 件をすべてクローズ前に直した

うち **5 件は複数視点が独立に指摘**しました。programmer と tester が同じ「記録したが
読めない」に達したのは、受入基準の「記録で満たす」という満たし方そのものが崩れていた
からです。

### 正典と突き合わせる canon テストが、書き写しのずれを見つけた

予約の状態の呼び名を正典と突き合わせる検査を足したところ、**4 件のずれ**が出ました
（経路通知済・予約確定・追跡番号発行済・配送完了）。既存の検査は「画面と実装が
揃っているか」しか見ておらず、**両方に同じ誤りを書き写したずれは緑のまま**でした。

## Problem

### P1: 「記録したが読めない」を 2 か所で作った

`ExceptionShipperNotifiedEvent` を購読する投影が無く、**US19 §3 は実質未達**のまま
「記録で達成」と計画に書いていました。対応開始の入力値も投影が捨てていました。

記憶にある教訓（「記録と読み口は対で出す」「値は全層を生き延びるか確かめる」）を
知っていながら、同じ IT で 2 回踏みました。**イベントを足したときに投影の受け口を
書いたか**を、機械的に確かめる手立てがありません。

### P2: 手動更新で引取済にできた

`CargoDeliveredEvent` を出すのは `advance` の 1 経路だけなのに、`isSetByHand` が
`DELIVERED` を許していました。**決定は経路を 1 度通す**という教訓の反対で、
契約イベントを足したときに「他にこの状態へ入る道はないか」を見ていません。

### P3: フルビルドを 5 回失敗させた（すべて実行の仕方）

- クラスタ E2E と同時に走らせ、CPU の奪い合いで双方を落とした（IT9 と同型）
- `--stop` を打って走っていたビルドを自分で止めた
- コミットフックとビルドを 1 本のコマンドに繋いで詰まらせた
- build ディレクトリの破損が 3 度（並行実行によるもの）

実装は正しいのに、**検証の段取りで 1 時間以上を失いました**。

### P4: `gulp k8s:images` がイメージを作り直さず、クラスタが IT9 のコードを動かしていた

「作り直した」という出力を信じて E2E を回し、**荷受人の確認なしの引取が 201 で通る**のを
見て実装を疑いました。実際にはイメージが 7 時間前のままでした。

加えて、zsh の `:l` 修飾子で `-t cargo-tracker/$s:latest` が `cargo-tracker/trackingmsatest`
に化け、壊れたタグを 3 つ作りました。

### P5: 品質ゲートの結果をコミットに書く習慣が 2 IT 続けて根付かない

IT9 に続き IT10 も未達です。「習慣にする」では 2 回とも守れませんでした。

### P6: 受け入れテストの feature が実装の変更に追随せず、CI だけが赤になった

呼び名を正典に揃えたとき、ステップ定義の対応表は直したのに **feature ファイルの
シナリオ文言が別ファイルにあり**、フルビルドで初めて赤になりました。同じことが
「引取済は手で選べない」でも起き、こちらは CI で初めて出ました。
