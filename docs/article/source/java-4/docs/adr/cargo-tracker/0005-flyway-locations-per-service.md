# ADR-0005 Flyway のマイグレーションをサービス名のサブディレクトリに分ける

各サービスのマイグレーションを `classpath:db/migration/<サービス名>/` に置き、`spring.flyway.locations` でサービスごとに指定する。共有の `classpath:db/migration` は使わない。

日付: 2026-09-04

## ステータス

2026-09-04 提案されました

## コンテキスト

IT2 のふりかえりで、契約イベントが**実際に別サービスへ届くこと**を確かめる検査（返済枠 R.1）を IT3 で入れると決めた。IT2 までの契約テストは、送り手の側でイベントの形を固定するだけで、受け手がそれを読めるかは見ていない。

往復を確かめるには、送り手（bookingms）と受け手（billingms）を同時に起動して、Axon Server を挟んだ実際の経路を通す必要がある。Testcontainers の Axon Server を 1 つ共有し、2 つの `SpringApplicationBuilder` を同じ JVM に載せる形にした。

ここで Flyway が止まった。

```
Found more than one migration with version 001
```

各サービスは `classpath:db/migration/V001__create_axon_tables.sql` を持っている。1 サービスだけを起動する分にはそれぞれの jar しかクラスパスに無いので衝突しないが、2 サービスを同じ JVM に載せると両方の `V001` が同じ場所に見える。

回避の案は 3 つあった。

1. **サービスごとに番号の帯を割り当てる**（bookingms は 001〜099、routingms は 100〜199 など）。サービスが増えるたびに帯を配り直すことになり、番号を取るのに他サービスの表を見る必要が生じる
2. **契約の往復をやめ、送り手側の固定で済ませる**。IT2 のふりかえりで「届くことを見ていない」と自分で書いた指摘を取り下げることになる
3. **置き場をサービス名で分ける**

## 決定

置き場をサービス名のサブディレクトリに分ける（案 3）。

1. マイグレーションは `<service>/src/main/resources/db/migration/<サービス名>/` に置く
2. 各サービスの `application.yml` で `spring.flyway.locations: classpath:db/migration/<サービス名>` を指定する
3. **ファイル名（`V001__create_axon_tables.sql` など）は変えない**
4. 同じ JVM に複数サービスを載せるテストでは、起動引数で `--spring.flyway.locations` を明示する（`application.yml` は 1 つしか読まれないため）

## 根拠

**番号の取り合いが構造的に起きなくなる。** サービスは自分の番号だけを見ればよく、他サービスの表を読む必要がない。新しいサービスを足すときに帯を配り直す作業も無い。

**適用済みの環境を壊さない。** `flyway_schema_history` の `script` 列はファイル名だけを保持し、ロケーションのパスは入らない。ファイル名を変えなかったので、すでに適用済みのクラスタでも checksum mismatch は起きない。既存環境を壊さずに移せるのは、この決定を今のうちに入れられる理由でもある。

**「同じ JVM に複数サービス」は今後も要る。** 契約の往復は BC が増えるほど検査対象が増える。IT3 の時点で片付けておかないと、後になるほど移行するファイルが増える。

## 影響

- 8 サービス全ての `application.yml` に `spring.flyway.locations` の指定が要る。**指定を忘れたサービスは `classpath:db/migration` を見に行き、マイグレーションが 1 つも見つからないまま起動する**（テーブルが無いという別の症状で出る）
- 契約の往復テストでは起動引数で明示する必要がある。忘れると片方のサービスがもう片方のマイグレーションを適用し、`BadSqlGrammar` で落ちる（IT3 で実際に踏んだ）

## 代替案

- **番号の帯を割り当てる**: サービスが増えるたびに帯の配り直しが要る。番号を取るのに他サービスの表を読む必要が生じ、取り違えは「衝突」ではなく「順序の入れ替わり」として静かに出る
- **契約の往復をやめる**: 送り手側の固定だけでは、受け手がイベントを読めるかを判別しない。IT2 で自分が挙げた指摘を取り下げることになる
