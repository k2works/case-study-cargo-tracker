# イテレーション 8 マルチパースペクティブレビュー

日付: 2026-08-23
対象: IT8（US17 貨物状態の手動更新・US18 追跡情報の照会・US19 遅延例外・US20 破損/紛失例外、9 SP／返済枠 10 件）
差分: `origin/java/take-7..HEAD`（137 ファイル・9,032 追加）

## 総合評価

**荷主が自分で貨物を追えるようになった**——IT8 の中心はここで、公開の追跡照会は認証の外に置かれ、返す項目は列挙で縛られている。ADR-024 の 11 決定は構造にそのまま現れており、集約に判定を寄せる規律・公開 DTO の分離・名簿を使わない認可検査は、IT7 のふりかえりから引き継いだ学びが形になったものである。

一方で、**5 視点が独立に同じ 2 つの形を指摘した**。

1. **宣言した性質を、コードが持っていない**（IT7 Problem 1 の再発）。とくに `X-Forwarded-For` は「そのまま信じない」と書きながら**最も信じてはいけない値**を採っており、**検査がその誤りを期待値として固定していた**
2. **表に書いたことで、確かめた気になっている**（IT7 Problem 3 の再発）。ADR-024 のコンプライアンス表 11 件のうち 3 件（決定 3・6・9）が実質的に空振りしていた

加えて **正典ドリフト**が本 IT 最大の量的問題である。計画が自ら挙げた「設計への反映が必要な箇所 13 件」のうち、レビュー時点で反映されていたのは 1 件だけだった。

## 5 視点が独立に指摘した形

- **荷役作業員が例外を起票できない**（architect・writer・user-rep の 3 視点）
