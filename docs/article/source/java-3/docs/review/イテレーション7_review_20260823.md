# イテレーション 7 レビュー結果

日付: 2026-08-23
対象: IT7（US15・US16、返済枠 0.1〜0.12）。`git diff 5d83af8b9..HEAD`（74 コミット・320 ファイル）
視点: xp-programmer / xp-tester / xp-architect / xp-technical-writer / xp-user-representative

## 総合評価

**IT6 のふりかえりで挙げた「規則を 1 か所に寄せる」は、構造として実現できた。** `HandlingType` が要件を持ち、`CargoSnapshot#isOffRoute` が照合を持ち、`ServiceArchitectureTest` が規則の適用側を奪った形は、5 視点すべてが評価している。

一方で高優先度の指摘が **11 件**出た。形は 3 つに分かれる。

1. **コメントが宣言した性質を、コードが持っていない**（3 件）— 「戻せる遷移は作らない」「書き込まない」「追跡管理者も見られる」
2. **検査が届いていない層がある**（4 件）— `offRoute` を応答・イベントで潰しても緑、追跡番号での照会が実 DB で未実行、否定の決定 2 件が文章のまま
3. **メニューに出しておきながら、そのロールで何もできない**（2 件）

**11 件すべてクローズ前に対応した。**

### 対応の過程で見つかったもの

- **空欄の作業日時が「2000-01-01 の作業」として記録される。** `new Date(':00Z')` は例外にならず 2000 年として読まれる。writer は `RangeError` になると報告したが、実測すると**もっと悪い壊れ方**だった（誤った値が記録される）。形式を明示的に検査し、存在しない日（2027-02-30 → 3/2 に繰り上がる）も読み戻しで弾くようにした
- **コンテナ起動の競合でビルドが不定期に落ちる。** クローズ作業中に 4 回踏んだ。サブプロジェクトを並列に走らせると Testcontainers が同時に何個も立ち上がる。Gradle のビルドサービスでテストだけを直列化した。**再実行で通るため「たまに落ちるテスト」として放置されやすい**

## スコープ外の発見

- `Cargo.canReviseSchedule` が `BookingStatus` を見ていない。現在の遷移では到達しないが、US30（キャンセル）の実装時に見直す

## 特筆すべき点

**5 視点のうち 3 つが独立に同じ欠陥（追跡の巻き戻り）を指摘した。** programmer は Javadoc とコードの食い違いとして、architect は契約の語彙の問題を追う中で、tester は再配送の検査が無いこととして。いずれも「全テストが緑のまま」潜んでいた。

**指摘の再現性を確かめてから直した。** writer が報告した `RangeError` は、実測すると別の（より悪い）壊れ方だった。報告をそのまま信じて直していたら、2000 年として記録される形は残っていた。
