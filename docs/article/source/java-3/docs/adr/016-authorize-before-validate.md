# ADR-016: 入力の検査は認可のあとに、メソッド本体で行う

権限の検査を、入力の検査より先に走らせる。そのために `@Valid` / `@Validated` をパラメータに付けず、入力の検査はメソッド本体で明示的に呼ぶ。

日付: 2026-08-21

## ステータス

承認済み

## コンテキスト

IT3 の kind 統合環境で、**権限の無い呼び出しに 400（入力の誤り）が返る**欠陥が見つかった。原因は Spring の仕組みそのものにある。`@Valid` をパラメータに付けると、検証は**引数の解決時**、つまりメソッド本体に入る前に走る。本体の先頭で権限を検査していても、本文が不正ならそこへ到達しない。

これは 2 つの問題を起こす。

1. **本人に間違ったことが伝わる。** 「この操作はできない」ではなく「入力を直せ」と読める。入力を直しても結局できないので、利用者は何が起きているか分からない
2. **権限の無い相手にエンドポイントの入力仕様を教える。** どの項目が必須で、どの形式を求めるかが 400 の本文から読み取れる

IT3 ではこの欠陥を bookingms で見つけ、両サービスの実装を直したが、**規則としてはどこにも記録しなかった**。ADR-004 はロール認可を、ADR-007 は利用者ヘッダの必須化を決めているが、どちらも順序には触れていない。

IT3 のふりかえりは「文章だけでは半分しか守られない」ことを実証している（[ADR の規則は同じ変更で検査に落とす](../development/retrospective-3.md)）。IT4 は新しいエンドポイント（経路候補算出）を足すため、規則が実行される形になっていなければ同じ欠陥がそこで再発する。

## 決定

1. **認可を、入力の検査より先に行う。** コントローラのメソッドは、権限の検査を最初に実行する
2. **`@Valid` / `@Validated` をパラメータに付けない。** 入力の検査は `Validator` をメソッド本体で明示的に呼ぶ。順序をフレームワークの都合ではなく、コードの並びで決められるようにする

### 対象

**認可の対象となるエンドポイント**、すなわち Gateway が付けた利用者ヘッダ（`AuthenticatedUser.USER_ID_HEADER`）を受け取るメソッドに適用する。ログイン（`POST /api/v1/auth/login`）のように認可が存在しない入口には、隠すべき権限差が無いため適用しない。

**免除するサービスやクラスを名簿で挙げない。** 対象はコードの形（利用者ヘッダを受け取るか）から導く。載せ忘れたものほど無検査になる名簿方式を避けるためである。

### 代替案

- **`@Valid` を使い、認可を `HandlerInterceptor` / `@PreAuthorize` で前段に置く**: 順序は解決するが、認可の判断がコントローラから離れる。本システムの認可は「ロール」だけでなく「その予約が経路設計者に開かれているか」といった業務判断を含む（[ADR-015](015-routing-requested-state.md)）ため、集約の述語を呼べる場所に置きたい
- **規約として文書に書くだけにする**: IT3 がまさにそれをして、規則が記録されないまま実装だけが直った。次のエンドポイントで再発する

## 影響

### ポジティブ

- 権限の無い呼び出しには、常に 403 が返る。利用者に伝わることが一つに定まる
- 入力仕様が権限の無い相手に漏れない
- 検査が構造的なので、**新しいエンドポイントを足して `@Valid` を付ければ、それだけで落ちる**

### ネガティブ

- **Spring の標準的な書き方から外れる。** `@Valid` は多くの Java 開発者にとって既定の選択であり、この規則を知らない人は「なぜ手で呼んでいるのか」と考える。ADR へのリンクをコード上のコメントに残す
- 各コントローラが `Validator` を持ち、`validate()` を呼ぶ定型が増える

## コンプライアンス

- `HexagonalArchitectureRules.validationAfterAuthorizationRule()` が、利用者ヘッダを受け取るメソッドのパラメータに `@Valid` / `@Validated` が付いていないことを全サービスで検査する。各サービスの `ArchitectureTest` から呼ぶ
- 適用漏れは `ArchitectureRuleCoverageTest`（shared のメタテスト）が検出する
- 各コントローラのテストに「本文が不正でも、権限が無ければ 403」を置く。**bookingms・routingms の双方で、順序を戻すと赤になることを確認済み**（IT4 で実測）
