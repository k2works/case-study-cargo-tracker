# イテレーション 8 完了報告書

日付: 2026-08-23
対象: IT8（US17 貨物状態の手動更新・US18 追跡情報の照会・US19 遅延例外・US20 破損/紛失例外）
計画 SP: 9 ／ 実績 SP: 9（達成率 100%）

## エグゼクティブサマリー

**荷主が自分で貨物を追えるようになった。** 追跡番号を入れれば、ログインなしで状態・現在地・到着予定日・履歴・お知らせが見える。IT7 までは追跡の状態を見られるのは DB とデモだけで、荷主には何も届いていなかった。

あわせて **追跡管理者の担当画面が初めて実装された**。このロールは IT7 の時点で「荷役の履歴しか見られない」状態にあり、ダッシュボードを開くと「担当の画面は次のリリースで使えるようになります」だけが出ていた。IT8 でその本体が入った。

**返済枠は 10 / 10 完了**（IT7 に続き 2 IT 連続）。

本 IT の特徴は、**実環境とレビューでしか出ない欠陥が集中した**ことである。単体・契約・往復テストがすべて緑のまま kind で 1 件、クローズレビューで高優先度 11 件が出た。うち 2 件は**検査が誤った実装を固定していた**。

### スコープ外にしたもの（理由つき）

- **メールの送信**（US17-4・US19-3・US20-4）。**代替**として、通知した事実を記録し荷主の画面に出す（[ADR-024](../adr/024-tracking-manual-update-and-exceptions.md) 決定 9）。メール送信の実装は Release 1.1 以降。**Release 0.2 の「US18 が出るまで無効化」という制約は US18 では解けない**ことが分かり、文言を「メール送信を実装するまで」に直した
- **`ROLE_SHIPPER` への予約参照開放**（決定 10）。[ADR-008](../adr/008-no-user-shipper-link-in-it2.md) が「US18 で広げ直す」と約束していたが、**US18 の受入基準では果たせない**——US18 は追跡番号だけで照会するストーリーで、利用者と荷主を結ぶキーを必要としない。**紐付けを扱うストーリーは、いまのリリース計画に無い**
- **`MISROUTE` / `CUSTOMS_HOLD` の起票**（決定 11）。誤配は US28（IT10）、税関保留は US29（IT9）が自動で検知する
- **`TrackingExceptionDetectedEvent` / `CargoDeliveredEvent` の発行**（決定 8）。購読者がいない。**発行しないことを検査に落とした**（`TrackingPublishesNothingTest`）

## 技術的成果

- **trackingms が読み書きの両方を持った。** IT7 までは状態を 1 列持つだけで、外から触れる入口も履歴も例外も無かった。公開照会 API・管理 API・履歴・例外・通知の代替・照会ログ・レート制限が入った
- **認証の外にある業務経路が初めてできた。** `/api/v1/public/` を接頭辞で分離し、[ADR-007] のフィルタからこの 1 本だけを除外した。**除外を両方向で検査している**——公開は開き、それ以外は閉じる
- **例外の発生前状態を列に持った**（決定 2）。履歴から再導出しない。**永続化のテストは「保存して読み直してから解決する」形**で、これが再導出と本物の永続化を見分ける唯一の形である
- **返済枠 10 件**。うち 0.3 は実バグ（`EXCEPTION` / `UNKNOWN` にいる貨物がどこへでも進める）を閉じた

## 実環境（kind）での確認

- **V4 マイグレーションが適用された**（`Successfully applied 1 migration ... now at version v4`）
- **公開の追跡照会が、認証なしで 200 を返す**
- 予約 → 通知 → 確定 → 追跡番号の発行を新しい貨物で通した

> **kind の検証で、テストが 1 つも捕まえられなかった欠陥が出た。** `CargoRoutedEvent` を独立したイベントにした設計は、単体・契約・実 RabbitMQ の往復がすべて緑のまま、**推定到着日が届かなかった**。2 つのイベントが別々のキューを通るため順序が保証されず、追跡の作成より先に届いた到着日が捨てられていた。1 つのイベントに畳み、経緯ごと ADR へ残した。

## 課題と残作業

### 運用で埋めるもの（IT9 まで）

- **例外の連絡は、追跡管理者から営業へ口頭で行う。** 荷主は公開画面で「ご依頼元の営業担当へ」と案内されるが、**営業のダッシュボードには例外に気づく手段が無い**。営業は電話を受けてから追跡管理者を探すことになる
- **予定外の作業が業務として処理されない**（待ち行列は US28・IT10）。公開追跡が開いたことで、**予定外のまま放置された貨物の状態を荷主が見る**ようになった。誰が、どの頻度で拾うのかを決める
- **総当たりの上限（1 分 30 件）はプロセス内で数える。** trackingms を N 台にすると実効の上限は N×30 になる。**台数を増やすときは閾値を割る**
