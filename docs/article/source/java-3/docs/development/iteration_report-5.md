## レビュー結果

高 12 件 / 中 17 件 / 低 7 件。**高はすべて対応済み。**

とくに重かった 3 件。

1. **接続先の既定値が bookingms 自身を指していた。** どの環境でも経路の確定が必ず失敗する状態で、全テストが緑だった。ACL の単体テストは別 URL で bind し、実バックエンド E2E は確定パスを踏まずに緑になっていた
2. **緩めた期限・出発希望日では確定できなかった。** サーバは予約の条件で再検証するため必ず 409 になり、しかも理由が「航海スケジュールが変わった」に見えた。業務上も荷主の合意が要るため、緩めている間は確定させない形にした
3. **経路設計者の一覧が、割り当て済み・差し戻し済みの予約を落としていた。** 判定が詳細（集約の述語）と一覧（コントローラの固定値）に分かれており、詳細だけを広げていた

中のうち、契約テストの名簿のリフレクション化・再検証失敗専用の例外型・地点マスタの N+1 は IT6 へ送った（[ふりかえり](retrospective-5.md)の引き継ぎ表）。
