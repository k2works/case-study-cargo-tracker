# ADR-025: 単一通貨（JPY）で確定する

## ステータス

承認済み（2026-08-12。IT20）

## コンテキスト

`release_scope.md` は多通貨を「**保留。Release 2.0 の料金設計時に判断する**」と書いていた。**Release 2.0 も 2.1 も出荷済みであり、判断されないまま 2 リリースが過ぎている。**

実測は次のとおりである（数え方も書く。IT20 の Try）。

| 対象 | 実測 | 数えた方法 |
| :--- | ---: | :--- |
| `domain-model.md` の「多通貨対応」の記述 | **1 か所**（`:379`） | `grep -n 多通貨 docs/design/domain-model.md` |
| DB の通貨列（相異なる列名） | **9 個** | `grep -rho "[a-z_]*_currency" src/main/resources/db/migration/ \| sort -u \| wc -l` |
| 通貨を跨ぐ演算の扱い | `requireSameCurrency` で**拒む** | `Money.java:87` / `:100` / `:115` |

**「多通貨対応」と書いてあるが、対応してはいない。** 実装がしているのは「異なる通貨どうしの足し算・引き算を例外で止める」ことだけであり、**換算レートも、レートの有効期間も、表示通貨の選択も存在しない**。`Money` は既定として `JPY` を持ち、復元時に通貨が欠けていれば `JPY` を補う（`MyBatisInvoiceRepository:244`）。

**この状態は「多通貨を保留している」のではなく、「単一通貨で動いている」。** 記述だけが別のことを言っている。

## 決定

**本システムの通貨は日本円（JPY）単一とする。**

- `Money` の `currency` は**残す**。落とすと、通貨が要るようになったときに DB とドメインの両方を作り直すことになる
- **通貨列も残す**（9 個）。`invoice_line_item` と同じ判断であり（ADR-016）、**使わないことと消すことは別である**
- **`requireSameCurrency` は「多通貨対応の一部」ではなく「単一通貨であることの検査」として位置づけ直す。** 異なる通貨が混ざったら、それは換算すべき場面ではなく**取り違えである**
- 換算レート・レートの有効期間・表示通貨の選択は**作らない**

## 結果

### 得たもの

- **「保留」が消えた。** 2 リリースにわたって「あとで判断する」と書かれていた行が、判断された行になる
- **`requireSameCurrency` の意味が変わる。** 「換算する前の入口検査」ではなく「取り違えの検出」であり、**通ってはならない**という位置づけになる

### 失ったもの

**多通貨が要るようになったときの作業は減らない。** この ADR は作業を前倒ししない。決めたのは「いま作らない」ことだけである。

**通貨列 9 個は使われないまま残る。** 読む人は「なぜ通貨列があるのに単一通貨なのか」と問うことになる。本 ADR がその答えである（`data-model.md` から参照する）。

### 変えなかったもの

- **`Money` の型そのもの。** 値と通貨のペアである
- **Routing の `Money` と Billing の `Money` が別の型であること**（ADR-005）

## 代替案

### 多通貨を実装する

**採らなかった。** 要求元が無い。換算レートを持つと、**レートの取得元・有効期間・どの時点のレートで請求するかという業務判断**が芋づる式に必要になる（`docs/article` の他言語版が `CurrencyRate` の有効期限判定で踏んでいる形である）。

### 通貨列と `currency` を落とす

**採らなかった。** ADR-016 が `invoice_line_item` について「**作らない判断であって、設計から消したのではない**」「削除は将来の判断を奪う」と書いており、同じ理由が当てはまる。

### 保留のままにする

**採らなかった。** これが 2 リリース続いた状態である。**「あとで判断する」と書いた時点から、判断した気になっている時間が延び続ける。**

## 何がどこで守るか

| 守るもの | 守り手 | 対象範囲 |
| :--- | :--- | :--- |
| 異なる通貨どうしの演算を通さない | **`Money.requireSameCurrency`**（`Money.java:115`） | Billing の `Money` の加算・減算のみ。**比較や生成は見ていない** |
| 通貨列が単一通貨で運用されていること | **守っていない。** | 検査は無い。DB へ `USD` を直接書けば通る。**要求元が無いため検査も作らない** —— この行はその判断の記録である |

## 正典への反映

- `docs/development/release_scope.md` —— 「保留」を「単一通貨（JPY）で確定（ADR-025）」に
- `docs/design/domain-model.md:379` —— 「多通貨対応」を実装に合わせる
- `docs/design/data-model.md` —— 通貨列が残る理由を本 ADR へ紐づける
