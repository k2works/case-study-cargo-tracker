# IT1 完了報告書（2026-08-06）

## エグゼクティブサマリー

**IT1 は計画どおり 4 ストーリー 9SP を完了した。** 認証・アカウントロック・荷主登録により、
「画面 → アプリケーション → ドメイン → DB」を貫通するウォーキングスケルトンが成立し、
アーキテクチャ基盤（Spring Security・MyBatis・Flyway・Testcontainers・Thymeleaf）が
実際に動くことを確認した。

**クローズ時のマルチパースペクティブレビューで高優先度 10 件が見つかり、すべて IT1 内で
対応した。** そのうち 4 件は「安全装置が入っているつもりで働いていなかった」ものであり、
実装中はすべて緑だった。負債を次イテレーションに持ち越していない。

品質ゲートは全項目を満たしている（テスト 96 件緑・Checkstyle 0・SpotBugs 0・
SonarQube Quality Gate PASS・CI 緑）。

### 未達・スコープ調整

**未達はない。** ただし次を明示する。

- **US31 の受入基準に矛盾がある。**「ロックされたことが利用者に通知される」と
  「ロック中と誤りで同一メッセージを返す」が両立しない。**同一メッセージを優先した**
  （通知するとアカウントの存在を第三者に教える）。受入基準の側を IT2 で修正する
- **法人荷主は登録できない**（US03 のスコープ）。ユーザー代表の判断により、
  **IT1 は社内の動作確認までとし、現場公開は US03 以降とする**

### アーキテクチャ

- **認証・認可を共有カーネルから `security` サブドメインへ分離**（ADR-007 起票）。
  共有カーネルは `Location` と `ShipperId` の 2 要素に保たれた
- **ArchUnit の 6 ルールのうち 5 つを有効化**（1・2・3・4・5・6 のうち、実装が無い層を除く全て）。
  各ルールは違反クラスを一時的に置いて**実際に落ちること**を確認済み
- 有効化の過程で、正典（`test_strategy.md`）のサンプルにあった `ignoreDependency` の
  引数の向きの誤りを発見・修正した

### 開発環境

- Spring Boot DevTools（自動再起動・LiveReload）と継続ビルドタスク（`app:watch`）
- ログイン情報の事前入力とロール別利用者の一覧（**既定は無効**。opt-in）
- マニュアルのキャプチャ自動生成（Playwright）

### 高優先度の代表例

| 指摘 | なぜ危険だったか |
| :--- | :--- |
| 動作確認用の利用者シードが本番にも適用される構成だった | パスワードがリポジトリに公開されているアカウントが本番 DB に作られる。ファイル冒頭の「本番では適用しない」というコメントは何も強制していなかった |
| 並行した認証失敗でロックが成立しない | 総当たり攻撃は逐次では来ない。US31 の価値そのものが並行実行下で成立していなかった |
| ロック期限切れ後 1 回の失敗で再ロック | 30 分待って復帰した利用者を、1 回の打ち間違いで再び締め出す |
| ログアウトのテストが偽の安全網 | 未認証から始めており、セッション破棄が壊れていても常に緑 |
| マニュアルが存在しない機能を約束 | 「管理者に連絡すると解除できます」と案内していたが解除手段が無く、連絡した利用者は結局待たされる |
