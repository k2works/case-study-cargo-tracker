## 技術的成果

### 人の記憶に預けていた規律を、検査に移した

| 検査 | 何を止めるか |
| :--- | :--- |
| `H2DialectCoverageTest` | 読み取りを H2 スモークに載せ忘れる（**メソッド単位**） |
| `MapperTableOwnershipTest`（逆方向） | 名簿に実体の無い表が残る |
| `ReadSideRuleLocationTest` | 読み取り側の規則が infrastructure に書かれる（ADR-022） |
| `PackageInfoPresenceTest` | パッケージの説明が無い（JIG の図が名前だけの箱になる） |
| `BookingFormRoundTripTest` | 入力欄を出しながら保存しない |

### 開発環境をマニュアルと同じ状態に（タスク 0）

`db/demo` の SQL は荷主・予約・航海までしか作れず、**追跡・荷役・請求・見積の章はすべて空の画面**だった。SQL では足せない理由は 3 つある。

1. 追跡の記録も請求書も、荷役を登録した結果として `AFTER_COMMIT` のドメインイベントが作る**派生データ**である
2. 追跡番号と請求書番号は**シーケンス採番**で、直接 INSERT すると一意制約で 500 になる
3. 途中の状態を直接作ると、**画面が到達しうる状態かを確かめないまま**図を作ることになる

**本番と同じ経路（アプリケーションサービス）で投入する `DemoDataInstaller` を作った。**

### ドメインモデルを構成要素ごとに分けた（ADR-024）

140 クラスを `aggregates` / `entities` / `valueobjects` / `commands` に分けた。**代償はカプセル化の一部喪失**であり、4 メソッドを `public` にした。埋め合わせの ArchUnit ルールは書いておらず、**D5 として実測付きで記名した**（違反 0 件）。

| # | 内容 | 育つ理由 |
