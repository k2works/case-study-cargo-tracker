## Keep（続けること）

### K1. 育つ負債を「次の IT で対象が増えるか」で先に返した

IT19 のふりかえりで決めた「落とす順序は見積もりでなく、次の IT で対象が増えるかで決める」を実行した。D5（ADR-024 の代償）と D1（`Cargo` 500 行）を Day 1〜3 に置き、**どちらも計画どおり返した**。

**`Cargo` は猶予 0 行だった。** 次に 1 メソッド足せば Checkstyle が赤になる状態であり、「余力があれば」に回していれば IT21 の最初の変更が止まっていた。

### K2. 規則を一般化せずに検査へ落とした

D5 は「集約ルート以外は呼べない」と書けば 3 行で済んだ。**そう書かなかった。** ADR-024 が定めているのは**メソッドごとに呼んでよい相手を書き分けた表**であり、一般化すると `ProposedRoute.of` を集約ルートへ移すことになって探索と提案の分離が壊れる。

**（型・メソッド・呼んでよい相手）の 3 つ組**で書いたことで、`ExceptionOccurrence.raise` や `commandService.resolve` を誤検知せず、設計も変えずに代償を返せた。

### K3. レビューアが実際にコードを書いて確かめた

tester が 3 種類のプローブを実際に書いて走らせ、**メソッド参照の素通り**と**真夜中の順序崩れ**を実測で示した。どちらも読むだけでは見つからず、こちらの「破壊検証で 4 メソッドすべて赤を確認した」という報告と矛盾しない形で潜んでいた。

**「壊して赤」を実演したレビューは、意見ではなく事実を持ってくる。**

### K4. 検査を足したことで、別の既存欠陥が芋づるで出た

キャプチャの重複検査（md5）を入れたところ、**レビューが指摘した 1 組に加えて既存の 2 組が即座に出た**（`04-booking-detail-assign` / `05-route-confirm`）。

**検査は「今回の欠陥」を止めるだけでなく、同型の既存欠陥を掘り出す。** 手で数えていたら 3 組目は見つからなかった。

## Problem（問題）

### P1. 新しく足した安全装置そのものに、過去の失敗が 3 種類再現した

| 装置 | 再現した失敗 | 由来 |
| :--- | :--- | :--- |
| `EntityEncapsulationTest` | **メソッド参照を素通り**（形が違えば通る） | 「緑のテストと壊れ方の設計は別物」 |
| `EntityEncapsulationTest` | 契約表が**文字列の名簿**で、実在を誰も確かめていない | 「検査は未登録を素通りさせない」（ADR-015 で 3 IT 素通り） |
| `RecentBusinessTime` | 真夜中の順序崩れを**直しきれていなかった**（01:00 で逆転） | 「安全装置は破るテストで固定する」 |
| `CargoMisrouteTest` | テスト名と検証内容が矛盾し、**欠陥を固定していた** | 「コメントは仕様として読み実装と突き合わせる」 |

**IT19 のふりかえり Try T1「検査を書くときは過去に起きた事故の粒度で Red を作る」は、型とメソッドの粒度までは効いた。呼び出しの形（直接呼び出し / メソッド参照 / リフレクション）の粒度には届かなかった。**

### P2. U4（既定を「有効」に）が、U5 が解こうとした問題を新しく作った

U5 は「何を直せばよいか分からない 0 件」をなくすためのものだった。ところが U4 の既定によって、**手持ちが全て期限切れの朝は、条件を 1 つも入れていないのに「条件を変えてお試しください」**が出るようになった。

**利用者代表・アーキテクト・テクニカルライターの 3 視点が独立に同じ箇所を指した。** 実装者には見えなかった。

**新しい既定は、それ自体が新しい状態を作る。** 「既定を入れた」で終わらせず、**既定が作った状態を一通り歩く**必要があった。

### P3. 「是正はタスク 7」と書いたまま、タスク 7 を完了にした

`test_strategy.md` に自分で「実装は 13 ルールあり本節は追随していない。**是正はタスク 7**」と書きながら、タスク 7 のコミットで是正せず完了扱いにした。

**ADR-025 が「あとで判断すると書いた時点から、判断した気になっている時間が延び続ける」と戒めた形を、同じ IT の中で踏んだ。**

### P4. マニュアルのキャプチャが 1 枚も更新されていなかった

計画には「マニュアル 12 章とキャプチャ再生成」と書いてあり、本文は更新した。**キャプチャは撮り直していなかった。** 本文が「表の上に該当 N 件と出ます」「右端に [同じ条件で再見積]」と書いているのに、画像にはどちらも写っていない。

**文章は実装に追随していたので、本文だけ読むレビューでは緑に見える。** 画像の古さは人の目にしかかからない。

### P5. 記録と実測のずれが 10・11 度目

計画の注 1 が「正典 6 か所を直す」と列挙していたが、**実測では 4 か所**だった（`release_plan.md:62` と進捗表は開始準備で更新済み）。

**本 IT の Try「数を書くときは数えた方法も書く」が、この計画自身には適用されていなかった。**

### P6. `CargoMisroute` の実装が、切り出しの動機に追いついていなかった

「他 BC の写しを集約から出す」という動機は妥当だが、初版は 3 ファクトリの本体が同一で、`isDetected()` は本番未使用、`null` は従来どおり外へ漏れていた。**アーキテクトが「行数を 15 行下げた以上の効果を主張しないほうが誠実」と指摘した。**
