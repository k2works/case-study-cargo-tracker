## Keep（続けること）

### K1. 安全装置を 6 つすべて壊して確認した

IT2 の Try T2 をそのまま実行した。**壊して赤を確認したのは 6 件。**

| 装置 | 壊し方 | 落ちた件数 |
| :--- | :--- | :--- |
| 業務タイムゾーンの時計 | UTC に戻す | 3 |
| ページ送りの LIMIT | 外す | 5 |
| `Schedule` の連結・時系列制約 | 検証を外す | 4 |
| 運送区間の読み戻し順序 | `ORDER BY` を逆順に | 6 |
| H2 方言スモーク | `LATERAL` に戻す | 3 |
| ArchUnit ルール 4 | BC をまたぐプローブ | 1 |

### K2. インサイドアウトが機能した

`Schedule` の連結制約（区間 n の到着港 = 区間 n+1 の出発港）と時系列制約は、
**行をまたぐため DB の CHECK 制約では守れない**。画面から作っていたら
気づかないまま「貨物が途中で消えるスケジュール」を登録できていた。
局面が中盤に変わる意味が、最初のイテレーションで実感できた。

### K3. 実バグを 3 件見つけた

いずれも「テストは緑なのに動かない」種類である。

| 見つけたもの | 見つかり方 |
| :--- | :--- |
| 日本時間 0〜9 時に当日着の予約が拒否される | 日付をまたいだ時刻に作業していて落ちた |
| 港マスタが空で航海を 1 件も登録できない | 計画時の突合 |
| `LATERAL` を H2 が解釈できず画面が 500 | キャプチャを撮ろうとして発覚 |

### K4. 繰り返しを仕組みで止めた

方言差でローカルが落ちるのが 3 回目だったため、**人の注意に頼るのをやめて
`H2DialectSmokeTest` を置いた**。全クエリサービスを H2 上で実行し、
「解釈できるか」だけを見る。ADR-003 にも「逆方向の失敗」として規律を追記した。

## Problem（問題点）

### P1. CI が赤のままクローズに入りかけた（最も重い）

ローカルは緑だったが、**CI（UTC）ではテストが 1 件落ちていた**。
原因は、**直したはずの不具合（UTC で業務日付を判断する）と同じ取り違えを、
テストの側でしていた**こと。ローカル（JST）では一致するため見えなかった。

さらに悪いのは、**同じ取り違えが 4 ファイルに残っていた**ことである。
1 か所直して満足し、他を探さなかった。

### P2. 画面から先への到達性を確かめていなかった

経路割り当て待ち一覧から**予約の内容を確認できなかった**。
IT2 の教訓に従ってロール別の到達性（開けるか・開けないか）は確かめたが、
**「開いた画面から次に何ができるか」は別の観点**であり、抜けていた。

正典（`ui_design.md`）が定める残り日数の色分けも実装していなかった。
**計画の設計節に画面遷移図を載せながら、画面の中の要素表を突き合わせていなかった。**

### P3. ビルドツール自身の依存を見落としていた

Trivy が Checkstyle の推移的依存に HIGH を 2 件検出した。
アプリの実行時には載らないが、**CI のビルド環境で実行されるコード**である。
「本番に載らないから無視してよい」とは言えない。

### P4. 方言差を 2 回踏んでから対策した

IT2 で 1 回（`setval`）、IT3 で 2 回（`INTERVAL 'N days'`・`LATERAL`）踏んでから
スモークテストを入れた。**1 回目の時点で「同じ型の失敗が続く」と読めたはずである。**
