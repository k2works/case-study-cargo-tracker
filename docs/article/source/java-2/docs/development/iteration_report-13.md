## エグゼクティブサマリー

**IT13 で Billing Context が立ち上がり、「運んだのに請求できない」状態が終わった。**

v1.1.0 は予約から引取までを通したが、その先が無かった。引取が済んだ貨物は「配送完了」のまま止まり、経理担当者にはダッシュボードのカードすら無かった。本 IT で、引取済みの貨物を見つけ、料金を算出し、割引の根拠を示し、確認して確定するところまでが画面を通してつながった。

**ここで決めた金額の扱いは、以降のすべての請求に効く。** 丸めは切り捨て（荷主に不利な方向へ丸めない）、段階丸め（基本料金・割引後・消費税のそれぞれで丸める）、丸め後の値と税率を請求書ごとに保持し再計算しない。**税制改正の日に過去の請求書が書き換わらない**ことをテストで固定した。

**設計書の計算例が「順序を決める必要性」を示せないことに気づいた。** 例（100,003 円）では段階丸めと一括丸めの結果が一致する。実際にずれる値を探して固定した（100,007 円で 1 円ずれる）。

一方で、**全緑の状態からレビューが高優先度を 13 件見つけた。5 イテレーション連続である。** うち最も重いのは 2 件で、どちらも「作ったつもり」の形だった。

- **画面に出す金額の内訳が足し算として成立していなかった**（3 視点が独立に指摘）。集約は正しく計算していたが、表示用の型が計算を作り直していた
- **自分で書いた運用要件が実装で成立していなかった。** 「料金調整は例外の記録を見ながら判断する」と書きながら、経理担当者は予約詳細を開けなかった

高 9 件は IT 内で対応した。残る高 4 件は IT14 の返済枠に名前で載せる。

## レビュー結果

XP 5 視点の並列レビューを実施（[統合レポート](../review/IT13実装_review_20260810.md)）。

| 重要度 | 件数 | 対応 |
| :--- | :--- | :--- |
| 高 | 13 | **9 件を IT 内で対応。** 残る 4 件は IT14 の返済枠に記名して送る |
| 中 | 10 | IT14 で扱う |
| 低 | 8 | IT14 のふりかえりで扱う |

### IT 内で対応した高優先度のうち重いもの

1. **割引後料金の表示が誤り**（3 視点が独立に指摘）。計算順序は 基本料金 → 調整 → 割引 → 消費税 で割引は調整後の額に掛かるが、画面は「基本料金 − 割引額」で作っていた。調整がある請求書で**内訳が足し算として成立しなかった**（基本 100,000 / 減額 10,000 / 補償 3,000 / 割引 15% で、画面 86,050 + 7,905 = 93,955 に対し請求総額 86,955）。**経理担当者が電卓で検算する場面で最初に見つかる種類の食い違い**である
2. **経理担当者が予約詳細を開けなかった**（403）。マニュアル 11.3 と運用要件 R1 が「料金調整は例外の記録を見ながら判断する」と書いているのに、その作業ができなかった。**自分で書いた運用が実装で成立していなかった**
3. **コメントが主張する守りが実在しなかった。** 「区間 0 本は請求できない」と書きながら守りが無く、画面に 500 が出る（3 IT 連続の再発）
