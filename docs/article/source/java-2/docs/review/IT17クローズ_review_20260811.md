## 実測で裏づけた懸念（architect の「検査の本数が増えるコスト」）

architect が「検査失敗時のメッセージから ADR や由来に辿り着けるか未検証」と述べたため、**実測した**。

| 検査 | 由来つきの失敗メッセージ |
| :--- | ---: |
| `CargoFixtureOwnershipTest` | 1/1 |
| `MapperTableOwnershipTest` | 2/6 |
| `ListQueryMeasurementTest` | 1/6 |
| `SelfLinkResolvesTest` | 0/4 |
| `PersistenceMarkerCallerTest` | 0/2 |
| その他 6 本 | 1/2 〜 1/3 |

**懸念は事実だった。** 走査 0 件の歯止めやメタテストのメッセージには由来が無いものが多い。ただし本検査の失敗（主検査）には多くが由来を持っており、**実害の大きい経路は概ね守られている**。**次 IT の返済枠に入れる。**

## 各視点の主な評価

<details>
<summary>xp-programmer</summary>

「直したこと」自体を検査で固定する規律が徹底されている。`SourceScan` は IT16 で 3 回踏んだ問題を**個別テストの規律ではなく API の既定**で潰した設計判断。コミット粒度も依存関係（検査基盤 → 分割）を踏まえた並びになっている。
</details>

<summary>xp-tester</summary>

</details>

<details>

</details>
