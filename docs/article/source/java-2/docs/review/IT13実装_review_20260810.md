日付: 2026-08-10

## レビュー対象

- コミット範囲: `b605b70a5..ebb9f034f`（IT13 の全実装）
- 対象: Billing Context の新規実装、ACL ポート 3 種、返済枠（C1 / C3 / C5 / C7 / C8 / C9 / C10）、運用要件（R1〜R3）
- 手法: XP 5 視点のマルチパースペクティブレビュー（並列）

## 総合評価

ドメインの語彙が業務の言葉で切られ、段階丸めを型に閉じ込め、ACL ポートを素の値だけに絞り、SQL 側にもドメインと同じ守りを二重で置いた点は水準が高い。ADR-015 の許容リストから「写しにできるもの」という分類ごと 2 行を返した返済も、負債の返し方としてあるべき形である。

一方で、**画面に出る金額の内訳が足し算として成立しないバグ**が残っていた。3 視点（programmer / technical-writer / user-representative）が独立に同じ箇所を指摘している。加えて、**自分で書いた運用要件（R1）とマニュアル（11.3）が実装で成立していない**ことが利用者代表の指摘で判明した。どちらも全緑の状態から出てきており、**全緑の状態からレビューが高優先度を見つけるのは 5 イテレーション連続**である。

## 本 IT の学び

- **同じ箇所を 3 視点が独立に指摘したものは実バグだった**（H1）。視点の重なりは冗長ではなく確度である
- **自分で書いた運用要件が実装で成立していなかった**（H2）。R1 を書いたのも実装したのも同じ IT であり、**書いた側が確かめる側になると成立を検査しない**
- **コメントが主張する守りが実在しない形が再発した**（H3）。IT11・IT12 に続き 3 回目
- **空振りテストは「守っているつもり」を作る**（H5）。破壊検証を安全装置だけでなく**既存のテストにも向ける**必要がある
