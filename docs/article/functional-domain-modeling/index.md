# 関数型ドメインモデリング：F# で作る Cargo Tracker

## 概要

本記事では、国際貨物輸送管理システム（Cargo Tracker）を **F# で関数型ドメインモデリングによって実装した実績**を、イテレーション単位で追います。

扱うのは「F# の文法」ではありません。**業務ルールを型に埋め込み、不正な状態を表現不可能にする**という設計手法が、実際の業務システムでどこまで通用するか。そして通用しない箇所ではどう折り合いをつけたか、という記録です。

同じ題材を 10 言語で実装した比較は、姉妹シリーズの [モノリスアーキテクチャ実装比較](../monolith-architecture/index.md) にあります。本シリーズはそのうち F# 実装 1 本を深く掘ります。

## 題材と実装

| 項目 | 内容 |
| :--- | :--- |
| システム | 国際貨物輸送管理システム（貨物の予約・経路設計・追跡・精算） |
| 言語 | F# 9 / .NET 10 (LTS) |
| Web | Giraffe（`HttpHandler` の関数合成）+ Giraffe.ViewEngine |
| データアクセス | Donald（F# の ADO.NET ラッパ・手書き SQL） |
| エラー処理 | FsToolkit.ErrorHandling（`asyncResult` / `validation`） |
| アーキテクチャ | モジュラーモノリス（DDD + ポートとアダプター + CQRS） |
| Bounded Context | Shared / Shipper / Booking / Estimation / Routing / Tracking / Handling / Billing |
| イテレーション | 8（Release 1.0 MVP → Release 1.1） |
| 最終規模 | ユニット 222 + 統合 149 + アーキテクチャ 31 件、カバレッジ 全体 89.0% / ドメイン層 88.8% |

## 本シリーズの主題

関数型ドメインモデリングの中核は、次の 4 つです。本シリーズはこれらが各イテレーションでどう現れたかを追います。

| 技法 | 何を得るか | 主に扱う章 |
| :--- | :--- | :--- |
| **スマートコンストラクタ + 単一ケース DU** | 値が存在する時点で検証済みであることを型が保証する | [第 2 章](02-iteration-01.md) |
| **和型（DU）で不正状態を排除** | 「危険物なのに申告がない」を型エラーにする | [第 3 章](03-iteration-02.md) |
| **状態がデータを持つ状態機械** | 「経路提案済みなのに旅程がない」を表現不可能にする | [第 5 章](05-iteration-04.md) |
| **Railway Oriented Programming** | 失敗を例外ではなく値として合成する | [第 2 章](02-iteration-01.md)・[第 8 章](08-iteration-07.md) |

## 各章の読み方

イテレーション章はすべて同じ構成です。

1. **このイテレーションのゴール** — 何を動く状態にするか
2. **扱うユーザーストーリー** — 受入基準と見積
3. **モデリング** — その回で使った関数型の技法と、実際の型定義
4. **ワークフロー** — ドメインをアプリケーション層でどう合成したか
5. **このイテレーションの学び** — ふりかえりで浮かんだ問題と対処

コードはすべて [参照元ソース](../source/fsharp/apps) の実ファイルからの引用です。

## 前提知識

- いずれかの静的型付き言語の基礎
- 代数的データ型（直積型・直和型）の概念
- DDD の用語（エンティティ・値オブジェクト・集約・境界づけられたコンテキスト）の概要

F# の構文そのものは各章で必要に応じて補足します。C# や Java の経験があれば読み進められる想定です。

用語の詳細は [ドメインモデル設計ガイド](../../reference/ドメインモデル設計ガイド.md)、要件は [要件](../../requirements/index.md) を参照してください。
