# モノリスアーキテクチャ実装比較：10 言語の Cargo Tracker

## 概要

本記事では、同一の題材（国際貨物輸送管理システム = Cargo Tracker）を **10 の言語・スタックでモノリスとして実装した実績**を、イテレーション単位で比較解説します。

比較の対象は「言語の文法」ではありません。**DDD・ヘキサゴナルアーキテクチャ・CQRS という同じ設計方針を、型システムとエコシステムの違うランタイムに載せたとき、どこが同じでどこが分かれるか**です。

軸となるのは Java（Spring Boot）実装です。Java の各イテレーションで下した設計判断を追いながら、章末で他 9 言語が同じユーザーストーリーをどう実装したかを比較します。

## 題材

| 項目 | 内容 |
| :--- | :--- |
| システム | 国際貨物輸送管理システム（貨物の予約・経路設計・追跡・精算） |
| 参照元 | Eclipse Cargo Tracker（Jakarta EE 参考実装）の設計思想 |
| Bounded Context | Shipper / Booking / Estimation / Routing / Tracking / Handling / Billing |
| ユーザーストーリー | US01〜US23（言語によって認証・航海マスタ等の US24 以降を追加） |
| アーキテクチャ | モジュラーモノリス（DDD + ポートとアダプター + CQRS） |
| 開発プロセス | XP（TDD・イテレーション・ふりかえり・マルチパースペクティブレビュー） |

「モノリス」と言っても単一レイヤの塊ではありません。Bounded Context ごとにパッケージ／モジュール／クレートを分け、コンテキスト間の参照は ACL（腐敗防止層）とポート越しにだけ許す **モジュラーモノリス** です。デプロイ単位が 1 つであることと、内部が結合していることは別問題である、というのが全実装に共通する前提です。

| 言語 | フレームワーク | データアクセス | ビュー | イテレーション数 |
| :--- | :--- | :--- | :--- | :--- |
| **Java** | Spring Boot 4.0 | MyBatis | Thymeleaf + htmx | 10 |
| C# | ASP.NET Core 10 | Dapper | Razor + htmx | 7 |
| F# | Giraffe（ASP.NET Core） | Donald | Giraffe.ViewEngine | 8 |

| Haskell | Servant + Warp | 手書き SQL | Lucid | 8 |
| Flix | JDK HttpServer ベース | JDBC | 自前テンプレート | 12 |
| Rust | axum + tokio | sqlx | 自前テンプレート | 8 |
| Go | chi + net/http | 手書き SQL | html/template | 8 |
| Ruby | Rails 8 + packs | Active Record | ERB + Hotwire | 9 |
| TypeScript | NestJS 11 | Kysely | TSX + htmx | 7 |

イテレーション数が違うのは、同じ 23 ストーリーを何回に割ったかの差です。Java の 10 イテレーションが最も細かく刻まれており、設計判断の推移を追うのに向いているため、本記事の骨格に採用しました。

## 各章の読み方

イテレーション章はすべて同じ構成です。

1. **このイテレーションのゴール** — 何を動く状態にするか
2. **扱うユーザーストーリー** — 受入基準と見積
3. **Java 実装** — 実際のコードと、そこで下した設計判断
4. **他言語ではどう書いたか** — 同じストーリーの実装を 9 言語で比較
5. **このイテレーションの学び** — ふりかえりで浮かんだ問題と対処

Java のコードは実装リポジトリからの引用です。他言語は要点（型定義・状態遷移・境界の引き方）を抜粋して差分を語ります。
