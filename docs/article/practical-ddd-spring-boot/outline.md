## 2. 通底する主題

イテレーション単位で追うと、Spring Boot 上の DDD 実装には繰り返し現れる形があります。各章はこの 5 つのいずれかに触れます。

| # | 主題 | 具体的に何が起きたか |
| :--- | :--- | :--- |
| M1 | **フレームワークをドメインに侵入させない** | 集約・値オブジェクトは POJO のまま。Spring への依存は `application` と `infrastructure` にだけ置き、ArchUnit で検査する |
| M2 | **BC は 1 パッケージ = 1 コンテキスト** | `booking` / `shipper` / `routing` / `tracking` / `handling` / `billing` / `estimation` の 7 パッケージ。越境は ACL ポート 1 点だけに絞る |
| M3 | **永続化は MyBatis の手書き SQL、テーブルの所有は BC** | JPA を採らない判断（ADR-004）と、Mapper・SQL・テーブルの所有規則（ADR-015） |
| M4 | **同期の越境は、失敗がどこに出るかを決めてから書く** | ドメインイベント（ADR-009）と、越境の状態変更（ADR-021） |
| M5 | **宣言した規則は、同じイテレーションで検査に落とす** | ArchUnit・Checkstyle・SpotBugs・カスタム lint。落とさなかった規則は守られなかった |

## 4. 各章の共通フォーマット

イテレーション章（第 2〜21 章）は同じ節構成にします。**読者が任意の章から入っても位置を見失わないため**です。

```markdown
# 第 N 章：ITx <主題>

## このイテレーションのゴール      … 計画の「ゴール」から。何が動くようになるか
## 扱うユーザーストーリー          … ID・要点・SP の表
## 前イテレーションからの引き継ぎ  … ふりかえりの Try / 持ち越し（無ければ節ごと省く）
## 実装                            … Spring Boot のコード。ドメイン → アプリケーション → インフラ → 画面の順
## 設計判断                        … このイテレーションで決めたこと（ADR があれば ID を示す）
## このイテレーションの学び        … 完了報告・ふりかえりから。効かなかったことも書く
```

- コード例は `docs/article/source/java-2/apps/` の実ファイルから転記します。**憶測のコードは書きません**
- 長い完成コードは `<details>` に入れ、本文には差分だけを載せます
- 引用したファイルは相対パスで示します（読者が同じファイルを開けるようにするため）
