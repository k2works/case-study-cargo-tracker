# 実践 AI 駆動開発：20 イテレーションの記録

## 概要

本記事では、国際貨物輸送管理システム（Cargo Tracker）を **開発者 1 名と AI エージェントで 20 イテレーション作り切った実績**を、開発プロセスの側から記録します。

扱うのは成果物ではありません。**AI と組んで開発すると何が起きるか**です。何を仕組みとして用意し、どの規律が品質を守り、どの規律が守らなかったか。20 回のふりかえりに残った失敗を、名前と件数のまま扱います。

**うまくいった話だけを書きません。** ふりかえりの価値の半分は「同じ罠に二度落ちない」ことにあり、その罠の多くは AI 固有ではなく、**AI が速いために従来より高い頻度で表面化した**ものでした。

## 実績サマリー

| 項目 | 値 |
| :--- | :--- |
| イテレーション | 20 |
| ユーザーストーリー | US01〜US36（36 本・117SP） |
| リリース | 0.1 / 0.2 / 1.0 / 1.1 / 2.0 / **2.1（出荷済み）** |
| Bounded Context | 8（Shipper / Booking / Estimation / Routing / Tracking / Handling / Billing / Shared） |
| テスト | **1,578 件**（Java 1,557 + E2E 21） |
| ADR | 26 件 |
| 実装期間 | 2026-08-06 〜 2026-08-13（**8 日**） |
| 体制 | 開発者 1 名 ＋ AI（Claude Code） |
| スタック | Java / Spring Boot 4.0 / MyBatis / Thymeleaf + htmx |

**20 イテレーションを 8 日で回しています。** この速度そのものが本シリーズの前提であり、同時に主題でもあります。速度は品質を上げも下げもしませんが、**検査の無い規律が壊れるまでの時間を短くします**。

## 通底する 5 つの主題

20 回のふりかえりを通読すると、**同じ形の失敗が名前を変えて繰り返されて**います。各章はこの 5 つのいずれかに帰着します。

| # | 主題 | 実際に起きたこと |
| :--- | :--- | :--- |
| M1 | **緑であることは、守られていることの根拠にならない** | 安全装置を入れたのに働いていない。IT1 でレビュー高 10 件のうち 4 件、IT11 で数え上げた 22 件中 3 件が空振り |
| M2 | **書いたことと、していることは別** | ADR・Javadoc・遷移表が仕様を語り、実装が守っていない。IT15 では遷移表・ADR-009・所有表の 3 か所で同型が出た |
| M3 | **記録は実態より小さくなる** | 起票時の件数と実測が 5 回連続でずれた。ある返済項目は記録 34 件に対し実測 249 件 |
| M4 | **落とした負債は育つ** | 「余力次第」と書いた返済枠は 3 IT 連続で繰り越された（ADR-008） |
| M5 | **規則は検査に落とさなければ守られない** | ADR-009 は 7 IT のあいだ半分しか守られず、その間に違反が 5 本増えていた |

## 各章の読み方

実践記録の章（第 9〜13 章）はすべて同じ構成です。

1. **この局面のゴール** — 何を動く状態にするか
2. **AI に何をさせたか** — 使った Skill・分業の形
3. **起きた失敗** — ふりかえりから、名前と件数つきで
4. **どう直したか** — 検査・運用・ドキュメントのどれに落としたか
5. **残った未達** — 次の局面へ持ち越したもの

仕組み・規律の章（第 2〜8 章）は次の構成です。

1. **解こうとした問題**
2. **仕組みの中身** — 実ファイルからの引用
3. **実際に働いたか** — イテレーション実績での検証
4. **働かなかったケース**
