# 未払い通知バッチ運用手順（US23-5）

支払期限（請求書発行日 + 30 日）を超過した未精算（PENDING）の請求書を検出し、`OVERDUE` 状態へ遷移させて経理担当者へ未払い通知（`INVOICE_OVERDUE`）を送る定期バッチの運用手順を定める。

> Solid Queue（非同期ジョブ基盤）は初期フェーズでは未導入のため、当面は Rake タスク + cron で駆動する。将来 Solid Queue 導入時に定期ジョブ（recurring task）へ移行する（ADR 起票候補）。

## バッチの実行

```bash
cd apps/cargo-tracker
bin/rails billing:mark_overdue
```

- 期限超過の PENDING 請求書を OVERDUE へ遷移させ、遷移した請求書ごとに経理担当者へ未払い通知を送る。
- 出力例: `[billing:mark_overdue] 3 件を OVERDUE にし未払い通知を送信しました`

## 冪等性

- 本バッチは **冪等** である。対象は「PENDING かつ期限超過」に限定し、既に `OVERDUE` の請求書は対象外とするため、同日に複数回実行しても二重通知は発生しない。
- 通知は「実際に OVERDUE へ遷移した請求書」に対してのみ発行される（状態遷移に通知を紐づけ、候補抽出とはドリフトしない）。

## 定期実行（cron）

毎日 1 回（例: 午前 2 時）実行する構成を推奨する。

```cron
# /etc/cron.d/cargo-tracker-billing
0 2 * * * deploy cd /path/to/apps/cargo-tracker && RAILS_ENV=production bin/rails billing:mark_overdue >> log/mark_overdue.log 2>&1
```

- 実行頻度は日次で十分（支払期限は日単位）。
- 本番では `RAILS_ENV=production` を指定する。

## 環境変数

| 変数 | 既定値 | 用途 |
|:--|:--|:--|
| `ACCOUNTANT_ADDRESS` | `accountant@cargo-tracker.example` | 未払い通知の宛先（経理担当者）。本番では実アドレスを設定する |

> MVP は固定アドレスへの通知記録（`notifications` テーブル）にとどまる。実送信アダプタ（メール等）は将来の `NotificationPort` 実装で対応する。
