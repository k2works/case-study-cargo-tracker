# 運用スクリプト

`ops/scripts/` 配下に配置された Gulp タスク群のリファレンスです。プロジェクトルートの `gulpfile.js` から各モジュールを読み込み、`npx gulp <タスク名>` の形式で実行します。

## 概要

- 実行コマンド: `npx gulp <タスク名>`（一部は `npm run <スクリプト>` のショートカットあり）
- 設定: ルートの `.env` を `dotenv/config` で読み込み、各タスクが環境変数を参照
- 構成: ES Modules（`import`/`export default`）でタスク関数をエクスポートし、`gulpfile.js` で `gulp` インスタンスを渡して登録

## ファイル構成

| ファイル | 用途 | 主なタスク名前空間 |
| :--- | :--- | :--- |
| `shared.js` | 共通ユーティリティ（Docker 環境変数・URL オープン） | -（他から import） |
| `develop.js` | バックエンド・フロントエンドの開発タスク | `dev:*` |
| `release.js` | セマンティックバージョニング・CHANGELOG 生成・タグ付け | `release:*` |
| `deploy_dev.js` | Heroku Container Registry へのマイクロサービスデプロイ | `deploy:dev:*` |
| `journal.js` | git log から日次作業履歴を Markdown 生成 | `journal:*` |
| `mkdocs.js` | MkDocs ドキュメントサーバーの起動・ビルド | `mkdocs:*` |
| `sonar_local.js` | SonarQube ローカル環境のセットアップ・スキャン・分析 | `sonar-local:*` |
| `ssh.js` | SSH 接続・リモートコマンド実行（ヘルパー関数も公開） | `ssh:*` |
| `vault.js` | `.env` の AES-256-GCM 暗号化・復号化 | `vault:*` |
| `pre_commit_gradle_check.mjs` | Husky pre-commit から呼び出される Gradle `check` ラッパー | -（直接実行） |

`gulpfile.js` で読み込まれているモジュール: `mkdocs`, `journal`, `vault`, `ssh`, `sonar_local`, `develop`, `deploy_dev`, `release`。

## shared.js（共通ユーティリティ）

他スクリプトから `import` して利用する関数を提供します。

| 関数 | 用途 |
| :--- | :--- |
| `cleanDockerEnv()` | `DOCKER_HOST` を除外した環境変数オブジェクトを返す（Docker Desktop での接続エラー回避） |
| `isDockerAvailable()` | `docker info` を実行し Docker デーモンの可用性を判定 |
| `openUrl(url)` | OS 別に既定ブラウザで URL を開く（win32/darwin/linux 対応） |

## release.js（リリース）

セマンティックバージョニング、`CHANGELOG.md` 生成、Git コミット・タグ付けを自動化。`apps/` および `packages/` 配下の `package.json` を再帰的に検出して同期更新。

### 品質ゲート（preflight）

| タスク | 内容 |
| :--- | :--- |
| `release:preflight:clean` | Git working tree がクリーンか確認 |
| `release:preflight:lint` | `npm run lint` |
| `release:preflight:test` | `npm run test` |
| `release:preflight:build` | `npm run build` |
| `release:preflight:e2e` | `npm run test:e2e` |
| `release:preflight` | 上記 5 つを順次実行 |

### リリース実行

| タスク | バンプ |
| :--- | :--- |
| `release:patch` | preflight → patch バージョン → CHANGELOG → commit + tag |
| `release:minor` | preflight → minor バージョン → CHANGELOG → commit + tag |
| `release:major` | preflight → major バージョン → CHANGELOG → commit + tag |
| `release:dry-run` | バージョンと CHANGELOG のプレビュー（変更なし） |

### リリース + デプロイ

`deploy:prd` タスクが別モジュールで登録されている場合のみ、以下が条件付きで登録されます。現状 `deploy:prd` は未実装のため、これらのタスクは登録されません。

| タスク | 内容 |
| :--- | :--- |
| `release:deploy:patch` | `release:patch` → `deploy:prd` |
| `release:deploy:minor` | `release:minor` → `deploy:prd` |
| `release:deploy:major` | `release:major` → `deploy:prd` |

`CHANGELOG.md` は Conventional Commits（`feat`/`fix`/`docs`/`refactor`/`test`/`chore`/`perf`/`ci`/`style`/`build`/`other`）でカテゴリ分類されます。

## deploy_dev.js（Heroku Container Registry デプロイ）

開発環境向けに、Heroku に全 8 アプリ（バックエンド 7 + フロントエンド）をマイクロサービスとしてデプロイします。

### 前提（手動実行）

```bash
heroku login
heroku container:login
```

`!` プレフィックスでセッション内実行可。

### 初回セットアップ・全体操作

| タスク | 内容 |
| :--- | :--- |
| `deploy:dev:setup` | 一括セットアップ（container login → app create → config → amqp → build → push → release） |
| `deploy:dev` | 更新デプロイ（build → push → release） |
| `deploy:dev:app:create` | 全 Heroku アプリを `container` stack で作成 |
| `deploy:dev:config` | 全アプリの Config Vars を設定（`SPRING_PROFILES_ACTIVE=product`、`JAVA_OPTS`、Gateway ルーティング、`API_GATEWAY_URL`） |
| `deploy:dev:build` | バックエンド `bootJar` + フロントエンド `npm run build` を並列実行 |
| `deploy:dev:push` | 全サービス Docker イメージを Heroku Container Registry へ push |
| `deploy:dev:release` | 全サービスを `container:release web` でリリース |

### CloudAMQP（RabbitMQ）

`bookingms` をプライマリとして CloudAMQP アドオンを追加し、`CLOUDAMQP_URL` を `bookingms`/`trackingms`/`handlingms`/`billingms` に分解配布します。

| タスク | 内容 |
| :--- | :--- |
| `deploy:dev:amqp:setup` | アドオン追加 → URL 共有（一括） |
| `deploy:dev:amqp:add` | `bookingms` に CloudAMQP アドオンを追加 |
| `deploy:dev:amqp:share` | `CLOUDAMQP_URL` を分解し `RABBITMQ_HOST`/`PORT`/`USERNAME`/`PASSWORD`/`VIRTUAL_HOST`/`SSL_ENABLED` に変換して配布 |
| `deploy:dev:amqp:info` | CloudAMQP の状態と各サービスへの設定状況を表示 |

### 個別サービス操作

サービス名: `gatewayms`/`authms`/`bookingms`/`routingms`/`trackingms`/`handlingms`/`billingms`/`frontend`

| タスク | 内容 |
| :--- | :--- |
| `deploy:dev:push:<service>` | 特定サービスを `buildx build` + `docker push` |
| `deploy:dev:release:<service>` | 特定サービスを `container:release web` |

### 確認・管理

| タスク | 内容 |
| :--- | :--- |
| `deploy:dev:status` | 全サービスの `heroku ps` を実行 |
| `deploy:dev:open` | フロントエンドアプリをブラウザで開く |
| `deploy:dev:logs` | 各サービスのログ確認コマンドを表示 |
| `deploy:dev:help` | ヘルプ表示 |
| `deploy:dev:login` | ログイン手順をコンソールに表示 |
| `deploy:dev:container:login` | `heroku container:login` を実行 |

### 必要な環境変数

| 変数 | 説明 | デフォルト |
| :--- | :--- | :--- |
| `DEV_HEROKU_APP_PREFIX` | Heroku アプリ名プレフィックス（必須） | - |
| `DEV_DOCKER_PLATFORM` | Docker ビルドプラットフォーム | `linux/amd64` |

アプリ名は `<prefix>-<service>` 形式で構築され、30 文字制約をチェックします。

### 既知の暫定対応

`HANDLINGMS_URL` は現状 `trackingms` に向けられています（`HandlingActivityController` が `trackingms` に同居しているため）。`handlingms` 独立後は `deploy_dev.js` の該当箇所を `handlingUrl` に戻してください。

## journal.js（作業履歴生成）

`git log` から日次の作業履歴を `docs/journal/YYYYMMDD.md` として生成。

| タスク | 内容 |
| :--- | :--- |
| `journal:generate` | 全コミット日付について履歴を生成（既存ファイルはスキップ） |
| `journal:generate:date --date=YYYY-MM-DD` | 指定日の履歴のみ生成 |

各エントリにはコミットハッシュ・メッセージ・変更ファイル一覧・diff 全文を含め、構造変更があれば PlantUML プレースホルダを挿入します。バッファサイズは 256 MB に拡張済み。

## mkdocs.js（ドキュメントサーバー）

Docker Compose 経由で MkDocs を操作。Docker 未起動時は警告を出してタスクをスキップします。

| タスク | 内容 |
| :--- | :--- |
| `mkdocs:serve` | `docker compose up -d mkdocs` で起動（<http://localhost:8000>） |
| `mkdocs:build` | `site/` を削除して `mkdocs build` を実行 |
| `mkdocs:stop` | `docker compose down` |
| `mkdocs:open` | ブラウザで <http://localhost:8000> を開く |

ショートカット: `npx gulp spec` / `npx gulp doc`（どちらも `mkdocs:serve` + `mkdocs:open`）。

## sonar_local.js（SonarQube ローカル）

Docker Compose で SonarQube + PostgreSQL をローカルに構築し、スキャン・Quality Gate 確認・イシュー分析を行います。設定は `sonarqube.config.json`（任意）で複数プロジェクトを定義可能。

### セットアップ・コンテナ操作

| タスク | 内容 |
| :--- | :--- |
| `sonar-local:setup` | `ops/docker/sonarqube-local/docker-compose.yml` を生成して起動、ヘルスチェック待機 |
| `sonar-local:start` | コンテナ起動 |
| `sonar-local:stop` | コンテナ停止 |
| `sonar-local:restart` | コンテナ再起動 |
| `sonar-local:status` | `docker compose ps` |
| `sonar-local:logs` | ログ表示（直近 50 行） |
| `sonar-local:open` | ダッシュボードをブラウザで開く |
| `sonar-local:clean` | コンテナ・イメージ・ボリュームを完全削除（確認プロンプト付き） |

### スキャン・分析

| タスク | 内容 |
| :--- | :--- |
| `sonar-local:scan` | 登録プロジェクトを順次スキャン |
| `sonar-local:gate` | Quality Gate ステータス確認 |
| `sonar-local:issues` | メトリクス・イシュー・重複コード詳細を表示 |
| `sonar-local:check` | `scan` → `gate` の一連フロー |
| `sonar-local:help` | ヘルプ表示 |

### スキャンタイプ

`sonarqube.config.json` の `scanType` で切り替え:

- `sonar-scanner`: `npx sonarqube-scanner`（デフォルト）
- `sbt`: `sbt sonarScan`
- `maven`: `mvn sonar:sonar`
- `gradle`: `./gradlew sonar`

### 環境変数

| 変数 | 説明 | デフォルト |
| :--- | :--- | :--- |
| `LOCAL_SONAR_PORT` | SonarQube ポート | `9000` |
| `LOCAL_SONAR_DB_PASSWORD` | PostgreSQL パスワード | `sonarqube_password` |
| `SONAR_HOST_URL` | SonarQube URL | `http://localhost:9000` |
| `SONAR_TOKEN` | 分析トークン（スキャン時必須） | - |
| `SONAR_PROJECT_KEY` | デフォルトプロジェクトキー | `my-project` |

## ssh.js（SSH 運用）

リモートサーバーへの SSH 接続と、外部スクリプトから利用できるヘルパー関数を提供。

### Gulp タスク

| タスク | 内容 |
| :--- | :--- |
| `ssh:ping` | 接続テスト |
| `ssh:login` | 対話シェルでログイン |
| `ssh:info` | ホスト名・OS・ディスク・メモリ情報を表示 |
| `ssh:help` | ヘルプ表示 |

### ヘルパー関数（`import { ... } from './ssh.js'`）

| 関数 | 用途 |
| :--- | :--- |
| `getSSHConfig(prefix)` | 環境変数から接続パラメータを取得 |
| `sshExec(command, options)` | リモートコマンド実行（`capture`/`ignoreError` 対応） |
| `scpUpload(localPath, remotePath, options)` | ファイル・ディレクトリのアップロード |
| `scpDownload(remotePath, localPath, options)` | ファイル・ディレクトリのダウンロード |

### 環境変数

`<PREFIX>` は `PRD`（デフォルト）/`STG`/`DEV` を切り替え可能。

| 変数 | 必須 | 説明 |
| :--- | :--- | :--- |
| `<PREFIX>_SSH_HOST` | 必須 | SSH ホスト |
| `<PREFIX>_SSH_USER` | 必須 | SSH ユーザー |
| `<PREFIX>_SSH_PORT` | 任意 | ポート（デフォルト 22） |
| `<PREFIX>_SSH_KEY` | 任意 | 秘密鍵ファイルパス |

`StrictHostKeyChecking=accept-new` でホスト鍵を自動受け入れ。リモートでは `export PATH=/usr/local/bin:$PATH` をプリペンドします。

## vault.js（`.env` 暗号化）

AES-256-GCM + PBKDF2 (SHA-512, 100,000 iterations) で `.env` を暗号化して `.env.vault` として保存します。

| タスク | 内容 |
| :--- | :--- |
| `vault:encrypt` | `.env` を暗号化して `.env.vault` を生成 |
| `vault:decrypt` | `.env.vault` を復号化して `.env` に書き出し |
| `vault:view` | 復号内容をコンソールに表示（ファイル書き出しなし） |
| `vault:rekey` | パスワードを変更して再暗号化 |

### 暗号化フォーマット

`salt (32 bytes) + iv (16 bytes) + authTag (16 bytes) + ciphertext`

### 環境変数

| 変数 | 説明 |
| :--- | :--- |
| `VAULT_PASSWORD` | 設定するとプロンプトをスキップ（CI 用途） |

パスワードは最低 8 文字。`.env.vault` を VCS にコミット可能、`.env` は `.gitignore` 対象とする運用を想定。

## pre_commit_gradle_check.mjs（pre-commit フック）

Husky の pre-commit フックから呼び出され、Java ソースファイルがステージングされたコミットで `apps/backend` の `./gradlew check -x test` を実行します。テストはスキップし、Lint・Checkstyle・SpotBugs などの静的検査のみ実施。タイムアウト 5 分。失敗時は `exit 1` でコミットをブロック。

## 環境変数一覧

各タスクが参照する環境変数の一覧です。プロジェクトルートの `.env` に記述し、`dotenv/config` 経由で読み込まれます。

| 変数 | 用途 | 関連タスク |
| :--- | :--- | :--- |
| `DEV_HEROKU_APP_PREFIX` | Heroku アプリ名プレフィックス | `deploy:dev:*` |
| `DEV_DOCKER_PLATFORM` | Docker プラットフォーム | `deploy:dev:push:*` |
| `LOCAL_SONAR_PORT` | SonarQube ポート | `sonar-local:*` |
| `LOCAL_SONAR_DB_PASSWORD` | SonarQube DB パスワード | `sonar-local:*` |
| `SONAR_HOST_URL` | SonarQube URL | `sonar-local:*` |
| `SONAR_TOKEN` | SonarQube 分析トークン | `sonar-local:scan` / `gate` / `issues` |
| `SONAR_PROJECT_KEY` | デフォルトプロジェクトキー | `sonar-local:gate` / `issues` |
| `PRD_SSH_HOST` ほか | SSH 接続情報（PRD/STG/DEV） | `ssh:*` |
| `VAULT_PASSWORD` | Vault パスワード（任意） | `vault:*` |

## 典型的なフロー

### 開発開始

```bash
npx gulp dev:db:start          # PostgreSQL + RabbitMQ 起動
npx gulp dev:backend           # 全バックエンド並列起動
npx gulp dev:frontend          # 別ターミナルでフロントエンド起動
npx gulp dev:open              # ブラウザで開く
```

### TDD

```bash
npx gulp dev:backend:tdd:bookingms     # bookingms のみ連続テスト
npx gulp dev:frontend:tdd              # フロントエンド watch
```

### 開発環境デプロイ

```bash
# 初回
heroku login
heroku container:login
npx gulp deploy:dev:setup

# 更新
npx gulp deploy:dev

# 個別サービス更新
npx gulp deploy:dev:push:bookingms
npx gulp deploy:dev:release:bookingms
```

### コード品質チェック

```bash
npx gulp sonar-local:setup     # 初回のみ
# ブラウザで初期設定 → SONAR_TOKEN を .env に追加
npx gulp sonar-local:check     # scan → Quality Gate 確認
npx gulp sonar-local:issues    # 詳細表示
```

### リリース

```bash
npx gulp release:dry-run       # プレビュー
npx gulp release:patch         # patch リリース
git push && git push --tags
```

### 秘密情報の管理

```bash
npx gulp vault:encrypt         # .env → .env.vault
git add .env.vault && git commit
# 別環境で:
npx gulp vault:decrypt         # .env.vault → .env
```
