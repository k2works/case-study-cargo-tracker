# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、国際貨物輸送管理システム（Cargo Tracker Rails 版）のアプリケーション開発環境をセットアップする手順を説明します。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。
> 三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — https://t-wada.hatenablog.jp/entry/clean-code-that-works

## 1. 前提条件

以下のツールがインストールされていることを確認してください。

| ツール | バージョン | 確認コマンド |
|--------|-----------|-------------|
| Ruby | 3.4.x | `ruby -v` |
| rbenv | 最新 | `rbenv -v` |
| Bundler | 2.x | `bundle -v` |
| Docker | 最新 | `docker -v` |
| Docker Compose | v2.x 以上 | `docker compose version` |
| Git | 最新 | `git -v` |
| Node.js | v22.x LTS 以上 | `node -v` |
| npm | v10.x 以上 | `npm -v` |

### Ruby のインストール

rbenv でインストールします。プロジェクトルートの `.ruby-version` によりバージョンが自動選択されます。

```bash
# rbenv でインストール
rbenv install 3.4.4

# バージョン確認（プロジェクトディレクトリ内で）
ruby -v
```

公式サイトから直接ダウンロードする場合：

- https://www.ruby-lang.org/ja/downloads/

### Docker のインストール

Docker Desktop をインストールします。

- **Windows**: https://docs.docker.com/desktop/install/windows-install/
- **macOS**: https://docs.docker.com/desktop/install/mac-install/

```bash
# バージョン確認
docker -v

docker compose version
```

### Node.js のインストール

開発タスクランナー（Gulp）と MkDocs 連携に Node.js が必要です。

- https://nodejs.org/

```bash
# バージョン確認
node -v

npm -v
```

## 5. プロファイル構成

開発・テスト・本番の全環境で PostgreSQL 16 を使用します（設計方針: 環境間の RDBMS 差異ゼロ）。
インメモリ DB による代替プロファイルは提供しません。

| 環境 | データベース | Docker | 用途 |
|------|------------|--------|------|
| development | PostgreSQL 16（Docker） | 必要 | 日常開発 |
| test | PostgreSQL 16（Docker、同一コンテナ別 DB） | 必要 | RSpec 実行 |
| production | AWS RDS PostgreSQL 16 | - | 本番 |

> **補足**: ドメイン層（`packs/*/app/domain`）のユニットテストは DB 非依存（`spec_helper` のみ）のため、
> PostgreSQL コンテナなしでも実行できます。

## 6. 開発サーバーの起動

### データベースの起動とセットアップ

```bash
# PostgreSQL コンテナを起動（プロジェクトルート）
docker compose up -d postgres

# DB 作成 + マイグレーション + シード
cd apps/cargo-tracker
bin/rails db:prepare
```

### 開発サーバーの起動

```bash
cd apps/cargo-tracker

# 開発サーバー起動
bin/rails server

# TDD モード（ファイル変更時にテスト自動再実行したい場合は guard 等を別途導入）
bundle exec rspec --only-failures
```

### アクセス確認

| サービス | URL | 説明 |
|---------|-----|------|
| アプリケーション | http://localhost:3000 | メインアプリケーション |
| ヘルスチェック | http://localhost:3000/up | Rails 8 標準ヘルスチェック |

## 9. コード品質管理

### 静的コード解析ツール

| ツール | 目的 | コマンド |
|--------|------|---------|
| RuboCop | コーディング規約の検証 | `bundle exec rubocop` |
| Brakeman | セキュリティ脆弱性検出 | `bundle exec brakeman` |
| Packwerk | 境界依存検証 | `bin/packwerk check` |
| SimpleCov | テストカバレッジ | `bundle exec rspec`（自動計測） |
| bundler-audit | 依存脆弱性チェック | `bundle exec bundler-audit check --update` |

### 品質チェックの実行

```bash
cd apps/cargo-tracker

# 品質チェックのみ
bundle exec rubocop && bundle exec brakeman -q && bin/packwerk check

# すべてのテストと品質チェック
bundle exec rubocop && bundle exec brakeman -q && bin/packwerk check && bundle exec rspec
```

### コード複雑度の基準

| 指標 | 閾値 | 説明 |
|------|------|------|
| 循環的複雑度 | 10 | 分岐・ループの複雑さ（RuboCop Metrics/CyclomaticComplexity） |
| ファイルサイズ | 500 行 | 1 ファイルの最大行数 |
| メソッドサイズ | 30 行 | 1 メソッドの最大行数（RuboCop Metrics/MethodLength） |
| パラメータ数 | 5 | メソッドの最大パラメータ数 |

### レポートの確認

| ツール | レポートパス |
|--------|-------------|
| SimpleCov | `apps/cargo-tracker/coverage/index.html` |
| Brakeman | 標準出力（CI では JSON 出力） |

## 12. Git 規約

### コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/ja/) に従います。

| タイプ | 説明 |
|--------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | コードの意味に影響しない変更 |
| `refactor` | バグ修正でも機能追加でもないコード変更 |
| `perf` | パフォーマンス改善 |
| `test` | テストの追加・修正 |
| `chore` | ビルドプロセス・補助ツールの変更 |

### スコープ

Bounded Context を示すスコープを使用します。

```
feat(booking): 貨物予約登録を追加
fix(tracking): 追跡番号の一意性検証を修正
docs: セットアップ手順を更新
```

## トラブルシューティング

### PostgreSQL に接続できない

**問題**: `bin/rails db:prepare` で接続エラーが発生する

```
connection to server at "127.0.0.1", port 5432 failed: Connection refused
```

**解決策**: PostgreSQL コンテナが起動しているか確認します。

```bash
docker compose ps
docker compose up -d postgres
```

### ポート 5432 が使用中

**問題**: ローカルに別の PostgreSQL が起動しておりポートが競合する

**解決策**: ローカルの PostgreSQL を停止するか、docker-compose.yml のポートマッピングを変更します。

```bash
# macOS（Homebrew の場合）
brew services stop postgresql
```

### bundle install が openssl 等のネイティブ拡張で失敗する

**問題**: gem のネイティブ拡張ビルドに失敗する

**解決策**: Xcode Command Line Tools と libpq を確認します。

```bash
xcode-select --install
brew install libpq
bundle config build.pg --with-pg-config=$(brew --prefix libpq)/bin/pg_config
```
