# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、**国際貨物輸送管理システム（case-study-cargo-tracker）** のアプリケーション開発環境をセットアップする手順を説明します。

本システムは **Axon Framework 5 + CQRS + Event Sourcing + Saga** を採用したマイクロサービス構成です。7 つのバックエンドサービス（authms / bookingms / routingms / trackingms / handlingms / billingms / gatewayms）+ フロントエンド（React SPA）+ Axon Server + PostgreSQL からなります。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — <https://t-wada.hatenablog.jp/entry/clean-code-that-works>

| サブシステム | ディレクトリ | 説明 | DB / App ポート |

| bookingms（予約） | `apps/backend/bookingms` | 貨物予約・見積・荷主管理、Saga（BookingSagaManager） | 5432 / 8082 |

| trackingms（追跡） | `apps/backend/trackingms` | 貨物追跡・状態更新・例外管理 | 5432 / 8084 |

## 5. プロファイル構成

開発効率を高めるため、複数のプロファイルを使い分けます。

| プロファイル | データベース | Axon Server | Docker | 用途 |
|-------------|------------|------------|--------|------|
| `local-h2` | H2（インメモリ） | Axon Server（dev mode）または Embedded EventStore | 不要 | 単体サービスの即座起動・TDD |
| `local-docker` | PostgreSQL（Docker） | Axon Server（Docker） | 必要 | 本番互換の結合確認 |
| `test` | Testcontainers（PostgreSQL + Axon Server） | 同上 | 自動起動 | 統合テスト実行 |

> **設計指針**: 集約の Event Store は Axon Server が必須。H2 は Read Model（Projection）と Auth DB の代替として使用。日常 TDD は単一サービス + H2 で完結させる。

### local-h2 プロファイル（推奨：単一サービスの TDD）

Docker なしで即座に起動できます（Axon Server は dev mode の埋め込みで代替）。

```bash
cd apps/backend/bookingms
./gradlew bootRun --args='--spring.profiles.active=local-h2'
```

### local-docker プロファイル（本番互換）

```bash
# Axon Server と PostgreSQL を起動
cd apps
docker compose up -d axonserver postgresql

# 個別サービスを起動（例: bookingms）
cd ../apps/backend
./gradlew :bookingms:bootRun --args='--spring.profiles.active=local-docker'
```

## 7. Docker Compose のセットアップ

### サービスの起動

```bash
cd apps

# Axon Server と PostgreSQL のみ起動（推奨：日常開発）
docker compose up -d axonserver postgresql

# 全サービス起動（バックエンド + フロント + Axon Server + PostgreSQL）
docker compose up -d

# コンテナの状態確認
docker compose ps
```

### Docker Compose の便利なコマンド

```bash
# Axon Server のログ確認
docker compose logs -f axonserver

# PostgreSQL に psql で接続
docker compose exec postgresql psql -U cargo -d booking_read_db

# 全コンテナ停止と削除
docker compose down

# ボリュームも削除（Axon Event Store と DB データを完全リセット）
docker compose down -v
```

### docker-compose.yml の主要サービス（抜粋）

```yaml
services:
  axonserver:
    image: axoniq/axonserver:2024.2-LTS
    ports:
      - "8024:8024"   # 管理 UI / REST API
      - "8124:8124"   # gRPC
    volumes:
      - axonserver-data:/axonserver/data
      - axonserver-events:/axonserver/events
      - axonserver-config:/axonserver/config
    environment:
      AXONIQ_AXONSERVER_NAME: axonserver
      AXONIQ_AXONSERVER_HOSTNAME: axonserver
      AXONIQ_AXONSERVER_DEVMODE_ENABLED: "true"
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8024/actuator/health"]
      interval: 10s
      retries: 12

  postgresql:
    image: postgres:16
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: cargo
      POSTGRES_PASSWORD: cargo
      POSTGRES_MULTIPLE_DATABASES: >-
        auth_db,booking_read_db,routing_read_db,
        tracking_read_db,handling_read_db,billing_read_db
    volumes:
      - postgres-data:/var/lib/postgresql/data
      - ./ops/postgres/init-databases.sh:/docker-entrypoint-initdb.d/init-databases.sh

  bookingms:
    build: ./backend/bookingms
    depends_on:
      axonserver:
        condition: service_healthy
      postgresql:
        condition: service_started
    environment:
      AXON_AXONSERVER_SERVERS: axonserver:8124
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgresql:5432/booking_read_db
    ports:
      - "8082:8082"

volumes:
  axonserver-data:
  axonserver-events:
  axonserver-config:
  postgres-data:
```

詳細は [docs/design/architecture_infrastructure.md](../design/architecture_infrastructure.md) を参照。

## 8. テストの実行

### 全テスト実行

```bash
cd apps/backend

# 全プロジェクトのテスト（カバレッジ付き）
./gradlew test jacocoTestReport

# 特定サブプロジェクトのみ
./gradlew :bookingms:test
```

### テストの種類

| テスト種別 | ツール | 説明 |
|-----------|--------|------|
| ユニットテスト | JUnit 5 + AssertJ + Mockito | 値オブジェクト・ドメインサービス・QueryHandler |
| Axon Test | AggregateTestFixture / SagaTestFixture | 集約のイベント検証・Saga の遷移検証 |
| 統合テスト | Testcontainers（PostgreSQL + Axon Server） + Spring MockMvc | REST API・Projection 反映 |
| Contract テスト | Spring Cloud Contract | サービス間のイベント・REST 契約 |
| アーキテクチャテスト | ArchUnit | レイヤー依存・JPA 禁止・MyBatis 規約 |
| ミューテーション | PIT | テストの強さ計測 |

### Frontend テスト

```bash
cd apps/frontend

# ユニット・コンポーネント

npm run test:run     # Vitest 1 回実行

# E2E
npm run e2e          # Playwright（ヘッドレス）
```


| コマンド | `<Verb><Noun>Command` | `BookCargoCommand`, `AssignRouteToCargoCommand` |

## 12. Git 規約

### コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/ja/) に従います。

| タイプ | 説明 |
|--------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | コードの意味に影響しない変更 |
| `refactor` | リファクタリング |
| `perf` | パフォーマンス改善 |
| `test` | テストの追加・修正 |
| `chore` | ビルドプロセス・補助ツールの変更 |

### スコープ

サブシステムまたはレイヤーを示すスコープを使用します。

```text
feat(bookingms): 予約集約のキャンセル機能を追加
fix(tracking): TransportStatus 遷移チェックの境界値バグを修正
docs(adr): ADR-0003 ○○の決定を追加
refactor(design): Phase 1 レビュー指摘の反映
```

### Git Hooks（Husky + lint-staged）

`npm install` 実行時に Husky は自動的にセットアップされます（`prepare` スクリプト）。

```bash
# 手動セットアップ（必要時のみ）
npx husky init
```

#### pre-commit フック

ソースファイルに変更がある場合、以下のチェックが自動実行されます。

| 対象 | ツール |
|------|--------|
| Java | Checkstyle / SpotBugs |
| TypeScript | ESLint / Prettier |
| Markdown | markdownlint（テンプレートに準拠した整形ルール） |

いずれかのチェックが失敗するとコミットがブロックされます。

#### フックをスキップする場合（非推奨）

```bash
git commit --no-verify -m "メッセージ"
```

> **Warning**: フックのスキップは緊急時のみ。品質チェックを通過しないコードはチームに影響します。


## トラブルシューティング

### Axon Server に接続できない

**問題**: `bookingms` 起動時に `io.axoniq.axonserver.connector.client` 関連の接続エラーが出る

```text
io.netty.channel.AbstractChannel$AnnotatedConnectException: Connection refused: localhost/127.0.0.1:8124
```

**解決策**: Axon Server コンテナが起動・ヘルスチェック合格しているか確認

```bash
docker compose ps axonserver
docker compose logs axonserver | tail -50

# 起動していない場合
docker compose up -d axonserver
```

### PostgreSQL のマルチデータベースが作成されない

**問題**: `booking_read_db` などのデータベースが見つからない

**解決策**: `ops/postgres/init-databases.sh` が `docker-entrypoint-initdb.d/` にマウントされているか確認。ボリュームを削除して再作成。

```bash
cd apps
docker compose down -v postgresql
docker compose up -d postgresql
docker compose exec postgresql psql -U cargo -l
```

### Java バージョン不一致でビルドが失敗

**問題**: `Unsupported class file major version` 等

**解決策**: Java 25 を使っているか確認。SDKMAN を使っている場合 `sdk use java 25-tem`。

```bash
java -version
./gradlew --version
```

### Frontend で API 502 / CORS エラー

**問題**: Vite 開発サーバから `/api/...` が 502 を返す

**解決策**: `vite.config.ts` の `server.proxy` で `localhost:8080`（gatewayms）に向ける。または gatewayms が起動しているか確認。

### pre-commit フックが失敗する場合

```bash
cd apps/backend

# 品質チェックを手動実行してエラーを確認
./gradlew check -x test

# Frontend
cd ../frontend
npm run lint
```

エラー修正後に再度コミット。
