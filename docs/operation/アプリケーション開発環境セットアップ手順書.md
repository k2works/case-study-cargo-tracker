# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、国際貨物輸送管理システム（Cargo Tracker Go 版）のアプリケーション開発環境をセットアップする手順を説明します。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。
> 三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — https://t-wada.hatenablog.jp/entry/clean-code-that-works

## 1. 前提条件

以下のツールがインストールされていることを確認してください。

| ツール | バージョン | 確認コマンド |
|--------|-----------|-------------|
| Go | 1.24 以上 | `go version` |
| golangci-lint | 最新 | `golangci-lint version` |
| Docker | 最新 | `docker -v` |
| Docker Compose | v2.x | `docker compose version` |
| Git | 最新 | `git -v` |
| Node.js | v22.x LTS 以上 | `node -v` |
| npm | v10.x 以上 | `npm -v` |

### Go のインストール

Go をインストールします。バージョン管理ツール（mise / asdf 等）を使用すると複数バージョンの管理が容易です。

```bash
# Homebrew でインストール（macOS）
brew install go

# バージョン確認
go version
```

公式サイトから直接ダウンロードする場合：

- https://go.dev/dl/

### golangci-lint のインストール

```bash
# Homebrew でインストール（macOS）
brew install golangci-lint

# バージョン確認
golangci-lint version
```

### Docker のインストール

Docker Desktop をインストールします。統合テスト（testcontainers-go）と PostgreSQL の起動に必要です。

- **Windows**: https://docs.docker.com/desktop/install/windows-install/
- **macOS**: https://docs.docker.com/desktop/install/mac-install/

```bash
# バージョン確認
docker -v

docker compose version
```

### Node.js のインストール

開発タスクランナー（Gulp）とコミット前の品質チェックに Node.js が必要です。

- https://nodejs.org/

```bash
# バージョン確認
node -v

npm -v
```

## 5. プロファイル構成

環境変数 `APP_ENV` でプロファイルを切り替えます。テスト用のインメモリ DB は使用せず、常に実 PostgreSQL を使用します（設計判断: ADR 0001）。

| プロファイル | データベース | Docker | 用途 |
|-------------|------------|--------|------|
| dev（デフォルト） | PostgreSQL 16（Docker Compose） | 必要 | 日常開発 |
| test | PostgreSQL 16（testcontainers-go が自動起動） | 必要 | 統合テスト |

### dev プロファイル（日常開発）

```bash
# データベースコンテナを起動
cd apps/cargo-tracker
docker compose up -d postgres

# アプリケーションを起動
make run
# または
go run ./cmd/server
```

### test プロファイル（統合テスト）

testcontainers-go がテスト実行時に使い捨ての PostgreSQL コンテナを自動起動するため、事前のコンテナ起動は不要です（Docker Desktop の起動のみ必要）。

```bash
cd apps/cargo-tracker
make test-integration
# または
go test -tags=integration ./...
```

## 8. テストの実行

テスト戦略の詳細は [テスト戦略](../design/test_strategy.md) を参照してください。

### 全テスト実行

```bash
cd apps/cargo-tracker

# 単体テスト（カバレッジ付き）
make test

# 統合テスト込み（testcontainers-go 使用。Docker 必須）
make test-all
```

### テストの種類

| テスト種別 | ツール | 説明 |
|-----------|--------|------|
| 単体テスト | testing + testify（テーブル駆動） | ドメイン・アプリケーション層のテスト |
| 統合テスト | testcontainers-go（実 PostgreSQL） | リポジトリ・マイグレーションのテスト（`-tags=integration`） |
| ハンドラテスト | net/http/httptest | HTTP ハンドラとテンプレートレンダリングの検証 |
| アーキテクチャテスト | go-arch-lint | レイヤー・BC 間依存関係の検証 |
| E2E テスト | Playwright | 画面操作の自動テスト |

### テストカバレッジ

```bash
# カバレッジプロファイル付きで実行（統合テスト込み）
go test -tags=integration -coverprofile=coverage.out ./...

# レポートの表示
go tool cover -html=coverage.out
```

## 12. Git 規約

### コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/ja/) に従います。

| タイプ | 説明 |
|--------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | コードの意味に影響しない変更 |
| `refactor` | バグ修正でも機能追加でもないコード変更 |
| `perf` | パフォーマンス改善 |
| `test` | テストの追加・修正 |
| `chore` | ビルドプロセス・補助ツールの変更 |

### スコープ

Bounded Context またはレイヤーを示すスコープを使用します。

```
feat(booking): 貨物予約登録機能を追加
fix(tracking): 追跡ステータスの表示不具合を修正
docs: 設計ドキュメントを更新
```

### Git Hooks（Husky + lint-staged）

コミット時に自動で品質チェックが実行されます。

#### セットアップ

`npm install` 実行時に Husky は自動的にセットアップされます（`prepare` スクリプト）。

#### pre-commit フック

Go ソースファイルに変更がある場合、以下のチェックが自動実行されます。

| ツール | 目的 |
|--------|------|
| gofmt / goimports | フォーマット検証 |
| golangci-lint | Lint（変更ファイルのみ） |

いずれかのチェックが失敗すると、コミットがブロックされます。

#### フックをスキップする場合

緊急時にフックをスキップしてコミットする場合（非推奨）：

```bash
git commit --no-verify -m "メッセージ"
```

> **Warning**: フックのスキップは緊急時のみ使用してください。

## トラブルシューティング

### testcontainers-go がコンテナを起動できない

**問題**: 統合テストで `Cannot connect to the Docker daemon` エラーが発生する。

**解決策**: Docker Desktop が起動していることを確認してください。

```bash
docker info
```

### ポート 8080 / 5432 が使用中

**問題**: `bind: address already in use` エラーが発生する。

**解決策**: 使用中のプロセスを確認して停止します。

```bash
lsof -i :8080
docker compose down
```

### sqlc 生成コードとスキーマの不一致

**問題**: マイグレーション変更後にビルドエラーが発生する。

**解決策**: sqlc のコード生成を再実行します。

```bash
cd apps/cargo-tracker
make generate
# または
sqlc generate
```

### pre-commit フックが失敗する場合

```bash
cd apps/cargo-tracker

# 品質チェックを手動実行してエラーを確認
make lint

# エラーを修正してから再度コミット
```
