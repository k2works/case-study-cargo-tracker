>
> - バージョン管理

>
> の 3 つです。

## 1. 前提条件

以下のツールがインストールされていることを確認してください。

| ツール | バージョン | 確認コマンド |
|--------|-----------|-------------|
| Java (JDK) | 25 | `java -version` |
| Docker | 最新 | `docker -v` |
| Docker Compose | v2.x | `docker compose version` |
| Git | 最新 | `git -v` |
| Node.js | v22.x LTS | `node -v` |
| npm | v10.x | `npm -v` |

> **Note**: Gradle は Gradle Wrapper（`apps/backend/gradlew`）を使用するため、別途インストールする必要はありません。Gradle Wrapper は 9.2.1 を使用しています。

### Java のインストール

Java 25 をインストールします。SDKMAN! を使用すると複数バージョンの管理が容易です。

```bash
# SDKMAN! でインストール
sdk install java 25-tem

# バージョン確認
java -version
```

公式サイトから直接ダウンロードする場合：

- https://adoptium.net/

### Docker のインストール

Docker Desktop をインストールします。

- **Windows**: https://docs.docker.com/desktop/install/windows-install/
- **macOS**: https://docs.docker.com/desktop/install/mac-install/

```bash
# バージョン確認
docker -v

docker compose version
```

### Node.js のインストール

コミット前の品質チェック（husky + lint-staged）およびタスクランナー（Gulp）に Node.js が必要です。

- https://nodejs.org/

```bash
# バージョン確認
node -v

npm -v
```

## 5. プロファイル構成

開発効率を高めるため、複数のプロファイルを使い分けます。

| プロファイル | データベース | Docker | 用途 |
|-------------|------------|--------|------|
| default | H2（インメモリ、PostgreSQL 互換モード） | 不要 | 日常開発・即座起動 |
| product | PostgreSQL | 必要 | 本番互換テスト |

### default プロファイル（推奨：日常開発）

Docker なしで即座に起動できます。各サービスは H2 インメモリデータベース（PostgreSQL 互換モード）を使用します。

```bash
cd apps/backend
./gradlew :bookingms:bootRun
```

### product プロファイル（本番互換）

```bash
# データベース・メッセージブローカーを起動
cd apps
docker compose up -d postgres rabbitmq

# product プロファイルで起動
cd backend
./gradlew :bookingms:bootRun --args='--spring.profiles.active=product'
```

## 7. Docker Compose のセットアップ

### タスクランナー経由（推奨）

```bash
# PostgreSQL + RabbitMQ 起動
npx gulp dev:db:start

# コンテナ状態確認
npx gulp dev:db:status

# コンテナログ表示
npx gulp dev:db:logs

# コンテナ停止
npx gulp dev:db:stop
```

### Docker Compose 直接実行

```bash
cd apps

# PostgreSQL と RabbitMQ を起動
docker compose up -d

# コンテナの状態確認
docker compose ps

# コンテナの停止と削除
docker compose down

# ログを確認
docker compose logs -f postgres

# データベースに接続
docker compose exec postgres psql -U cargo_tracker -d booking_db
```

> **Note**: `docker-compose.yml` は `apps/` 直下に配置されています。Gradle 設定（`apps/backend/`）とは別の階層です。

### テストの種類

| テスト種別 | ツール | 対象 | 説明 |

### テストカバレッジ

```bash
# バックエンド
cd apps/backend
./gradlew test jacocoTestReport
# レポート: apps/backend/bookingms/build/reports/jacoco/test/html/index.html

# フロントエンド
cd apps/frontend
npm test
```

### タスクランナー経由のテスト実行

```bash
# バックエンド全テスト
npx gulp dev:backend:test

# フロントエンド全テスト
npx gulp dev:frontend:test

# TDD モード（バックエンド）
npx gulp dev:backend:tdd

# TDD モード（フロントエンド）
npx gulp dev:frontend:tdd
```

### テスト実行時の注意事項

- Java 25 で Byte Buddy の ClassFileVersion 解決の問題があるため、テスト時に `-Dnet.bytebuddy.experimental=true` が自動設定されます
- Testcontainers 使用時は Docker Desktop が起動している必要があります
- `DOCKER_API_VERSION=1.43` が環境変数として自動設定されます

## 12. Git 規約

### コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/ja/) に従います。

| タイプ | 説明 |
|--------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | コードの意味に影響しない変更 |
| `refactor` | バグ修正でも機能追加でもないコード変更 |
| `perf` | パフォーマンス改善 |
| `test` | テストの追加・修正 |
| `chore` | ビルドプロセス・補助ツールの変更 |

### スコープ

サブシステムを示すスコープを使用します。

```
feat(booking): 貨物予約の登録機能を追加
fix(tracking): 追跡情報の更新が反映されない問題を修正
docs: アプリケーション開発環境セットアップ手順書を作成
chore(setup): Gradle マルチプロジェクト基盤を構築
```

### Git Hooks（Husky + lint-staged）

コミット時に自動で品質チェックが実行されます。

#### セットアップ

`npm install` 実行時に Husky は自動的にセットアップされます（`prepare` スクリプト）。

```bash
# 手動でセットアップする場合
npx husky init
```

#### pre-commit フック

Java ソースファイル（`apps/**/src/**/*.java`）に変更がある場合、以下のチェックが自動実行されます。

| ツール | 目的 |
|--------|------|
| Checkstyle | コーディング規約の検証 |
| SpotBugs | バグパターン検出 |
| JUnit 5 | テスト実行 |
| JaCoCo | カバレッジレポート生成 |

> **実行の仕組み**: `npx lint-staged` → `ops/scripts/pre_commit_gradle_check.mjs` → `cd apps/backend && ./gradlew check`（タイムアウト 300 秒）

いずれかのチェックが失敗すると、コミットがブロックされます。

#### フックをスキップする場合

緊急時にフックをスキップしてコミットする場合（非推奨）：

```bash
git commit --no-verify -m "メッセージ"
```

> **Warning**: フックのスキップは緊急時のみ使用してください。品質チェックを通過しないコードはチームに影響を与える可能性があります。

## 14. CI/CD

CI/CD による継続的インテグレーション・デプロイを設定予定です。

### ワークフロー一覧（予定）

| ワークフロー | ファイル | トリガー | 説明 |
|-------------|----------|----------|------|
| Backend CI | `.github/workflows/backend-ci.yml` | `apps/**/backend/**` 変更時 | 品質チェック・テスト・ビルド |
| Frontend CI | `.github/workflows/frontend-ci.yml` | `apps/frontend/**` 変更時 | Lint・テスト・ビルド |
| Docker Publish | `.github/workflows/docker-publish.yml` | タグ push / 手動実行 | イメージを ECR に公開 |
| Docs Deploy | `.github/workflows/docs.yml` | main ブランチ push | ドキュメントをデプロイ |

### Backend CI（予定）

バックエンドの変更時に自動実行される予定です。

```
実行内容:

  1. JDK 25 セットアップ
  2. Gradle キャッシュ復元
  3. 品質チェック（Checkstyle、SpotBugs）
  4. テスト実行（単体・統合・アーキテクチャ）
  5. カバレッジレポート生成（JaCoCo）
  6. ビルド（JAR 生成）
  7. レポートアップロード
```

## トラブルシューティング

### Gradle ビルドが失敗する

**問題**: Java バージョンが一致しない

```
Unsupported class file major version 69
```

**解決策**: Java 25 がインストールされていることを確認

```bash
java -version
# SDKMAN! で切り替え
sdk use java 25-tem
```

### Gradle Wrapper が見つからない

**問題**: `gradlew: No such file or directory`

**解決策**: `apps/backend/` ディレクトリに移動してから実行

```bash
cd apps/backend
./gradlew build
```

### ポートが既に使用されている

**問題**: サービス起動時に `Port already in use` エラー

**解決策**: 使用中のプロセスを確認して停止

```bash
# macOS / Linux
lsof -i :8082
kill -9 <PID>
```

### pre-commit フックが失敗する場合

```bash
cd apps/backend

# 品質チェックを手動実行してエラーを確認
./gradlew checkstyleMain spotbugsMain

# エラーを修正してから再度コミット
```

### H2 Console に接続できない

**問題**: H2 Console にアクセスできない

**解決策**: `application.yml` で H2 Console が有効になっていることを確認

```yaml
spring:
  h2:
    console:
      enabled: true
      path: /h2-console
```

**接続情報**:

| 項目 | 値 |
|------|-----|
| JDBC URL | `jdbc:h2:mem:booking_db` |
| User Name | `sa` |
| Password | （空欄） |

### RabbitMQ に接続できない

**問題**: メッセージング機能が動作しない

**解決策**: Docker で RabbitMQ を起動

```bash
cd apps
docker compose up -d rabbitmq

# 管理 UI で確認
# http://localhost:15672 (guest/guest)
```

### PostgreSQL に接続できない（product プロファイル）

**問題**: product プロファイルで DB 接続エラー

**解決策**: Docker で PostgreSQL を起動

```bash
cd apps
docker compose up -d postgres

# 接続確認
docker compose exec postgres psql -U cargo_tracker -d booking_db
```
