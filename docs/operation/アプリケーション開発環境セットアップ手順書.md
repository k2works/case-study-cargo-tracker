# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、**国際貨物輸送管理システム（case-study-cargo-tracker）** のアプリケーション開発環境をセットアップする手順を説明します。

本システムは **Axon Framework 5 + CQRS + Event Sourcing + Saga** を採用したマイクロサービス構成です。7 つのバックエンドサービス（authms / bookingms / routingms / trackingms / handlingms / billingms / gatewayms）+ フロントエンド（React SPA）+ **Axon Kafka Extension** + **Aiven Managed Kafka** + PostgreSQL からなります。

### 整備状況の凡例

本ドキュメント内では各項目の実装ステータスを以下の記号で示します。

- ✅ 整備済み（実際に動作確認できる）
- 🚧 雛形のみ（`.gitkeep`、計画記載のみ）
- 📋 Phase 2 以降に実装予定

**IT1 完了時点で動かせる範囲**: `apps/backend/authms`（port 8081）、`apps/backend/bookingms`（port 8082）、`apps/frontend`（port 5173）。それ以外のサービス（routingms/trackingms/handlingms/billingms/gatewayms）は雛形（.gitkeep）配置のみで起動できません（ADR-0003 参照）。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — <https://t-wada.hatenablog.jp/entry/clean-code-that-works>

### Gradle Wrapper の初回生成（クローン直後に 1 度だけ）

`apps/backend/` に `gradlew` / `gradlew.bat` / `gradle/wrapper/gradle-wrapper.jar` が無い状態でクローンした場合は、Docker 経由で Gradle 9.5 を起動して生成します（ホストに Gradle が未インストール、または Gradle 8 系で Java 25 をパースできない環境でも確実に動作）。

```powershell
# PowerShell（Windows）
docker run --rm `
  -v "${PWD}/apps/backend:/ws" `
  -w "/ws" `
  gradle:9.5.0-jdk25 `
  gradle wrapper --gradle-version 9.5 --distribution-type bin
```

```bash
# Git Bash / WSL / macOS / Linux
MSYS_NO_PATHCONV=1 docker run --rm \
  -v "$(realpath apps/backend):/ws" \
  -w "/ws" \
  gradle:9.5.0-jdk25 \
  gradle wrapper --gradle-version 9.5 --distribution-type bin
```

> **補足**: 各サービスの `Dockerfile` は `gradle:9.5.0-jdk25` 公式イメージをビルダーに使うため、コンテナビルドだけなら wrapper 無しでも動作します。Wrapper はホスト側 `dev:<service>` / `tdd:<service>` の Gradle 実行で必要です。

## 5. プロファイル構成

開発効率を高めるため、複数のプロファイルを使い分けます。

| プロファイル | データベース | メッセージング | Docker | 用途 |
|-------------|------------|--------------|--------|------|
| `local-h2` | H2（インメモリ） | Axon ローカルバス（Kafka なし） | 不要 | 単体サービスの即座起動・TDD |
| `local-docker` | PostgreSQL（Docker） | Kafka（Confluent）コンテナ | 必要 | 本番互換の結合確認 |
| `test` | Testcontainers（PostgreSQL） | Axon ローカルバス | 自動起動 | 統合テスト実行 |
| `heroku` | Heroku Postgres | Aiven Kafka（SSL 接続） | - | Heroku 本番・ステージング |

> **設計指針**: Event Store は JpaEventStorageEngine（PostgreSQL）を使用。イベントバスは Axon Kafka Extension 経由で Kafka に接続。H2 は Read Model（Projection）と Auth DB の代替として使用。日常 TDD は単一サービス + H2 で完結させる。

### local-h2 プロファイル（推奨：単一サービスの TDD）

Docker なしで即座に起動できます（Kafka なしの Axon ローカルバスを使用）。

```bash
cd apps/backend/bookingms
./gradlew bootRun --args='--spring.profiles.active=local-h2'
```

### local-docker プロファイル（本番互換、Docker でフルスタック起動）

`apps/docker-compose.yml` で基盤（Kafka + ZooKeeper + PostgreSQL）と全マイクロサービス
（authms / bookingms / routingms / gatewayms）を一括起動します。Gulp の
`local-docker:*` タスク経由が推奨です。

```bash
# 全サービスの Docker イメージをビルド
npx gulp local-docker:build

# フル起動（基盤 + 4 ms）
npx gulp local-docker:up

# 5 サービスの health 疎通確認
npx gulp local-docker:smoke

# コンテナ停止（ボリューム保持）
npx gulp local-docker:down

# Event Store / DB を含めた完全リセット（実行直前に y/n 確認プロンプトあり）
npx gulp local-docker:clean
```

> **IT2 範囲**: `apps/docker-compose.yml` には `authms` / `bookingms` /
> `routingms` / `gatewayms` がアクティブです。`trackingms` / `handlingms` /
> `billingms` は IT5 以降で、`frontend` は IT3 で追加予定（コメントアウト
> 行として残置）。
>
> **Event Processor**: local-docker でも IT2 暫定で `subscribing` モードを
> 使用します（PostgreSQL の `TokenEntry` 自動生成を整備するまで）。詳細は
> ADR-0008 を参照。

### Spring Boot DevTools による自動再起動

`bootRun` で起動中にコードを変更すると DevTools がクラスパスの変化を検知して
自動で再起動する。手順は 2 つのターミナルが必要：

```bash
# ターミナル 1: bootRun で常駐起動（restartedMain スレッドで動作）
./gradlew :bookingms:bootRun --args='--spring.profiles.active=local-h2'

# ターミナル 2: 継続コンパイル（保存ごとに :classes タスクを再実行）
./gradlew :bookingms:classes --continuous
```

ターミナル 2 でクラスファイルが更新されると、ターミナル 1 のアプリが
通常 0.5〜1 秒で再起動する（フルブートではなく restartedMain による高速再起動）。

**動作仕様**:

- `application-local-h2.yml` で `spring.devtools.restart.enabled: true`・
  `spring.devtools.livereload.enabled: true` をプロファイル別に有効化済み
- `developmentOnly(libs.spring.boot.devtools)` で依存スコープを開発のみに限定
  しているため、`bootJar` での本番ビルドには DevTools は含まれない
- IntelliJ IDEA から起動する場合は「Build project automatically」を ON にし、
  Registry で `compiler.automake.allow.when.app.running` を有効化すると
  ターミナル 2 が不要になる

## 7. Docker Compose のセットアップ

### Compose ファイル構成

リポジトリには 2 つの compose ファイルがあります（ADR-0003 で分離）。

| ファイル | 役割 | 主な利用者 |
|---------|------|-----------|
| `apps/docker-compose.yml` | アプリ実行環境（Kafka / ZooKeeper / PostgreSQL / authms / bookingms / routingms / gatewayms。Frontend と tracking/handling/billing は将来追加） | 開発者 |
| `docker-compose.docs.yml` | ドキュメントサイト（MkDocs）専用 | ドキュメント執筆 |

### `.env` の準備（必須）

`apps/docker-compose.yml` は `.env` からシークレットを読み込みます。**ハードコードは廃止されています**（ADR-0003）。

```bash
cp .env.example .env

# 最低限以下を設定してから compose を起動
#   POSTGRES_USER           : PostgreSQL ユーザー名
#   POSTGRES_PASSWORD       : PostgreSQL パスワード（必須、未設定だと起動失敗）
#   JWT_SECRET              : authms/gatewayms 連携時に必須
```

### サービスの起動

```bash
# 推奨：local-docker フル起動（Kafka + ZooKeeper + PostgreSQL + authms + bookingms + routingms + gatewayms）
gulp local-docker:up

# 基盤のみ起動（IDE で個別 bootRun する場合）
docker compose -f apps/docker-compose.yml up -d kafka zookeeper postgresql

# 状態確認
gulp local-docker:smoke
# または
docker compose -f apps/docker-compose.yml ps
```

### 便利なコマンド

```bash
# Kafka のログ確認
docker compose -f apps/docker-compose.yml logs -f kafka

# PostgreSQL に psql で接続
docker compose -f apps/docker-compose.yml exec postgresql \
  psql -U "$POSTGRES_USER" -d booking_read_db

# 全コンテナ停止（ボリューム保持）
docker compose -f apps/docker-compose.yml down

# ボリュームも削除（Event Store と DB データを完全リセット、破壊的）
docker compose -f apps/docker-compose.yml down -v
```

### docker-compose.yml の主要サービス（抜粋）

```yaml
services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.6.0
    ports:
      - "2181:2181"
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181

  kafka:
    image: confluentinc/cp-kafka:7.6.0
    ports:
      - "9092:9092"
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:29092,PLAINTEXT_HOST://localhost:9092
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: PLAINTEXT:PLAINTEXT,PLAINTEXT_HOST:PLAINTEXT
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    depends_on:
      - zookeeper

  postgresql:
    image: postgres:16
    ports:
      - "${POSTGRES_PORT:-5432}:5432"
    environment:
      POSTGRES_USER: ${POSTGRES_USER:?POSTGRES_USER not set in .env}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?POSTGRES_PASSWORD not set in .env}
      POSTGRES_MULTIPLE_DATABASES: >-
        auth_db,booking_read_db,routing_read_db,
        tracking_read_db,handling_read_db,billing_read_db

  bookingms:
    build:
      context: ./backend
      dockerfile: bookingms/Dockerfile
    depends_on:
      kafka:
        condition: service_healthy
      postgresql:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: local-docker
      KAFKA_BOOTSTRAP_SERVERS: kafka:29092
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgresql:5432/booking_read_db
      SPRING_DATASOURCE_USERNAME: ${POSTGRES_USER}
      SPRING_DATASOURCE_PASSWORD: ${POSTGRES_PASSWORD}

  # authms / routingms / gatewayms も IT2 完了時点で同様に compose 内で定義済み

feat(bookingms): 予約集約のキャンセル機能を追加

```

### Git Hooks（`.githooks/` ディレクトリ）

本プロジェクトは Husky を使わず、`.githooks/` ディレクトリに Git Hooks を管理します。クローン後に以下のコマンドで 1 度だけ設定します。

```bash
git config core.hooksPath .githooks
```

> **確認**: `git config --get core.hooksPath` が `.githooks` を返せば設定済みです。

#### pre-commit フック

ステージングされたファイルに応じて、以下のチェックが自動実行されます。

| 対象 | チェック内容 |
|------|------------|
| Java（`.java`） | `./gradlew check`（Checkstyle + SpotBugs + テスト） |
| TypeScript / TSX / JS / JSX（`apps/frontend/`） | ESLint（`--max-warnings=0`）+ テスト + ビルド |

対象ファイルがなければスキップされます。いずれかのチェックが失敗するとコミットがブロックされます。

#### commit-msg フック

[Conventional Commits](https://www.conventionalcommits.org/ja/) フォーマットを検証します。

```text
<type>(<scope>): <subject>

利用可能な type: feat, fix, docs, style, refactor, test, chore, perf, ci, build, revert
```

#### フックをスキップする場合（非推奨）

```bash
git commit --no-verify -m "メッセージ"
```

> **Warning**: フックのスキップは緊急時のみ。品質チェックを通過しないコードはチームに影響します。

## トラブルシューティング

### Kafka に接続できない（ローカル）

**問題**: `bookingms` 起動時に Kafka 接続エラーが出る

```text
org.apache.kafka.common.errors.TimeoutException: Topic cargo-events not present in metadata after 60000 ms.
```

**解決策**: Docker Compose で kafka コンテナが起動しているか確認

```bash
docker compose -f apps/docker-compose.yml ps kafka zookeeper
docker compose -f apps/docker-compose.yml logs kafka | tail -50

# 起動していない場合
docker compose -f apps/docker-compose.yml up -d zookeeper kafka
```

### PostgreSQL のマルチデータベースが作成されない

**問題**: `booking_read_db` などのデータベースが見つからない

**解決策**: `apps/ops/postgres/init-databases.sh` が `docker-entrypoint-initdb.d/` にマウントされているか確認。ボリュームを削除して再作成。

```bash
docker compose -f apps/docker-compose.yml down -v postgresql
docker compose -f apps/docker-compose.yml up -d postgresql
docker compose -f apps/docker-compose.yml exec postgresql \
  psql -U "$POSTGRES_USER" -l
```

### Java バージョン不一致でビルドが失敗

**問題**: `Unsupported class file major version` 等

**解決策**: Java 25 を使っているか確認。SDKMAN を使っている場合 `sdk use java 25-tem`。

```bash
java -version
./gradlew --version
```

### Frontend で API 502 / CORS エラー

**問題**: Vite 開発サーバから `/api/...` が 502 を返す

**解決策**: `vite.config.ts` の `server.proxy` で `localhost:8080`（gatewayms）に向ける。または gatewayms が起動しているか確認。

### フロントエンドから authms / bookingms への CORS エラー

**問題**: フロントエンド（localhost:5173）から API リクエスト時に CORS エラーが発生する

```text
Access to fetch at 'http://localhost:8081/...' from origin 'http://localhost:5173' has been blocked by CORS policy
```

**解決策**: 各サービスの `SecurityConfig` に `CorsConfigurationSource` Bean が正しく定義されているか確認。`allowedOriginPatterns` に `http://localhost:5173` が含まれている必要があります。

```java
// apps/backend/authms（または bookingms）/.../config/SecurityConfig.java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    var configuration = new CorsConfiguration();
    configuration.setAllowedOriginPatterns(List.of(
            "http://localhost:3000",
            "http://localhost:5173",
            "https://*.herokuapp.com"
    ));
    configuration.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
    configuration.setAllowedHeaders(List.of("*"));
    configuration.setAllowCredentials(true);
    var source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/**", configuration);
    return source;
}
```

### フロントエンドから荷主 API が 404 になる

**問題**: 荷主一覧・登録 API が 404 を返す

**解決策**: フロントエンドの API クライアントが正しいサービスに向いているか確認。`bookingApiClient`（port 8082）を使用し、パスは `/api/v1/shippers` であることを確認。

```typescript
// 正しい実装: bookingApiClient + /api/v1/shippers
bookingApiClient.get<Shipper[]>('/api/v1/shippers')

// よくある誤り 1: authApiClient（port 8081）を使用
// よくある誤り 2: パスに /api/booking/ プレフィックスを付ける
```

### pre-commit フックが失敗する場合

```bash
cd apps/backend

# 品質チェックを手動実行してエラーを確認
./gradlew check -x test

# Frontend
cd ../frontend
npm run lint
```

エラー修正後に再度コミット。
