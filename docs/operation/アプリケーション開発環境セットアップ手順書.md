> - バージョン管理

>
> の 3 つです。

### 5.2 `flix.toml`

```toml
[package]
name        = "cargo-tracker"
description = "国際貨物輸送管理システム（Flix 実装）"
version     = "0.1.0"
flix        = "0.75.1"

"com.h2database:h2"         = "2.3.232"
```

> **Maven 依存の宣言形式**: `[mvn-dependencies]` セクションに `"groupId:artifactId" = "version"` の形式で記述します。
> `flix build` 実行時に Maven Central から解決され、`lib/cache/` 配下にダウンロードされます。
> 推移的依存も自動的に解決されます（実測: postgresql → checker-qual）。

## 6. ビルドとテスト

### 6.1 タスクランナー経由（推奨）

日常の開発はリポジトリルートから Gulp タスクで実行します。全コマンドは `npx gulp dev:help` で確認できます。

```bash
npm run dev:build      # ビルド（依存解決 + コンパイル）
npm run dev:test       # テスト実行
npm run dev:tdd        # TDD モード（変更を監視してテストを自動実行）
npm run dev:verify     # ビルド + テスト（コミット前の確認）
npm run dev:run        # main を実行
npm run dev:jar        # 実行可能 JAR を生成（build-fatjar）
npm run dev:clean      # ビルド生成物を削除
npm run dev:help       # ヘルプを表示
```

| タスク | 用途 |
|--------|------|
| `dev:check` | 型検査のみ。最も速く、編集中の確認に使う |
| `dev:build` | 依存解決 + コンパイル |
| `dev:test` | テスト実行 |
| `dev:tdd` | `src/**/*.flix`・`test/**/*.flix` を監視し、保存のたびにテストを実行する |
| `dev:verify` | `dev:build` → `dev:test`。コミット前の確認 |
| `dev:jar` / `dev:jar:run` | fat JAR の生成と実行 |
| `dev:format` / `dev:doc` / `dev:outdated` | 整形 / API ドキュメント生成 / 依存の更新確認 |

### 6.2 Flix CLI の直接実行

```bash
cd apps/cargo-tracker

java -jar ../../ops/tools/flix/flix.jar check        # 型検査
java -jar ../../ops/tools/flix/flix.jar build        # ビルド
java -jar ../../ops/tools/flix/flix.jar test         # テスト
java -jar ../../ops/tools/flix/flix.jar build-fatjar # 依存込みの実行可能 JAR
java -jar ../../ops/tools/flix/flix.jar repl         # REPL
```

### 6.3 実行可能 JAR の生成（`build-jar` と `build-fatjar` の違い）

**`build-jar` が生成する JAR は Maven 依存を含みません**（実測で確認）。マニフェストに `Class-Path` も
設定されないため、単体で実行すると JDBC などの依存を使う箇所で `ClassNotFoundException` になります。

| コマンド | 依存の同梱 | サイズ（実測） | 用途 |
|---------|:---------:|--------------|------|
| `build-jar` | **含まない** | 765 KB | 依存を使わない検証のみ |
| `build-fatjar` | **含む** | 4.6 MB | **配布・デプロイはこちらを使う** |

```bash
# 推奨（依存を同梱。単体で実行できる）
npm run dev:jar
java -jar apps/cargo-tracker/artifact/cargo-tracker.jar

# build-jar を使う場合は lib/ をクラスパスに追加する必要がある
java -cp "artifact/cargo-tracker.jar:$(find lib -name '*.jar' | tr '\n' ':')" Main
```

> **Dockerfile への影響**: 実行イメージには `build-fatjar` の成果物 1 ファイルをコピーすれば十分です。
> [インフラアーキテクチャ](../design/architecture_infrastructure.md) を参照してください。

## 7. Flix の実装上の注意点（検証で判明した事項）

> **本章の位置づけ**: 環境構築時と IT1 の実装で実機検証した結果を集約している。
> Flix は 0.x 系でありドキュメントが薄いため、**同じ罠を二度踏まないことを目的**とする。
> 新しい制約が判明したら本章へ追記すること。

### 7.0 制約の一覧

| # | 制約 | 対処 | 判明時期 |
|:--:|------|------|:---:|
| 1 | 同名のトップレベルモジュールを複数ファイルで宣言できない | モジュール名は階層を**接頭辞**で表現（`SharedDbPool`） | IT1 |
| 2 | ドット区切りの `mod A.B.C` は参照解決できない | 入れ子 `mod` か接頭辞命名を使う | IT1 |
| 3 | 型エイリアス（`pub type alias`）はモジュール境界を越えて公開されない | `enum` で包む | IT1 |
| 4 | `resources/` は fat JAR には入るが `flix test` の classpath には載らない | Flyway の location に `classpath:` と `filesystem:` の両方を指定 | IT1 |
| 5 | テストランナーが **stderr 出力をテスト失敗として扱う** | ライブラリのログを抑止（`slf4j-nop` 等） | IT1 |
| 6 | `run`・`as`・`handler` が予約語 | 命名を避ける（`exec`・`actual`・`httpHandler`） | IT1 |
| 7 | `String.contains` は名前付き引数 `substr` を取る | `String.contains(substr = "x", s)` | IT1 |
| 8 | メソッドチェーンで改行前にドットを置けない | 中間変数へ分割する | IT1 |
| 9 | JDBC ドライバの ServiceLoader 自動登録が機能しない | `Class.forName` で明示登録（7.4 参照） | 環境構築 |
| 10 | `build-jar` は Maven 依存を同梱しない | 配布用は `build-fatjar` を使う（6.3 参照） | 環境構築 |
| 11 | 仮想スレッド Executor はデーモンスレッドを生成する | サーバ起動後に `CountDownLatch.await()` 等で待機する | IT1 |
| 12 | **`try/catch` を含むネストしたラムダで不正なバイトコードが生成される**（`java.lang.VerifyError`） | 例外に依存しない実装へ書き換える。コンパイルは通り**テスト実行時に初めて failing する** | IT1 |
| 13 | テストランナーは同一 JVM で全テストを実行する | 統合テストは DB 名を分ける。マイグレーションに業務データを含めない（7.6 参照） | IT1 |
| 14 | `query` が予約語（Datalog 構文） | 変数・引数名に使わない（`queryMap`・`queryParams`） | IT2 |
| 15 | `import java.lang.String` のあるモジュールでは `String.split` 等の**標準ライブラリ関数が解決できなくなる** | 文字列ユーティリティを java import のないモジュールへ分離する | IT2 |

### 7.6 マイグレーションに業務データを含めない

Flyway の Repeatable マイグレーション（`R__*.sql`）に業務データを入れると、
**テストが自前で用意するデータと一意制約で衝突する**（IT1 で 7 件のテストが失敗した）。

| 種別 | 配置 | 理由 |
|------|------|------|
| マスタデータ（`location` 等） | Flyway の Repeatable マイグレーション | 全環境で必要。テストの JOIN 検証にも使う |
| 業務データ（追跡サンプル等） | アプリ起動時に開発環境のみ投入（`SharedDbDevSeed`） | テストのデータ前提と干渉するため |

開発環境の判定は `DATABASE_URL` の有無（未設定 = H2 = 開発）で行う。


設計ドキュメントの擬似コードと実際の Flix 0.75.1 の構文には差があります。以下は実機で確認した正しい記述です。

### 7.1 効果とハンドラ

```flix
/// 効果宣言（出力ポート）
pub eff CargoRepo {
    def findById(id: String): Option[String]
    def store(value: String): Unit
}

/// 効果を要求する関数。必要な副作用がシグネチャに現れる
pub def findCargo(id: String): String \ CargoRepo =
    match CargoRepo.findById(id) {
        case Some(v) => CargoRepo.store("stored:" + v); v
        case None    => "not-found"
    }

/// ハンドラによる実装の注入。効果の除去は `ef - CargoRepo` で表す
pub def withInMemoryCargoRepo(f: Unit -> a \ ef + CargoRepo): a \ ef - CargoRepo =
    run f() with handler CargoRepo {
        def findById(id, k) = k(if (id == "C1") Some("cargo-1") else None)
        def store(_v, k)    = k()
    }
```

- ハンドラの各操作は**継続 `k` を最後の引数として受け取り**、`k(戻り値)` で呼び出し元に返す
- `run f() with handler X { ... }` の形式（ハンドラを関数として渡す形式ではない）

### 7.2 テストの記述

```flix
@Test
def testSomething(): Unit \ Assert =
    Assert.assertEq(expected = 2, 1 + 1)

/// IO を伴う場合は効果を追加する
@Test
def testWithIo(): Unit \ Assert + IO = ...
```

- テスト関数は `Bool` ではなく **`Unit \ Assert`** を返す
- 期待値は名前付き引数 `expected =` で渡す

### 7.3 Java 相互運用

```flix
import java.lang.Class
import java.sql.DriverManager
import java.util.ArrayList

def example(): Int32 \ IO =
    let list = new ArrayList();
    discard list.add("a");   // 戻り値を捨てる場合は discard
    list.size()
```

- インスタンスメソッドは `obj.method(...)` の形式で呼ぶ
- 静的メソッドは `Class.forName(...)` のようにクラス名経由で呼ぶ
- 戻り値を使わない場合は `discard` が必要

### 7.4 JDBC ドライバの登録（重要）

**Flix の実行時クラスローダでは JDBC ドライバの ServiceLoader 自動登録が機能しません。**
`DriverManager.getConnection` の前に `Class.forName` で明示的にドライバを登録してください。

```flix
discard Class.forName("org.h2.Driver");        // または "org.postgresql.Driver"
let conn = DriverManager.getConnection(jdbcUrl);
```

これを怠ると `java.sql.SQLException: No suitable driver found for jdbc:...` が発生します（実測）。

## 8. データベース環境

### 8.1 プロファイル構成

| プロファイル | データベース | Docker | 用途 |
|-------------|------------|--------|------|
| default | H2（インメモリ、PostgreSQL 互換モード） | 不要 | 日常開発・テスト・即座起動 |
| product | PostgreSQL 16 | 必要 | 本番互換確認 |

H2 は PostgreSQL 互換モードで使用します。

```text
jdbc:h2:mem:cargotracker;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE
```

> **方言差のリスク**: H2 と PostgreSQL は型変換・日付関数・`ON CONFLICT` 等で挙動が異なります。
> 「H2 で緑・本番で赤」を防ぐため、CI の日次ジョブとリリース前ステージで実 PostgreSQL に対して
> 同じ統合テストを実行します（[テスト戦略](../design/test_strategy.md) 3.2.1・7.1）。

### 8.2 PostgreSQL コンテナの起動

## トラブルシューティング

### `No suitable driver found for jdbc:...`

**問題**: JDBC 接続時にドライバが見つからない。

```text
java.sql.SQLException: No suitable driver found for jdbc:h2:mem:probe
```

**原因**: Flix の実行時クラスローダでは JDBC ドライバの ServiceLoader 自動登録が機能しません。

**解決策**: `DriverManager.getConnection` の前に明示的にドライバを登録します。

```flix
discard Class.forName("org.h2.Driver");
```

### `build-jar` で作った JAR が実行時にクラスを見つけられない

**問題**: `java -jar artifact/cargo-tracker.jar` が `ClassNotFoundException` で落ちる。

**原因**: `build-jar` は Maven 依存を JAR に含めず、マニフェストに `Class-Path` も設定しません。

**解決策**: 依存 JAR をクラスパスに含めて実行します。

```bash
java -cp "artifact/cargo-tracker.jar:$(find lib -name '*.jar' | tr '\n' ':')" Main
```

### `cannot find static method` / 型が合わない（Java 相互運用）

**問題**: Java メソッド呼び出しがコンパイルエラーになる。

**原因**: Flix は自動ボクシング・アンボクシングを行わず、引数の型が厳密に一致する必要があります。
また、インスタンスメソッドを静的メソッドのように呼ぶことはできません。

**解決策**: `obj.method(...)` の形式で呼び、引数の型を厳密に合わせます。戻り値を使わない場合は `discard` を付けます。

### ビルドが遅い

**原因**: Flix のコンパイルは Java より時間がかかります。初回は依存解決も走ります。

**解決策**: `lib/` を削除しないでください。CI では `~/.flix` と `lib/` をキャッシュします。
