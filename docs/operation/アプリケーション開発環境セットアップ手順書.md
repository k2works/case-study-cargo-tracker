# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、国際貨物輸送管理システム（Cargo Tracker Rust 版）のアプリケーション開発環境をセットアップする手順を説明します。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。
> 三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — https://t-wada.hatenablog.jp/entry/clean-code-that-works

## 1. 前提条件

以下のツールがインストールされていることを確認してください。

| ツール | バージョン | 確認コマンド |
|--------|-----------|-------------|
| Rust | stable（edition 2024） | `rustc --version` |
| cargo | stable（Rust 同梱） | `cargo --version` |
| Docker | 最新 | `docker -v` |
| Docker Compose | v2.x | `docker compose version` |
| Git | 最新 | `git -v` |
| Node.js | v22.x LTS | `node -v` |
| npm | v10.x | `npm -v` |

### Rust のインストール

Rust は rustup でインストールします。rustup を使用すると stable / beta / nightly のツールチェーン管理が容易です。

```bash
# rustup でインストール
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# バージョン確認
rustc --version
cargo --version
```

公式サイトから直接ダウンロードする場合：

- https://rustup.rs

### 追加ツールのインストール

開発・品質管理に使用する cargo サブコマンドをインストールします。

```bash
# カバレッジ計測
cargo install cargo-llvm-cov

# TDD 用ファイル監視（テスト自動再実行）
cargo install cargo-watch

# セキュリティ監査・依存関係ポリシーチェック
cargo install cargo-audit
cargo install cargo-deny

# sqlx CLI（マイグレーション・オフラインキャッシュ生成）
cargo install sqlx-cli --no-default-features --features postgres
```

### Docker のインストール

Docker Desktop をインストールします。

- **Windows**: https://docs.docker.com/desktop/install/windows-install/
- **macOS**: https://docs.docker.com/desktop/install/mac-install/

```bash
# バージョン確認
docker -v

docker compose version
```

### Node.js のインストール

開発タスクランナー（npm scripts / gulp）と Playwright（E2E テスト）の実行に Node.js が必要です。

- https://nodejs.org/

```bash
# バージョン確認
node -v

npm -v
```

## 5. データベース構成

Rust 版ではプロファイル切り替えは行いません。sqlx が SQL をコンパイル時に PostgreSQL スキーマと照合して検証するため、H2 のような代替インメモリ DB は使用しません。

| 用途 | データベース | Docker | 説明 |
|------|------------|--------|------|
| 単体テスト（ドメイン層） | 不要 | 不要 | ドメイン層はインフラ非依存のため DB なしで実行可能 |
| 統合テスト | PostgreSQL 16（testcontainers-rs） | 必要 | testcontainers-rs が自動で PostgreSQL コンテナを起動 |
| ローカル開発サーバー | PostgreSQL 16（docker compose） | 必要 | サービス名 `postgres`、DB `cargo_tracker`、ユーザー `cargo` |

### ローカル開発（docker compose）

```bash
# データベースコンテナを起動
cd apps/cargo-tracker
docker compose up -d postgres

# 環境変数を設定（.env.example を参考に）
cp .env.example .env

# マイグレーションを適用
sqlx migrate run --source crates/infra-persistence/migrations
```

### sqlx オフラインキャッシュ

CI や DB 未接続環境でもコンパイルできるよう、オフラインキャッシュ `.sqlx` を生成してコミットします。

```bash
# オフラインキャッシュを生成（.sqlx ディレクトリ）
cargo sqlx prepare --workspace

# オフラインモードでビルド
SQLX_OFFLINE=true cargo build --workspace
```

## 8. テストの実行

### 全テスト実行

```bash
cd apps/cargo-tracker

# 全テスト実行（単体・統合）
cargo test --workspace

# カバレッジレポート付き
cargo llvm-cov --workspace
```

> **Note**: 統合テストは testcontainers-rs が自動で PostgreSQL コンテナを起動するため、Docker が起動している必要があります。

### テストの種類

| テスト種別 | ツール | 説明 |
|-----------|--------|------|
| 単体テスト | cargo test / mockall / proptest | ドメインロジックのテスト（DB 不要） |
| 統合テスト | cargo test / testcontainers-rs / wiremock | 実 PostgreSQL・外部 API モックを使用したテスト |
| E2E テスト | Playwright | htmx の動的更新を含む画面の E2E テスト |
| アーキテクチャ検証 | コンパイラ（クレート分割） | クレート間依存はコンパイラが強制するため ArchUnit 相当のツールは不要 |

### テストカバレッジ

```bash
# テストを実行してカバレッジレポートを生成
cargo llvm-cov --workspace

# HTML レポートの生成・表示
cargo llvm-cov --workspace --html
# target/llvm-cov/html/index.html
```

カバレッジ目標: ドメイン層 85% / 全体 80%（実測でキャリブレーション）

## 9. コード品質管理

### 静的コード解析ツール

| ツール | 目的 | コマンド |
|--------|------|---------|
| clippy | Lint・バグパターン検出 | `cargo clippy --workspace --all-targets -- -D warnings` |
| rustfmt | フォーマット検証 | `cargo fmt --all -- --check` |
| cargo-audit | 依存クレートの脆弱性監査 | `cargo audit` |
| cargo-deny | ライセンス・依存関係ポリシーチェック | `cargo deny check` |
| cargo-llvm-cov | テストカバレッジ | `cargo llvm-cov --workspace` |

### 品質チェックの実行

```bash
cd apps/cargo-tracker

# フォーマットチェック
cargo fmt --all -- --check

# Lint（警告をエラー扱い）
cargo clippy --workspace --all-targets -- -D warnings

# セキュリティ・ポリシーチェック
cargo audit
cargo deny check

# すべてのテスト
cargo test --workspace
```

### コード複雑度の基準

| 指標 | 閾値 | 説明 |
|------|------|------|
| 循環的複雑度 | 10 | 分岐・ループの複雑さ |
| ファイルサイズ | 500 行 | 1 ファイルの最大行数 |
| メソッドサイズ | 150 行 | 1 関数の最大行数 |
| パラメータ数 | 7 | 関数の最大パラメータ数 |

### レポートの確認

| ツール | レポートパス |
|--------|-------------|
| cargo-llvm-cov | `target/llvm-cov/html/index.html` |
| cargo test | 標準出力（CI では GitHub Actions のログ） |

## 12. Git 規約

### コミットメッセージ

[Conventional Commits](https://www.conventionalcommits.org/ja/) に従います。

| タイプ | 説明 |
|--------|------|
| `feat` | 新機能 |
| `fix` | バグ修正 |
| `docs` | ドキュメントのみの変更 |
| `style` | コードの意味に影響しない変更 |
| `refactor` | バグ修正でも機能追加でもないコード変更 |
| `perf` | パフォーマンス改善 |
| `test` | テストの追加・修正 |
| `chore` | ビルドプロセス・補助ツールの変更 |

### スコープ

サブシステムを示すスコープを使用します。

```
feat(cargo-tracker): 貨物予約 API を追加
fix(cargo-tracker): 追跡ステータスの表示不具合を修正
docs: セットアップ手順書を更新
```

### Git Hooks（Husky + lint-staged）

`npm install` 実行時に Husky は自動的にセットアップされます（`prepare` スクリプト）。

```bash
# 手動でセットアップする場合
npx husky init
```

> **Note**: pre-commit フック（`cargo fmt` / `cargo clippy` の自動実行）は現状未設定のため、今後整備します。
> それまではコミット前に「9. コード品質管理」のコマンドを手動実行してください。

#### フックをスキップする場合

緊急時にフックをスキップしてコミットする場合（非推奨）：

```bash
git commit --no-verify -m "メッセージ"
```

> **Warning**: フックのスキップは緊急時のみ使用してください。品質チェックを通過しないコードはチームに影響を与える可能性があります。

## 14. CI/CD

GitHub Actions による継続的インテグレーションを設定しています。詳細は [docs/design/architecture_infrastructure.md](../design/architecture_infrastructure.md) を参照してください。

### ジョブ一覧

| ジョブ | 説明 |
|--------|------|
| check | fmt / clippy / test / llvm-cov を実行（`SQLX_OFFLINE=true`、統合テストは testcontainers で PostgreSQL を起動） |
| sqlx-check | postgres サービスコンテナ上で `cargo sqlx prepare --check` を実行し、`.sqlx` オフラインキャッシュの鮮度を検証 |

### check ジョブ

```
実行内容:

  1. Rust ツールチェーンセットアップ
  2. キャッシュ復元（cargo registry / target）
  3. フォーマットチェック（cargo fmt --all -- --check）
  4. Lint（cargo clippy --workspace --all-targets -- -D warnings）
  5. テスト実行（cargo test --workspace、SQLX_OFFLINE=true + testcontainers）
  6. カバレッジレポート生成（cargo llvm-cov --workspace）
```

## トラブルシューティング

### sqlx のコンパイルエラーが発生する場合

**問題**: `DATABASE_URL` が未設定、または `.sqlx` オフラインキャッシュが未生成のため、`query_as!` マクロのコンパイルに失敗する。

```
error: set `DATABASE_URL` to use query macros online, or run `cargo sqlx prepare` to update the query cache
```

**解決策**: オフラインモードを使用するか、キャッシュを再生成します。

```bash
# オフラインキャッシュを利用してビルド
SQLX_OFFLINE=true cargo build --workspace

# キャッシュを再生成する場合（DB 起動 + DATABASE_URL 設定が必要）
docker compose up -d postgres
sqlx migrate run --source crates/infra-persistence/migrations
cargo sqlx prepare --workspace
```

### testcontainers を使う統合テストが失敗する場合

**問題**: Docker Desktop が起動していないため、testcontainers-rs が PostgreSQL コンテナを起動できない。

**解決策**: Docker Desktop を起動してからテストを再実行します。

```bash
# Docker が起動しているか確認
docker info

# 再実行
cargo test --workspace
```

### ポート 5432 が競合する場合

**問題**: ローカルの PostgreSQL や他プロジェクトのコンテナがポート 5432 を使用している。

**解決策**: 競合しているプロセス・コンテナを停止します（killing-processes スキル相当の操作）。

```bash
# ポート使用プロセスを確認
lsof -i :5432

# 他プロジェクトのコンテナを停止
docker compose down

# ローカル PostgreSQL を停止する場合（macOS / Homebrew）
brew services stop postgresql@16
```
