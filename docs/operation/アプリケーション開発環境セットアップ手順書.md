## 6. ビルドとテスト

### 6.1 基本コマンド

```bash
cd apps/cargo-tracker

# ビルド（依存解決 → コンパイル）
java -jar ../../ops/tools/flix/flix.jar build

# テスト実行
java -jar ../../ops/tools/flix/flix.jar test

# 実行可能 JAR の生成
java -jar ../../ops/tools/flix/flix.jar build-jar

# REPL
java -jar ../../ops/tools/flix/flix.jar repl
```

### 6.2 実行

**重要**: `build-jar` が生成する JAR は **Maven 依存を含みません**（実測で確認済み）。
マニフェストにも `Class-Path` は設定されないため、実行時に `lib/` 配下の JAR をクラスパスへ明示的に追加します。

```bash
# 依存を使わない場合（動作するが JDBC 等は使えない）
java -jar artifact/cargo-tracker.jar

# 依存を含めて実行（本番と同じ形）
java -cp "artifact/cargo-tracker.jar:$(find lib -name '*.jar' | tr '\n' ':')" Main
```

> **Dockerfile への影響**: 実行イメージには `artifact/*.jar` に加えて `lib/` 配下の依存 JAR も
> コピーする必要があります。[インフラアーキテクチャ](../design/architecture_infrastructure.md) を参照してください。

### 6.3 環境検証用スモークテスト

`src/Bootstrap.flix` / `test/TestBootstrap.flix` は、**設計が前提とする 2 つの機構が実際に動作すること**を確認するために配置しています。

| テスト | 検証内容 |
|--------|---------|
| `testEffectHandlerInjectsAdapter` | 代数的効果で宣言した出力ポートに、ハンドラで実装を注入できる（ヘキサゴナルの中核） |
| `testEffectHandlerNotFound` | ハンドラの返す値でユースケースの分岐が変わる（テストダブルとして機能する） |
| `testH2Connection` | Java 相互運用で JDBC 接続できる（永続化アダプタの中核） |

```bash
java -jar ../../ops/tools/flix/flix.jar test
# => Passed: 3, Failed: 0. Skipped: 0.
```

実装が始まったら本モジュールは削除して構いません。

## 7. Flix の実装上の注意点（検証で判明した事項）

設計ドキュメントの擬似コードと実際の Flix 0.75.1 の構文には差があります。以下は実機で確認した正しい記述です。

### 7.1 効果とハンドラ

```flix
/// 効果宣言（出力ポート）
pub eff CargoRepo {
    def findById(id: String): Option[String]
    def store(value: String): Unit
}

/// 効果を要求する関数。必要な副作用がシグネチャに現れる
pub def findCargo(id: String): String \ CargoRepo =
    match CargoRepo.findById(id) {
        case Some(v) => CargoRepo.store("stored:" + v); v
        case None    => "not-found"
    }

/// ハンドラによる実装の注入。効果の除去は `ef - CargoRepo` で表す
pub def withInMemoryCargoRepo(f: Unit -> a \ ef + CargoRepo): a \ ef - CargoRepo =
    run f() with handler CargoRepo {
        def findById(id, k) = k(if (id == "C1") Some("cargo-1") else None)
        def store(_v, k)    = k()
    }
```

- ハンドラの各操作は**継続 `k` を最後の引数として受け取り**、`k(戻り値)` で呼び出し元に返す
- `run f() with handler X { ... }` の形式（ハンドラを関数として渡す形式ではない）

### 7.2 テストの記述

```flix
@Test
def testSomething(): Unit \ Assert =
    Assert.assertEq(expected = 2, 1 + 1)

/// IO を伴う場合は効果を追加する
@Test
def testWithIo(): Unit \ Assert + IO = ...
```

- テスト関数は `Bool` ではなく **`Unit \ Assert`** を返す
- 期待値は名前付き引数 `expected =` で渡す

### 7.3 Java 相互運用

```flix
import java.lang.Class
import java.sql.DriverManager
import java.util.ArrayList

def example(): Int32 \ IO =
    let list = new ArrayList();
    discard list.add("a");   // 戻り値を捨てる場合は discard
    list.size()
```

- インスタンスメソッドは `obj.method(...)` の形式で呼ぶ
- 静的メソッドは `Class.forName(...)` のようにクラス名経由で呼ぶ
- 戻り値を使わない場合は `discard` が必要

### 7.4 JDBC ドライバの登録（重要）

**Flix の実行時クラスローダでは JDBC ドライバの ServiceLoader 自動登録が機能しません。**
`DriverManager.getConnection` の前に `Class.forName` で明示的にドライバを登録してください。

```flix
discard Class.forName("org.h2.Driver");        // または "org.postgresql.Driver"
let conn = DriverManager.getConnection(jdbcUrl);
```

これを怠ると `java.sql.SQLException: No suitable driver found for jdbc:...` が発生します（実測）。

|-------------|------------|--------|------|

H2 は PostgreSQL 互換モードで使用します。


> **方言差のリスク**: H2 と PostgreSQL は型変換・日付関数・`ON CONFLICT` 等で挙動が異なります。
> 「H2 で緑・本番で赤」を防ぐため、CI の日次ジョブとリリース前ステージで実 PostgreSQL に対して
> 同じ統合テストを実行します（[テスト戦略](../design/test_strategy.md) 3.2.1・7.1）。

## トラブルシューティング

### `No suitable driver found for jdbc:...`

**問題**: JDBC 接続時にドライバが見つからない。

```text
java.sql.SQLException: No suitable driver found for jdbc:h2:mem:probe
```

**原因**: Flix の実行時クラスローダでは JDBC ドライバの ServiceLoader 自動登録が機能しません。

**解決策**: `DriverManager.getConnection` の前に明示的にドライバを登録します。

```flix
discard Class.forName("org.h2.Driver");
```

### `build-jar` で作った JAR が実行時にクラスを見つけられない

**問題**: `java -jar artifact/cargo-tracker.jar` が `ClassNotFoundException` で落ちる。

**原因**: `build-jar` は Maven 依存を JAR に含めず、マニフェストに `Class-Path` も設定しません。

**解決策**: 依存 JAR をクラスパスに含めて実行します。

```bash
java -cp "artifact/cargo-tracker.jar:$(find lib -name '*.jar' | tr '\n' ':')" Main
```

### `cannot find static method` / 型が合わない（Java 相互運用）

**問題**: Java メソッド呼び出しがコンパイルエラーになる。

**原因**: Flix は自動ボクシング・アンボクシングを行わず、引数の型が厳密に一致する必要があります。
また、インスタンスメソッドを静的メソッドのように呼ぶことはできません。

**解決策**: `obj.method(...)` の形式で呼び、引数の型を厳密に合わせます。戻り値を使わない場合は `discard` を付けます。

### ビルドが遅い

**原因**: Flix のコンパイルは Java より時間がかかります。初回は依存解決も走ります。

**解決策**: `lib/` を削除しないでください。CI では `~/.flix` と `lib/` をキャッシュします。
