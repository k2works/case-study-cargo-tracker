# アプリケーション開発環境セットアップ手順書

## 概要

本ドキュメントは、国際貨物輸送管理システム（Cargo Tracker TypeScript 版）のアプリケーション開発環境をセットアップする手順を説明します。

テスト駆動開発（TDD）のゴールは **動作するきれいなコード** です。それを実現するためには [ソフトウェア開発の三種の神器](https://t-wada.hatenablog.jp/entry/clean-code-that-works) が必要です。

> 今日のソフトウェア開発の世界において絶対になければならない 3 つの技術的な柱があります。
> 三本柱と言ったり、三種の神器と言ったりしていますが、それらは
>
> - バージョン管理
> - テスティング
> - 自動化
>
> の 3 つです。
>
> — https://t-wada.hatenablog.jp/entry/clean-code-that-works

> **Note**: アプリケーション本体（`apps/cargo-tracker/`）はウォーキングスケルトン（開発フェーズ IT1）で作成します。本手順書のアプリケーション関連セクションは、スケルトン作成後に有効になります。

## 1. 前提条件

以下のツールがインストールされていることを確認してください。

| ツール | バージョン | 確認コマンド |
|--------|-----------|-------------|
| Node.js | v24.x LTS（24.18 以降推奨） | `node -v` |

| Docker | 最新 | `docker -v` |

Node.js をインストールします。バージョン管理ツール（nix / mise / nvm 等）を使用すると複数バージョンの管理が容易です。

```bash

# バージョン確認
node -v
```

公式サイトから直接ダウンロードする場合：

- https://nodejs.org/

### Docker のインストール

Docker Desktop をインストールします。

- **Windows**: https://docs.docker.com/desktop/install/windows-install/
- **macOS**: https://docs.docker.com/desktop/install/mac-install/

```bash
# バージョン確認
docker -v

docker compose version
```

## 5. プロファイル構成

開発効率を高めるため、2 つのプロファイルを使い分けます（[ADR-004](../adr/004-pgmem-local-testcontainers-ci.md) 参照）。

| プロファイル | データベース | Docker | 用途 |
|-------------|------------|--------|------|
| default | pg-mem（インメモリ PostgreSQL 互換） | 不要 | 日常開発・即座起動 |
| product | PostgreSQL 16（Docker Compose） | 必要 | 本番互換テスト・マイグレーション検証 |

### default プロファイル（推奨：日常開発）

Docker なしで即座に起動できます。起動時に node-pg-migrate のマイグレーションが pg-mem に適用され、シードデータが投入されます。

```bash
cd apps/cargo-tracker
npm run dev
```

### product プロファイル（本番互換）

```bash
# データベースコンテナを起動
docker compose up -d db

# product プロファイルで起動
cd apps/cargo-tracker
DATABASE_URL=postgres://postgres:postgres@localhost:5432/cargo_tracker npm run serve
```

## 7. Docker Compose のセットアップ

実 PostgreSQL での検証（マイグレーション検証・SQL 互換性確認・永続データ）が必要な場合に使用します。

### データベースコンテナの起動

```bash
# データベースを起動
docker compose up -d db

# コンテナの状態確認
docker compose ps
```

### Docker Compose の便利なコマンド

```bash
# データベースを起動
docker compose up -d db

# コンテナの停止と削除
docker compose down

# ログを確認
docker compose logs -f db

# データベースに接続
docker compose exec db psql -U postgres -d cargo_tracker
```

## 8. テストの実行

テスト戦略の全体は [テスト戦略](../design/test_strategy.md) を参照してください。

### 全テスト実行

```bash
cd apps/cargo-tracker

# 全テスト実行（カバレッジレポート付き）
npm run test:coverage
```

### テストの種類

| テスト種別 | ツール | 説明 |
|-----------|--------|------|
| 単体テスト | Vitest | ドメインロジック・アプリケーションサービスのテスト |
| 統合テスト | Vitest + @testcontainers/postgresql + supertest + cheerio | 実 PostgreSQL・HTTP エンドポイント（SSR HTML）のテスト |
| 契約テスト | nock（IT2 以降） | 外部 5 ポート（経路・税関・決済・港湾・通知）のスタブ検証。IT1 では外部ポート未実装 |
| アーキテクチャテスト | dependency-cruiser | レイヤー依存関係・BC 間参照禁止の検証 |
| E2E テスト | Playwright | 主要ユーザーシナリオのブラウザテスト |

> **Note**: 統合テスト・E2E テストは Docker が起動している必要があります（Testcontainers が PostgreSQL 16 コンテナを自動起動します）。テストの合否判定に pg-mem は使用しません。

### テストカバレッジ

```bash
# テストを実行してカバレッジレポートを生成（v8 provider）
npm run test:coverage

# レポートの表示
# apps/cargo-tracker/coverage/index.html
```

カバレッジ目標: ドメイン層 85% / アプリケーション層 80% / 全体 75%

## 9. コード品質管理

### 静的コード解析ツール

| ツール | 目的 | コマンド |
|--------|------|---------|
| ESLint（typescript-eslint） | コーディング規約・バグパターンの検証 | `npm run lint` |
| Prettier | コードフォーマット | `npm run format` |
| dependency-cruiser | アーキテクチャルール検証 | `npm run arch` |
| tsc | 型検査（TSX テンプレート含む） | `npm run typecheck` |

### 品質チェックの実行

```bash
cd apps/cargo-tracker

# 品質チェックのみ（lint + typecheck + arch）
npm run check

# すべてのテストと品質チェック
npm run verify
```

### アーキテクチャルール（dependency-cruiser）

1. domain 層が infrastructure 層に依存しないこと
2. domain 層に NestJS デコレータ（`@nestjs/*`）を使用しないこと
3. application 層が infrastructure 層を直接参照しないこと（Port 経由）
4. 異なる Bounded Context 間でモジュールを直接参照しないこと（ACL / Event 経由のみ）

### コード複雑度の基準

| 指標 | 閾値 | 説明 |
|------|------|------|
| 循環的複雑度 | 10 | 分岐・ループの複雑さ |
| ファイルサイズ | 500 行 | 1 ファイルの最大行数 |
| 関数サイズ | 150 行 | 1 関数の最大行数 |
| パラメータ数 | 7 | 関数の最大パラメータ数 |

| タイプ | 説明 |

## トラブルシューティング

### ポート 8080 が使用中

**問題**: 開発サーバー起動時にポート競合が発生する

```
Error: listen EADDRINUSE: address already in use :::8080
```

**解決策**: 既存プロセスを終了してから再起動します

```bash
lsof -ti:8080 | xargs kill -9
```

### Testcontainers が起動しない

**問題**: 統合テストで PostgreSQL コンテナの起動に失敗する

**解決策**: Docker Desktop が起動していることを確認します

```bash
docker info
```

### ローカル（pg-mem）で通るが CI（Testcontainers）で落ちる

**問題**: pg-mem が一部の SQL 機能（window 関数・型キャスト・照合順序等）を再現できないため、ローカルと CI で結果が乖離する

**解決策**: SQL の正当性判断は Testcontainers（実 PostgreSQL）を正とします。Docker Compose の PostgreSQL で該当クエリをローカル検証してください

```bash
docker compose up -d db
DATABASE_URL=postgres://postgres:postgres@localhost:5432/cargo_tracker npm run serve
```
