# 開発環境セットアップ手順書

## 概要

本ドキュメントは、**国際貨物輸送管理システム（case-study-cargo-tracker）** の開発環境を Heroku Container Registry でセットアップする手順を説明します。

IT1 完了状態（authms + bookingms + gatewayms + frontend）を対象とし、バックエンドサービスは **H2 インメモリ DB**（開発初期）または **Heroku Postgres**（本番互換）+ **Axon Kafka Extension + Aiven Managed Kafka** で動作します。

---

## 1. 構成

| 項目 | 内容 |
| :--- | :--- |
| 実行基盤 | Heroku Container Registry / Runtime |
| デプロイ方式 | サービスごとに個別の Heroku アプリ |
| 命名規則 | `{prefix}-{service}`（例: `cargo-tracker-5-authms`） |
| バックエンド | Spring Boot 4.0.x / Java 25 |
| フロントエンド | React 19 + Vite + Nginx |
| データベース | H2（開発初期）/ Heroku Postgres（本番互換） |
| イベントバス | Axon Kafka Extension + Aiven Managed Kafka |
| HTTP ポート | Heroku が注入する `$PORT` |

### サービス一覧

| サービス | Heroku アプリ名 | ローカルポート | 説明 |
| :--- | :--- | :--- | :--- |
| Auth Service | `{prefix}-authms` | 8081 | ユーザー認証・JWT 発行 |
| Booking Service | `{prefix}-bookingms` | 8082 | 貨物予約・荷主管理 |
| Gateway Service | `{prefix}-gatewayms` | 8080 | API Gateway・JWT 検証 |
| Handling Service | `{prefix}-handlingms` | 8083 | 荷物取り扱いイベント記録（IT5 追加） |
| Tracking Service | `{prefix}-trackingms` | 8084 | 貨物追跡（IT6 追加） |
| Frontend | `{prefix}-frontend` | 5173 | React SPA + Nginx Proxy |

### リクエストフロー

```
ブラウザ
  └─ frontend（Nginx）
       └─ /api/* → proxy → gatewayms（JWT 検証）
                              ├─ /api/v1/auth/** → authms
                              ├─ /api/v1/bookings/**, /api/v1/shippers/**, /api/ping → bookingms
                              ├─ /api/v1/handling/** → handlingms
                              └─ /api/v1/tracking/** → trackingms
```

> **注意**: Heroku の新規アプリはランダムサフィックス付きドメイン（`appname-xxxxxxxx.herokuapp.com`）が割り当てられます。`heroku domains -a <app>` で実際のドメインを確認してください。

## 3. アプリケーション設定

### 3.1 Spring プロファイル（`heroku`）

各バックエンドサービスに `heroku` プロファイルが追加済みです。

#### authms の `application-heroku.yml`

```yaml
server:
  port: ${PORT:8080}
spring:
  datasource:
    url: jdbc:h2:mem:authms;DB_CLOSE_DELAY=-1;MODE=PostgreSQL
    driver-class-name: org.h2.Driver
    username: sa
    password: ""
  h2:
    console:
      enabled: false
  flyway:
    locations: classpath:db/migration
    baseline-on-migrate: true
```

#### bookingms の `application-heroku.yml`

```yaml
server:
  port: ${PORT:8080}
spring:
  kafka:
    bootstrap-servers: ${KAFKA_BOOTSTRAP_SERVERS}
    security:
      protocol: ${KAFKA_SECURITY_PROTOCOL:SSL}
axon:
  kafka:
    publisher:
      enabled: true
    fetcher:
      enabled: true
```

### 3.2 gatewayms の設定

Spring Cloud Gateway によるルーティング。JWT 検証フィルター（`JwtAuthenticationFilter`）を内蔵しています。

`apps/backend/gatewayms/src/main/resources/application.yml`:

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          routes:
            - id: authms
              uri: ${AUTHMS_URL:http://localhost:8081}
              predicates:
                - Path=/api/v1/auth/**
            - id: bookingms
              uri: ${BOOKINGMS_URL:http://localhost:8082}
              predicates:
                - Path=/api/v1/bookings/**,/api/v1/shippers/**,/api/ping
            - id: handlingms
              uri: ${HANDLINGMS_URL:http://localhost:8083}
              predicates:
                - Path=/api/v1/handling/**
            - id: trackingms
              uri: ${TRACKINGMS_URL:http://localhost:8084}
              predicates:
                - Path=/api/v1/tracking/**

server:
  port: ${PORT:8080}

app:
  jwt:
    secret: ${JWT_SECRET:dev-secret-key-change-in-production-min-32-chars}
```

公開パス（JWT 検証スキップ）:
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/register`
- `/actuator/**`

### 3.3 フロントエンド（Nginx）

`apps/frontend/nginx.heroku.conf`:

```nginx
server {
    listen ${PORT};

    root /usr/share/nginx/html;
    index index.html;

    location /api/ {
        proxy_pass ${GATEWAY_URL};
        proxy_set_header Host ${GATEWAY_HOST};
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Heroku は SNI ベースルーティングのため必須
        proxy_ssl_server_name on;
        proxy_ssl_name        ${GATEWAY_HOST};

        # JWT などの大きなレスポンスヘッダーに対応
        proxy_buffer_size          128k;
        proxy_buffers              4 256k;
        proxy_busy_buffers_size    256k;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

> **重要**: `GATEWAY_HOST` は `GATEWAY_URL` からスキーム（`https://`）を除いたホスト名です。Heroku の SNI ルーティング対応のために必要です。

## 4. Dockerfile 構成

### Dockerfile 分離方針

| ファイル | 用途 |
|---------|------|
| `Dockerfile` | ローカル開発・CI 用（Gradle マルチステージビルド） |
| `Dockerfile.heroku` | Heroku デプロイ用（ローカルビルド済み JAR のみコピー） |

Heroku 向けは `Dockerfile.heroku` を使用します。Gradle マルチプロジェクト構成ではコンテナ内ビルド時にサブプロジェクトのディレクトリ不在エラーが発生するため、ローカルで事前に `bootJar` を実行してから JAR をコピーします。

### バックエンド（authms / bookingms / gatewayms / handlingms / trackingms）

```dockerfile
FROM eclipse-temurin:25-jre

RUN groupadd --system --gid 10001 cargo \
    && useradd --system --uid 10001 --gid cargo --create-home cargo

WORKDIR /app

COPY build/libs/{service}.jar /app/{service}.jar

USER cargo

ENV JAVA_TOOL_OPTIONS=""

ENTRYPOINT ["java", "-jar", "/app/{service}.jar"]
```

> **注意**: `JAVA_TOOL_OPTIONS` 環境変数を使用します（`JAVA_OPTS` ではありません）。JVM が自動的に読み込む標準環境変数のため、exec 形式 ENTRYPOINT との組み合わせで確実に反映されます。また、`bootJar` タスクに `archiveFileName.set("{service}.jar")` を設定して JAR 名を固定しています。

### フロントエンド

`apps/frontend/Dockerfile.heroku`:

```dockerfile
# Stage 1: ビルド
FROM node:24-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# Stage 2: Nginx で静的ファイルを配信
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.heroku.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["sh", "-c", "envsubst '${PORT} ${GATEWAY_URL} ${GATEWAY_HOST}' < /etc/nginx/conf.d/default.conf > /tmp/default.conf && cp /tmp/default.conf /etc/nginx/conf.d/default.conf && nginx -g 'daemon off;'"]
```

## 5. 環境変数の設定

### 5.1 `.env` 設定

プロジェクトルートの `.env` に以下を追加します（`.env` は `.gitignore` 対象）。

```dotenv
# Heroku 開発環境
DEV_HEROKU_APP_PREFIX=cargo-tracker-5
DEV_DOCKER_PLATFORM=linux/amd64

# JWT シークレット（authms / gatewayms で共有）
JWT_SECRET="$(openssl rand -base64 48)"

# Aiven Kafka 接続情報
KAFKA_BOOTSTRAP_SERVERS=<aiven-host>:<port>
KAFKA_SECURITY_PROTOCOL=SSL
```

| 変数名 | 必須 | 説明 |
| :--- | :--- | :--- |
| `DEV_HEROKU_APP_PREFIX` | はい | Heroku アプリ名のプレフィックス |
| `DEV_DOCKER_PLATFORM` | いいえ | Docker プラットフォーム（デフォルト: `linux/amd64`） |
| `JWT_SECRET` | はい | JWT 署名キー（authms / gatewayms / trackingms で同一値を使用・ADR-0013） |
| `KAFKA_BOOTSTRAP_SERVERS` | はい | Aiven Kafka のブートストラップサーバー（host:port） |
| `KAFKA_SECURITY_PROTOCOL` | はい | `SSL`（Aiven Kafka は SSL 必須） |
| `TRACKING_TOKEN_EXPIRATION_DAYS` | いいえ | 追跡照会用 JWT の有効日数（既定 30・ADR-0013） |
| `TRACKING_TOKEN_GRACE_DAYS` | いいえ | 配送完了後の追加有効日数（既定 7・ADR-0013） |

## 9. トラブルシューティング

### アプリが起動しない（R10 タイムアウト）

| 原因 | 対処 |
| :--- | :--- |
| `application-heroku.yml` で `server.port: ${PORT}` が未設定 | `server.port: ${PORT:8080}` を確認 |
| JAR が存在しない | `npx gulp deploy:dev:build:backend` または `./gradlew bootJar` を実行 |
| JAR ファイル名が `{service}.jar` でない | `build.gradle.kts` に `archiveFileName.set("{service}.jar")` を追加 |

### 起動直後にクラッシュする（Process exited with status 0）

| 原因 | 対処 |
| :--- | :--- |
| `JAVA_OPTS` をシェル経由で展開しようとしている | `ENTRYPOINT ["java", "-jar", "..."]` の exec 形式に変更し、`JAVA_TOOL_OPTIONS` 環境変数を使用する |

### docker push が失敗する

| 原因 | 対処 |
| :--- | :--- |
| Container Registry の認証が切れている | `heroku container:login` を再実行 |
| OCI provenance メタデータエラー | `docker build --provenance=false` を追加 |
| ARM64 イメージを push している | `docker build --platform linux/amd64` を追加 |

### 502 Bad Gateway（frontend → gateway）

| 原因 | 対処 |
| :--- | :--- |
| `GATEWAY_URL` が古いドメイン形式（`appname.herokuapp.com`） | `heroku domains -a {prefix}-gatewayms` で実際のドメインを確認し、`GATEWAY_URL` と `GATEWAY_HOST` を更新 |
| nginx の `proxy_buffer_size` が不足（JWT ヘッダーが大きい） | `nginx.heroku.conf` に `proxy_buffer_size 128k` を設定 |
| Heroku の SNI ルーティングが機能しない | `proxy_ssl_server_name on` と `proxy_ssl_name ${GATEWAY_HOST}` を設定 |

### ログインできない（401 または "ユーザー名またはパスワードが正しくありません"）

| 原因 | 対処 |
| :--- | :--- |
| `AUTHMS_URL` が古いドメイン形式 | `heroku domains -a {prefix}-authms` で確認し、`gatewayms` の `AUTHMS_URL` を更新 |
| authms が起動していない | `heroku logs -a {prefix}-authms` で確認 |
| `JWT_SECRET` が authms と gatewayms で異なる | 両アプリに同じ `JWT_SECRET` が設定されているか確認 |

### Kafka 接続エラー

| 原因 | 対処 |
| :--- | :--- |
| `KAFKA_BOOTSTRAP_SERVERS` が未設定または誤り | Aiven コンソールで接続情報を確認し、Config Vars を更新 |
| SSL 接続に失敗する | `KAFKA_SECURITY_PROTOCOL=SSL` が設定されているか確認 |
| Aiven Kafka のファイアウォール制限 | Aiven コンソールで Heroku の出口 IP を許可リストに追加 |

### R14（メモリ超過）

| 原因 | 対処 |
| :--- | :--- |
| `JAVA_TOOL_OPTIONS` が未設定 | `npx gulp deploy:dev:config` で最適化版に更新 |
| Eco dyno（512MB）では不足 | Standard-2X（1024MB）にアップグレード |

### CORS エラーが出る

| 原因 | 対処 |
| :--- | :--- |
| `allowedOriginPatterns` に Heroku URL が含まれていない | `SecurityConfig.java` の `corsConfigurationSource` に `https://*.herokuapp.com` が含まれているか確認 |

## 10. 制約

- `heroku` プロファイルは開発初期に H2 インメモリ DB を使用するため、dyno 再起動でデータは失われます（開発・検証用途に限定）。本番互換環境では Heroku Postgres アドオンを追加し `DATABASE_URL` を使用してください
- Heroku の新規アプリはランダムサフィックス付きドメインが割り当てられます。Config Vars のドメインは `heroku domains` で取得した実ドメインを使用してください
- Eco dyno（512MB）のメモリ制約のため `MaxRAMPercentage=50` に絞っています
- `container` stack は base image の自動更新を行わないため、セキュリティ修正には再ビルド・再デプロイが必要です
- Aiven Kafka の無料プランにはメッセージ保持期間・パーティション数に制限があります
