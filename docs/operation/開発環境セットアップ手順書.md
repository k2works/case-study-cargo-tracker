# 開発環境セットアップ手順書

## 概要

本ドキュメントは、**国際貨物輸送管理システム（case-study-cargo-tracker）** の Heroku 開発環境をセットアップする手順を説明します。

IT1 完了状態（authms / routingms / gatewayms / frontend）を対象とし、バックエンドサービスは **H2 インメモリ DB** で動作します。

---

## 1. 構成

| 項目 | 内容 |
| :--- | :--- |
| 実行基盤 | Heroku Container Registry / Runtime |
| デプロイ方式 | サービスごとに個別の Heroku アプリ |
| 命名規則 | `{prefix}-{service}`（例: `cargo-tracker-5-authms`） |
| バックエンド | Spring Boot 3.4.x / Java 21（コンテナ内） |
| フロントエンド | React + Vite + Nginx |
| データベース | H2 インメモリ DB（開発環境） |
| HTTP ポート | Heroku が注入する `$PORT` |

### サービス一覧（IT1）

| サービス | Heroku アプリ名 | 説明 |
| :--- | :--- | :--- |
| Auth Service | `{prefix}-authms` | ユーザー認証・JWT 発行 |
| Routing Service | `{prefix}-routingms` | 航路・航路管理 |
| Gateway Service | `{prefix}-gatewayms` | API Gateway・JWT 検証 |
| Frontend | `{prefix}-frontend` | React SPA + Nginx リバースプロキシ |

### リクエストフロー

```
ブラウザ
  └─ frontend（Nginx）
       └─ /api/* → proxy → gatewayms（JWT 検証）
                              ├─ /api/auth/**, /api/v1/users/** → authms
                              └─ /api/v1/voyages/**, /api/v1/routes/** → routingms
```

> **注意**: Heroku の新規アプリはランダムサフィックス付きドメイン（`appname-xxxxxxxx.herokuapp.com`）が割り当てられます。`heroku domains -a <app>` で実際のドメインを確認してください。

---

## 2. 前提条件

| ツール | バージョン目安 | 確認コマンド |
| :--- | :--- | :--- |
| Heroku CLI | 10.x 以上 | `heroku --version` |
| Docker Desktop | 最新 | `docker version` |
| Node.js | 24 | `node -v` |
| Git | 最新 | `git --version` |

Heroku Container Runtime は `x86_64` イメージのみサポートします。Apple Silicon 環境では `--platform linux/amd64 --provenance=false` でビルドする必要があります（Gulp タスクで自動設定済み）。

## 3. アプリケーション設定

### 3.1 Spring プロファイル（`heroku`）

各バックエンドサービスに `src/main/resources/application-heroku.yml` を配置しています。

#### authms の `application-heroku.yml`

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:authdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
    driver-class-name: org.h2.Driver
    username: sa
    password: ""
  h2:
    console:
      enabled: false
  flyway:
    enabled: false
  sql:
    init:
      mode: always

mybatis:
  mapper-locations: classpath:mapper/*.xml

jwt:
  secret: ${JWT_SECRET}
  expiration-ms: 86400000

server:
  port: ${PORT:8081}
```

初期ユーザーは `src/main/resources/data.sql` が `sql.init.mode: always` により自動投入されます。

#### routingms の `application-heroku.yml`

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:routingdb;MODE=PostgreSQL;DB_CLOSE_DELAY=-1
    driver-class-name: org.h2.Driver
  flyway:
    enabled: false
  sql:
    init:
      mode: always

axon:
  axonserver:
    enabled: false
  kafka:
    publisher:
      enabled: false
    fetcher:
      enabled: false
  eventhandling:
    processors:
      default:
        mode: subscribing

server:
  port: ${PORT:8083}
```

#### gatewayms の `application-heroku.yml`

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: authms
          uri: ${AUTHMS_URL}
          predicates:
            - Path=/api/auth/**, /api/v1/users/**
        - id: routingms
          uri: ${ROUTINGMS_URL}
          predicates:
            - Path=/api/v1/voyages/**, /api/v1/routes/**

server:
  port: ${PORT:8080}
```

### 3.2 フロントエンド（Nginx）

`apps/frontend/nginx.heroku.conf`:

```nginx
server {
    listen ${PORT};

    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass ${GATEWAY_URL};
        proxy_set_header Host ${GATEWAY_HOST};
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_ssl_server_name on;
    }
}
```

環境変数 `${PORT}`、`${GATEWAY_URL}`、`${GATEWAY_HOST}` は `envsubst` で展開されます。

## 4. Dockerfile 構成

### バックエンド（authms / routingms / gatewayms）

`apps/backend/{service}/Dockerfile` に Gradle マルチステージビルドを定義しています。

```dockerfile
# Stage 1: Gradle でビルド（Java 21、ツールチェーンを 21 に固定）
FROM gradle:8.14-jdk21 AS builder
WORKDIR /workspace
COPY gradle/ gradle/
COPY settings.gradle build.gradle ./
COPY shared/build.gradle shared/build.gradle
COPY {service}/build.gradle {service}/build.gradle
RUN sed -i 's/java = "25"/java = "21"/' gradle/libs.versions.toml && \
    gradle :{service}:dependencies --no-daemon || true
COPY shared/src/ shared/src/
COPY {service}/src/ {service}/src/
RUN gradle :{service}:bootJar --no-daemon -x test && \
    find {service}/build/libs/ -name "{service}*.jar" ! -name "*plain*" \
      -exec cp {} {service}/build/libs/{service}.jar \;

# Stage 2: 軽量実行イメージ
FROM eclipse-temurin:21-jre
RUN groupadd --system --gid 10001 cargo && \
    useradd --system --uid 10001 --gid cargo --create-home cargo
WORKDIR /app
COPY --from=builder /workspace/{service}/build/libs/{service}.jar /app/{service}.jar
USER cargo
EXPOSE {port}
ENTRYPOINT ["java", "-jar", "/app/{service}.jar"]
```

> **ポイント**:
> - `sed` でツールチェーンバージョンを 21 に上書き（`gradle:8.14-jdk21` に合わせる）
> - `ENTRYPOINT` を exec 形式（JSON 配列）にし、シェル変数展開の問題を回避
> - `server.port` は `application-heroku.yml` の `${PORT:デフォルト}` で指定

### フロントエンド

`apps/frontend/Dockerfile`:

```dockerfile
# Stage 1: Node.js で React SPA をビルド
FROM node:20-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: nginx で配信
FROM nginx:1.27-alpine
RUN apk add --no-cache gettext
COPY --from=builder /app/dist /usr/share/nginx/html
COPY nginx.heroku.conf /etc/nginx/templates/default.conf.template
EXPOSE 80
CMD ["/bin/sh", "-c", \
  "envsubst '${PORT} ${GATEWAY_URL} ${GATEWAY_HOST}' \
    < /etc/nginx/templates/default.conf.template \
    > /etc/nginx/conf.d/default.conf && nginx -g 'daemon off;'"]
```

## 5. 環境変数の設定

### 5.1 `.env` 設定

プロジェクトルートの `.env` に以下を追加します（`.gitignore` 対象）。

```dotenv
# JWT シークレット（authms / gatewayms で共有）
JWT_SECRET="<openssl rand -base64 48 で生成した値>"
```

### 5.2 Heroku Config Vars 一覧

| アプリ | 変数名 | 値 |
| :--- | :--- | :--- |
| authms | `SPRING_PROFILES_ACTIVE` | `heroku` |
| authms | `JAVA_TOOL_OPTIONS` | JVM メモリ制限オプション |
| authms | `JWT_SECRET` | JWT 署名キー（256 bits 以上） |
| routingms | `SPRING_PROFILES_ACTIVE` | `heroku` |
| routingms | `JAVA_TOOL_OPTIONS` | JVM メモリ制限オプション |
| gatewayms | `SPRING_PROFILES_ACTIVE` | `heroku` |
| gatewayms | `JAVA_TOOL_OPTIONS` | JVM メモリ制限オプション |
| gatewayms | `JWT_SECRET` | JWT 検証キー（authms と同一値） |
| gatewayms | `AUTHMS_URL` | `https://{authms ドメイン}` |
| gatewayms | `ROUTINGMS_URL` | `https://{routingms ドメイン}` |
| frontend | `GATEWAY_URL` | `https://{gatewayms ドメイン}` |
| frontend | `GATEWAY_HOST` | `{gatewayms ドメイン}`（スキームなし） |

`JAVA_TOOL_OPTIONS` の推奨値:
```
-XX:MaxRAMPercentage=50.0 -XX:ReservedCodeCacheSize=64m -XX:MaxMetaspaceSize=128m -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Tokyo
```

## 6. 初回セットアップ手順

### 6.1 Heroku ログイン

```bash
heroku login           # ブラウザ認証（手動実行）
heroku container:login # Container Registry 認証
```

### 6.2 アプリ作成

```bash
PREFIX=cargo-tracker-5

heroku create ${PREFIX}-authms    --stack container
heroku create ${PREFIX}-routingms --stack container
heroku create ${PREFIX}-gatewayms --stack container
heroku create ${PREFIX}-frontend  --stack container
```

既存アプリでスタックが未設定の場合:

```bash
heroku stack:set container --app ${PREFIX}-authms
heroku stack:set container --app ${PREFIX}-routingms
heroku stack:set container --app ${PREFIX}-gatewayms
heroku stack:set container --app ${PREFIX}-frontend
```

### 6.3 JWT_SECRET を生成して `.env` に保存

```bash
echo "JWT_SECRET=\"$(openssl rand -base64 48)\"" >> .env
```

> **注意**: JWT_SECRET は Base64 で 48 バイト以上（384 bits）必要です。短い値を設定すると `WeakKeyException` で起動に失敗します。

### 6.4 Config Vars を一括設定

```bash
npx gulp deploy:dev:config
```

このタスクは `heroku domains` コマンドで各アプリの実ドメインを自動取得して Config Vars を設定します。

### 6.5 デプロイ

```bash
npx gulp deploy:dev
```

全サービス（authms → routingms → gatewayms → frontend）を順次ビルド・プッシュ・リリースします。

## 9. トラブルシューティング

### アプリが起動しない（R10 タイムアウト）

| 原因 | 対処 |
| :--- | :--- |
| `application-heroku.yml` に `server.port: ${PORT:...}` が未設定 | 各サービスの `application-heroku.yml` を確認 |
| コンテナビルドが失敗している | `npx gulp deploy:dev:push:{service}` のビルドログを確認 |

### 起動直後にクラッシュする（Process exited with status 0）

| 原因 | 対処 |
| :--- | :--- |
| `ENTRYPOINT` がシェル形式で `$JAVA_OPTS` 等を展開している | `ENTRYPOINT ["java", "-jar", "..."]` の exec 形式に変更 |
| `JWT_SECRET` が短すぎる（256 bits 未満） | `openssl rand -base64 48` で再生成し Config Vars を更新 |

### docker push が失敗する（"unsupported"）

| 原因 | 対処 |
| :--- | :--- |
| OCI manifest list（マルチプラットフォーム）形式 | `--platform linux/amd64 --provenance=false` を追加（Gulp タスクで自動設定済み） |
| Container Registry の認証切れ | `heroku container:login` を再実行 |

### `stack:set container` が必要

Heroku で `This command is for Docker apps only` エラーが出た場合:

```bash
heroku stack:set container --app {app-name}
```

### ログインできない（401）

| 原因 | 対処 |
| :--- | :--- |
| H2 DB に初期ユーザーが未投入 | `application-heroku.yml` の `sql.init.mode: always` と `data.sql` の存在を確認 |
| BCrypt ハッシュが誤り | `data.sql` のハッシュが実際のパスワードと一致しているか確認 |
| `JWT_SECRET` が authms と gatewayms で異なる | 両アプリに同じ値が設定されているか `heroku config -a {app}` で確認 |
| `AUTHMS_URL` が古いドメイン形式 | `heroku domains -a {prefix}-authms` で実ドメインを確認し `gatewayms` の Config Vars を更新 |

### 502 Bad Gateway（frontend → gateway）

| 原因 | 対処 |
| :--- | :--- |
| `GATEWAY_URL` / `GATEWAY_HOST` が未設定または古い | `heroku domains -a {prefix}-gatewayms` で確認し frontend の Config Vars を更新 |

### R14（メモリ超過）

| 原因 | 対処 |
| :--- | :--- |
| `JAVA_TOOL_OPTIONS` が未設定 | `npx gulp deploy:dev:config` で最適化版に更新 |
| Eco dyno（512MB）では不足 | Standard-2X（1024MB）にアップグレード |

## 10. 制約

- `heroku` プロファイルは H2 インメモリ DB を使用するため、dyno 再起動でデータは失われます（開発・検証用途に限定）
- Heroku の新規アプリはランダムサフィックス付きドメインが割り当てられます。Config Vars のドメインは `heroku domains` で取得した実ドメインを使用してください
- Eco dyno（512MB）のメモリ制約のため `MaxRAMPercentage=50` に設定しています
- `container` stack では base image の自動更新が行われません。セキュリティ修正には再ビルド・再デプロイが必要です

## 11. Aiven Kafka 設定

IT2 以降のイベント駆動サービス（bookingms / handlingms / trackingms）では Aiven Managed Kafka を使用します。

### 11.1 接続情報の取得

Aiven コンソール（[console.aiven.io](https://console.aiven.io)）でサービスを作成し、以下の情報を取得します。

| 項目 | 取得場所 |
| :--- | :--- |
| Bootstrap サーバー | サービス詳細 > Connection information > Service URI |
| セキュリティプロトコル | `SSL`（Aiven Kafka は SSL 必須） |

### 11.2 `.env` への追加

```dotenv
# Aiven Kafka 接続情報
KAFKA_BOOTSTRAP_SERVERS=<aiven-host>:<port>
KAFKA_SECURITY_PROTOCOL=SSL
```

### 11.3 Heroku Config Vars への設定

```bash
PREFIX=cargo-tracker-5

# bookingms（IT2 追加）
heroku config:set \
  KAFKA_BOOTSTRAP_SERVERS="${KAFKA_BOOTSTRAP_SERVERS}" \
  KAFKA_SECURITY_PROTOCOL=SSL \
  --app ${PREFIX}-bookingms

# handlingms（IT5 追加）
heroku config:set \
  KAFKA_BOOTSTRAP_SERVERS="${KAFKA_BOOTSTRAP_SERVERS}" \
  KAFKA_SECURITY_PROTOCOL=SSL \
  --app ${PREFIX}-handlingms

# trackingms（IT6 追加）
heroku config:set \
  KAFKA_BOOTSTRAP_SERVERS="${KAFKA_BOOTSTRAP_SERVERS}" \
  KAFKA_SECURITY_PROTOCOL=SSL \
  --app ${PREFIX}-trackingms
```

`deploy:dev:config` タスクは IT1 のサービスのみ対象です。Kafka 設定は上記コマンドで手動設定してください。

### 11.4 `application-heroku.yml` での Kafka 設定例

```yaml
spring:
  kafka:
    bootstrap-servers: ${KAFKA_BOOTSTRAP_SERVERS}
    security:
      protocol: ${KAFKA_SECURITY_PROTOCOL:SSL}
axon:
  kafka:
    publisher:
      enabled: true
    fetcher:
      enabled: true
```

### 11.5 Kafka トラブルシューティング

| 原因 | 対処 |
| :--- | :--- |
| `KAFKA_BOOTSTRAP_SERVERS` が未設定または誤り | Aiven コンソールで接続情報を確認し、Config Vars を更新 |
| SSL 接続に失敗する | `KAFKA_SECURITY_PROTOCOL=SSL` が設定されているか確認 |
| Aiven Kafka のファイアウォール制限 | Aiven コンソールで Heroku の出口 IP を許可リストに追加 |
| Aiven 無料プランの制限 | メッセージ保持期間・パーティション数の上限に注意 |
