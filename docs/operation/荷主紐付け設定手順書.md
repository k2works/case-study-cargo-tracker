# 荷主紐付け設定手順書

利用者アカウント（`ROLE_SHIPPER`）を荷主に紐付ける運用手順です。**紐付けの設定手段は画面にありません**（[ADR-013](../adr/013-user-shipper-link.md) が受け入れた代償）。設定はシステム管理担当が本手順で行います。

## この手順が要る理由

荷主が自分で予約を照会するには、システムが「いまログインしている利用者はどの荷主か」を答えられる必要があります。その答えは `users.shipper_id` にあります（ADR-013）。

**紐付けが無い荷主の利用者には、予約が 1 件も見えません。** ADR-013 は「絞るかどうかはロールで決め、紐付けの有無では決めない」と定めています。「紐付けが無い = 絞らない」にすると、設定を忘れた荷主に全社の予約が見えてしまうためです。**設定漏れは、情報漏洩ではなく「何も見えない」として現れます。**

## 紐付けを確認する（画面）

営業担当者・システム管理担当は、**荷主詳細（`/shippers/{shipperId}`）の「ログインできる利用者」** で現在の紐付けを確認できます（IT12 / C11）。

- 紐付いた利用者名が並びます
- 紐付けが無い荷主には「この荷主に紐付いた利用者はありません」と案内先が出ます

**画面は読み取り専用です。** 設定は以下の手順で行います。

## 前提

- 対象の荷主が登録済みであること（`/shippers` で荷主コードを確認）
- 対象の利用者アカウントが作成済みで、`ROLE_SHIPPER` を持つこと
- データベースへの接続手段があること（環境ごとの接続情報は [開発環境セットアップ手順書](開発環境セットアップ手順書.md) を参照）

## 手順

### 1. 対象を確認する

```sql
-- 荷主（荷主コードは営業担当者から連絡される）
SELECT id, shipper_code, name FROM shipper WHERE shipper_code = 'SHP-000001';

-- 利用者（すでに別の荷主に紐付いていないかを見る）
SELECT id, username, shipper_id FROM users WHERE username = 'shipper1';
```

**すでに別の荷主 ID が入っている場合は、そのまま上書きしないでください。** 依頼元に「どちらの荷主の予約を見せるのか」を確認します。上書きすると、その利用者からは**前の荷主の予約が見えなくなります**。

### 2. 紐付ける

```sql
UPDATE users
   SET shipper_id = (SELECT id FROM shipper WHERE shipper_code = 'SHP-000001'),
       updated_at = CURRENT_TIMESTAMP
 WHERE username = 'shipper1';
```

**荷主コードで引き当てます。** 荷主 ID（UUID）を手で書き写すと、1 文字違いで存在しない荷主に紐付き、その利用者からは予約が 0 件に見えます。

### 3. 確認する

```sql
SELECT u.username, s.shipper_code, s.name
  FROM users u
  JOIN shipper s ON s.id = u.shipper_id
 WHERE u.username = 'shipper1';
```

さらに、**荷主詳細の「ログインできる利用者」に名前が出ること**を画面で確認します。SQL だけで終えると、画面の表示経路が壊れていても気づけません。

### 4. 依頼元に伝える

営業担当者へ「設定した荷主コードと利用者名」を返します。**利用者に再ログインを案内してください。** 紐付けは認証の時点で読み込まれるため、ログイン中のセッションには反映されません。

## 紐付けを外す

利用者が退職した、荷主との契約が終わったなどの場合は `NULL` に戻します。

```sql
UPDATE users SET shipper_id = NULL, updated_at = CURRENT_TIMESTAMP
 WHERE username = 'shipper1';
```

**アカウント自体を消す必要はありません。** 紐付けを外した利用者には予約が 0 件に見えます（ロールで絞るため）。アカウントを止めるなら `enabled = FALSE` を併用します。

## よくある問い合わせ

| 症状 | 原因 | 対応 |
| :--- | :--- | :--- |
| 荷主がログインできるが予約が 0 件 | 紐付けが無い、または存在しない荷主 ID | 手順 1 → 2 |
| 設定したのに 0 件のまま | ログイン中のセッションに反映されていない | 再ログインを案内する |
| 他社の予約が見える | **起きてはならない。** ロールに `ROLE_SHIPPER` が無く別ロールで見えている可能性 | `user_roles` を確認し、開発担当へ連絡する |
| 予約詳細を開くと「見つかりません」 | 他社の予約である（**403 ではなく 404 を返す**。ADR-013） | 仕様どおり。荷主コードを確認する |
