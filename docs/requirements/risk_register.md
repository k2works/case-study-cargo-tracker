# リスク台帳：国際貨物輸送管理システム

AI に任せる範囲と、人の承認ゲートで止めるリスクを定義します。以降の AI 生成物（ストーリー・Unit・設計・コード・計画）はすべてこの台帳を前提にします。Unit 定義と各スキルの `PROJECT.md` はリスクを ID で参照し、本文をここに一元化します。

組織のリスク台帳は存在しません（ケーススタディ）。「由来」欄は、インセプションデッキのリスク番号、`CLAUDE.md` の確認必須の操作、既存レビューのいずれに由来するかを示します。

## AI に渡せる範囲（In/Out）

本プロジェクトはケーススタディ（架空の国際貨物輸送会社）であり、本番データ・実在する顧客情報・決済情報は存在しません。業務データとコードは原則 In です（[AI-DLC 移行計画](../development/aidlc_migration_plan.md) の決定事項 1）。

| トピック | In | Out | AI に任せる | 備考 |
| :--- | :---: | :---: | :--- | :--- |
| 要件・ユースケース・ストーリー | ✓ | | 書き直し・欄の追加・Unit への配置 | 既存の文面の意味を変えない。曖昧なものは要確認として戻す |
| ドメインモデル・設計 | ✓ | | 初稿の生成、選択肢とトレードオフの提示 | 境界付けられたコンテキスト・Unit の境界・アーキテクチャ判断は人が決める（R-06, R-08） |
| アプリケーションコード・テスト | ✓ | | TDD による実装 | 技術スタック選定と ADR は人が承認する |
| テストデータ | ✓ | | 生成 | 荷主・港湾などは架空の値でよい。UN/LOCODE を使う場合は実在コードを使う（R-09） |
| 参照実装（`docs/article/source/`） | ✓ | | 設計・実装のコンテキストとして読む | 別プロジェクトの実装。採番（US36 まで）・スコープ・状態モデルを持ち込まない（R-07） |
| 外部システム（港湾管理・税関・決済機関・通知） | ✓ | | ポート（インタフェース）・スタブ・契約テストの生成 | 実在機関の API 仕様を仮定で作らない（R-01） |
| 認証・認可 | ✓ | | 方式承認後の設計と実装 | 方式の選択は確認必須（R-02） |
| 環境変数・接続情報（`.env`、`.env.vault` の復号鍵） | | ✓ | — | 開発・ステージング・本番の SSH 接続先を含む。AI は値を読まない・書かない。環境操作は `docs/operation/` の手順書のタスク経由で行う（R-10） |

## 確認必須の操作

`CLAUDE.md` の「確認必須」と同じ範囲です。該当するステップは計画に注記し、実行前に停止して人の承認を得ます。

- 新規ファイル作成（承認済みの計画に無いもの）
- ファイル削除（重要ファイル）
- アーキテクチャ・フォルダ構造の大規模な変更
- 外部 API・外部ライブラリの導入
- 認証・認可の実装
- データベースのスキーマ変更・マイグレーション
- デプロイ設定・環境変数の変更・本番環境への操作
