# 非機能要件定義 - 国際貨物輸送管理システム

## 概要

本ドキュメントは、国際貨物輸送管理システム（7 マイクロサービス + React SPA）の非機能要件を測定可能な形で定義する。ISO/IEC 25010 品質モデルに基づき、性能・セキュリティ・可用性・保守性・拡張性の 5 カテゴリで数値目標を設定する。

### 品質属性の優先順位

| 優先度 | 品質属性 | 根拠 |
| :--- | :--- | :--- |
| 1 | **セキュリティ** | 国際貨物輸送は規制産業。荷主情報・通関情報の保護が最優先 |
| 2 | **可用性** | 荷役作業は 24 時間稼働。追跡情報のリアルタイム性が業務に直結 |
| 3 | **性能** | 追跡照会のポーリング（30 秒間隔）と荷役登録の応答速度がユーザー体験を左右 |
| 4 | **保守性** | 7 マイクロサービスの独立デプロイ・運用を持続可能にする |
| 5 | **拡張性** | 港湾・航路の追加、新規貨物種別への対応 |

## 1. 性能要件

### 1.1 レスポンスタイム

| 操作 | 対象サービス | p50 | p95 | p99 | 備考 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| ログイン（JWT 発行） | authms | 200ms | 500ms | 1s | BCrypt 検証を含む |
| 貨物予約登録 | bookingms | 300ms | 800ms | 1.5s | DB 書き込み + イベント発行 |
| 予約一覧取得 | bookingms | 200ms | 500ms | 1s | ページネーション 20 件 |
| 経路候補算出 | routingms | 500ms | 1.5s | 3s | 航海スケジュール検索を含む |
| 追跡情報照会 | trackingms | 100ms | 300ms | 500ms | ポーリング対象のため厳しい目標 |
| 荷役作業登録 | handlingms | 200ms | 500ms | 1s | イベント発行を含む |
| 請求書一覧取得 | billingms | 200ms | 500ms | 1s | フィルタ付き |
| SPA 初期ロード | frontend | 1s | 2s | 3s | Vite バンドル + API 初期取得 |
| SPA ページ遷移 | frontend | 100ms | 300ms | 500ms | クライアントサイドルーティング |

## 2. セキュリティ要件

### 2.1 認証・認可

| 要件 | 仕様 | 実装方式 |
| :--- | :--- | :--- |
| 認証方式 | JWT Bearer Token | authms が発行、API Gateway が検証 |
| トークン有効期限 | アクセストークン: 1 時間、リフレッシュトークン: 7 日 | Zustand ストアで管理 |
| パスワードポリシー | 8 文字以上、英数字混在必須 | BCrypt (strength 12) でハッシュ化 |
| 認可モデル | RBAC（Role-Based Access Control） | Spring Security `@PreAuthorize` |
| API エンドポイント保護 | 全 API に認証必須（追跡照会を除く） | API Gateway JWT フィルタ |
| CORS | フロントエンドオリジンのみ許可 | Spring Cloud Gateway CORS 設定 |

### 2.2 ロールと権限

| ロール | 権限範囲 | 対応アクター |
| :--- | :--- | :--- |
| `ROLE_ADMIN` | 全操作 + ユーザー管理 | システム管理者 |
| `ROLE_OPERATOR` | 予約・経路・荷役・精算の全操作 | 営業担当者・経路設計者・荷役作業員・追跡管理者・経理担当者 |
| `ROLE_SHIPPER` | 自身の予約照会・追跡照会 | 荷主・荷受人 |

### 2.3 データ保護

| 保護対象 | 対策 | 備考 |
| :--- | :--- | :--- |
| 通信経路 | TLS 1.3（ACM 証明書） | ALB 終端 + 内部通信は VPC 内 |
| パスワード | BCrypt ハッシュ (strength 12) | 生パスワードを保存しない |
| DB 保存データ | RDS 暗号化（AES-256） | AWS KMS マネージドキー |
| S3 監査ログ | SSE-S3 暗号化 | バケットポリシーでアクセス制限 |
| 個人情報 | 荷主名・メールアドレスは最小限保持 | 不要になったデータは削除 |

### 2.4 監査ログ

| ログ種別 | 記録内容 | 保存先 | 保持期間 |
| :--- | :--- | :--- | :--- |
| 認証ログ | ログイン成功/失敗、IP アドレス、User-Agent | CloudWatch Logs | 1 年 |
| 操作ログ | 誰が・いつ・何を操作したか | CloudWatch Logs | 1 年 |
| データ変更ログ | `created_at` / `updated_at` カラム | 各サービス DB | テーブル保持期間に準拠 |
| API アクセスログ | リクエストパス・ステータスコード・レスポンスタイム | CloudWatch Logs | 90 日 |

### 2.5 脆弱性対策（OWASP Top 10）

| 脅威 | 対策 |
| :--- | :--- |
| A01 アクセス制御の不備 | RBAC + API Gateway での一元的な認可チェック |
| A02 暗号化の失敗 | TLS 1.3、BCrypt、RDS 暗号化 |
| A03 インジェクション | MyBatis パラメータバインディング（SQL インジェクション防止） |
| A05 セキュリティ設定ミス | Spring Security デフォルト拒否、不要なエンドポイント無効化 |
| A07 認証の不備 | JWT + リフレッシュトークン、アカウントロックアウト（5 回失敗で 15 分ロック） |
| A09 ログと監視の不足 | 構造化ログ + CloudWatch アラート |

## 3. 可用性要件

### 3.1 稼働率目標（SLA）

| 環境 | 稼働率目標 | 年間許容ダウンタイム | 計画停止 |
| :--- | :--- | :--- | :--- |
| 本番 | 99.9% | 8.77 時間 | 月 1 回、深夜 2:00-4:00 |
| ステージング | 99.0% | 87.6 時間 | 随時 |
| 開発 | 95.0% | 438 時間 | 随時 |

### 3.2 障害復旧目標

| 指標 | 目標値 | 備考 |
| :--- | :--- | :--- |
| RTO（復旧時間目標） | 4 時間以内 | 重大障害（全サービス停止）の場合 |
| RPO（復旧時点目標） | 1 時間以内 | RDS 自動バックアップの頻度に依存 |
| MTTR（平均復旧時間） | 30 分以内 | 単一サービス障害の場合 |
| 障害検知時間 | 5 分以内 | CloudWatch アラート + ヘルスチェック |

### 3.3 障害許容性

| 障害シナリオ | 影響範囲 | 対策 | 復旧方法 |
| :--- | :--- | :--- | :--- |
| 単一サービス障害 | 該当サービスの機能のみ | ECS タスク自動再起動（ヘルスチェック） | 自動復旧（30 秒以内） |
| DB 障害 | 該当サービスの読み書き | RDS Multi-AZ フェイルオーバー | 自動復旧（1-3 分） |
| RabbitMQ 障害 | サービス間非同期通信 | Amazon MQ クラスター構成 | 自動復旧 + メッセージ再送 |
| AZ 障害 | 該当 AZ のサービス | マルチ AZ デプロイ | ALB がヘルシーな AZ に振り分け |
| API Gateway 障害 | 全 API リクエスト | 最低 2 タスクの冗長構成 | ECS 自動再起動 |

### 3.4 ヘルスチェック

| サービス | エンドポイント | チェック間隔 | タイムアウト | 失敗閾値 |
| :--- | :--- | :--- | :--- | :--- |
| 全マイクロサービス | `/actuator/health` | 30 秒 | 10 秒 | 3 回連続失敗で再起動 |
| API Gateway | `/actuator/health` | 15 秒 | 5 秒 | 2 回連続失敗で再起動 |
| RDS | `pg_isready` | 10 秒 | 5 秒 | 5 回連続失敗でアラート |
| RabbitMQ | AMQP 接続確認 | 30 秒 | 10 秒 | 3 回連続失敗でアラート |

## 4. 保守性要件

### 4.1 コード品質

| 指標 | 目標値 | 測定ツール |
| :--- | :--- | :--- |
| テストカバレッジ（ドメイン層） | 90% 以上 | JaCoCo |
| テストカバレッジ（全体） | 80% 以上 | JaCoCo |
| 循環複雑度 | 10 以下 | SonarQube |
| コード重複率 | 3% 以下 | SonarQube |
| 技術的負債レーティング | A | SonarQube |
| バグ密度 | 0.5 件/KLOC 以下 | SonarQube |

### 4.2 ログ出力

| ログレベル | 用途 | 出力例 |
| :--- | :--- | :--- |
| ERROR | 業務継続不可能なエラー | DB 接続失敗、外部サービスタイムアウト |
| WARN | 業務継続可能だが注意が必要 | 再試行成功、閾値超過 |
| INFO | 業務処理の開始・完了 | 予約登録完了、イベント発行 |
| DEBUG | 開発・調査用の詳細情報 | SQL パラメータ、リクエスト/レスポンス |

**ログフォーマット**: JSON 構造化ログ

```json
{
  "timestamp": "2026-04-24T10:30:00.000Z",
  "level": "INFO",
  "service": "bookingms",
  "traceId": "abc123",
  "spanId": "def456",
  "userId": "user-001",
  "message": "Cargo booked successfully",
  "bookingId": "BK-1234"
}
```

**ログ保持期間**:

| ログ種別 | 保存先 | 保持期間 |
| :--- | :--- | :--- |
| アプリケーションログ | CloudWatch Logs | 30 日 |
| アクセスログ | CloudWatch Logs | 90 日 |

## 5. 拡張性要件

### 5.1 スケーラビリティ

| スケーリング方式 | 対象 | 方針 |
| :--- | :--- | :--- |
| 水平スケーリング | ECS タスク数 | CPU 使用率 70% 超で自動スケールアウト（最大タスク数まで） |
| 垂直スケーリング | RDS インスタンスサイズ | 月次レビューで必要に応じてインスタンスクラスを変更 |
| DB 読み取りスケーリング | RDS Read Replica | 追跡照会の負荷が高い場合に trackingms 用リードレプリカを追加 |

**サービス別スケーリング設定**:

| サービス | 最小タスク | 最大タスク | スケールアウト条件 | スケールイン条件 |
| :--- | :--- | :--- | :--- | :--- |
| authms | 2 | 4 | CPU > 70% (3 分) | CPU < 30% (10 分) |
| bookingms | 2 | 4 | CPU > 70% (3 分) | CPU < 30% (10 分) |
| routingms | 2 | 4 | CPU > 70% (3 分) | CPU < 30% (10 分) |
| trackingms | 2 | 6 | CPU > 60% (3 分) | CPU < 30% (10 分) |
| handlingms | 2 | 4 | CPU > 70% (3 分) | CPU < 30% (10 分) |
| billingms | 1 | 2 | CPU > 70% (3 分) | CPU < 30% (10 分) |
| gatewayms | 2 | 4 | CPU > 60% (3 分) | CPU < 30% (10 分) |

### 5.2 将来の拡張シナリオ

| シナリオ | 影響範囲 | 対応方針 |
| :--- | :--- | :--- |
| 新規港湾の追加 | 全サービスの `location` テーブル | Flyway マイグレーションで各 DB に INSERT |
| 新規貨物種別の追加 | bookingms, handlingms | `CargoType` 列挙型に値追加 + バリデーション拡張 |
| 新規決済方法の追加 | billingms | `PaymentMethod` 列挙型に値追加 |
| 多言語対応 | frontend | i18n ライブラリ（react-i18next）の導入 |
| 通知チャネル追加 | 通知サービス（新規） | 新規マイクロサービスとして追加 |
| モバイルアプリ対応 | API Gateway | 既存 REST API をそのまま利用可能 |
| イベントソーシング導入 | trackingms | CQRS 読み取り側モデルが既に分離済み |

### 5.3 技術的制約

| 制約 | 内容 | 根拠 |
| :--- | :--- | :--- |
| Java バージョン | OpenJDK 25 | LTS ではないが最新機能を活用 |
| DB | PostgreSQL 16.x | マネージドサービス（RDS）の対応バージョン |
| メッセージブローカー | RabbitMQ（Amazon MQ） | Spring Cloud Stream のデフォルトバインダー |
| コンテナランタイム | Docker + ECS Fargate | サーバーレスコンテナで運用負荷を低減 |
| フロントエンド | React 19.x + Vite 6.x | 最新の React Server Components には非対応（SPA 構成） |

| カテゴリ | 主要指標 | 目標値 |
