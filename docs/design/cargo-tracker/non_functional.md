# 非機能要件 - 国際貨物輸送管理システム（CQRS / Event Sourcing 版）

## 概要

[CQRS / Event Sourcing のマイクロサービス](architecture_backend.md)（Axon Framework 5 + Axon Server SE）の非機能要件を、測定できる形で定めます。

CQRS / Event Sourcing に固有の非機能要件は次の 3 つです。それ以外は参照元 2 つの値を引き継ぎます。

1. **反映の遅れ**（コマンド受付から投影の反映まで）に目標値を置く。利用者にとっては応答時間の一部である
2. **Axon Server SE が単一障害点**であることを可用性の前提として明記し、許容する停止と回復の目標を置く
3. **イベントは削除できない**ため、個人情報の削除要求への対応を要件として定める

## 1. 性能効率性

### 1.1 応答時間

| 操作 | 例 | p50 | p95 | p99 |
| :--- | :--- | :--- | :--- | :--- |
| 認証 | ログイン | 200ms | 500ms | 1.0s |
| 投影の単純照会 | 予約詳細・追跡照会 | 200ms | 500ms | 1.0s |
| 一覧（最大 100 件） | 予約一覧 | 300ms | 800ms | 1.5s |
| 経路候補の算出（Query Bus 往復 + ドメインサービス） | UC06 | 500ms | 1.5s | 3.0s |
| コマンド受付（集約の結果を返すまで） | 予約登録・確定 | 200ms | 500ms | 1.0s |
| **コマンド → 投影の反映** | 登録直後の詳細が `202` から `200` になるまで | **1.0s** | **3.0s** | **5.0s** |
| **Saga 完了** | 予約確定 → 追跡開始 | 3.0s | 10s | 15s |
| 初回表示（LCP） | ダッシュボード | 1.5s | 2.5s | 4.0s |

反映の遅れは利用者から見れば応答時間です。p95 が 3 秒を超える状態が 5 分続いたら、画面ヘッダに「反映が遅れています」を出し、警告を通知します（UI 設計・インフラ設計と整合）。

| 指標 | 通常 | ピーク |
| :--- | :--- | :--- |
| HTTP 全体 | 50 req/s | 200 req/s |
| コマンド | 20 cmd/s | 100 cmd/s |
| Event Store 書き込み | 50 evt/s | 200 evt/s |
| 投影（Event Processor 全体） | 50 evt/s | 200 evt/s（ピーク後 5 分以内に遅れゼロへ戻る） |
| クエリ | 30 qry/s | 150 qry/s |
| 公開追跡照会（配送通知後のスパイク） | — | 500 req/s（5 分間） |

### 1.3 Axon 固有

| 指標 | 目標 |
| :--- | :--- |
| 集約の復元（スナップショット無し・100 イベント） | 50ms 以内 |
| 集約の復元（スナップショット有り） | 10ms 以内。スナップショットは 50 イベントごと |
| Event Processor の遅れ（最新イベントとの差） | 通常 100 イベント未満かつ 2 秒未満。**1,000 イベントまたは 5 分で警告、停止は即通知** |
| Saga の関連付け検索 | 100ms 以内 |
| Axon Server の接続数 | サービスあたり最大 50、合計 350 |

## 2. 信頼性

### 2.1 稼働率

| 対象 | 目標 | 月間許容停止 |
| :--- | :--- | :--- |
| 業務画面（平日 8:00–20:00 JST） | **99.9%** | 約 13 分 |
| 業務画面（24 時間） | 99.5% | 約 3.6 時間 |
| 公開追跡照会（24 時間） | **99.9%** | 約 43 分 |
| ステージング | 99% | — |

**Axon Server SE は単一ノードであり、その停止は全サービスのコマンド受付停止です。** 上の目標はそれを含みます。Axon Server のバージョンアップ（月 1 回・10 分以内）は計画停止として業務時間外に行い、稼働率の計算から除きます。読み取り（投影テーブルからのクエリ）は Axon Server の停止中も応答するため、公開追跡照会の目標は業務画面より高く置けます。

### 2.2 障害許容性

| 事象 | 要件 |
| :--- | :--- |
| 業務サービス 1 台の障害 | ECS が再起動。2 台構成のため利用者影響なし。Event Processor のセグメントは残る 1 台が引き継ぐ |
| Axon Server の停止 | コマンドは `503`、クエリは投影から応答。**無音で in-memory に落ちない**。復旧後、サービスは自動再接続し、Event Processor はトークンから再開する |
| 投影サービスの停止 | Event Store にイベントは残る。復旧後に遅れを取り戻す。取り戻す速度は 200 evt/s 以上 |
| Saga の宛先サービスの停止 | Saga が再試行（指数バックオフ、上限 5 回・合計 10 分）。超過したら補償イベントを出し、要確認一覧に写す |
| 投影の失敗（SQL エラー） | Processing Group が止まり、トークンは進まない。同じイベントが 2 度投影されない。停止を即通知 |
| RDS の障害 | Multi-AZ で自動フェイルオーバー、60 秒以内 |
| AZ 障害 | 業務サービスと RDS は継続。Axon Server は復旧手順で別 AZ に再構築（RTO 4 時間） |

### 2.3 回復性

| 指標 | 値 |
| :--- | :--- |
| 検知（MTTD） | 5 分以内 |
| 一次切り分け | 15 分以内 |
| RTO（軽微） | 30 分 |
| RTO（重大・Axon Server 再構築） | **4 時間** |
| RPO（Event Store） | **1 時間**（EBS スナップショット 1 時間 + S3 連続エクスポートで実質 5 分） |
| RPO（投影） | Event Store に従う。再構築で回復 |
| RPO（`auth_db`） | 24 時間 |
| 投影の再構築（全サービス・300 万イベント） | 4 時間以内（200 evt/s） |

**復元演習を四半期に 1 度**ステージングで行い、EBS スナップショットからの復元と全投影のリプレイが RTO 内に終わることを確かめます。演習をしていないバックアップは要件を満たしていません。

### 2.4 データ整合性

| 範囲 | 保証 |
| :--- | :--- |
| 集約 1 つ | Event Store への追記が原子的。同一集約への並行コマンドは楽観的並行制御で片方が失敗する |
| 投影 | 少なくとも 1 回配送 + 冪等な書き込み。投影とトークンは同一トランザクション |
| サービス間 | 結果整合。Saga の補償で戻す。**失敗はイベントとして残り、要確認一覧に出る** |
| 一意制約 | 事前の存在確認 + 投影の UNIQUE + 拒否の記録の三段 |

## 3. セキュリティ

### 3.1 認証・認可

| 項目 | 要件 |
| :--- | :--- |
| 認証 | `authms` の JWT（HS256、有効期限 8 時間）。`gatewayms` が検証 |
| アカウント保護 | 認証失敗 5 回で 15 分ロック。ロック中・誤り・無効化で同一メッセージ（US31） |
| 認可 | ロールベース。表示制御と API の実行可否は同一の RBAC マトリクス。**認可は入力検証より先** |
| 荷主のデータ分離 | `ROLE_SHIPPER` は authms の `user_shipper_link` で紐付いた荷主の貨物だけを読む。他社の追跡番号は `404` |
| 公開追跡照会 | 認証不要。例外の詳細・荷主名・金額を出さない。レート制限 60 req/分/IP |
| セッション | `sessionStorage`。無操作 15 分で警告、20 分で破棄 |

### 3.2 ロールと権限

| ロール | 主な権限 |
| :--- | :--- |
| `ROLE_SALES` | 荷主・見積・予約の登録、通知、確定、キャンセル申請 |
| `ROLE_ROUTING` | 航海の登録・更新、経路設計、追跡番号発行 |
| `ROLE_TRACKER` | 追跡の手動更新、例外、キャンセル承認、通関状態の更新 |
| `ROLE_HANDLER` | 荷役記録、通関申告の登録 |
| `ROLE_ACCOUNTANT` | 請求の算出・発行・入金 |
| `ROLE_SHIPPER` | 自社貨物の追跡照会 |
| `ROLE_ADMIN` | 利用者管理、ロック解除、荷主の紐付け |

### 3.3 データ保護

| 対象 | 要件 |
| :--- | :--- |
| 通信 | ALB で TLS 1.2 以上。VPC 内は平文 |
| 保存 | RDS・EBS は AWS KMS で暗号化。**Event Store の EBS も暗号化** |
| パスワード | BCrypt（コスト 12） |
| Axon Server | アクセス制御を有効化。サービスごとのトークン。管理 UI は VPC 内から踏み台経由のみ |
| シークレット | Secrets Manager。コードと設定ファイルに書かない |

### 3.4 個人情報とイベントの削除不能

イベントは追記専用であり、荷主の氏名・メール・住所が `ShipperRegisteredEvent` に載ります。削除要求（保存期間の満了、本人の申し出）に対する要件を次のとおり定めます。

| 要件 | 内容 |
| :--- | :--- |
| 個人情報を載せるイベントの名簿 | `ShipperRegisteredEvent`・`ShipperContactUpdatedEvent` に限る。他のイベントは `shipperId` だけを持つ。ArchUnit で名簿を固定 |
| 削除の手段 | **暗号化キーの破棄（crypto-shredding）**。荷主ごとの鍵で個人情報フィールドを暗号化して保存し、削除要求には鍵を破棄する。破棄後のイベントは復元時に個人情報フィールドが `null` になり、集約とプロジェクションはそれを許容する |
| 投影 | 鍵の破棄後にリプレイし、投影テーブルからも個人情報を消す |
| 保存期間 | 精算済みまたはキャンセルから 7 年（会計）。満了後に鍵を破棄 |
| 実装時期 | 初回リリースの前に鍵による暗号化を入れる。**後から入れると既存イベントが平文のまま残る** |

### 3.5 監査ログ

| 対象 | 内容 | 保持 |
| :--- | :--- | :--- |
| 業務の変更 | Event Store のイベント列そのもの。イベントのメタデータに操作者（`AuthenticatedUser.username`）と `traceId` を載せる | 7 年 |
| 認証 | `auth_audit_log`（成功・失敗・ロック・解除、理由は画面に出さない） | 1 年 |
| 管理操作 | 鍵の破棄、投影のリプレイ、Axon Server の操作 | 7 年 |

Event Sourcing では業務の監査ログを別に作りません。イベント列が監査ログです。そのためイベントのメタデータに「誰が」を必ず載せます。

### 3.6 脆弱性対策

OWASP Top 10 に対する標準対策（入力検証、パラメタ化 SQL、CSRF はステートレス JWT のため対象外、セキュリティヘッダ）に加え、依存関係の脆弱性走査を CI で毎回、コンテナイメージの走査をビルドごとに行います。高深刻度の脆弱性はマージを止めます。走査の導入失敗と検出は別の赤にします。

## 4. 使用性

| 項目 | 要件 |
| :--- | :--- |
| アクセシビリティ | WCAG 2.1 AA。キーボード操作、フォーカス可視、色だけに頼らない状態表示、反映中バナーの `aria-live` |
| 反映中の表示 | コマンド成功後 1 秒以内に「受け付けました」。詳細の `202` は「反映中」。30 秒で再読込の案内 |
| モバイル | 荷役記録と公開追跡照会は 375px 幅で操作できる |
| ブラウザ | 最新 2 版の Chrome / Edge / Safari / Firefox |
| 日時 | 業務タイムゾーン（`Asia/Tokyo`）で表示・入力。期限は日付単位 |
| エラー | 状態の競合（`409`）と業務規則違反（`422`）は理由を利用者の言葉で出す |

## 5. 保守性

| 項目 | 要件 |
| :--- | :--- |
| モジュール性 | サービスは `shared` 以外の他サービスに依存しない。契約の名簿（イベント 6・コマンド 2・クエリ 2）を ArchUnit で固定し、増やすときは ADR |
| 試験性 | `test_strategy.md` のカバレッジと品質ゲート。投影・Saga・往復を Testcontainers で検査 |
| 解析性 | 構造化ログ（JSON）。全ログとイベントのメタデータに `traceId`、業務キー（`bookingId` / `trackingNumber`）。Micrometer Tracing でサービスをまたいで追える |
| 修正性 | イベントは追記専用。形の変更は Upcaster + ゴールデン JSON。投影の変更はリプレイ |
| 時刻 | 業務判定は `Clock` を注入し業務タイムゾーンで行う。テストも同じ `Clock` |
| ドキュメント | 設計文書は OKF バンドル。ADR は決定の数だけ検査を持つ |
| 技術的負債 | 返済枠を「余力次第」にしない。IT 序盤の独立コミット枠で着手する |

## 6. 拡張性

| 項目 | 要件 |
| :--- | :--- |
| 業務サービスの水平スケール | 2 → 4 台。Processing Group のセグメント数を台数に合わせる |
| Axon Server | SE は 1 ノード。**スケールしない**。年間イベント 1,000 万件または稼働率 99.95% が要件になった時点で Enterprise Edition（クラスタ）を ADR で再評価 |
| 投影 DB | 読み取りが増えたらリードレプリカ。投影の書き手は 1 つのまま |
| 新しい読み取りモデル | 既存のイベント列からリプレイで作れること（新画面の追加にマイグレーションが要らない） |
| 外部システム連携 | 契約イベントを外部へ出す必要が生じたら、Axon Server の外に Outbox + メッセージブローカーを置く。ADR を起こす |

## 7. SLI / SLO / SLA

| 区分 | SLI | SLO | SLA |
| :--- | :--- | :--- | :--- |
| 可用性 | 業務時間内の業務画面 | 99.9% | 99.5% |
| 可用性 | 公開追跡照会（24h） | 99.9% | 99.5% |
| 応答 | 一般 API p95 | < 1.0s | < 1.5s |
| **反映** | コマンド → 投影 p95 | **< 3.0s** | < 5.0s |
| **反映** | Event Processor の遅れ | < 100 イベント（p99） | < 1,000 |
| Saga | 予約確定 → 追跡開始 p95 | < 10s | < 15s |
| エラー率 | 5xx | < 0.5% | < 1% |
| データ保護 | RPO（Event Store） | < 1 時間 | < 4 時間 |
| データ保護 | RTO | < 30 分（軽微）/ < 4h（重大） | < 4 時間 |
| 復元演習 | 四半期に 1 回、RTO 内 | 実施 | — |

## 8. 検証方法

| 要件 | 手段 | 頻度 |
| :--- | :--- | :--- |
| 応答時間・反映の遅れ | k6 でコマンドを流し、投影の反映を `202` → `200` で計測。Micrometer の遅れ指標 | リリース前 + 月次 |
| スループット | k6（ピーク 200 evt/s を 10 分） | リリース前 + 四半期 |
| 可用性 | CloudWatch SLO ダッシュボード | 週次 |
| Axon Server 停止時の挙動 | ステージングで停止し、コマンド `503`・クエリ応答・再接続・トークンからの再開を確認 | 四半期 |
| RPO / RTO | 復元演習（EBS スナップショットから復元 → 全投影リプレイ） | 四半期 |
| 個人情報の削除 | 鍵の破棄 → リプレイ → 投影と復元した集約に個人情報が無いことを確認 | リリース前 + 年次 |
| セキュリティ | 依存関係・イメージの走査（CI）、OWASP ZAP（週次）、ペネトレーション（年 1） | — |
| アクセシビリティ | axe-core + 手動 | リリース前 |

## 9. トレードオフ

| トレードオフ | 優先 | 理由 |
| :--- | :--- | :--- |
| 整合性 vs 可用性 | 可用性（結果整合を受容） | CQRS + Saga が前提。整合は補償と要確認一覧で回収する |
| 可用性 vs コスト | **SE の単一ノードを受容** | 学習目標と規模に対して EE は過剰。停止時もクエリは応答する設計で影響を狭める |
| 監査 vs 削除 | 両立（crypto-shredding） | イベントは消さず、個人情報だけ読めなくする |
| 開発速度 vs セキュリティ | セキュリティ | 物流データと個人情報を扱う |
| 監視の細かさ vs ノイズ | シグナル重視 | 反映の遅れと Processor の停止だけを即通知に |

## 10. リスクと緩和策

| リスク | 影響 | 緩和 |
| :--- | :--- | :--- |
| Axon Server SE の単一障害点 | 全コマンド停止 | クエリは投影で継続。監視・1 時間バックアップ・四半期の復元演習・EE 移行の再評価条件 |
| イベントの形の非互換 | 起動失敗・投影破損 | Upcaster、両側のゴールデン JSON、名簿の固定 |
| 投影の遅れが慢性化 | 「反映中」が常態化し障害に見える | 遅れの SLO と警告、セグメント数の調整、投影の SQL の計測 |
| 個人情報を平文でイベントに残す | 削除できない | 初回リリース前に鍵による暗号化を入れる |
| 追跡照会のスパイク | 5xx | CloudFront の短期キャッシュ、投影 DB のリードレプリカ |
| Axon 5 系の API 変更 | 実装の手戻り | IT1 スパイクで確定、バージョンを固定 |
