# ドメイン用語集：国際貨物輸送管理システム

ストーリー・ユースケース・ドメインモデル・コードで共通に使う語を定義します。AI はユースケース内の語のゆれを別の概念として扱いやすいため、文書を書く・読むときはこの用語集を正とします（[リスク台帳](../requirements/risk_register.md) R-07）。

- 出典: [要件定義書](../requirements/requirements_definition.md)（情報モデル・状態モデル・バリエーション）、[システムユースケース](../requirements/system_usecase.md)、[ユーザーストーリー](../requirements/user_story.md)、[インセプションデッキ](../strategy/inception-deck.md)
- コード上の英語名は、ドメインモデル設計で決めて本表に列を追加します。参照実装（`docs/article/source/`）やオリジナルの Cargo Tracker の名前・列挙値をそのまま持ち込みません（R-06）
- 「語のゆれと統一案」「採番の不一致」は 2026-09-16 に承認済みです。要件定義書・ビジネスユースケース・システムユースケース・ストーリーに反映済みです

## アクター

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 荷主 | 貨物の輸送を依頼し、見積確認・経路の承認・予約確定・追跡確認を行う者。個人荷主と法人荷主がある | 「顧客」は荷主の意味で使わない |
| 荷受人 | 貨物の到着を待ち、追跡情報を確認し、貨物を引き取る者 | |

| 経路設計者 | 経路候補の算出・選択・確定、航海スケジュールの管理、追跡番号の発行を行う社内担当者 | |
| 追跡管理者 | 貨物状態の更新、例外対応、通関状態の管理、輸送中キャンセルの承認を行う社内担当者 | |
| 荷役作業員 | 受領・積込・荷降し・引取の荷役作業を実施して記録し、通関申告を登録する作業員 | |
| 経理担当者 | 輸送料金の算出・割引の適用・精算を行う社内担当者 | |

| 通知システム | 荷主・荷受人へ状況変更をメール・SMS で送る外部システム | 外部連携（R-01） |

## 業務の概念

### 予約

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 見積 | 荷主の輸送要件（出発地・目的地・希望期限・貨物種別・重量）に対する、経路の概算候補ごとの所要日数と概算料金。見積番号で識別する | 「見積り」「見積もり」と書かない |
| 貨物予約 | 荷主が依頼した 1 件の輸送の申し込み。予約番号で識別し、貨物仕様・経路情報・追跡情報・輸送料金を持つ | 文中で文脈が明らかなら「予約」と略してよい。「輸送予約」は業務（BUC）名としてのみ使う |
| 貨物仕様 | 予約に含まれる貨物の種別・重量・危険物申告・温度条件などの情報 | |
| 希望期限 | 荷主が指定する目的地への到着期限 | 経路設計の制約条件「期限遵守」の基準 |
| キャンセル | 荷主の申し出による貨物予約の取り消し。輸送中のキャンセルは追跡管理者の承認と陸揚げ地の指定を要する。配送完了以降は取り消せない（返送は別業務） | UC22 |
| キャンセル料 | キャンセル時の予約状態に応じて算定する料金。輸送開始後は高くなる | 料率は未定義 |
| 陸揚げ地 | 輸送中キャンセルで貨物を降ろす港。現在地の港または次の寄港地から追跡管理者が指定する | |
| 船腹 | 航海で貨物を積める容量。予約が確保し、キャンセルで解放する | |

### 経路設計

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 航海 | 運送会社が運航する 1 回の船の運航。航海番号で識別し、出発日・到着日・寄港地を持つ | 「航路」は運航管理（スコープ外）の語として使わない |
| 航海スケジュール | 航海の一覧とその出発日・到着日・寄港地。経路設計者が登録・更新する | UC19 |
| 寄港地 | 航海が立ち寄る港 | |
| 経由港 | 経路のうち、出発地と目的地の間で航海を乗り継ぐ港 | 「経由地」と書かない（統一案 5） |
| 港湾 | 出発地・目的地・寄港地となる港とその施設。UN/LOCODE で識別する | R-09 |
| 出発地・目的地 | 経路の起点と終点の港湾 | |
| 経路 | 出発地から目的地までの、航海の区間（レグ）の並び | 「ルート」と書かない（統一案 1） |
| 経路候補 | 制約条件を満たす経路の案。経由港・所要日数・費用・航海番号を持つ | |
| 経路情報 | 経路設計者が確定し、貨物予約に紐付けた経路 | |
| 制約条件 | 経路候補の算出に用いる条件。航海スケジュール・寄港地の接続・期限遵守・貨物種別対応・港湾制約の 5 つ | R-04。要件定義書「経路設計の制約条件」が正 |
| 誤配 | 荷役作業の場所が予約の経路に含まれないこと。例外として起票し、現在地から経路を再設計する | US28 |

### 荷役・追跡

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 追跡番号 | 貨物を追跡するための番号。予約確定後に経路設計者が発行する | |
| 追跡情報 | 1 件の貨物予約に対する貨物状態と追跡イベントの履歴 | 荷主・荷受人が照会する |
| 追跡イベント | 貨物に起きた出来事の記録（荷役作業・出港・着港・例外など） | 荷役作業によるものを文中で「荷役イベント」と呼ばない（統一案 7） |
| 荷役作業 | 港湾で貨物を扱う作業。受領・積込・荷降し・引取の 4 種 | |
| 貨物状態 | 追跡情報が示す貨物の現在の状態（下記「状態」） | |
| 例外 | 輸送中に起きた通常と異なる事象。遅延・破損・紛失・誤配・税関保留がある | 例外種別は下記「区分値」 |

### 通関

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 通関申告 | 輸入港に到着した貨物について税関へ行う申告。申告番号・申告日時を登録する | 「通関」は手続き、「税関」は機関を指す |
| 通関状態 | 通関申告の審査結果の状態（下記「状態」）。通関済でなければ引取はできない | |

### 精算

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 輸送料金 | 貨物予約に対して算出する料金 | |
| 法人割引 | 法人荷主に適用する契約上の割引 | 要件定義書の「割引適用」と同じ |
| 精算 | 輸送料金を確定し、荷主の支払いを記録する業務。結果を精算実績として残す | 「決済」は決済機関が実行する支払い処理を指し、精算と区別する |

### 認証

| 用語 | 定義 | 備考 |
| :--- | :--- | :--- |
| 利用者 ID | システム利用者を識別する ID | |
| ロール | 利用者に与える役割。アクターに対応し、利用できる機能を決める | |

## 状態

### 予約状態

要件定義書の状態モデルは次のとおりです。ストーリーとユースケースで使われていた別の名前（仮予約・経路提案済・確認済・経路設計中・配達完了）は、統一案 2 によりこの名前に揃えます。

| 状態 | 意味 | 次の状態 |
| :--- | :--- | :--- |
| 仮受付 | 貨物予約を登録した | 経路提案中、キャンセル |
| 経路提案中 | 経路設計者に引き渡し、経路を検討している（内部に経路検討中・経路候補算出済・経路選択済） | 予約確定、キャンセル |
| 予約確定 | 経路情報を紐付け、荷主が承認した | 追跡番号発行済、キャンセル |
| 追跡番号発行済 | 追跡番号を発行した | 輸送中 |
| 輸送中 | 荷役作業が始まった | 配送完了、キャンセル（要承認） |
| 配送完了 | 最終の荷役作業（引取）が完了した | 精算済 |
| 精算済 | 精算が完了した | — |
| キャンセル | 予約が取り消された | — |

### 貨物状態

要件定義書の状態モデルの 9 状態です（R-06）。

| 状態 | 遷移のきっかけ |
| :--- | :--- |
| 受領待ち | 追跡番号の発行 |
| 受領済 | 荷役作業（受領） |
| 積込済 | 荷役作業（積込） |
| 輸送中 | 出港 |
| 荷降し済 | 荷役作業（荷降し） |
| 引取待ち | 最終港への着港 |
| 引取済 | 荷役作業（引取） |
| 例外発生 | 例外の起票 |
| 対応中 | 例外対応の開始。正常復帰で輸送中、解決して引取完了で引取済へ |

### 通関状態

| 状態 | 意味 |
| :--- | :--- |
| 審査中 | 申告を登録し、税関の結果を待っている |
| 通関済 | 通関が認められた。引取が可能になる |
| 留置 | 税関に留め置かれている。例外「税関保留」を起票し、3 日を超えると督促する |
| 不可 | 通関が認められなかった。荷主に返送または廃棄の判断を求める |

## 区分値

| 区分 | 値 |
| :--- | :--- |
| 貨物種別 | 一般貨物、危険物、冷凍・冷蔵貨物 |
| 荷主種別 | 個人荷主、法人荷主 |
| 荷役作業種別 | 受領、積込、荷降し、引取 |
| 例外種別 | 遅延、破損、紛失、誤配、税関保留 |

例外種別は、要件定義書のバリエーションでは遅延・破損・紛失の 3 つで、誤配（US28）と税関保留（UC21）はユースケースとストーリーで追加されています（統一案 8）。

| # | 概念 | 現在の表記 | 統一案 | 根拠 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 出発地から目的地までの航海の並び | 経路／ルート（「ルート候補」「予定ルート」「ルート選択」など） | **経路** | 情報モデル・ユースケース名・状態モデルの主語が「経路」。「ルート」は各文書に 2〜22 回、「経路」は 29〜151 回 |
| 2 | 予約状態の名前 | 要件定義書: 仮受付／経路提案中／予約確定／配送完了。UC22・US30: 仮予約／経路提案済／確認済／配達完了。UC11・US13: 経路設計中 | **要件定義書の状態モデルの名前**（仮受付・経路提案中・予約確定・配送完了） | 状態モデルが唯一の遷移図。ストーリー側の名前は参照実装の状態名が混入した可能性がある（R-07） |
| 3 | 荷受人へ貨物を渡す荷役作業 | 引取／引き取り | **引取** | 荷役作業種別・貨物状態（引取済・引取待ち）の表記 |
| 4 | 温度管理が必要な貨物 | 冷凍貨物／冷凍・冷蔵貨物 | **冷凍・冷蔵貨物** | 要件定義書の貨物種別。US05 のタイトル「危険物・冷凍貨物」は略記として残すか要判断 |
| 5 | 乗り継ぐ港 | 経由港／経由地／寄港地 | 経路上の乗り継ぎ港は **経由港**、航海が立ち寄る港は **寄港地** | 経由港は経路候補の表示項目、寄港地は航海の属性で、別の概念 |
| 6 | 貨物を渡す行為 | 引き渡し（予約情報の引き渡し／貨物の引き渡し） | 経路設計者へ予約を渡す業務は **予約情報引き渡し**、荷受人へ貨物を渡すことは **引取** | 同じ語が別の概念を指している |
| 7 | 荷役作業の記録 | 追跡イベント／荷役イベント／例外イベント | **追跡イベント**（種類として荷役・例外を持つ） | 情報モデルは「追跡イベント」と「荷役情報」 |
| 8 | 例外種別 | 要件定義書: 3 種。UC16・UC21・US28: 誤配・税関保留を追加 | **5 種**（遅延・破損・紛失・誤配・税関保留）に揃え、要件定義書のバリエーションに追記する | 後から追加されたストーリーが正しく、要件定義書が追従していない |

## 採番の不一致（2026-09-16 承認）

- ユースケース ID: 要件定義書の付録と状態モデルは旧採番（UC01〜UC12、UC_R01〜UC_R07）、[システムユースケース](../requirements/system_usecase.md) とストーリーは新採番（UC01〜UC22）を使っており、同じ ID が別のユースケースを指していた（例: 要件定義書の UC05 は「追跡番号発行」、システムユースケースの UC05 は「航海スケジュールを検索する」）。システムユースケースの採番を正とし、要件定義書を追従させた（反映済み）
- UC21 は「ADR-006」を参照していたが、`docs/adr/` に ADR は無い（参照実装の ADR 番号が残った可能性。R-07）。参照を外し、「税関とは電子連携せず手入力とする」判断は ADR 化が必要と注記した（反映済み。ADR の作成はリリース計画の Level 1 計画）
- 状態の英字コード（`CLAIM`・`UNLOAD`・`PENDING`・`CLEARED`・`HELD`・`REJECTED`）が UC21・US29 に現れていた。コード上の名前はドメインモデル設計で決めるため、文書から外した（反映済み）
