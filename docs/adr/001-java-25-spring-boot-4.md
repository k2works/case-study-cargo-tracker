# ADR-001: Java 25 LTS + Spring Boot 4.0 を採用する

実行基盤として Java 25 LTS と Spring Boot 4.0.x を採用し、Java 21 + Spring Boot 3.4 での開始案は採らない。

日付: 2026-08-06

## ステータス

承認済み

## コンテキスト

設計ドキュメント間でバージョン方針が分岐したまま実装着手を待っている状態にあった。

- `non_functional.md`・`architecture_backend.md`・`architecture_infrastructure.md` は Java 25 / Spring Boot 4.0.5（JDK 25）を確定として記述している
- 一方 `tech_stack.md` は「Java 25 / Spring Boot 4.0 はリリース直後であるためエコシステムの成熟状況を監視しながら採用する。GA が不安定な場合は Java 21 LTS + Spring Boot 3.4.x で開発を開始し、4.0 GA 後に移行するロードマップを ADR に記録する」としていた
- さらに同ファイルの「LTS 優先選定」節は「Java: LTS バージョン（Java 21）を実績ベースとし」と書きつつ、アップグレード計画表の現行バージョンは Java 25 という自己矛盾を抱えていた
- `test_strategy.md` には「Spring Boot 3.4+ では `@MockBean` は deprecated」という 3.x 前提のコメントが残っている

参照先の ADR が存在しないため、**採用バージョンが未決定のままイテレーション 1 の着手が止まる**状態だった。

本プロジェクトはグリーンフィールドであり、移行対象の既存コードベースを持たない。

## 決定

**Java 25 LTS + Spring Boot 4.0.x を採用する。** Java 21 + Spring Boot 3.4 で開始して後から移行する案は採らない。

判断根拠は次のとおり。

- Java 25 は 2025-09 に LTS として GA、Spring Boot 4.0 は 2025-11 に GA しており、本決定時点でいずれも約 9 か月の実績がある。`tech_stack.md` が想定していた「リリース直後」の状態は既に解消している
- グリーンフィールドであるため、3.4 で始めて 4.0 に移行する案は**移行コストを自ら作り出すだけ**で得るものがない。移行が正当化されるのは既存資産がある場合に限る
- 既に 3 つの設計ドキュメントが Java 25 / Boot 4.0 前提で非機能要件・インフラ構成を記述しており、そちらに揃えるほうが変更量が小さい

### 変更箇所

- `tech_stack.md`: 「バージョン採用方針」の但し書き（Java 21 + Boot 3.4 での開始案）を削除し、本 ADR への参照に置き換える
- `tech_stack.md`: 「LTS 優先選定」の「Java: LTS バージョン（Java 21）を実績ベースとし」を Java 25 LTS に修正する
- `test_strategy.md`: 「Spring Boot 3.4+ では `@MockBean` は deprecated」のコメントを Boot 4.0 前提（`@MockitoBean` を使う）に修正する

### 代替案

| 代替案 | 却下理由 |
| :--- | :--- |
| Java 21 LTS + Spring Boot 3.4 で開始し、後に 4.0 へ移行 | グリーンフィールドで移行コストを自ら作る。GA 後 9 か月経過しており「様子を見る」理由が失効している |
| Java 21 LTS + Spring Boot 4.0 | Spring Boot 4.0 は Java 17 以上で動作するが、Java 25 の言語機能（パターンマッチング・レコードパターンの成熟形）は DDD の値オブジェクト設計と相性がよく、LTS を選ぶなら新しいほうを採る理由がある |

## 影響

### ポジティブ

- バージョン未決定によるイテレーション着手のブロックが解消する
- 移行イテレーションを計画に組み込む必要がなくなる
- Java 25 のレコード・sealed interface・パターンマッチングを値オブジェクトと状態遷移の表現にそのまま使える

### ネガティブ

- Spring Boot 4.0 は 3.x からの破壊的変更を含むため、Web 上の解説記事の多くが 3.x 前提であり、調査時に読み替えが必要になる
- `@MockBean` → `@MockitoBean` のように、テスト周りの API 名が 3.x 系のサンプルと異なる
- 一部のサードパーティライブラリが Boot 4.0 対応を完了していない可能性がある。依存追加時は対応状況の確認を要する

## コンプライアンス

- ビルド定義（`build.gradle` / `pom.xml`）の `sourceCompatibility` / `spring-boot` プラグインバージョンが本 ADR と一致すること
- CI のセットアップジョブが JDK 25 を指定していること
- `tech_stack.md` のバージョン表と本 ADR に差異がないこと（差異が生じた場合は ADR 側を正典とし、`tech_stack.md` を修正する）
