# ADR-0016 料率は設定に置き、見積と請求で同じものを読む

料金の料率（基準運賃・地域係数・貨物種別係数・税率・国の地域区分）は `application.yml` の `billing.rates.*` に置く。コードに埋めない。

日付: 2026-09-11

## ステータス

2026-09-11 提案。IT13（US21・US22）。

## コンテキスト

**同じ式を読む場所が 2 つできます。** 正典の料金計算は `Invoice`（請求・US21）と `Quotation`（見積・US01・IT14）の両方が使い、`domain-model.md` は「Booking の `Quotation` はこの式と同じ料率で概算を出す」と書いています。**料率をコードに埋めると、片方だけ直ります**——見積が旧料率、請求が新料率という状態は、荷主から見れば「言われた金額と違う」です。

**料率は業務が決める数字です。** 燃料費や為替で変わります。変えるたびにビルドが要る形は、変えない理由になります。

**検査が別の料率を持つ危険もあります。** テストのフィクスチャに料率を書くと、設定を直しても検査は元の値のまま緑です（IT10 の「判定はテスト側に書き直さない」と同じ形）。

## 決定

**決定 1. 料率は `application.yml`（`billing.rates.*`）に置く。** `RateTable`（値オブジェクト）へ組み立てるのは `RateTableConfiguration` 1 か所です。**欠けていれば組み立ての時点で断ります**——請求のたびに落ちるより、起動してすぐ分かるほうがよい。

**決定 2. 検査のフィクスチャと、起動したアプリの料率が一致することを検査する。** 片方を直したらもう一方も直すことになります。**どちらかが古いまま緑になる形を作らない。**

**決定 3. 料率表に無い値は断る。** 知らない貨物種別を黙って 1.0 で通すと、危険物が一般貨物の料金で請求されます（名簿方式の検査が「載っていないものを通す」のと同じ形）。**例外は国の地域区分だけ**で、表に無い国は**遠洋**として数えます——安いほうに倒すと、取りこぼした請求はあとから取り返せません。

## 検査

**決定の数だけ検査を用意する。** 検査に落とさなかった決定は守られません。

| 決定 | 検査 |
| :--- | :--- |
| 1 | `RateTableTest#refusesIncompleteConfiguration`・`#refusesEachMissingSetting`（基準運賃・地域係数・貨物種別係数・税率のそれぞれが欠けたら断る） |
| 2 | `RateTableConfigurationIT#readsTheCanonicalRatesFromConfiguration`（**起動したアプリの `RateTable`** と検査のフィクスチャを突き合わせる。`application.yml` を書き換えると赤になる） |
| 3 | `RateTableTest#refusesUnknownCargoType`・`FreightChargeCalculatorTest#refusesUnknownCargoType`（知らない貨物種別を断る）。`RateTableTest#classifiesPortsByCountry`（表に無い国は遠洋） |

**IT14 で足す検査。** 見積（US01）が入ったら、**同じ入力に対する見積と請求の出力を突き合わせる契約テスト**を足します。入力が違う（見積は候補経路、請求は実際の区間）ので金額は一致しませんが、**同じ料率表を読んでいること**は固定できます。

## 代替案

| 案 | 内容 | 却下の理由 |
| :--- | :--- | :--- |
| コードに定数で持つ | `FreightChargeCalculator` に `private static final` | 変えるたびにビルドが要る。見積と請求の 2 か所に書くことになる |
| DB のマスタ表に持つ | `rate_table` を作る | 読むのは請求のたび。**料率の履歴**が要るのは「いつの料率で出した請求書か」を追うときだが、それは請求書が自分の金額を持つことで足りる。表を足すと、どの Read DB に置くか（billingms か bookingms か）でまた分かれる |
| 共有カーネルに定数として置く | `shared.domain.rate` | 共有カーネルの名簿を太らせる理由にならない。料率は**設定**であって型ではない |

## 結果

**よくなること。** 料率の出典が 1 つになる。変更にビルドが要らない。欠けていれば起動で分かる。

**代償。** 設定の誤りは起動するまで分からない（コンパイルでは捕まらない）。環境ごとに料率がずれる余地ができる——**本番の設定を正典とし、その差は運用手順書で見る**。

**守りきれなくなる兆し。** 料率に有効期間が要るようになったとき（「4 月から改定」）。そのときは設定では足りず、履歴を持つ置き場が要る。
