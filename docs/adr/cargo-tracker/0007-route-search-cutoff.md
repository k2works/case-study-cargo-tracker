# ADR-0007 経路探索を乗り継ぎ 3 回・候補 20 件で打ち切る

経路探索（US08）は**乗り継ぎ 3 回（区間 4 本）・候補 20 件**で打ち切る。打ち切ったことは「候補が無い」と区別して呼ぶ側に返す。

日付: 2026-09-05

## ステータス

2026-09-05 提案されました

## コンテキスト

`RouteSearchService` は寄港地の接続をたどって経路候補を探す（US08 §受入基準 1・2）。航海と寄港地の数が増えると、たどれる組合せは急速に増える。上限を置かないと、航海が数百本になったときに応答が返らず、経路設計者の画面が固まる。

上限そのものは実装の都合に見えるが、**どこで切るかは業務の判断**である。

- 乗り継ぎが増えるほど、積み替えの事故・遅延・保管費が積み上がる。**4 回積み替える経路を現場が選ぶことは、まず無い**
- 候補が 20 件を超えると、経路設計者は上から数件しか見ない。多く出すことは「選びやすさ」に寄与しない

これをコードのコメントや定数に書くだけにすると、次に「もっと出してほしい」と言われたときに、なぜ 3 と 20 なのかの根拠が残らない。上げてよいのか、上げると何が壊れるのかを判断できない。

### 打ち切りを黙って行わない

上限に当たったことを呼ぶ側に返さないと、**「上限を超える経路しか無い予約」と「そもそも便が無い予約」が同じ見え方になる**。前者は条件（期限・除外港）を変えても直らないのに、経路設計者は条件を変え続けることになる。

候補件数だけで打ち切りを判断するのも足りない。乗り継ぎ上限で捨てた枝は件数に現れないので、**候補 0 件・打ち切り無しと表示される**。実装では、枝を捨てた事実も打ち切りとして数える。

## 決定

1. **乗り継ぎは 3 回まで**（`MAX_TRANSFERS = 3`。区間は 4 本まで）。**探索が有限に終わることは、この上限と「同じ港を 2 度通らない」が担う。**
2. **候補は 20 件まで**（`MAX_CANDIDATES = 20`）。ただし**これは探索の打ち切りではなく、並べたあとの表示の上限**である（IT5 レビューで改めた。下記「決定 2 の訂正」）。
3. **上限に当たったことを `RouteSearchResult.truncated` で返す。** 真にするのは次の 2 つだけ:
   - 推奨順に並べた結果が 20 件を**超えた**（実際に候補を落とした）
   - **候補が 1 件も無く**、かつ乗り継ぎ上限で枝を捨てた（条件を変えても増えない）

   候補が出ているときに「行き止まりの深い枝があった」ことは真にしない。実データの港湾ネットワークではそういう枝がほぼ必ずあり、警告が常時点灯して**合図として働かなくなる**。
4. **画面に出す**（S31）。「上限まで探しました。条件を絞ると別の候補が出ることがあります」の形で、0 件の案内とは別の文にする。
5. **上限は業務の判断なので、変えるときはこの ADR を改める。** 定数だけを書き換えない。

## 結果

### 良い点

- 航海が増えても応答時間の上限が読める（探索は上限つきの幅優先で、深さも幅も有限）
- 「候補が無い」「上限まで探した」「探索できなかった（503）」の 3 つを言い分けられる。経路設計者は次に何をすればよいかを判断できる
- 上限を上げる判断に根拠が残る

### 決定 2 の訂正（IT5 レビュー・2026-09-05）

**当初は「上限に達した時点で探索を止める」と実装した。これは誤りだった。**

探索の途中で件数を切ると、返るのは「推奨順の上位 20 件」ではなく**「先に見つかった 20 件」**になる。並べ替えは切ったあとの集合にしか効かないためである。幅優先で先に見つかるのは出発の早い便なので、**出発の遅い直行便が乗り継ぎ候補に押し出されて一覧から消える**。受入基準 4（推奨順）と 5（直行便を最優先）が、候補が 20 件を超える航路で破れる。

この症状はクラスタ E2E で実測していた（登録した便が候補に出なかった）。そのときは「同着の並びが決まらないため」と誤診してテスト側を回避しており、実装の欠陥として残っていた。

**訂正**: 期限内の候補をすべて集めてから並べ、`limit(20)` を最後に効かせる。探索が有限に終わることは乗り継ぎ上限（決定 1）と「同じ港を 2 度通らない」が担うので、件数で切る必要は無い。

### 悪い点・受け入れるリスク

- **4 回以上の乗り継ぎでしか着かない経路は、この機能では出せない。** 実務でそうした経路が必要になったら（極端な小口・特殊港）、手作業に落ちる。US10（条件調整・IT6）で除外港を外すことでも変わらない
- 21 件目以降の候補は出ない。**推奨順の下位**なので当初の実装より害は小さいが、上限に当たったことは画面に出す
- 幅優先で全候補を集めるので、**乗り継ぎ 3 回・港数 N に対して最大 N⁴ 程度の枝を歩く**。港が数百に増えたら、深さか訪問数の上限を追加で置く判断が要る（そのときはこの ADR を改める）

## 代替案

| 案 | 内容 | 判断 |
| :--- | :--- | :--- |
| 上限なし | 全経路を探す | 却下。航海数に対して組合せが指数で増え、応答が返らなくなる時点を予測できない |
| 時間で打ち切る | 「500ms 探して打ち切る」 | 却下。同じ入力で結果が変わる。テストで固定できず、機械の速さで候補が変わる |
| 所要時間で打ち切る | 「期限 + 7 日を超える枝は捨てる」 | 併用しうるが、単体では不十分。期限内でも組合せは増える。将来の絞り込みとして残す |
