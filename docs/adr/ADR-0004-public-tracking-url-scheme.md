# ADR-0004: 公開貨物追跡の URL 設計

公開貨物追跡は `/public/tracking/{trackingNumber}`（共有用）と `/public/tracking?trackingNumber=...`（フォーム送信）の 2 つの URL で同じ画面を返す。フォームは GET で送信し、状態を変更しないため CSRF トークンを持たない。

## ステータス

承認済み（2026-08-28・IT2）

## コンテキスト

US18「追跡情報を照会する」は、荷主・荷受人が**認証なしで**貨物の状況を確認できることを求める。IT1 では `/public/tracking/{trackingNumber}` のみを実装し、追跡番号を URL に直接打ち込む前提だった。IT2 で入力フォームを追加するにあたり、次の 3 つを同時に満たす必要が生じた。

1. **QR コードからの直接アクセス**（[UI 設計](../design/ui_design.md)）— 1 つの URL で結果画面に到達できること
2. **結果 URL の共有・再訪** — 荷主が荷受人へ URL を転送する運用がある
3. **追跡番号を知らない状態での入口** — フォームだけを表示する画面が必要（[UI 設計](../design/ui_design.md) に定義がなかった）

HTML の GET フォームは `action` にクエリ文字列を付けて送信するため、フォームからの遷移先は必然的に `?trackingNumber=...` になる。パスパラメータ形式へ送信するには JavaScript による書き換えが必要だが、本プロジェクトは htmx 以外のクライアントサイド JavaScript を持たない方針である（[フロントエンドアーキテクチャ](../design/architecture_frontend.md)）。

## 決定

### 1. 2 つの URL を許容し、いずれも同じ画面を返す

| URL | 用途 |
| :--- | :--- |
| `GET /public/tracking/{trackingNumber}` | **共有・QR コード用の正規 URL**。荷主が転送する URL はこちら |
| `GET /public/tracking?trackingNumber=...` | フォームの送信先。ブラウザが自動生成する形 |
| `GET /public/tracking` | 追跡番号未指定の入口（フォームのみを表示） |

`?trackingNumber=` からパス形式へ 302 リダイレクトする案も検討したが、採用しない。リダイレクトは 1 往復増えるうえ、**照会のたびに URL が書き換わることが利用者にとっての利点にならない**（結果画面はどちらの URL でも同じであり、共有する人は表示されている URL をそのままコピーする）。

### 2. フォームは GET で送信する

状態を変更しない照会であり、次の 3 点で GET が適切である。

- 結果 URL を共有・再訪できる（POST では戻る操作で再送信の警告が出る）
- ブラウザの履歴・ブックマークが機能する
- CSRF トークンが不要（`Components.form` は GET のときトークンを付けない）

### 3. 追跡番号の未指定と空文字を区別する

| 状態 | 表示 |
| :--- | :--- |
| パラメータなし（入口を開いた） | フォームのみ |
| 空文字（未入力のまま送信した） | フォーム + 「追跡番号を入力してください」 |
| 該当なし | フォーム + 未検出メッセージ + 書式例・問い合わせ導線 |

空文字で「フォームのみ」に戻すと、利用者からは「追跡するを押したのに画面が戻っただけ」に見え、故障と受け取られる（IT2 レビュー M3）。

## 影響

### 正の影響

- JavaScript を持ち込まずに、QR コード・フォーム・URL 共有のすべてを満たせる
- CSRF トークンの生成・検証を公開画面に導入しなくてよい（認証基盤は IT3）

### 負の影響

- **同一リソースに 2 つの URL が存在する**。正規 URL を選ぶ必要が出た場合（SEO・アクセス解析・外部連携）は、`rel="canonical"` の付与かリダイレクトの導入を再検討する
- ルーティング表に 2 行必要になる（`Composition.routes()`）

### この判断を見直す条件

- 外部システムが公開追跡を機械的に参照し始めたとき（URL の一意性が要件になる）
- 追跡番号以外の検索条件（予約 ID・期間）が加わり、クエリ文字列が複雑化したとき

## コンプライアンス

- 公開追跡のルートはすべて `RequiredRole.Anonymous` であること（ルーティング表）
- GET フォームに CSRF トークンが含まれないこと（`ComponentsTest.testFormOmitsCsrfForGet`）
- 未指定・空文字・該当なしの 3 状態が区別されること（`TrackingPublicPagesTest`・`PublicTrackingHttpTest`）
