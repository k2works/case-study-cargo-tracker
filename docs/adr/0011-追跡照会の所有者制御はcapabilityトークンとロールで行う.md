# ADR-0011: 追跡照会の所有者制御は capability トークン（公開）とロール（認証）で行う

追跡照会（US18）の認可を、未認証の公開照会は推測困難な access_token（capability ベース）で、認証済み照会は RBAC ロールで制御し、レコード単位の所有者チェックは現時点では導入しない決定。

日付: 2026-07-17

## ステータス

2026-07-17 提案（IT6・retro-5 Try#4 の所有者制御方針の明文化）

## コンテキスト

IT5 で追跡照会（US18）に 2 つの経路を実装した。

1. **認証あり**（`GET /tracking/{trackingNumber}`）: `ROLE_SHIPPER`／`ROLE_CONSIGNEE`／`ROLE_TRACKER` のいずれかを持つユーザーが追跡番号で照会する。
2. **未認証の公開ページ**（`GET /public/tracking/{accessToken}`）: 荷主が URL を共有して荷受人等に見せるための、推測困難な `access_token`（Guid 2 本＝64 桁相当）で照会する。

このうち認証あり経路は、追跡番号さえ知っていれば当該ロールを持つ任意のユーザーが照会できる。「その荷主本人の貨物か」というレコード単位の所有者チェックは行っていない。IT5 レビュー・retro-5 Try#4 で、この所有者制御方針を明文化し、意図的な設計判断として確定することが求められた。

現状のドメインモデルには、追跡活動（`TrackingActivity`）と荷主（`ShipperId`）を直接結ぶ所有関係が存在しない。`tracking_activity` は `booking_id` を保持するが、認証ユーザー（`users`）と荷主（`ShipperId`）の対応付けも未モデル化である（割り切り事項・release_plan スコープ外）。

## 決定

**追跡照会の認可は「公開＝capability トークン」「認証＝RBAC ロール」の 2 層で行い、認証経路のレコード単位所有者チェックは本リリースでは導入しない。**

- **公開経路**は access_token を capability（所有していること自体が閲覧権限）として扱う。トークンは推測困難で、発行時に荷主へ通知し（US14・レビュー高#6 で発行通知に URL を同梱）、URL を知る者だけが閲覧できる。
- **認証経路**は RBAC ロール（荷主・荷受人・追跡管理者）で制御する。これらは業務上の信頼済みアクターであり、追跡管理者は全貨物を横断的に扱う必要があるため、レコード単位の所有者制限はむしろ業務を阻害する。
- **荷主本人限定の照会**が将来必要になった場合は、`users`↔`ShipperId` の対応付けと `tracking_activity`↔`ShipperId` の所有関係をモデル化したうえで、認証経路に所有者チェックを追加する（本 ADR を改訂）。

### 代替案

- **案 B: 認証経路にレコード単位の所有者チェックを追加**（却下）: `users`↔`ShipperId`↔`tracking_activity` の所有関係が未モデル化で、追跡管理者の横断業務とも矛盾する。所有関係のモデル化は release_plan のスコープ外であり、現時点で導入すると過剰設計になる。
- **案 C: 公開ページを廃止しすべて認証必須にする**（却下）: 荷受人（未認証の外部関係者）が追跡番号照会で貨物状態を確認する US18 の要件を満たせない。capability トークンによる共有は要件そのものである。

## 影響

### ポジティブ

- 公開共有（capability）と内部照会（RBAC）という 2 つの要件を、それぞれに適した認可方式で満たせる。
- 追跡管理者の横断業務を阻害しない。
- 所有関係の未モデル化という割り切りを、意図的な設計判断として明文化できる（暗黙の未対応ではない）。

### ネガティブ

- 認証経路では、追跡番号を知る当該ロールのユーザーが他荷主の貨物も照会できる。荷主本人限定の秘匿性が要る場合は追加設計が必要。
- access_token が漏洩すると URL を知る誰でも閲覧できる（capability の性質）。トークンの推測困難性・再発行手段は将来の検討事項。

## コンプライアンス

- 公開経路のトークンが推測困難（Guid 2 本連結）で、不正トークンが 404 を返すことを受け入れテストで確認する（既存 `TrackingAcceptanceTests`）。
- 認証経路が未認証アクセスを拒否し、許可ロール以外を `Forbidden` にすることを受け入れテストで確認する。
- 荷主本人限定照会を導入する際は本 ADR を改訂し、所有関係のモデル化とセットで行う。
