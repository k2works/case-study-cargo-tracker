# ADR-004: 個人情報の扱い（荷主を CRUD にし、イベントに載せない）

荷主（個人情報）はイベントソーシングにせず PostgreSQL の表（更新・削除可）に置き、イベントには荷主 ID と割引率の写しだけを載せる。

## コンテキスト

- イベントは追記専用で消せない。氏名・住所・連絡先・メールをイベントに載せると、訂正・削除に応えられない。
- 荷主のメール重複は「登録を続ける」を選べるため一意制約にしない（US02 AC-02。要確認）。
- 荷主の個人情報の保持と削除は法令・社内規程の確認が要る（NFR-D06）。

## 決定

**荷主（U-02）は PostgreSQL の表で管理し（更新・削除可。論理削除 `deleted_at`）、予約などのイベントには荷主 ID・荷主種別・割引率の写しだけを載せる**。ログ・指標・エラー文面にも個人情報を出さない。これは永続化方式だけの例外であり、荷主登録がコア能力であることは変わらない。

### 変更箇所

- `booking.shipper` を書き込み側の表とする。
- 公開照会の応答に個人情報を含めない（公開スキーマの項目を固定。A7）。

### 代替案

- **荷主もイベントソーシングにし、暗号化して鍵を捨てる方式で削除に対応する**：運用と鍵管理が複雑になる。規模に対して過剰なため却下

## 影響

### ポジティブ

- 個人情報の訂正・削除ができ、イベントは消さずに済む。

### ネガティブ

- 永続化方式が 2 種類になる。
- バックアップからの個人情報の削除の扱いは別途決める必要がある。

## コンプライアンス

- イベントのスキーマに個人情報のフィールドが無いことの検査、ログの走査（NFR-S22）。
