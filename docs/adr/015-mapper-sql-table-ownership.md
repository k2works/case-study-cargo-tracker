# ADR-015: BC 間の結合は SQL の層でも検査する

マッパーの SQL が触るテーブルの所有 BC を検査し、**他 BC のテーブルを触る SQL を落とす**。やむを得ず残すものは、理由とともに名前で登録する。

日付: 2026-08-09

## ステータス

承認済み

## コンテキスト

ADR-012 は「BC 間の依存の向きを一方通行に保ち、越境してよいのは `infrastructure/acl` のアダプタだけである」と定めた。これを守っているかは ArchUnit ルール 4 が検査している。

**IT11 で、この検査を 1 件も破らずに BC 間の結合が増えた。**

予約詳細に「誤配を検知した場所と日時」を出すため、`BookingQueryMapper` が `handling_activity` を相関サブクエリで読んだ。Java のクラスは 1 つも参照していないため、**ArchUnit にも JIG にも映らなかった**（どちらも Java の依存グラフしか見ない）。

クローズ前のレビューが指摘するまで、誰も気づかなかった（IT11 レビュー C28）。

### なぜ「読むだけだから」で済ませられないか

- **Handling のテーブルを変えれば Booking の SQL が黙って壊れる。** 壊れるのは実行時であり、コンパイルも ArchUnit も通る
- ADR-012 が「BC を別モジュールに切り出すとき、動かすのはアダプタだけで済む」と述べた主張は、**SQL の越境があると成立しない**
- 検査が守っていないものを「守っている」と読む状態そのものが危うい。**ArchUnit が緑であることが、越境していないことの根拠にならない**

## 決定

**`MapperTableOwnershipTest` を置く。** `*Mapper.java` のソースを走査し、`FROM` / `JOIN` / `INTO` / `UPDATE` の直後のテーブル名を取り出して、そのマッパーが属する BC の持ち物かどうかを検査する。

- **テーブルの所有 BC の正典は `data-model.md`** である。テストはそれを書き写した表を持ち、ずれたら正典を読み直して直す
- **共有のマスタ（`location`）と認証（`users` / `user_roles`）はどの BC からも読んでよい。** 前者は共有カーネルの実体（ADR-005）、後者は支援サブドメインとして全 BC の入口に効く（ADR-007）
- **やむを得ず残す越境は `ALLOWED` に理由とともに書く。** 黙って通すのではなく、名前で残す
- **フィクスチャは実コードの形で作る。** 「最小の違反例」だけだと、メタテストが緑でも実コードの違反を見逃す。実際にあった違反の形（相関サブクエリ・複数 JOIN・別名付き）をそのまま使う

### 検査は 3 つを見る

| 検査 | 何を守るか |
| :--- | :--- |
| マッパーは自分の BC のテーブルだけを触る | 本 ADR の主目的 |
| 実コードの形の違反を検出できる | **検査そのものが働くこと**（メタテスト） |
| 自分の BC のテーブルは違反にしない | 常に落ちる検査で緑にしない |

## 何がどこで守るか

| 守るもの | 守り手 |
| :--- | :--- |
| マッパーは自分の BC のテーブルだけを触る | **`MapperTableOwnershipTest`** |
| 検査そのものが実コードの形の違反を検出できる | **`MapperTableOwnershipTest` のメタテスト**（フィクスチャは実コードの形で作る） |
| 自分の BC のテーブルを違反にしない | **`MapperTableOwnershipTest`**（常に落ちる検査で緑にしない） |
| **所有表に載っていないテーブルを素通りさせない** | **守れていない。** 名簿に無いテーブルは黙って通る（IT16 のタスク 4 で「未登録 → 赤」を追加する） |
| **テーブルの所有 BC の正典が `data-model.md` にある** | **無い。** 所有者を示すのは検査コードの `OWNER` だけである（IT16 の C10 で `data-model.md` に所有表を新設する） |

> **「正典は `data-model.md`」と書きながら、`data-model.md` に所有表が無かった。**
> 所有者を示していたのは検査コードの `OWNER` だけであり、**正典と名指しされた側が空白**
> だった。IT16 の C10 で表を新設する。
>
> **名簿方式は、載っていないものを通すという反転した性質を持つ。** `handling_correction`
> が IT12 から 3 イテレーション漏れていた。**載せ忘れたものほど検査から漏れる。**

## 結果

### よい影響

- **測ってみたら 9 本あった。** レビューは 2 本と言ったが、検査は 7 本の既存の越境も見つけた。**指摘の件数は「見つかった数」であって「ある数」ではない**
- IT11 が足した誤配の現在地は、**結果整合の写しに置き換えて解消した**（ADR-009）。荷役の登録が既に運んでいた事実を Booking が自分の表に写す
- 残る 8 本は 3 つの型に分かれることが分かった。**一覧の表示に要る名前**（N+1 の回避）・**集計**・**写しにできるもの（次に返す候補）**

### 受け入れる代償

- **SQL の文字列を正規表現で読む。** 動的 SQL（`<script>`）の条件分岐まで解釈しないため、実行されない分岐のテーブルも拾う。**過剰に拾う側に倒している** — 見逃すより、理由を書かせるほうがよい
- **テーブルの所有 BC を 2 か所に持つ**（`data-model.md` とテスト）。ずれる余地は残る。テストの Javadoc に「正典は data-model.md である」と明記して運用する
- `ALLOWED` が長くなるのは設計が緩んだ合図である。**行を足すたびに、まず ACL ポートを疑う**

## 検討したが採らなかった案

| 案 | 内容 | 不採用の理由 |
| :--- | :--- | :--- |
| BC ごとに DB スキーマを分ける | 物理的に触れなくする | **本 IT の規模で払う代償が大きすぎる。** マイグレーション・トランザクション・既存の読み取り側 JOIN のすべてに影響し、US35 / US36 が入らなくなる。将来モジュールを切り出すときの選択肢として残す |
| 読み取り専用の越境は許す | 更新だけを検査する | **「読むだけ」でも壊れる向きは同じである。** Handling のテーブルを変えれば Booking の SQL が壊れる。許すと、検査は更新の無い越境をすべて見逃す |
| レビューで見つける | 人の目で確かめる | **IT11 で実際に見逃した。** 見つけたのはクローズ前のレビューであり、その時点で 7 本の既存の越境には誰も触れていなかった |
