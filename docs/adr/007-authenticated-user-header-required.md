# ADR-007: 業務サービスは Gateway が付けた利用者ヘッダを必須とし、共有フィルタで検査する

各マイクロサービスは `X-Authenticated-User-Id` / `X-Authenticated-Roles` が付いていないリクエストを 401 で拒否する。この検査は共有ライブラリのフィルタとして 1 箇所に置き、登録されていないサービスをテストで落とす。

日付: 2026-08-20

## ステータス

承認済み

## コンテキスト

[ADR-004](004-gateway-jwt-verification.md) で、JWT の署名検証は Gateway に一元化し、各サービスは Gateway が付け直したヘッダを信じてロール認可だけを行うと決めた。

この決定は「**Gateway を通らずにサービスへ到達できない**」ことを前提にしている。ところが IT1 の時点で、その前提を確かめる手段がどこにもなかった。サービスは 2 つ（authms・bookingms）だったため目視で足りていたが、IT2 以降で 6 サービスに増える。

前提が破れる経路は 2 つある。

- **ネットワークとして到達できてしまう**（kind の Service は namespace 内から直接引ける）
- **サービス側がヘッダの有無を確かめていない**。ヘッダが無ければロールの集合が空になるだけで、認可が不要なエンドポイントは素通りする

後者のほうが危険で、しかも気づきにくい。ロール検査を書いた画面は守られるが、書き忘れた 1 本が無認証で開く。名簿方式の検査は「載っていないもの」を通すため、載せ忘れたものほど漏れる。

## 決定

1. **共有ライブラリに `AuthenticatedUserFilter` を置き、全業務サービスが登録する。** ヘッダが無いリクエストは 401 で拒否する。サービスごとに書くと、書き忘れたサービスだけが無防備になる
2. **ヘルスチェック（`/actuator/health` 配下）は除外する。** 横断的な防御を一律適用すると、Kubernetes の liveness / readiness が 401 を受けて再起動ループに入る（IT1 で Gateway の JWT フィルタが同じ形で失敗した）
3. **登録漏れをメタテストで落とす。** 既存の `ArchitectureRuleCoverageTest` と同じ形で、業務サービス（gatewayms を除く全サービス）がこのフィルタを登録していることを、サービスのソースを走査して確認する。ここで gatewayms だけを除外リストに載せ、**除外リストに無いサービスは登録必須**とする（未登録を素通りさせない）
4. **ネットワーク側は Kubernetes の NetworkPolicy で塞ぐ。** ただしこれは多層防御の外側であり、アプリ側の検査（1〜3）を省く理由にはしない。開発環境（Heroku）は各サービスが個別の URL を持つため NetworkPolicy が使えず、アプリ側の検査だけが働く

### 代替案

- **各サービスの SecurityConfig で `anyRequest().authenticated()` を書く**: Spring Security の認証主体は Gateway が付けたヘッダから組み立てるため、結局ヘッダの有無を見る処理が要る。サービスごとの記述になり、書き忘れを検出できない
- **Gateway が共有秘密のヘッダを付け、サービスが照合する**: 秘密の配布と更新が要る。到達経路を塞ぐ NetworkPolicy と、ヘッダ必須の検査で足りると判断した
- **NetworkPolicy だけで担保する**: 開発環境（Heroku）では使えない。「本番だけ守られる」検査は、開発で壊したことに気づけない

## 影響

### ポジティブ

- ADR-004 の前提が、サービスが増えても検査で維持される
- 認可の書き忘れが「無認証で開く」ではなく「401」に倒れる

### ネガティブ

- サービス間の直接呼び出し（IT3 以降の ACL）でもヘッダを引き継ぐ必要がある。引き継ぎを忘れると自サービスの呼び出しが 401 になる
- ヘルスチェックの除外パスが増えたときに、除外の判断が 2 箇所（Gateway の JWT フィルタと本フィルタ）に分かれる

## コンプライアンス

- `AuthenticatedUserFilter` の登録漏れをメタテストが落とす
- 各サービスの統合テストで、ヘッダ無しの業務エンドポイントが 401 を返すことを検証する
- フィルタを外すとそのテストが赤になることを確認する（壊して赤の確認）
