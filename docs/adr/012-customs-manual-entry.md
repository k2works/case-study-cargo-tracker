# ADR-012: 税関と電子連携せず、通関結果を手入力で記録する

税関との電子連携は行わず、通関申告の結果は担当者の手入力で記録する（通関済でなければ引取不可）。

## コンテキスト

- UC21 は税関との電子連携を行わず担当者の手入力としているが、**この判断は ADR が未記録**と明記されている。リリース計画の Level 1 計画にも「税関と電子連携せず手入力とする判断を ADR に残す」がある。
- インセプションデッキは税関申告システムをスコープ外（連携は行うが申告業務自体は対象外）とし、フェーズ 3 の「外部連携強化」に税関を含む。
- 外部システムの API 仕様は不明で、AI が仮定してはならない（R-01）。

## 決定

**税関とは電子連携せず、荷役作業員が申告を登録し、追跡管理者が税関からの結果を手入力で通関状態（審査中・通関済・留置・不可）に反映する**。通関済でなければ引取荷役を拒否する（`Tracking` 集約の不変条件）。税関のポートは**定義しない**（連携が必要になったら、スタブと契約テストでポートから足す）。

### 変更箇所

- 通関申告は `Tracking` 集約の中に置く（引取の前提条件を 1 つの集約の不変条件にするため）。
- 留置のまま 3 日を超えたら追跡管理者に督促を通知する。

### 代替案

- **電子連携**：税関の API 仕様が不明で、フェーズ 3 の外部連携強化に先送りする（R-01）

## 影響

### ポジティブ

- 外部仕様を仮定せずに、通関の業務ルールをシステムで守れる。

### ネガティブ

- 担当者の転記の手間と誤りが残る。電子連携をフェーズ 3 で足すときに入力の経路が増える。

## コンプライアンス

- 引取は通関済でなければ拒否される（US29 AC-04）をドメインと画面の両方から検査する。
- 電子連携を導入する場合は、この ADR を置換する新しい ADR を作る。
