# ADR-008: 経路候補の費用は概算式で算出する

## ステータス

承認（2026-08-07 / IT4）

## コンテキスト

US08「経路候補を算出する」の受入基準は **「経路候補ごとに所要日数・経由港・費用・航海番号が
表示される」** と定めている。`ui_design.md` も候補テーブルに費用の列を置き、
「費用が無いと荷主に提案できない（提案時に最初に聞かれる）」と理由を書いている。

**しかし、費用を計算する材料がどこにも無い。**

| 必要なもの | 現状 |
| :--- | :--- |
| 運賃表（航路別・貨物種別別の単価） | 存在しない。テーブルも設計に無い |
| 航海ごとの運賃 | `voyage` テーブルにカラムが無い（`data-model.md`） |
| 港間の距離 | `location` は UN/LOCODE・名称・国コード・タイムゾーンのみ。座標を持たない |
| 船会社の運賃 API | ADR-006 により**外部連携は実装しない** |

`proposed_route.estimated_cost_value` は `NOT NULL` で既に存在するため、
**何らかの値を入れないと候補を 1 件も保存できない。**

選択肢は 3 つあった。

1. **運賃マスタを新設し、経路設計者が登録する。** 実際の運賃に最も近い。ただし
   US08 に運賃登録の受入基準は無く、**US24（航海スケジュール登録）の画面と
   マニュアルにも入力項目が増える**。IT3 で確定した成果に波及し、8SP の
   イテレーションに運賃マスタの CRUD が丸ごと乗る
2. **費用の列を出さない。** 受入基準に明記された項目であり、削るなら受入基準の
   変更が要る。**「提案時に最初に聞かれる」ものを出さない提案画面は使えない**
3. **概算式で算出する。** 材料が無いことを認め、持っている値（重量・所要日数）から
   概算を出す

## 決定

**費用は概算式でドメインが算出する。実際の運賃は扱わない。**

```text
概算費用 = 基準単価 × 重量（トン） × 所要日数 + 貨物種別の割増
```

判断の要点は 4 つある。

1. **概算であることを利用者に伝える。** 画面・マニュアルの両方に「概算」と明示し、
   単位を添える。**荷主に実額として渡ると業務上の事故になる。** 数字は、
   それが何であるかを添えて初めて情報になる
2. **単価と割増率はハードコーディングしない。** 設定値（`application.yml`）として
   外に出す。ソースを変えずに調整できることが、この式が暫定であることの証拠になる
3. **`FreightEstimator` をドメインサービスとして置く。** 費用の決め方は業務の関心事で
   あり、SQL やコントローラに置くと変更のたびに層をまたぐ
4. **候補の並び順は費用に依存しすぎない。** 推奨順は「期限を満たす → 直行 → 所要日数 →
   費用」の順であり、**概算値である費用は最後の基準に留める**。精度の低い数字を
   順位の主軸にしない

**ADR-006 との関係**: 外部連携を内部シミュレーションで代替する方針と同じ形である。
違いは、シミュレーションであることを**画面上でも明示する**点にある。輸送状態の
シミュレーションは利用者から見て「そういう動作」だが、**費用は利用者が金額として
読み取る**ためである。

## 何がどこで守るか

| 守るもの | 守り手 | 対象範囲（何を見ているか） |
| :--- | :--- | :--- |
| 単価と割増率をハードコーディングしない | **設定値**（`application.yml` の `freight`）＋ `RoutingDomainConfiguration` が読む | **値が設定から来ること**のみ。値そのものの妥当性は見ない |
| 費用の決め方をドメインに置く | **`FreightEstimator`**（ドメインサービス）＋ `RouteProposalDomainTest` | **ドメインサービスの単体テスト**のみ。画面に出るまでの経路は見ない |
| 候補の並び順で費用を主軸にしない | **`RouteSearchTest`**（推奨順は「期限 → 直行 → 所要日数 → 費用」） | **検索結果の並び順**のみ |
| **画面とマニュアルに「概算」と明示する** | **守らない。** | **検査の外。** 表示文言を検査しておらず、ラベルを消しても落ちない |

## 影響

### 実装

- `routing/domain/model/FreightEstimator`（ドメインサービス）
- 単価・割増率は `app.freight.*` として `application.yml` に置く
- `proposed_route.estimated_cost_value` / `estimated_cost_currency` に保存する

### 画面・マニュアル

- 経路割り当て画面の費用の列見出しを「**費用（概算）**」とし、注記を添える
- マニュアル「05. 航路管理」の注意・補足に**実額ではないこと**を書く

### 今後

**運賃マスタが必要になったら、この ADR を差し替える。** 精算（Release 2.0 / US21
輸送料金を算出する）では実額が要るため、その時点で再検討する。本 ADR が扱うのは
**経路候補を比べるための相対的な目安**であり、請求に使う金額ではない。
