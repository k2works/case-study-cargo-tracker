# ADR-006: 外部システム連携は実装せず内部シミュレーションで代替する

5 つの外部システム連携を実装対象から外し、内部シミュレーションで代替する。ACL ポートの定義も併せて縮小する。

日付: 2026-08-06

## ステータス

承認済み

## コンテキスト

外部システム連携の有無について、設計ドキュメント群の前提が二分していた。

| 立場 | ドキュメント | 記述内容 |
| :--- | :--- | :--- |
| 連携あり | `tech_stack.md` | 外部 5 システム + WireMock を採用技術として列挙 |
| 連携あり | `domain-model.md` | 外部 5 システムをすべて出力ポート（`ExternalRoutingServicePort` 等）として抽象化 |
| 連携あり | `non_functional.md` | タイムアウト 3 秒 / リトライ 3 回 / サーキットブレーカー 5 回・60 秒を規定 |
| 連携なし | `test_strategy.md` | 「外部システムとの HTTP 連携は実装していない…WireMock で検証するテストは現時点で対象外」 |

**存在しない連携のために ACL・タイムアウト・リトライ・サーキットブレーカーの設計コストを払っている**状態だった。

加えて、BC 間 ACL ポートの一覧も 3 文書で食い違っていた。

| ドキュメント | 挙げているポート |
| :--- | :--- |
| `architecture_backend.md` | `CargoSnapshot`（Handling → Booking） |
| `domain-model.md` | `ShipperExistenceChecker`（Booking → Shipper） |
| `test_strategy.md` | `TrackingPort` / `ShipperDiscountPort` / `BookingSettlementPort` |

ポート名はコンテキスト間の契約そのものであり、三者三様であることは契約が定まっていないことを意味する。

## 決定

**外部システム連携は実装せず、内部シミュレーションで代替する。**（`test_strategy.md` の現行方針を全社的な決定として確定させる。）

あわせて次を決める。

1. **外部 ACL ポート 5 件（`ExternalRoutingServicePort` 等）を設計から削除する。** 実装しないものをポートとして定義し続けると、「定義済みだが誰も検証しない要件」が残り続ける
2. **外部連携向けの非機能要件（タイムアウト 3 秒 / リトライ 3 回 / サーキットブレーカー）を `non_functional.md` から削除する。** 対象が存在しない要件は達成も未達も判定できない
3. **BC 間 ACL ポートの一覧は `domain-model.md` に集約し、他文書は参照に留める。** 現存する BC 間ポートを `domain-model.md` に一覧化し、`architecture_backend.md`・`test_strategy.md` の個別列挙を削除する
4. **WireMock は採用しない。** 契約テストの対象がないため。将来外部連携を実装する場合の導入手順は `test_strategy.md` に記載済みの復帰手順を維持する

判断根拠は次のとおり。

- 本プロジェクトはケーススタディであり、外部システムの実体が存在しない。実体のない連携先に対する契約テストは、契約が正しいことを何も保証しない
- YAGNI に従い、必要になった時点で ADR を改訂して導入する。`test_strategy.md` に復帰手順が既に書かれているため、判断は可逆である

### 変更箇所

- `tech_stack.md`: 外部 5 システムの行と WireMock を削除する。「選定理由の総括」の第 2 項（外部システム分離）を内部シミュレーション方針に書き換える
- `domain-model.md`: 外部 ACL ポート 5 件を削除する。BC 間 ACL ポートの一覧節を新設し、現存するポートを列挙する
- `non_functional.md`: 外部システム連携 5 件の記述と、それに紐づくタイムアウト / リトライ / サーキットブレーカーの規定を削除する
- `architecture_backend.md`: 外部クライアントの図示を削除する。ACL ポートの個別列挙を `domain-model.md` への参照に置き換える
- `test_strategy.md`: ACL ポートの個別列挙を `domain-model.md` への参照に置き換える。将来の WireMock 復帰手順は維持する

### 代替案

| 代替案 | 却下理由 |
| :--- | :--- |
| 外部連携を実装し WireMock で契約テストする | 連携先の実体が存在しないため、スタブは自分で書いた期待を自分で検証するだけになり、契約を保証しない |
| ポート定義だけ残し実装を先送りする | 「定義済みだが誰も検証しない要件」が残る。設計ドキュメントの記述量に対して保証される品質が伴わない状態は、読み手に誤った安心を与える |

## 何がどこで守るか

| 守るもの | 守り手 | 対象範囲（何を見ているか） |
| :--- | :--- | :--- |
| WireMock / Spring Cloud Contract を採用しない | **ビルド**（`verifyProductionDependencies`） | `runtimeClasspath` の**依存**のみ |
| 外部へ HTTP を出さない | **守らない。** | **検査の外。** 使用箇所が 0 件であることを見ている検査が無い |
| 外部 ACL ポートを定義しない | **守らない。** | **検査の外。** `domain-model.md` の一覧と実体を突き合わせる検査が無い |

> **2 件を「守らない」と書いた。** どちらも「使っていないものを使い始めたら落ちる」形の
> 検査であり、書けないわけではない。**書いていないだけである。** 外部連携の実装が
> 議題に上った時点（ADR-006 の改訂時）に検査を足す。それまでは、
> **守っていないことを名前で残す**。

## 影響

### ポジティブ

- 実体のない連携に対する ACL・レジリエンス設計のコストがなくなる
- 「実装していないものが設計に載っている」ことによる、設計ドキュメントの信頼性低下が解消する
- BC 間 ACL ポートの正典が `domain-model.md` に一本化され、契約が定まる

### ネガティブ

- 将来、実際の外部連携が必要になった時点で ACL とレジリエンス設計をやり直すことになる。ただしその時点の実際の連携先仕様に基づいて設計するほうが、想像で書いた設計より確度が高い
- 内部シミュレーションで動くことは、実連携で動くことを保証しない。経路算出（`RoutingService`）が内部シミュレーションである点は、ドキュメント上で明示し続ける必要がある

## コンプライアンス

- `domain-model.md` に `ExternalRoutingServicePort` を含む外部 ACL ポートの記述が残っていないこと
- 依存に `spring-cloud-contract-wiremock` が存在しないこと
- BC 間 ACL ポートを列挙している箇所が `domain-model.md` の 1 節のみであること（他文書は参照のみ）
- 内部シミュレーションであるサービスに、その旨がドキュメントとコードコメントの両方で明記されていること
