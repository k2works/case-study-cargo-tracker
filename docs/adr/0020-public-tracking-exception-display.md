# 0020 公開追跡画面における例外情報の表示方針

公開追跡画面 (`/public/tracking/:trackingNumber`、未認証アクセス可) で、貨物に発生した例外イベント (Delay / Damage / Lost / CustomsHold) をどの粒度で表示するかを決定する。

日付: 2026-06-24

## ステータス

2026-06-24 承認・適用 (IT8 タスク 0.14)。IT8 0.8 (Delay UI) 実装時にこの ADR に従う。

## コンテキスト

IT7 実装レビュー (`docs/review/it7_implementation_review_20260623.md`) で **H8 (高優先指摘 8 件目、業務代表者観点)** として「公開追跡画面に例外情報を表示すべきか不明確」が指摘された。

### 公開追跡画面の特性

- **URL**: `/public/tracking/:trackingNumber`（未認証アクセス）
- **対象ユーザー**: 荷主・荷受人・取引先（追跡番号を共有された全関係者）
- **表示情報** (IT7 時点): 追跡番号、貨物概要、現在の輸送ステータス、寄港地履歴、到着予定日
- **未表示**: 料金、割引、内部対応状況、担当者氏名、例外詳細

### 業務代表者の懸念事項

1. **過剰開示リスク**: 例外詳細（紛失場所、損傷品名、税関保留理由）を未認証ユーザーに表示すると、機密情報漏洩・取引先信頼低下を招く可能性
2. **情報遮断リスク**: 例外発生時に何も表示しないと、荷主が「サイレント遅延」と認識し信頼低下を招く可能性
3. **対応状況の責任範囲**: 「対応中」と表示すべきか、社内対応の状態 (調査中 / 補償交渉中 / 完了) を公開すべきか曖昧

### 例外種別と業務影響

| ExceptionType | 業務影響 | 公開表示の妥当性 |
| :--- | :--- | :--- |
| Delay (遅延) | 到着予定日の変更 | **公開すべき**（業務に直結） |
| Damage (損傷) | 受領可否・補償交渉 | 一部公開（発生事実のみ） |
| Lost (紛失) | 補償交渉・代替手配 | 一部公開（発生事実のみ） |
| CustomsHold (税関保留) | 通関対応必要 | 公開（受取人による対応が必要） |

## 決定

**段階的開示方針を採用する**: ステータスバッジ + 簡易メッセージ + 連絡先誘導 のみ公開し、対応詳細・原因分析・補償状況は社内画面 (`/admin/tracking/:trackingNumber`) のみで開示する。

### 公開追跡画面 (`/public/tracking/:trackingNumber`) の表示仕様

#### 例外がない場合（IT7 までと同じ）

```
[追跡番号: TRK-000001]
状態: 輸送中
現在地: シンガポール港 (経由)
到着予定: 2026-10-15
```

#### 例外がある場合（IT8 で追加）

```
[追跡番号: TRK-000001]
状態: 輸送中 ⚠️ 注意事項あり

⚠️ 遅延発生
   現在の到着予定: 2026-10-18（当初予定: 2026-10-15、3 日遅延）
   詳細はお問い合わせください: support@example.com

現在地: シンガポール港 (経由)
```

### 表示する情報（公開）

| 項目 | 表示有無 | 例 |
| :--- | :---: | :--- |
| 例外種別バッジ | ✅ | "⚠️ 遅延発生" / "⚠️ 損傷発生" / "⚠️ 紛失調査中" / "⚠️ 税関保留中" |
| 発生日時 | ✅ | "2026-10-12 14:30 JST" |
| 業務影響の要約 | ✅ | "到着予定が 3 日遅延" / "通関対応が必要です" |
| 改訂後 ETA（Delay のみ） | ✅ | "2026-10-18" |
| 問い合わせ先 | ✅ | "support@example.com" |

### 表示しない情報（社内画面のみ）

| 項目 | 理由 |
| :--- | :--- |
| 例外発生の原因詳細 | "天候不良" "船舶故障" "コンテナ落下" 等は調査中の情報を含むため公開リスク |
| 担当者氏名 | 個人情報保護 |
| 補償交渉の進捗状況 | 取引先間交渉に影響 |
| 損傷品の具体的内訳 | 商品機密・取引先機密 |
| 紛失場所の特定情報 | 調査中段階での誤った確定情報リスク |
| 対応ステータス (調査中 / 補償交渉中 / 完了) | 社内ワークフローを露出させない |

### CustomsHold の特別対応

税関保留は **受取人による行動が必要** なため、公開画面に「税関対応のため受取人様による書類提出が必要です」と明示し、受取人への直接通知（IT9+ で実装予定）を計画する。IT8 ではバッジ表示と問い合わせ先誘導のみ。

## 影響

### iteration_plan-8.md 改訂

タスク 0.8「公開追跡画面に Delay 例外表示追加」の実装内容を以下に具体化:

- Twirl テンプレート `app/views/public/tracking/show.scala.html` に例外表示ブロック追加
- `TrackingQueryService.findPublic(trackingNumber): PublicTrackingView` が `List[PublicExceptionView]` を含むよう拡張
- `PublicExceptionView(exceptionType, occurredAt, businessImpactMessage, revisedEta: Option[LocalDate], contactEmail)` の DTO 新設
- ExceptionType 別の表示テンプレート (`fragments/public/_delay_exception.scala.html` 等) を Delay / Damage / Lost / CustomsHold の 4 種類で用意

### ui_design.md 改訂（0.12 で実施）

- 公開追跡画面ワイヤーフレームに「例外バッジ + 簡易メッセージ + 連絡先」セクション追加
- 社内追跡画面 (`/admin/tracking/:trackingNumber`) との表示差分マトリクスを追加

### セキュリティテスト

- Playwright E2E で「公開画面から内部詳細フィールドが返ってこない」テストを追加
- `PublicTrackingController` のレスポンス DTO に内部情報（原因、担当者、補償状況）が含まれないことを ScalaTest で assert

### 帰結

- **業務透明性向上**: 荷主・荷受人が例外発生を即座に認識可能、サイレント遅延クレーム削減
- **機密保護**: 原因・補償・担当者情報の外部漏洩を防止
- **問い合わせ集中の懸念**: 例外バッジ表示で「support@example.com」への問い合わせが増加する可能性。IT9+ で受取人別通知メールを追加して問い合わせを分散化する計画
- **新規 DTO 追加コスト**: PublicTrackingView の拡張により Query Service と Twirl テンプレートの双方に変更が入る（IT8 0.8 で吸収）

## コンプライアンス
