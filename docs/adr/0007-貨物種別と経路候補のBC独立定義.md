# ADR-0007: 貨物種別・経路候補の BC 独立定義

同一概念に見える型（貨物種別 CargoType、経路候補）を、境界づけられたコンテキスト（BC）ごとに独立して定義し、共有カーネルには昇格しない。共通化は変更頻度・語彙が揃った時点で再判断する。

日付: 2026-07-09

## ステータス

2026-07-09 承認されました

## コンテキスト

IT2・IT3 の実装で、複数 BC に「同名・類似概念」の型が現れた。

- **CargoType（貨物種別）**: Booking Context（`CargoTracker.Booking.Domain.Model.CargoType`）と Estimation Context（`CargoTracker.Estimation.Domain.Model.CargoType`）に、いずれも General / Hazardous / Refrigerated を持つ列挙型が独立に存在する。domain-model.md は当初「Estimation Context（Booking Context と共通）」と記述していた。IT3 では Routing Context も対応貨物種別（`SupportedCargoType`）を独自に持つ。
- **経路候補**: Estimation Context の `RouteCandidate`（見積用）と、IT3 Routing Context の `CandidateRoute`（経路設計者向け・US08）が、いずれも「ルート候補」を表す。

IT2 開発成果物レビュー（H4）および IT2 ふりかえり Try（T3）で、この二重定義を放置せず ADR で判断基準を明文化するよう求められた。domain-model.md の「共通」記述とコード（BC 独立）が矛盾している状態も是正が必要だった。

## 決定

**同名・類似概念でも、BC ごとに独立して型を定義する（共有カーネルへ昇格しない）。**

1. **CargoType は各 BC が独立定義する**。Booking・Estimation・Routing はそれぞれ自 BC の名前空間に貨物種別を持つ。DB では `VARCHAR` の列挙値（`GENERAL`/`HAZARDOUS`/`REFRIGERATED`）として保持し、値の互換性は文字列表現で担保する。
2. **経路候補は BC ごとに別型**とする。Estimation の `RouteCandidate`（見積の文脈）と Routing の `CandidateRoute`（経路設計の文脈）は別概念として扱い、相互参照・共有しない。経路候補算出ポートも Estimation の `IExternalRoutingServicePort`（見積用）と Routing の `IRouteCandidateService`（経路設計用）に分離する。
3. **共有カーネルは最小に保つ**。真に全 BC 横断で同一の概念（`Location`＝UN/LOCODE、`ShipperId`）のみを `CargoTracker.Shared.Domain.Model` に置く。貨物種別・経路候補は各 BC のライフサイクル・語彙が異なるため昇格しない。
4. **ArchUnit で境界を守る**。各 BC は他 BC のドメイン型に依存しない（Booking→Estimation・Routing→Booking/Estimation/Shipper の直接参照禁止）。BC 間連携は ACL（`ShipperExistenceChecker`・`IBookingLookup`）で行う。

### 共通化の再判断トリガー

以下がすべて揃った時点で、共有カーネルへの昇格を新 ADR で再判断する。

- 複数 BC の同名型が**同一の値集合・不変条件・変更頻度**を持つことが安定して観測される。
- 一方の変更が他方に常に追随する（独立して変わらない）ことが確認される。

現時点では各 BC の貨物種別・経路候補は文脈依存で変わり得るため、独立を維持する。

### 代替案

- **共有カーネルへ昇格（共通 CargoType）**: BC 間結合を生み、一方の都合の変更が全 BC に波及する。DDD の BC 独立原則に反する（却下）。
- **一方の BC の型を他 BC が参照**: 依存方向が生まれ ArchUnit ルールに違反（却下）。

## 影響

### 良い影響

- BC が独立して進化でき、変更の波及が閉じる（変更を楽に安全にできる）。
- 設計ドキュメントとコードの矛盾が解消する（domain-model.md を「BC 独立」に整合）。

### 悪い影響

- 同名型の重複定義が存在し、初見では「共通化漏れ」に見える（本 ADR とコードコメントで意図を明示して緩和）。
- BC 間で貨物種別を受け渡す際は文字列表現での変換が必要（ACL 境界で吸収）。
