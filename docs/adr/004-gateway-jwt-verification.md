# ADR-004: JWT の署名検証は Gateway に一元化し、各サービスはロール認可のみを行う

JWT の署名検証を API Gateway（gatewayms）に一元化し、各マイクロサービスはクレームのロールに基づく認可判定のみを行う。

日付: 2026-08-19

## ステータス

承認済み

## コンテキスト

マイクロサービス構成（7 サービス）で認証・認可をどこで行うかには複数の選択肢がある。バックエンドアーキテクチャ設計は「JWT の検証は API Gateway で実施し、各マイクロサービスは JWT のクレームからロール情報を取得して認可チェックする」と定めているが、この分担は次の理由で壊れやすい。

- Gateway は WebFlux、各サービスは Spring MVC で技術スタックが異なり、**ArchUnit ではサービス境界をまたぐ規則を守れない**
- 各サービスに Spring Security を入れると、既定で署名検証まで行う構成に流れやすく、鍵の配布・ローテーションが 7 サービスに拡散する
- 逆に分担を明文化しないと「Gateway が検証しているから」とサービス側の認可（403）が省略され、Gateway をバイパスした内部呼び出しで権限確認が消える

リリース計画レビュー（2026-08-19、指摘 M14）で「ADR に落とさない規則は守られない」として起票が求められた。

## 決定

1. **署名検証（真正性の確認）は gatewayms のみが行う。** JWT の秘密鍵/公開鍵を保持するのは authms（発行）と gatewayms（検証）に限定する
2. **各マイクロサービスは署名を再検証しない。** Gateway が転送時に付与する検証済みクレーム（ユーザー ID・ロール）を信頼し、**ロールに基づく認可判定（403）のみを行う**
3. **公開経路（認証不要）は gatewayms の public-paths 設定だけが決める。** 一覧に無い経路は必ず認証を要求する（名簿方式は未登録を素通りさせない）
4. この分担は次のテストで固定する
   - Gateway: 保護経路が未認証で 401 になること・public-paths のパターンが業務 API まで素通りさせないことの破壊検証
   - 各サービス: 「サービス側は署名検証を行わずロールのみを見る」ことを保証する統合テスト（不正署名でもロールが正しければ処理される = 署名はサービスの関心事でないことの検証）
   - 認可: 他ロールのクレームで 403 になることを、認可を外すと赤になる形で検証

### 代替案

- **各サービスでも署名を再検証する（ゼロトラスト寄り）**: 内部ネットワークの侵害に強いが、鍵配布が 7 サービスに広がり、ローテーションの運用コストが高い。本システムの内部通信はプライベートネットワーク（kind / Heroku / VPC）内であり、初期フェーズでは過剰防衛と判断して却下。将来必要になれば本 ADR を置換する
- **認可も Gateway に集約する**: エンドポイント × ロールの表を Gateway が持つ形。業務的な認可（自分の予約だけ見られる等）はドメイン知識を要するため Gateway に置けず、二重管理になる。却下
- **Spring Security を各サービスにフル導入**: 既定構成の吸引力で署名検証が分散し、本決定と矛盾する構成が混入しやすい。サービス側はクレーム読み取りの薄いフィルタのみとする

## 影響

### ポジティブ

- 鍵管理が authms / gatewayms に閉じ、ローテーションが 2 箇所で済む
- サービス側の認可テストが「ロール → 403」の単純な形になり、破壊検証を書きやすい
- 公開経路の判断が 1 箇所（public-paths）に集まり、監査しやすい

### ネガティブ

- Gateway をバイパスする直接アクセスに対して署名の防御が無い。ネットワーク層（kind の Service / Heroku のアプリ分離 / VPC のセキュリティグループ)で Gateway 以外からの到達を制限することが前提になる
- Gateway が単一障害点かつセキュリティ境界になる。Gateway の変更には破壊検証の実行を必須とする

## コンプライアンス

- IT1 で上記 3 種のテストを実装する（iteration_plan-1.md タスク 1.4・4.3）
- 各サービスに JWT ライブラリ（jjwt 等）の依存が追加されていないことを依存関係で確認する（署名検証の混入検知）
- public-paths の変更は必ず破壊検証（過剰許可の検出テスト）とセットでコミットする
