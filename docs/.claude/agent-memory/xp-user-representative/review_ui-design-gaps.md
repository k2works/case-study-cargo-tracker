docs/design/ui_design.md の業務視点レビューで検出した欠落（2026-07-04 時点）。

**画面が存在しない業務機能（実装されないと業務が止まる）**:
1. 例外登録画面がない — 追跡管理者の遅延(US19)・破損紛失(US20)登録、対応内容入力、荷主通知の導線なし。追跡詳細は EXCEPTION を読み取り表示するのみ
2. 荷主登録画面がない — 営業担当者の US02/US03（RegisterShipperCommand は存在）
3. 航海スケジュール登録・更新画面がない — 経路設計者の US24/US25。航路一覧は「閲覧専用・管理機能から」と書くが管理画面が未定義
4. 貨物状態手動更新画面がない — 追跡管理者の US17（出港・入港等）
5. 引取作業の荷受人確認（署名/確認コード）入力欄がない — US16。荷役登録に CLAIM 種別はあるが確認フィールドなし
6. 経路設計者ワークフロー（航海検索→候補算出→条件調整）の画面がほぼない — UI は営業担当者の単純な「経路割り当て」に集約されており US07-US11 の実体がない
7. 経路通知(US12)・料金の例外調整(US21 減額/補償)・未払い通知(US23) の導線が薄い

**US 番号の不整合（トレーサビリティ defect）**:
ui_design.md 画面一覧の「対応 US」列が user_story.md の US 番号と大きくずれている。例: 予約一覧に US02/03（実際は荷主登録）、荷役登録に US10/US11（実際は経路条件調整/紐付け）、追跡入力に US13（実際は予約確定）。UI は旧番号体系に対して書かれた疑い。
