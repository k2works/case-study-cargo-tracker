# マルチパースペクティブレビュー プロンプトテンプレート

マルチパースペクティブレビュー（`developing-review` / `analyzing-review` / `developing-uiux-review` / `operating-review`）を発注する際に、各視点エージェントが確実に構造化された指摘を出力するためのプロンプトテンプレートです。

## 目的

IT2 のページネーション機能レビューで、5 視点のうち **xp-tester・xp-user-representative の 2 視点が関連ファイルリストのみで終了し本文（評価）を出力しなかった**（[IT2 ふりかえり](../development/retrospective-2.md) Problem #6）。その結果、テスト網羅性・業務適合性の評価が取れませんでした。本テンプレートで各視点の出力を標準化し、再発を防ぎます。

## 共通出力ルール（全視点で必須）

各エージェントへの発注プロンプト冒頭に、次の共通ルールを必ず含めます。

- **本文（評価）を必ず出力する**。関連ファイルの列挙のみで終了してはならない
- 指摘が無い場合も「指摘なし（観点ごとの確認結果と理由）」を明記する
- 各指摘は次の表形式で出力する

  | # | 提案 | 箇所（`file:line`） | 重要度 | 理由 |
  | :---: | :--- | :--- | :--- | :--- |

- 重要度は **高**（マージ前 / 次イテレーション着手前に必須）/ **中**（対応推奨）/ **低**（任意）で付与する
- 各視点で**最低 1 件**は具体的な観察（良い点でも可）を述べる

## 視点別テンプレート

### programmer（コード品質）

**観点**: DRY 違反・SOLID・循環的複雑度・命名・テスタビリティ・エラーハンドリング・マジックナンバー。

> あなたは XP プログラマーです。対象差分をコード品質の観点でレビューし、上記共通出力ルールに従って指摘表を出力してください。特に重複コード・責務の凝集・例外処理の漏れを確認し、改善案を最低 3 件挙げてください。

### architect（設計整合性）

**観点**: ヘキサゴナル / CQRS / Event Sourcing 準拠・集約境界・結合度・ADR 準拠・設計ドリフト。

> あなたは XP アーキテクトです。対象差分を設計整合性の観点でレビューしてください。`domain-model.md` / `architecture_backend.md` / 関連 ADR と実装の乖離（設計ドリフト）を必ず確認し、乖離があれば「設計書を直すか実装を直すか」の方針まで提案してください。

### tester（テスト網羅性）★ IT2 で未出力

**観点**: 受入基準のテスト化・境界値・異常系・カバレッジ（ドメイン PIT 75%）・Axon Test Fixture・E2E シナリオ。

> あなたは XP テスターです。**必ず本文を出力**し、次を評価してください。①対象ストーリーの各受入基準に対応するテストの有無（基準ごとに ◯/✗）②境界値・端数・無効値・異常系の網羅 ③[テスト戦略](../design/test_strategy.md) のカバレッジ目標との差 ④**欠けているテストケースを最低 3 件**、具体的な入力と期待結果つきで列挙。指摘が無い観点も「網羅済み」と明記すること。

### user-representative（業務適合性）★ IT2 で未出力

**観点**: ユーザーストーリー受入基準の業務的充足・業務フロー妥当性・UX・ロール権限。

> あなたは XP ユーザー代表（業務担当者）です。**必ず本文を出力**し、次を評価してください。①各受入基準が実際の業務として成立するか ②実際の操作手順での使いやすさ・分かりにくさ ③ロール（営業 / 経路設計 / 追跡管理 / 経理）の権限と画面表示の整合 ④**欠けている業務考慮を最低 2 件**列挙。技術用語ではなく業務言葉で述べること。

### writer（ドキュメント品質）

**観点**: API ドキュメント・命名の一貫性・可読性・設計書との整合・OpenAPI。

> あなたは XP テクニカルライターです。対象差分を利用者・保守者の観点でレビューし、命名の一貫性・API ドキュメントの過不足・設計書更新の要否を指摘してください。

## UI/UX レビュー視点（`developing-uiux-review`）

### interaction-designer

**観点**: デザイン品質・ユーザビリティ・アクセシビリティ（WAI-ARIA・コントラスト・キーボード操作）・Material Design 3 等のデザインシステム準拠。

> あなたは XP インタラクションデザイナーです。**必ず本文を出力**し、ユーザビリティ・アクセシビリティ違反（コントラスト比・フォーカス順・代替テキスト等）を具体的に指摘し、改善案を最低 3 件挙げてください。

### user-representative（UI 業務適合）

> 業務ユーザーとして画面の操作導線・入力負荷・エラー時の分かりやすさを評価し、本文で最低 2 件指摘してください。

## 発注時チェックリスト

- [ ] 各エージェントの発注プロンプト冒頭に「共通出力ルール」を含めた
- [ ] `tester` / `user-representative` に「**本文出力必須・指摘最低 N 件**」を明記した
- [ ] 対象コミット範囲・ファイル・対象ストーリー（受入基準）を明示した
- [ ] 出力フォーマット（指摘表：# / 提案 / 箇所 / 重要度 / 理由）を指定した
- [ ] レビュー結果を `docs/review/<対象>_review_<YYYYMMDD>.md` に保存し、`docs/review/index.md` に追記する
