# IT2 実装 マルチパースペクティブレビュー（2026-07-28）

対象コミット範囲: `f0d4d420..HEAD`（US04/US05/US06 貨物予約、Booking Context、Booking→Shipper の ACL、DIP/privacy 負債返済）。5 つの XP 視点で並列レビューを実施した。

## サマリー

- **クローズ前対応済み（高）**: US06 引き渡しの非アトミック更新、重量空文字の内部例外露出、受入基準の未検証テスト（US06 通知・ファサード分岐・ACL アダプタ）、ADR-0003 の設計正典同期（ShipperId VO 削除）、ui_design のロール/フィールド語彙統一（T6）。
- **次イテレーション対応（Try に反映）**: US05 動的表示の JS テスト（capybara-playwright）、荷主 ID 数値入力→荷主名選択 UX、ドメイン層 AR 禁止 RuboCop cop（T2）、SonarQube 導入（T8）、Cargo.reconstitute 分離、公開ビュー生成の重複解消。

## 視点別指摘と対応方針

### テスター（テスト品質）

- **対応済み（高）**: US06 経路設計依頼通知の spy 検証、CargoBookingService の `:ok/:not_found/:invalid` 分岐 spec、ACL アダプタ委譲 spec、重量空文字メッセージ spec を追加。
- **次 IT（高）**: US05 の「種別選択で入力欄が表示」は rack_test では JS 未実行のため未検証 → capybara-playwright の `:js` driver で検証（Try）。なお「必須」制約はサーバ側で担保・テスト済み。
- **次 IT（中）**: US04「見積整合性」（US01 依存）・寸法/個数/希望引渡日・US06「不備修正フロー」は IT2 スコープ外として計画に明記（後続 IT）。冷凍の system spec 非対称も JS テストと同時に補完。
