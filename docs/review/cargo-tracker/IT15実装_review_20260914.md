## 良い点（統合）

- **陸揚げ地の判定を `DischargeCandidates` 1 本に寄せ、集約と読み口の両方が呼んでいる。** `DischargeCandidatesTest#everyCandidateIsAccepted` が候補全件を集約の断る側に通しており、「画面に出ているのに押すと断られる港」を構造で消している（programmer・tester が独立に挙げた）
- **`CancellationRoundTripIT` が 3 つの購読先を 1 本で見ている。** 発行側ではなく購読側の表を見ており、どれか 1 つが欠ければ赤くなる。承認だけでは閉じない／指定港の荷降しで閉じる、も同じ本で判別している
- **料率表の名簿が手書きでない。** `RateTableParityTest` が `BookingStatus` の列挙から回すので、状態を足したときに「名乗り出ない漏れ」が起きない
- **`Outcome` と `FeeOutcome` を別の sealed interface に分け、`default` を置かずに受けている。** 種類を足すとコンパイルが赤になる
- **入口が 1 つ。** 営業は状態を意識せず同じ場所から申し出るだけで、即時か申請かは集約が決める。画面はボタンの文言だけを変える
- **承認しても追跡を閉じない**という業務上いちばん誤解されやすい判断が、画面の説明文・一覧の見出し・マニュアルの 3 か所で同じ言葉で書かれている
- **`.feature` とステップ定義が同じ変更で揃っている**（IT14 の「定義 0 件で緑」を繰り返していない）。しかも状態を書き換える裏口を作らず、契約イベントを BC の入口から流している

## この IT で分かったこと

- **層が全部緑でも、業務は回らないことがある。** 高 11 件のうち 4 件は「記録はあるのに読み口が無い」形で、集約・投影・往復テスト・クラスタ E2E がすべて緑のまま残っていた。クラスタ E2E ですら、**追跡番号を持って API を直接叩いた**ので荷役の穴を踏まなかった
- **名簿方式の検査は、次に足すものを守らない。** 認可の穴は、同じ形の実測がコメントに残っている場所で再発した。名簿に足すのではなく、**名簿そのものを宣言から数え上げる**検査に変えた
- **正典が実装より先に正しいことがある。** 却下の知らせも陸揚げ待ちも、`ui_design.md` には書かれていた。正典と実装の突き合わせを、クローズのレビューまで遅らせない形が要る（Try 候補）
