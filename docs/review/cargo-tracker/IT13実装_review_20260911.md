## いちばん重い指摘：検査そのものが走っていなかった

**Try T8 で置いた規約検査 3 本が、1 件も実行されていませんでした**（テスター #1）。`shared/build.gradle.kts` に足した入力宣言のパスが 1 つ上の階層を指しており（`../../frontend/src`）、Gradle が `Test` タスクの構成で失敗して**テストに到達する前に落ちていた**。しかも `:shared:build` を回したときの赤を「カバレッジの調整中」と読み違え、そのまま進めていました。

**その陰で、実際に 1 件すり抜けていました。** 受入基準の表が名指しした `BillingReactionHandlerTest` はリポジトリに存在せず（実物は `...IT`）、「書いただけの検査」を捕まえるはずの検査が空振りしていたのです。IT12 のレビューで懸念されたことが、そのままの形で起きました。

**直したあと、その検査が最初の仕事として `BillingReactionHandlerTest` と `BillingReplayIT` の 2 件を赤で出しました。**

## 評価すべき点（記録として）

- **係数を 1 つずつ動かす検査**（`FreightChargeCalculatorTest`）。区間の「足す／掛ける」の取り違え、重量係数の途中丸めを、それぞれ 1 本だけ赤にする形で固定できている
- **判定をテスト側に書き直していない**。`RateTableConfigurationIT` は起動済みアプリの料率とフィクスチャを突き合わせ、`DiscountPolicyTest` は本番の述語（`ShipperType#discountable`）を回している
- **クラスタ E2E でしか出ない欠陥を 2 件捕まえ、見つかった場所に回帰検査を置いた**（請求書 ID の桁あふれ・調整明細の重複）
- リプレイ安全性（算出明細は入れ直し、調整は元イベントで一意、区間は消して入れ直し）が 3 か所とも効いている
