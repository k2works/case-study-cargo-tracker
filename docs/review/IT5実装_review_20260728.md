# IT5 実装マルチパースペクティブレビュー統合レポート

対象: US14/US15/US16/US17（Tracking Context・Handling Context の新設）と負債返済枠（reconstitute 分離・legs 条件置換・購読冪等ガード・多区間フォールバック・差分確認）。
5 視点（programmer / tester / architect / technical-writer / user-representative）で並列レビュー。全対象 spec は green（287 例）。

## エグゼクティブサマリー

BC 独立性（tracking/handling→booking の一方向・公開 API 射影＋プリミティブ Hash イベントのみ・Packwerk 違反ゼロ）、`reconstitute` 分離、`install_once` 冪等ガード、悲観ロックが一貫して適用され、設計意図が明快。構造破綻級の欠陥はない。一方で **UX（MISROUTED 警告の見せ方・CLAIM 動的フィールド）**、**状態機械の不変条件（TrackingStatus 遷移ガード不在・Booking/Tracking の乖離）**、**BC 越境副作用の原子性とテスト網羅**に高優先の指摘が集中した。

## 高優先度の指摘と対応方針

| # | 視点 | 指摘 | 対応 |
|:--|:--|:--|:--|
| H1 | user-rep/tester/tw | US15 MISROUTED 警告が成功トースト（notice・緑）で表示され、現場で異常を見落とす | **対応**: 警告を `flash.alert`（警告スタイル）で分離表示 |
| H2 | user-rep/tw/tester | US16 CLAIM の荷受人確認フィールドが常時表示・Stimulus 未実装・dangling data 属性 | **対応**: Stimulus で CLAIM 選択時のみ表示に |
| H3 | tester/architect | TrackingStatus/BookingStatus に順序不変条件がなく、RECEIVE 直後の CLAIM で両状態が乖離 | **対応**: CLAIM は IN_TRANSIT（積込済）を前提とする precondition を RegisterHandlingActivity に追加 |
| H4 | tester | `handling_activity_registered` の 3 ハンドラ（追跡/予約/通知）の副作用を 1 イベントで同時検証していない（荷主通知永続化が未 assert） | **対応**: 3 効果を検証する結合 spec を追加 |
| H5 | tw | ui_design:118 に未実装ルート（GET /tracking/:tn/status → trackings#status）が残存・173 行のルート構造が実装と乖離 | **対応**: ui_design を実装（PATCH /tracking/:tn/status）に整合 |

## 良い点

- 越境が公開サービス（CargoBookingService・CargoSnapshot 射影）とプリミティブ Hash イベントに徹底し ADR-0001/0003 に忠実。tracking/handling→booking の一方向依存で循環なし・Packwerk 違反ゼロ。
- イベント発行がアプリサービスのコミット後・購読側例外は非伝播（ADR-0002）。`install_once` 冪等ガードで多重購読防止とテスト分離を両立。
- 値オブジェクトの生成時検証＋freeze＋値等価、`reconstitute` による復元時再検証回避の分離が明快。
- legs churn 回避（T25）・悲観ロック RMW・購読ポリューション対策（rails_helper の reset!→3 wiring 再結線）が効いている。
