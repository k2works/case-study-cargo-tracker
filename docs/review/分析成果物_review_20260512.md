## 総合評価

設計ドキュメント間のクロスリファレンス整合性は高く、ADR・OOUX・ハイブリッドピラミッドテスト戦略・運用 KPI など個別の構造品質は優れている。一方で、設計が **「Axon 5 + CQRS + ES + Saga + マイクロサービス 7 分割」という技術的卓越に寄りすぎ**、MVP スコープ管理・業務適合性・運用現実性で重大な懸念がある。具体的には次の 3 つが横断的な根本課題である。

1. **業務規模と技術選定の不均衡**: 年間 10 万件・同時 300 名規模に対する 7 マイクロサービス分割は過剰投資。モジュラモノリスからの段階移行を ADR 化すべき
2. **SLA 99.95% と Axon Server SE 単一ノードの論理矛盾**: SE 単一ノード制約・RPO 24h と SLA 99.95% は両立しない。EE 移行を初期スコープに含めるか SLA を引き下げる必要がある
3. **業務適合性の弱さ**: 荷主自身の Web 接点・複数貨物明細・船積書類・税関業務・支払条件等、国際海運業務の常識的論点が抜け落ちている

これら以外にも、公開追跡画面の認証方針が 3 文書で矛盾、モバイル荷役 UX の仕様不足、受入基準とテストの欠落 US などの整合性課題が残る。**重要度「高」の指摘を消化してから開発フェーズに進むことを強く推奨する。**

### 評価サマリー

12 件の設計ドキュメント間のクロスリファレンスは概ね整合しており、ADR-0001/0002 と各設計の方針も一貫している。一方で、業務規模（年間予約 10 万件・同時利用 300 名）に対する CQRS + ES + Saga + マイクロサービス 7 分割は過剰投資、Axon Server SE 単一ノード制約と SLA 99.95% / RPO 24h の組合せには本質的な矛盾が残っている。

### 良い点

- ADR の質：採用根拠・代替案・コンプライアンス（ArchUnit 検証項目）まで含む構造的記述
- CQRS 規律の徹底：MyBatis と JdbcTokenStore/JdbcSagaStore の同一 DataSource 配置で at-least-once 配信の冪等性確保
- ハイブリッドピラミッド：Axon Test を独立した中間層として置く判断が ES 特性に合致
- コンテキスト境界の根拠：Routing/Booking を中核、Auth/Shared を一般領域へ分類した戦略的設計
- 業務監査と Event Store の二重保証：監査ログを Event Store で兼ねる設計は ES 採用の正当な果実
- OWASP A03 と MyBatis の親和性：`#{...}` バインド変数の ArchUnit 強制

### 改善提案（要約）

- 【高】SE 単一ノードと SLA 99.95% の論理矛盾 → 99.9% への引下げ or EE 移行
- 【高】RPO Event Store 24h は業務的に許容不可 → EBS スナップショット頻度 1h or 手動レプリケーション
- 【高】7 マイクロサービス分割は統治分割原則に反する → モジュラモノリス開始、段階移行を ADR-0003 で記録

### 評価サマリー

国際貨物輸送の主要業務フロー（見積 → 予約 → 経路設計 → 追跡 → 精算）と 7 ロールの責任分担は丁寧に整理されており大筋で業務に乗せられるレベル。一方で、現場が日々直面する「複数貨物・コンテナ単位の取扱い」「実際の荷主接点（Web 自助）」「税関・船積書類」「モバイル現場運用」「与信・支払条件」といった国際海運の常識的論点が薄く、このままでは荷主・荷役・経理のいずれの現場でも違和感が残る。

- 【高】US15/US16 の荷役記録がモバイル前提として弱い（スキャン・オフライン・写真添付）

- 【高】支払条件・与信・前払／後払の区別、督促段階の追加
