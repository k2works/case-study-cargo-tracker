# 開発成果物レビュー: IT7（US-ADM-01/US21/US22/US23 割引・請求・精算）

## レビュー対象

- 範囲: IT7 の全変更（コミット `dac7ca60`..`cffc5735`）
- 対象: Billing（Domain/Application/Infrastructure）・Booking（Domain/Application/Infrastructure）・Shipper（Infrastructure）・Web（App/Views）・テスト・マイグレーション
- レビュー日: 2026-07-17
- レビュアー: xp-programmer / xp-tester / xp-architect / xp-technical-writer / xp-user-representative（並列）

## 総合評価

Billing ドメインの設計品質は高い。`PaymentState`/`DiscountRate` DU による不正状態排除、`Money` の銀行家丸め、BC ローカル ID 型、`PaymentGatewayPort` 抽象、`writeNotificationLog` の DRY 集約など、関数型・ROP・BC 分離の規律が一貫している。一方で指摘は「**ドメインは堅いが、合成層・失敗経路・上流連携に穴がある**」に集中した。特に (1) 精算完了の Settled 同期が Booking 集約のガードを射影更新でバイパスしエラーも握り潰す、(2) 割引ポリシーマスタ（US-ADM-01）が料金算出に接続されず「飾り」になっている、(3) `invoice` の data-model と実装スキーマが全面乖離、(4) Billing の ArchUnit BC 分離検証が未追加（ADR-0013/0014 のコンプライアンス条項未達）、(5) US21/US23 の業務要件（輸送実績表示・支払期限・消費税）未達、が高指摘として複数エージェントで一致した。品質基盤（375 テスト緑・カバレッジ 90.6%/89.7%）は堅牢。

## 懸念事項

- **入金確認がスタブ決済で常に成功**（`stubPaymentGateway`）: 決済拒否の失敗系受入テストが書けない。WireMock.Net 差し替え時に失敗パス検証が必要（ADR-0014）。
- **消費税未実装で「45,000/50,000」を正解にしている**: 後付けで税を入れると全アサートが破綻。仕様確定を要する。
