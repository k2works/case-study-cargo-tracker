## 視点別フィードバック

### xp-programmer（高 1 / 中 2 / 低 0）

**良い点**: `InvoiceView` の分割で**委譲アクセサを残し、テンプレート 71 箇所を無変更にした**判断がよい。まとまりに分けたのは組み立て側の都合であり、読む側に押し付けていない。Checkstyle の複雑度に当たったときも、コメントを削らず `nesting(char)` に切り出している（IT15 の K4 の踏襲）。

**改善提案**: H2・M2・M3。

**懸念**: 無し。

### xp-tester（高 1 / 中 0 / 低 0）

**良い点**: 新設した検査 8 本すべてで破壊検証を行い、赤を確認している。とくに **H2（並び順）の初版が空振りだったことを検出し、判別できる形に直した**のは、本イテレーションの主題（「入れたこと」と「働くこと」は別）をテストの側でも実践している。

**改善提案**: H1。

**懸念**: 空振りを 3 回見つけた（C1 のステータス絞り込み・並び順・名簿の逆方向）。**発見できたのは、いずれも破壊検証を回したからである。**

### xp-architect（高 0 / 中 1 / 低 0）

**良い点**: BC 独立性が保たれている。C4 の検査は **ArchUnit で捕まらない領域**（依存ではなくメソッド呼び出し）を正しく補っている。ADR に守り手を書き出したことで、**どこが人の注意に預けられているか**が名前で残った。

**改善提案**: M2。

**懸念**: 無し。

### xp-technical-writer（高 0 / 中 0 / 低 2）

**良い点**: マニュアル 8.8 が「荷降し手配は指示であって記録ではない」を利用者の言葉で説明している。ADR 19 件の守り手は、**検査の無い規則を「守らない」と明示した**点で読み手に誤った安心を与えない。

**改善提案**: L1・L2。

**懸念**: 無し。

### xp-user-representative（高 0 / 中 1 / 低 0）

**良い点**: 請求書に種別が出たことで、経理担当者は**何のお金を督促しているのか**が読めるようになった。請求書詳細から予約詳細への導線も、料金調整の判断に要る情報へ実際に行けるようにしている（開いているだけでは足りない）。

**改善提案**: M1。

**懸念**: 無し。
