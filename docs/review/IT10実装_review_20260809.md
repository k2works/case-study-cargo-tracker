## 総合評価

例外という「うまくいかない道」を集約の内側に正しく置き、発生前状態の永続化・二重解決の防止・拒否を結果型で返すなど、過去 9 イテレーションの教訓がよく効いた実装である。安全装置 10 件の破壊検証も全件が赤になった。

**それでもレビューは 5 件の高優先度の欠陥を見つけた。共通点は「テストが全部緑のまま壊れていた」ことである。**

| 見つかった形 | 具体例 |
| :--- | :--- |
| 実データが無いから緑 | 発生場所が NULL の行を読み戻すと集約ごと 500。**その列に書き込む機能が IT10 まで無かったため、実データが空で気づけなかった** |
| 「無いこと」しか見ていない | 管理者の詳細画面で「対応を記録する」が無いことだけを見ており、**403 のエラーページでも緑** |
| 装置を置いて戻り値を捨てた | 二重解決の SQL の砦を置きながら結果を見ておらず、**DB に書けていないのに荷主へ通知が飛ぶ** |
| 見出しの存在だけを見た | ダッシュボードの件数テストが、**件数を 0 固定に潰しても緑** |
| 同じファイル内の参照が追随しない | 付録 B の番号を振り直したとき、早見表の 10 本のアンカーが壊れた |

**IT9 のふりかえりで「安全装置は破るテストで固定する」と書き、IT10 で 10 件すべてを破壊検証した。それでもなお、破壊検証の対象にしなかった装置が 3 つ壊れていた。** 検証する装置を自分で選んでいる限り、選ばなかったものは守られない。
