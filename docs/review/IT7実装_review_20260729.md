## 中・低優先度指摘の対応方針

**対応済み**:
- SonarQube 違反 2 件（Invoice#initialize 8 引数 → InvoiceAmounts で 7 以下・estimates#new 空メソッド → コメント）。

**次イテレーション対応（IT8/将来）**:
- programmer/architect 中: 請求番号採番（`all.size + 1`）の競合・非決定性 → DB シーケンス/`INV-{id}` 形式へ（二重請求は `booking_id` UK で防御済み）。
- programmer/architect 中: 金額の丸め方針を `MoneyAmount`（通貨別最小単位）に集約（現状は境界の `.to_i` に散在）。割引率の逆算依存も discount_amount 直接保持へ。
- **tester 高（受入基準の残）**: US23 受入基準5「支払期限超過時の未払い通知」は `mark_overdue_if_due`（ドメイン）まで実装済みだが、OVERDUE 遷移を駆動する定期バッチ（スケジューラ）が未実装 → **IT8/運用で対応**。US21 受入基準6「例外発生時の料金調整（減額・補償費用）」は未実装 → **IT8**。正直に未達として記録する。
- tech-writer 中: 見積の状態表示の日本語化（`estimate_status_label`）・危険物申告/温度条件の入力が create に渡らず破棄 → IT8 で整合。OVERDUE/REFUNDED の UI 挙動。
- architect 低: 楽観ロック競合（`StaleObjectError`）の業務エラー変換。

## 良い点（記録）

- 両新設 BC（Estimation/Billing）はドメイン層を Rails 非依存 PORO で保ち、`reconstitute` で永続化境界を明確化。
- BC 依存グラフは Estimation→{Routing,Billing}・Billing→{Booking,Shipper} の非循環 DAG で、全越境が公開 API + ADR-0003 越境識別子・プリミティブ受け渡し（Packwerk privacy ゼロ違反）。
- 両 BC が同名 `RouteCandidate` を各 BC 内別型として持ち、`CreateEstimate#build_candidates` で ACL 変換する設計は ADR-0004 決定4 と完全整合。
- 二重請求は `booking_id` UK + アプリ層 `exists_for_booking?`、二重精算は状態機械（`confirm_payment` の PENDING ガード）で防御。
- `AddBaseAmountToInvoices` で「total からの逆算＝再導出を避ける」T33 の意識が徹底（本レビューで割引・shipper_id も同原則に統一）。
