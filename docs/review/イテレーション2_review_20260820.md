# イテレーション 2 開発成果物レビュー

- **対象**: IT2 の実装（US03 荷主の法人契約情報・US04 貨物予約の登録・US05 貨物予約の一覧、8 SP）
- **レビュー日**: 2026-08-20
- **観点**: XP の 5 役割（programmer / tester / architect / technical-writer / user-representative）による並列レビュー

## エグゼクティブサマリー

受入基準はすべて満たしており、CI・Quality Gate・kind・Heroku のいずれも緑です。一方で **5 視点すべてが「緑のまま素通りしている欠陥」を報告しました**。ダッシュボードの到達性判定が本番コードとテストで別実装になっていた件（user-representative）と、ADR-007 が承認済みなのに実装も検査も存在しない件（architect）が典型で、いずれも「テストが通っている」ことが正しさの証拠になっていません。

指摘件数: 高 8 件 / 中 14 件 / 低 6 件。

## 視点別の要点

### programmer

- 復元経路で値オブジェクトの検査を通している（H1）。既存行を壊す不変条件の追加と同じ形。
- `useBookCargo` の無効化漏れ（H2）。`src` 全体で `invalidateQueries` が 0 件。
- 荷主の検索だけ件数の上限が無い（中）。貨物予約側は 100 件で打ち切っている。

### tester

- 常に成り立つテスト 2 件（H4・H5）。
- `RegisterShipperUseCaseTest` の fake `save()` が契約情報を捨てる（中）。
- `CargoTest#cannotMixSpecialInformation` が判別しない（中）。
- `iteration_plan-2.md` タスク 2.7 が ADR-008 と矛盾したまま `[x]`（中）。

### architect

- ADR-007 の未実装（H3）。**ADR の規則は同じ変更で検査に落とす**という IT1 の学びが守られていない。
- 共有カーネルの範囲を守る検査が無い（中）。`serviceIsolationRule` が `com.example.shared` をまるごと除外。
- `ui_design.md:79` が ADR-008 と矛盾（中）。

### technical-writer

- 「目的地は出発地と同じ港を選べません」が実装と食い違う（高）。実際は選べて、押した後に断られる。
- サーバ由来のメッセージに入力値が連結され、表の字面と一致しない（中）。
- テンプレート逸脱（04 章と 3.4 節が index.md の様式と別形）（中）。
- `npx gulp manual:build` が運用手順書のコマンド表に無い（中）。

### user-representative

- 到達性判定の二重実装（H6）、荷主名の列（H7）。
- 危険物クラスが自由入力（高）。法定分類を自由入力にしている。
- 法人契約情報を登録後に確認する手段が無い（中）。
- 荷主一覧・荷主セレクトに上限が無い（中）。
- 予約登録画面に「荷主を探す」導線が無い（中）。

## 次イテレーションへ送る主な項目

- ADR-007 の `AuthenticatedUserFilter` 実装と ArchUnit 検査（H3 の後半）
- 危険物クラスの選択式化（法定分類）
- 荷主一覧・セレクトのページング、荷主詳細画面
- 共有カーネルの範囲を守る検査
- 予約の訂正・取消

## 通底する原因

IT1 のふりかえりで挙げた「緑のテストと壊れ方の設計は別物」が、IT2 でも同じ形で 4 件（H4・H5・H6 とマニュアルの食い違い）再現しました。**テストが本番コードと別の判定を持っている**（H6）のはその極端な例です。IT3 では「その検査は壊したら赤になるか」を DoD に加えます。
