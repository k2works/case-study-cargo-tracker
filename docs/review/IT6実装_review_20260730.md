## クローズ内で対応した指摘（11 件）

1. **例外解決後の復帰先が例外中に到着したイベントを失う**（programmer H1 / tester 1・2）: 復帰先を「発生前状態とイベント由来状態のうち輸送フェーズ順で進んでいる方」へ是正（`transportPhaseRank`）。解決順の同時刻タイブレークを id で決定化し、「EXCEPTION 中に UNLOAD → 解決 → UNLOADED」等をドメインテストで固定。
2. **公開ページに推定到着日と例外要約がない**（user H1/H7・US18/US19 の業務価値）: 推定到着日（YYYY-MM-DD 頃 / 未確定）、未解決例外の「例外発生（種別）・対応中」、報告済みの「新しい到着予定日」を表示。description・荷主情報の非露出はテストを固有値で強化（tester 6 / 対応 10）。
3. **解決済み例外への対応報告の上書き**（programmer M5）: `report()` で拒否。
4. **exceptionId の NaN 素通り**（programmer M4）: 数値検証を追加。
5. **解決操作が確認なし 1 クリック**（user M4）: 確認ステップを追加。
6. **EXCEPTION が赤バッジで強調されない**（writer 2）: `text-bg-danger` + 種別併記。
7. **通関画面が無効な遷移ボタンを提示**（writer 3）: 許可遷移のみ表示（HELD 行に留置を出さない）。
8. **通関 HELD フラッシュの断定表現**（programmer M3）: fire-and-forget の実態に合わせ非断定表現へ。HELD 注記に対応手順（再提出依頼 → CLEARED 更新）を追記（writer 4/5）。
9. **DAMAGE 非エスカレーションの負テスト欠落**（tester 4）: escalationFlag=false・ESCALATION 0 件を明示検証。
10. **公開ページ露出テストの脆弱なアサーション**（tester 6）: 固有値（'ACME商事'・SECRET-DESC）で非露出を検証。
11. **通知アサートの同期前提**（tester 7）: 前提コメントを明記。

## 次イテレーション（IT7）引き継ぎ

- **認証境界の fail-closed 化**（architect H1）: 認証が「デフォルト公開・opt-in ガード」構造。グローバル APP_GUARD + `@Public()` の反転を ADR 起票のうえ実施する。
- **notification_record の所有決定と種別の型化**（architect M2 / user H2）: 3 BC 書き込み・種別のマジックリテラル増殖。通知本文（新 ETA・対応方針）が荷主へ届かない伝達欠落も同根で、Notification の所有 / 本文設計を ADR で決定する（公開ページ要約はクローズ内対応で部分緩和済み）。
- **CUSTOMS_HOLD の冪等キー**（architect M3）: 種別単位の冪等が申告番号単位の複数留置を破棄する。業務要否をユーザー代表に確認のうえ (種別+申告番号) キー化を判断。
- **正当な 2 件目例外の破棄可否**（tester 3）: 未解決同種スキップが別内容の新規遅延を捨てる仕様の業務確認。
- **管理職への実効的なエスカレーション**（user M-H3）: ロール・横断ビュー不在で「監視されない記録」状態。管理職向け未解決緊急例外ビューの要否を計画へ。
- **追跡管理者の未解決例外横断一覧**（user M5）・**荷役作業員の追跡番号起点の例外登録導線**（user M6）。
- **AFTER_COMMIT の構造的担保・ACL 直読の返済ロードマップ**（architect M4/M5）: transaction()/アウトボックスの横断課題と、参照専用スナップショットの単一ソース化（返済枠は IT 序盤の独立コミットで固定）。
- **CLEARED→HELD 再留置の要否**（architect L7）・**発生日時の未来日ガード**（programmer M2 / user L8）・**POST 認可マトリクスの表駆動化**（tester 8）・**サービス層認可の単体テスト**（tester 5）・**CustomsHeldEvent クラスの二重定義解消**（architect L8）。
