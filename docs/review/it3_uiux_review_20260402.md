# IT3 UI/UX レビュー結果

- **レビュー日**: 2026-04-02
- **対象イテレーション**: IT3（US05/07/08/09）
- **レビュー方法**: マルチパースペクティブ（xp-interaction-designer + xp-user-representative）

---

## レビュー対象

| ファイル | 概要 |
|---|---|
| `booking/register.html` | 予約登録フォーム（特殊貨物フィールド追加） |
| `booking/detail.html` | 予約詳細（追跡番号カード・確定ボタン） |
| `booking/list.html` | 予約一覧（ステータスバッジ） |
| `routing/search.html` | ルート検索・割り当て |

---

## 総合評価

Bootstrap 5 の標準パターンに沿った堅実な実装で、「予約登録 → ルート割り当て → 確定」という業務フローの骨格は機能している。貨物種別連動フィールドの動的表示やバリデーション後の状態復元など、基本的な UX への配慮も見られる。

一方で、**アクセシビリティの基盤欠如（`lang`・`<main>` ランドマーク未設定）**、**ステータスバッジの一覧/詳細間不整合**、**enum 生値の日本語化漏れ**という 3 点が複数エージェントから指摘されており、リリース前の対応が必須。また特殊貨物条件（UN番号・温度帯）が詳細画面で確認できない点は、国際物流の業務要件として重大な欠陥。

## モダンデザイン準拠サマリー

| 評価項目 | 状態 | 備考 |
|---|---|---|
| カラーシステム | ⚠️ 要改善 | 一覧バッジが CONFIRMED でも常時 `bg-warning`（詳細は正しく条件分岐済み） |
| タイポグラフィ | ⚠️ 要改善 | `h4` をページタイトルに使用（本来は `h1`）、見出しレベルのスキップあり |
| Elevation & Surface | ✅ OK | `shadow-sm` を全カードに統一適用 |
| コンポーネント一貫性 | ⚠️ 要改善 | ステータスバッジ・enum 表示が画面間で不整合 |
| スペーシング | ✅ OK | Bootstrap スペーシングスケールに概ね準拠（`mb-3`/`mb-4`/`gap-2`） |
| レスポンシブ / Adaptive | ⚠️ 要改善 | detail.html のボタン群（最大4つ）がモバイルで `flex-wrap` 未設定 |
| ダークモード | 未対応 | Bootstrap デフォルトのみ（現フェーズのスコープ外） |
| 状態デザイン（空 / Loading / Error） | ⚠️ 要改善 | 空状態はテキストのみ・動的フィールドのエラー表示に `is-invalid` 付与なし |

## 改善提案（重要度順）

### 高（リリース前に対応すべき）

| # | 提案 | 箇所 | 指摘元 | 理由 |
|---|------|------|--------|------|
| H1 | `<html lang="ja">` と `<main>` ランドマーク追加 | register.html / detail.html / list.html | デザイナー | WCAG 2.1 AA 必須。スクリーンリーダーの読み上げ言語とキーボードナビのランドマークが欠落。search.html には両方あるのに不整合 |
| H2 | ステータスバッジ色を一覧でも条件分岐（CONFIRMED=緑） | list.html L52–53 | デザイナー・ユーザー | 詳細では正しく色分けされているのに一覧で全件黄色のため、業務担当者がステータスを目視識別できない |
| H3 | enum 生値を displayName で日本語表示 | list.html・detail.html（status・cargoType） | デザイナー・ユーザー | `PROVISIONAL`/`CONFIRMED`/`DANGEROUS_GOODS` が日本語ユーザーに直接露出。`CargoType.displayName` は search.html で使用済み |
| H4 | 動的フィールドに `aria-hidden` 連動・`required` 動的制御 | register.html L67–118 | デザイナー | `d-none` 切替時に `aria-hidden` と `required` 属性を JS で連動させないと、非表示フィールドへのフォーカストラップと誤 HTML5 バリデーションが発生 |
| H5 | 特殊貨物条件（UN番号・温度帯）を詳細画面に表示 | detail.html 貨物仕様セクション | デザイナー・ユーザー | 危険物は IMDG コード上、書類確認が必須。登録した UN番号・危険品等級・温度帯が確認できないのは業務上の欠陥 |
| H6 | 特殊貨物フィールドのバリデーションエラー表示（`is-invalid` クラス付与） | register.html（unNumber・temperatureフィールド） | ユーザー | UN 番号・温度フィールドに `th:classappend="... ? 'is-invalid'"` がなく、エラー時に `invalid-feedback` が表示されない |

### 中（対応推奨）

| # | 提案 | 箇所 | 指摘元 | 理由 |
|---|------|------|--------|------|
| M1 | 寸法フィールドに個別 `aria-label` 追加・`<label for>` 修正 | register.html L133–153 | デザイナー | 3つの数値入力（長さ・幅・高さ）が `placeholder` のみで無名。WCAG 1.3.1 違反 |
| M2 | 「予約を確定する」ボタン色を `btn-warning` または `btn-danger` に変更 | detail.html | ユーザー | 「ルート検索（btn-success）」と同色の緑で並んでいる。不可逆操作は色で区別すべき |
| M3 | 確定ボタンに確認ダイアログ追加 | detail.html | ユーザー | 確定後に PROVISIONAL に戻せないため、誤クリック防止の確認ステップが必要 |
| M4 | 追跡番号にコピーボタン追加・「確認できます」の導線を整備 | detail.html 追跡番号カード | ユーザー | 追跡番号は他システムへのコピーが頻繁。リンク先がない「輸送状況を確認できます」テキストは宙ぶらりん |
| M5 | 「この予約に割り当てる」ボタンを通常サイズ化・`aria-label` 追加 | search.html L143 | デザイナー・ユーザー | `btn-sm` で最重要アクションが目立たない。複数ルートで同テキストボタンが並ぶと WCAG 2.4.6 違反 |
| M6 | UNLOCODE フィールドの `maxlength` を 5 に修正・`pattern` 追加 | register.html L186・L198 | デザイナー | `maxlength="200"` は実態（5文字固定）と乖離。クライアントサイドバリデーションで早期フィードバック |
| M7 | detail.html ボタン群に `flex-wrap` 追加 | detail.html ヘッダーボタン群 | デザイナー | 4ボタン横並びがモバイル幅でオーバーフロー |
| M8 | テーブル `<th>` に `scope="col"` 追加 | list.html L26–33 | デザイナー | スクリーンリーダーがヘッダーとデータセルの関連を解釈できない（WCAG 1.3.1） |

### 低（改善の余地あり）

| # | 提案 | 箇所 | 指摘元 | 理由 |
|---|------|------|--------|------|
| L1 | `<script>` を `</body>` 直前に移動 | register.html L109–118 | デザイナー・ユーザー | HTML の仕様上 `<form>` 内の `<script>` はリスクあり。CSP 対応の観点からも `</body>` 直前が推奨 |
| L2 | 温度フィールドに `placeholder` 例示追加 | register.html 最低/最高温度フィールド | ユーザー | `placeholder="例: -18.0"` 等の例示で入力ミス（単位誤り等）を防止 |
| L3 | 予約一覧の荷主 UUID 表示を削除または荷主名に変更 | list.html・detail.html | デザイナー・ユーザー | UUID は担当者に不要な情報。画面ノイズを削減 |
| L4 | search.html の `✅` emoji を Bootstrap Icons に置換 | search.html L125 | デザイナー | OS・ブラウザで表示が異なる。`bi-check-circle-fill` で安定化 |
| L5 | `aria-live="polite"` を動的コンテンツに追加 | register.html 動的フィールド | デザイナー | search.html では適切に実装済みだが、register.html の動的エリアに未適用 |

## エージェント別フィードバック詳細

<details>
<summary>xp-interaction-designer（高: 5 / 中: 6 / 低: 5）</summary>

### 評価サマリー

Bootstrap 5 の標準パターンに沿った堅実な実装で、業務フローの基本的な UI 要件は満たされています。ただし、`lang` 属性・`<main>` ランドマークの欠落（register/detail/list の 3 ファイル）、ステータス enum の未ローカライズ（一覧で常時 `bg-warning`）、動的フィールドのアクセシビリティ欠如という 3 点が、実用前に必ず対処すべき問題として残っています。

### 良い点

- 動的フィールドの初期化対応（バリデーションエラー後の状態復元）
- `invalid-feedback` の一貫した使用
- `PROVISIONAL and assignedRoute != null` の 2 条件 AND 結合による業務ロジック反映
- 空状態の `colspan=7` + `py-4` 対応
- 再検索フォームでの変更不可項目 `hidden` 引き継ぎ設計
- search.html の `aria-live="polite"` アクセシビリティ対応

### 高優先指摘

1. **`lang="ja"` と `<main>` ランドマーク欠落**（register/detail/list）— WCAG 必須
2. **ステータスバッジ常時 `bg-warning`**（list.html L52–53）— 一覧と詳細の不整合
3. **enum 生値の日本語化**（全ページ）— `CargoType.displayName` が search.html で使用済みなのに他で未使用
4. **動的フィールドの `aria-hidden` 連動・`required` 動的制御**（register.html）
5. **寸法フィールドの個別 `aria-label` 欠落**（register.html L133–153）

</details>

<details>
<summary>xp-user-representative（高: 4 / 中: 3 / 低: 1）</summary>

### 評価サマリー

「予約登録 → ルート割り当て → 確定」という基本フローは実装されており、業務の骨格として機能します。ただし、1 日に複数の予約を処理する現場担当者が実際に使う観点で見ると、ステータスの視認性・特殊貨物情報の追跡可否・英語表記の残存という 3 点に、業務効率を損なうリスクがあります。

### 良い点

- 貨物種別プルダウンの連動表示（紙の申込書に慣れたベテランも戸惑わない）
- ルート検索結果の「✅ 間に合います」バッジ（最初に確認する項目）
- 候補なし時の再検索フォーム（着日だけ変更して再試行）
- 「予約を確定する」ボタンがルート割り当て後のみ表示
- 追跡番号カードが CONFIRMED 後に自動表示

### 高優先指摘

1. **予約一覧ステータスバッジが全件黄色**— 1 日に数十件処理する担当者が CONFIRMED を目視識別不可
2. **全画面でステータス・貨物種別が英語表記**— `PROVISIONAL`/`DANGEROUS_GOODS` が日本語ユーザーに直接露出
3. **特殊貨物フィールドのバリデーションエラーが視覚的に表示されない**— `is-invalid` クラス付与なし
4. **特殊貨物の登録内容が詳細画面で確認できない**— 危険物は IMDG コード上の書類確認義務あり

### その他指摘

- 「予約を確定する」と「ルート検索」が同色（btn-success）— 不可逆操作は色で区別
- 確定ボタンに確認ダイアログなし
- 追跡番号コピーボタン・導線なし
- 「この予約に割り当てる」ボタンが `btn-sm` で目立たない

</details>

## 対応方針

### IT3 中に対応（重要度「高」のうち実装コスト低いもの）

| # | 対応 | 工数目安 |
|---|------|----------|
| H2 | list.html ステータスバッジ色修正 | 5 分 |
| H3 | list.html・detail.html enum 日本語化（displayName 使用） | 15 分 |
| H6 | 特殊貨物フィールドへの `is-invalid` クラス付与修正 | 20 分 |
| H5 | detail.html に UN番号・温度帯表示追加 | 20 分 |
| H1 | `lang="ja"` と `<main>` 追加（3 ファイル） | 10 分 |

### IT4 計画に含める（実装コストが高め・設計検討が必要）

- 動的フィールドの `aria-hidden` / `required` JS 制御（H4）
- 確認ダイアログ実装（M3）
- 追跡番号コピーボタン・輸送状況確認画面への導線（M4）
- 寸法フィールドアクセシビリティ改善（M1）
- UNLOCODE `pattern` バリデーション（M6）

### 許容・保留

- ダークモード対応（現フェーズのスコープ外）
- UNLOCODE オートコンプリート（中長期課題）
- `script` タグ移動（動作に影響なし、リファクタリングとして扱う）
