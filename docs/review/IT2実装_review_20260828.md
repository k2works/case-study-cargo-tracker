## 総合評価

「効果 = ポート」「合成ルートへの集約」「画面関数の純粋性」という IT1 で確立した構造は
IT2 でも崩れておらず、テストは 61 件すべて緑・CI は 47 秒で完走している。
一方で**品質ゲートそのものに穴**が見つかった。`arch-lint` は 1 行単位の正規表現で照合していたため、
本プロジェクトが実際に採っている「SQL を `"..." +` で改行して連結する」書き方の違反を
**検出できない**状態だった（実測で検出 0 件）。メタテストが 17 件緑であることが検査器を信用する
根拠になっていなかったことになる。この 1 件が本レビュー最大の収穫である。

利用者視点では、US18 の受入基準は項目としては満たすものの、**Bootstrap の CSS が読み込まれておらず**
（設計にはある `resources/static/` が未実装）、「一目で状態が分かる」という公開追跡の価値が
実際には成立していない。これは IT3 へ送る。

### 「現在地」の表示について（受入基準の解釈）

利用者視点から、**「現在地」と言い切ると積込港が表示されている貨物を「まだ出港していない」と
読み違える**という指摘があった。表示しているのは最新イベントの発生場所であり、輸送中の現在位置ではない。

クローズ前に「最終確認地点: Tokyo（JPTYO）（2026-08-03 09:15 時点）」へ変更した。
受入基準 2「現在の状態・位置（港湾名）・推定到着日が表示される」は、この表示で満たしたと判断する。

## レビューを受けての気づき

**メタテストが緑であることは、検査器が正しいことを意味しない。** IT1 で `arch-lint` の
メタテストを「検査器を信用するための補償策」として設計したが、フィクスチャが単一行の違反形しか
持たなかったため、実コードと同じ書き方の違反を見逃していた。フィクスチャは
「規約に違反する最小の例」ではなく「**このコードベースで実際に書かれる形の違反**」で
作る必要がある。
