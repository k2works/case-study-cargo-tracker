**設計判断の言語化と「都合の悪い事実を隠さない」姿勢は 5 視点すべてが高く評価した。**

一方で **IT8 が返済したはずの欠陥が、同じ IT の中で新しいコードに再発していた**。

**Estimation 側の翻訳では同じ 0 埋めを書いており、しかもコメントは「落とす」と主張していた**。

同型の問題として、**「全ルートを叩く」と宣言したテストが手書きリストで
新規 BC の 3 ルートを取りこぼしていた**。宣言と実態の乖離が 2 件重なった点は、
次イテレーションへの教訓として記録する。

## 利用者代表からの機能要望（IT9 のストーリー候補）

**受入基準に書かれていないが業務上必要**として挙がったもの。いずれも
「電話口で答える」場面は成立するが「あとで見返す」場面が成立しないという指摘である。

| # | 内容 | 理由 |
| :--: | :--- | :--- |
| U1 | 見積一覧に**作成日**と**引き合い元**の列 | JPOSA→USLAX の見積は毎週何件も作られる。番号・出発地・目的地だけでは同じ行が並び、「先週もらった見積の件」で探せない |
| U2 | 見積の候補に**出発予定日・到着予定日** | 荷主の質問は「いくら」と「いつ着くか」。所要日数 18 日と言われても、いつ出る便かが分からなければ着日を答えられない |
| U3 | 見積詳細に**「◯月◯日時点の候補です」** | 候補は作成時点で凍結される（記録として正しい）。明示しないと営業が古い候補を今の候補と読み違える。IT7 の「出港済みの便」と同型 |
| U4 | 作成後の遷移先を**詳細**へ | 電話口で見たいのはその見積の候補。一覧には最安概算しかなく、日数を答えるにもう 1 クリック要る |
| U5 | 見積一覧の**絞り込み** | 営業所単位で 1 か月に数百件になる |
| U6 | 予約一覧に**「いつから今の状態か」**の列と業務順の並び | `operation.md` 09:30 の手順は「前営業日以前から残っていないか」だが、現在の列では判断できず結局全部見ることになる |
| U7 | **見積から予約への導線** | 「その条件で頼む」と言われた瞬間、営業は同じ内容を手で入れ直す。転記ミスが起きる |
| U8 | 見積の**有効期限** | 実務では「有効期限 2 週間」を必ず添える。運賃が変動すると画面自身が書いている以上、業務上必要 |
| U9 | 「**割引適用前の概算です**」の明記 | 法人割引（US22）が入ると見積と請求がずれる |

## 懸念事項

### IT9 の書き戻しは現在の ACL の形では受け止められない（architect）

IT9（US09・US11・US13）は **Routing が Booking の状態を変える**ことを要求する。
現在の `RoutingJdbcBookingRouteRequest` は読み取り専用であり、書き込みが加わると
(1) Booking の集約不変条件を迂回する経路ができ、(2) ADR-0010 の穴が
読み取りだけでなく**書き込みにも広がる**。読み取りの取り違えは「候補が出ない」で済むが、
書き込みの取り違えはデータが壊れる。

**IT9 着手前に ADR-0010 の適用範囲を「読み取りに限る」と明記し、
書き込み方向は別 ADR で扱う**ことを推奨する。BC 間の意味的な結合は既に 3 件あり
（`RouteFinder` 呼び出し・`cargo` テーブル・貨物種別の文字列）、
4 件目が書き込みなら `composition/acl/` の導入コストを払う妥当なタイミングである。

### `POST /login` に CSRF 検証が効いていない（tester・スコープ外）

`Composition.flix:134` で `anonymous()` として登録され、`Auth.flix:116` の
`requiresCsrf` は `Anonymous` に `false` を返す。一方 `AuthPages.flix:58` は
フォームに `_csrf` を描画している——**出しているが検証していない**。
ログイン CSRF（攻撃者のセッションへ被害者をログインさせる）が成立する。
IT8 の変更ではなく既存の設計判断だが、**セキュリティのため IT9 の高優先度として起票する**。

### 間欠的なログイン失敗（`Set-Cookie` 欠落・計 3 回）

tester の分析により、**現在の失敗メッセージでは原因を特定できない**ことが判明した。
最有力の仮説は「ポート再割り当てで別インスタンスが応答している」（`TestApp` 自身が
IT6 レビュー H5 の残る仮説として明記しているもの）であり、
**これは `X-App-Instance` の突合でしか切り分けられない**。
アカウントロックは原因ではない（誤ったパスワードでのログインが無く、DB 名も一意）。

H10・H11 で観測手段と残留の両方を手当てした。**次の観測を待つ**。
