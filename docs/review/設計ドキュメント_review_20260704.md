# 設計ドキュメント マルチパースペクティブレビュー（2026-07-04）

## レビュー結果

### レビュー対象

- `docs/design/` 配下の設計ドキュメント一式（C# 版・10 件）
  - architecture_backend.md / architecture_frontend.md / architecture_infrastructure.md
  - data-model.md / domain-model.md / ui_design.md
  - test_strategy.md / non_functional.md / operation.md / tech_stack.md
- 技術前提: .NET 10 / ASP.NET Core 10 MVC + Razor + htmx / Dapper + DbUp（開発 SQLite・本番 PostgreSQL 16）/ MediatR / AWS ECS Fargate

### 総合評価

戦略的設計（8 コンテキストの境界・ユビキタス言語・依存方向の ArchUnitNET 検証・ACL による外部分離）と運用要件は完成度が高く、追跡機能など利用者の中核ニーズも的確に押さえています。一方で、(1) UI 設計・テスト戦略の「対応 US」番号が user_story.md と全面的にずれておりトレーサビリティが機能していない、(2) 例外登録・経路設計者ワークフロー・荷主/航海スケジュール登録など「ないと業務が回らない」画面が欠落している、(3) Dapper 化に伴う戦術的設計（集約永続化・Unit of Work + post-commit イベント・二方言運用）が未設計、という 3 系統の重大な問題が実装着手前に残っています。

### 評価サマリー

設計全体の完成度は高く、特にドメインモデルと運用要件は筋の通った作り。追跡の 30 秒自動更新や公開追跡ページなど荷主・荷受人の中核機能も押さえている。一方で、業務フロー全体を通しで回そうとすると、いくつかのアクターの中核業務が画面として存在しない重大な問題がある。

- 【高】経路設計者の実務画面が実質ない（US07〜US11・US14）: UI では営業の単純選択に集約され、ドメインのアクター責務と食い違い
