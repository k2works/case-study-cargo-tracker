# IT6 開発成果物 マルチパースペクティブレビュー（2026-05-29）

## レビュー対象

- イテレーション: IT6（追跡照会 + 例外処理、Phase 2 / 2）
- コミット範囲: `main..HEAD`（21 件、afbeba88 ～ f1a0069c）
- 範囲スコープ:
  - US18 公開追跡照会（5 SP）: TrackingTokenService、PublicTrackingTokenFilter、TrackingPublicPage
  - US19 遅延例外処理（2 SP）+ US20 破損・紛失例外処理（2 SP）: TrackingException、Controller、NotificationAcl 拡張、S18 / S19
  - ADR-0012 / 0013 / 0014 起票
- レビュー実施: 2026-05-29、5 XP エージェント並列起動

## 総合評価

IT6 は計画 9/9 SP を完全達成し、ADR 起票 → 設計 → 実装 → テストの順序が一貫している。US18/US19/US20 すべての受入基準を充足し、特に LOSS 自動 escalation・JWT 検証失敗時 403・ResponseStatus 単方向遷移という業務ガードがエンティティ内に閉じている設計は良好。一方で、**(1) ADR-0012 で「集約発火型に統一」と決定しながら IT5 から残る `CargoDeliveredEventPublisher` の二段イベント実装が未撤去、(2) Controller 間で例外ハンドリングが完全コピー（IT7 で @RestControllerAdvice に抽出すべき）、(3) `EXCEPTION_REGISTRABLE_STATES` に EXCEPTION 自身が含まれず複数例外の同時登録が業務的に拒否される、(4) `architecture_backend.md` API カタログに IT6 追加 7 endpoint が未記載** が技術的・業務的負債として残る。これらは IT7 以降のフォローアップとして明示する。

## 既知の懸念事項（ふりかえり Try 候補）

- **`TrackingControllerIntegrationTest` の event store 汚染 flaky 再発**（IT5 H6 の不完全解決、auto-memory `trackingms-spring-context-event-store-pollution` 既出）：今回新設の `PublicTrackingControllerIntegrationTest` が同じ ApplicationContext を共有することで悪化する可能性が高い。Gradle で `forkEvery=1` または `--tests` 分割を CI で恒久化するのが妥当
- **タスク 0.1（Testcontainers Reusable + H6/H7）が IT6 で着手できなかった**：構造変更で確認必須として保留したまま IT7 へ持ち越し
