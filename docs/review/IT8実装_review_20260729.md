## 中・低優先度指摘の対応方針

**対応済み**:
- programmer 中（T33）: `mark_overdue` を「実際に OVERDUE へ遷移した時だけ通知」に変更（状態遷移と通知を紐づけ）。
- tester 中: `add_adjustment` に請求金額 0 未満の下限ガードを追加。
- SonarQube 違反 2 件: seed の重複メール文字列を定数化（S1192）。

**次イテレーション対応（IT9/将来）**:
- **user-rep 高2**: 「補償費用（COMPENSATION）」の増減方向が業務意味と逆の疑い（当社が荷主へ負担するなら請求減額のはず）→ 業務確認のうえ方向を確定（現状は追加請求＝正値。減額したい場合は REDUCTION を使用）。**業務判断待ちとして IT9 で確定**。
- user-rep 中: 料金調整の取消・訂正 API・調整の監査証跡（担当者/日時/理由）・例外画面から料金調整への導線・OVERDUE 後の再通知/エスカレーション。
- architect 中: seed の生 SQL による invoices 直接更新は privacy バイパス（開発シード限定・Packwerk 非検知）→ `calculate_freight` に発行日時引数を通す公開経路の検討。
- architect 中: `mark_overdue` の save→publish 非トランザクション（IT5 既知 partial-apply の継続・冪等性は担保）→ 将来 Outbox。
- tech-writer/tester 中: 公開追跡の推定到着日に「（遅延により更新）」の補足表示・料金調整フォームの符号説明・T37 の負同値/順序/境界テスト。
