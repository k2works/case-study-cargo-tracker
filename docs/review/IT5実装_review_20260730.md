## クローズ内で対応した指摘

1. **TRACKER が navbar から /tracking に到達できない**（user H1）: 「貨物追跡」メニューの roles に `Role.TRACKER` を追加。US17 の主役がメニューから作業画面へ到達できるようになった。
2. **手動更新経路から US16 の不変条件（引取ガード）を迂回できる**（tester H1）: 手動更新の許可イベント種別をホワイトリスト化（RECEIVE / LOAD / UNLOAD / DEPARTURE / ARRIVAL）。CLAIM は「通関 CLEARED + 荷受人確認」を持つ荷役登録経路に限定し、迂回不可を統合テストで検証。
3. **手動更新の選択肢が荷役種別の焼き直しで US17 の目的を満たさない**（user H2 / writer H1）: 輸送イベント `DEPARTURE`（出港 → 輸送中）・`ARRIVAL`（入港 → 引取待ち）を追加。ONBOARD_CARRIER / AWAITING_CLAIM が到達可能になり、UI 設計の 7 状態遷移と実装が一致した。ラベルも「記録するイベント」へ是正（writer M2）。
4. **荷役登録が冪等でない**（tester H2）: 同一種別・同一日時の登録済み作業を検出して登録・イベント・通知をスキップ。CLAIM の二重 `CargoClaimedEvent`（二重精算開始）を防止し、統合テストで荷役行数・通知数の不変を検証。
5. **completionTime がドメイン未検証で Invalid Date が素通り**（programmer H1 / tester M5）: `HandlingActivity.register` と `TrackingActivity.addEvent` で `NaN` を拒否。冪等判定の NaN 破綻を封じ、controller の文字列一致エラー判定を撤去。
6. **手動更新の位置が無検証**（tester M4）: `TrackingActivity.addEvent` で UN/LOCODE 形式を検証。
7. **冪等スキップ時に「更新しました」と誤表示**（tester M6）: `addEvent` の戻り値でスキップを判定し、警告フラッシュ「記録済みのためスキップ」を表示。
8. **状態伝播イベントと通知の失敗を同一 try で握っていた**（programmer M6）: emit（状態同期）と notify（宛先通知）を別 try に分離し、emit 失敗は要リカバリとしてログを格上げ。
9. **MISROUTED フラッシュが非同期反映の成否を先取りして断言**（programmer M4）: 文言を結果整合前提（「として記録します（反映後に一覧へ表示）」）へ緩和。
10. **予約詳細から追跡画面への導線欠落 / ui_design ドリフト**（writer M3）: 予約詳細に「追跡を表示」リンクを追加し、ui_design の IT6 予定記述を実装済みへ更新。
11. **通知内容が未算出でも無警告で送信可能**（user M6）: NotifyConfirm に未算出時の警告表示を追加。
12. **語彙・記述の是正**（writer M4/M5、tester L8）: ui_design の `CUSTOMS_CLEARANCE` 残存を `CUSTOMS` へ統一、荷受人確認の常設表示を実態へ整合（CLAIM 時のみ必須・htmx 表示制御は IT6 検討）、ロール×操作の越権負テスト（TRACKER→荷役登録 / SALES→手動更新）を補完、ADR-009 に at-most-once の含意を補足。

## 次イテレーション引き継ぎ（IT6 で対応）

- **通関申告のドメイン集約化**（architect H1）: `CustomsDeclarationService` が AppDatabase 直依存で集約・状態遷移規則がない。通関ステータス画面（IT6 スコープ）実装時に `CustomsDeclaration` 集約 + Repository ポートへ引き上げ、CLEARED 到達後の `cleared_at` 保持（programmer M5）も合わせて是正する。読み取り QueryService の db 直依存は CQRS 読みモデルの意図的例外として ADR 化を検討。
- **通知アダプタの生 JOIN と notification_record の所有**（architect H2/M3）: 荷主連絡先解決をポート抽象へ統一し、3 BC が書き込む notification_record の所有方針（将来 Notification Context）を整理。ADR-008 に追記済み。
- **イベント契約の型共有**（architect M6 / programmer M2）: handling.registered のペイロード型が発行側クラス + 購読側 2 箇所の手書き interface に分散。契約型を 1 箇所に定義して import する。
- **AFTER_COMMIT の字義的担保**（architect M4）: 荷役登録コマンドは単発 insert（自動コミット）で機能的には等価だが、`transaction()` で明示的に包み emit タイミングの統合テストを追加する。
- **追跡レコード遅延作成の競合**（programmer M3）: 同時リクエストで UNIQUE 違反 → イベント消失の可能性。upsert + 再読込のリトライ可能な冪等操作へ。単一プロセス・低頻度のため IT6 で対応。
- **荷受人確認の永続化**（tester M3）: 確認コードが検証のみで記録されない。引き渡し証明として保存し、確認コード検証 ACL の要否も検討（programmer L7）。
- **業務 UX の改善**（user M3/M5/L7/L8）: 場所不一致時の登録前確認（誤入力の荷主誤警報防止）、荷役作業員が反映後の貨物状態を確認できる導線、追跡番号での荷役一覧検索、作業日時の未来日ガード（ui_design は投機的登録を許容しており要業務判断）。
- **通知の種別分岐**（tester L7）: US17「状態変更の種類に応じて」の通知対象/非対象を明文化しデシジョンテーブル化。
