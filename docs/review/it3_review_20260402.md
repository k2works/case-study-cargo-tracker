# IT3（US05/07/08/09）コードレビュー結果

## レビュー対象

- **対象範囲**: `origin/java/take-1..HEAD`（5 コミット、25 ファイル、+803/-121 行）
- **レビュー日**: 2026-04-02

## 総合評価

IT3 の実装は全 US の受入条件を満たしており、TDD インサイドアウト方式での品質確保は概ね達成されている。
`CargoDimensions` / `SpecialHandling` Record 導入による構造化と `REDIRECT_BOOKINGS` 定数化など細部の整理も良い方向性。
一方、**`booking → tracking` の直接 DI**（既存 ACL パターンとの不整合）と **Record とフラットフィールドの二重管理**の 2 点が設計上の重要な課題として残っている。
テスト面では一部テストメソッドがアサートなしの空実装になっており、265 件全通過という数字の信頼性に影響する。

## アーキテクチャ固有の補足

### `BookingConfirmedEvent` の shared 移動について（アーキテクト指摘）

`tracking` BC が `booking.domain.event.BookingConfirmedEvent` を直接 import している循環依存は、
`BookingConfirmedEvent` を `shared.domain.event` に移動することで解消できる。
ただしこれは中規模の変更のため IT4 の計画に含めることを推奨。

### `CargoType` の BC 間重複定義について（アーキテクト指摘）

`booking` / `quote` / `routing` の 3 BC で独立定義されている。
Shared Kernel への統合か「BC ごとに独立管理する」方針の ADR 明示が必要。

### ADR-006 との不整合について（アーキテクト指摘）

H2 コンソール設定の削除は ADR-006「H2 コンソールを有効化する」を覆す変更。
ADR-006 を `Superseded` に更新し、削除理由を記録した ADR を新設することを推奨。
