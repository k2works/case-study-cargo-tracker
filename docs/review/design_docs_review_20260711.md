## 総合評価

DDD + ヘキサゴナル + CQRS を軸に、設計判断の根拠・測定可能な非機能要件・US トレーサビリティまで揃った完成度の高い成果物群である。一方で、(1) ドキュメント間の用語・列挙値・ロール名の不整合（BookingStatus / TransportStatus / CargoType / ロール名 / BC 数）、(2) 設計と実装の乖離（Handling BC、WireMock 契約テスト、JPA 記述）、(3) 業務上必須の画面欠落（荷受人入力・通関・例外登録）と英語 enum 表示の常態化、という 3 系統の問題が横断的に検出された。実装フェーズでの手戻り再発を防ぐため、重要度「高」から是正すべきである。

## 懸念事項（横断）

- RDS 接続数上限（10 タスク×20 接続=200）により RDS Proxy が実質必須。Auto Scaling の前提条件として明示すべき（アーキテクト）
- 同期イベント（ApplicationEventPublisher）のリスナー失敗時リカバリ経路が未設計。SLA 99.9% との整合要検討（アーキテクト）
- 公開追跡 API 1,000 RPS / 99.99% は Read Replica / 別サービス分離の第一候補（アーキテクト）
- 監査ログ audit_logs（5 年保持）のテーブルが data-model に不在。CloudWatch Logs のみで法令要件を満たすなら明記が必要（アーキテクト、PM）
- カメラスキャンのフォールバック（非対応端末・権限拒否・スクリーンリーダー）未記述（デザイナー）
- domain-model.md のユビキタス言語テーブルに文字化けあり。要修正（PM）
- 実装コードに RBAC が一切存在しない（先行定義自体は問題なし、実装着手時の要確認事項）（アーキテクト）
- ルートの `test-results/`、`tmp/` 配下の別リポジトリ複製が CI グロブに拾われるリスク。`.gitignore` 確認推奨（テスター）
