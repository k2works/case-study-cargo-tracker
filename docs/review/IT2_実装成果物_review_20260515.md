## 総合評価

IT2 は「Axon 5.1 Event Sourcing をマイクロサービス分割の中で実装し、End-to-End で動かせる状態に到達した」点で大きな前進です。ADR-0007 / ADR-0008 の連鎖した意思決定記録、bootRun 死角を埋めるスモークテスト、UI からバックエンドまでの貫通実装、SonarQube Quality Gate PASS まで含めて、技術的にも品質的にも IT2 受入条件を満たしています。

一方、(1) Controller の翻訳ロジック肥大化と Form コンポーネントの ボイラープレート重複、(2) PIT 未稼働で主指標未達成、(3) Aggregate 登録の死角を本質的に塞ぐ統合テスト不在、(4) 業務利用に耐えない入力 UI（荷主 ID 数値直入力、危険物コード フリーテキスト、日付・寄港地連続性検証なし）、(5) 一部ドキュメントの陳腐化、の 5 領域に IT3 で着手すべき改善余地があります。

## 重要度「高」の対応方針

IT2 受入条件は達成済みのため、上記 H1-H13 は **IT3 以降の改善 backlog** として扱う。ただし以下は IT3 早期に着手すべき:

- **H8 / H9（ドキュメント陳腐化）**: 数十分の作業で即対応可能。IT2 終了処理の一部として今すぐ修正
- **H11 / H12 / H13（業務上の安全に直結する入力検証）**: IT3 の最優先項目として US24 改善ストーリーに含める
- **H3（PIT 導入）**: IT3 タスク 7.2 として明示済み。IT3 開始時に対応
- **H6（ArchUnit）**: trackingms / handlingms 着手前（IT5 前）には必須

## IT3 への申し送り

このレビュー結果から、IT3 で優先的に対応すべき項目を以下にまとめる。

1. **業務利用に耐える入力検証**（US24 改善ストーリー）
   - 荷主インクリメンタルサーチ、IMO クラス/UN 番号バリデーション、温度範囲チェック、出発日<到着日、寄港地連続性
2. **PIT 75% 主指標達成**（IT2 タスク 7.2 持越し）
3. **アーキテクチャ強制機構**
   - ArchUnit でパッケージ間依存ルール検証
   - `@SpringBootTest` + 実 CommandGateway スモーク統合テスト
4. **ドキュメント陳腐化の解消**（IT2 終了処理の一部として即対応）
   - e2e/README.md、運用手順書 §7、ADR-0007 のクロスリンク追記
5. **コード設計改善**
   - DTO → VO 変換を Assembler に分離
   - フォームステート管理を `useReducer` or `react-hook-form` に置換
