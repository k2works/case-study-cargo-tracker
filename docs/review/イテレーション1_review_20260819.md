# イテレーション 1 開発成果物レビュー

実施日: 2026-08-19
対象: `git diff 11f48786e..HEAD`（15 コミット / 137 ファイル）
対象ストーリー: US26（ログイン）US27（ログアウト）US31（アカウント保護）US02（荷主登録）

## 総合評価

ヘキサゴナル 4 層の依存方向・BC 独立性・ADR-004 の分担は、宣言ではなく**実行される検査**（ArchUnit・破壊検証・メタテスト）に落ちており、IT1 の目的（型の確立と品質ゲートの実配線）は達成できています。

一方で、**全テストが緑のまま素通りした欠陥が 3 件**ありました。いずれもフロントの検証が MSW モックで完結していること、および「検査を入れたこと」と「検査が働くこと」の差から生じています。

| # | 欠陥 | なぜ緑をすり抜けたか |
| :--- | :--- | :--- |
| 1 | 認証トークンが一度もリクエストに載らない | フロントの検証がモック越しで、ヘッダを見ていなかった |
| 2 | ロック解除後の 1 回の誤入力で即再ロック | 固定 Clock では時間を進められず、解除後の経路を通れなかった |
| 3 | 担当外ロールのダッシュボードが全部行き止まり | ルーティングとナビゲーションの整合を誰も見ていなかった |

## 懸念事項（IT2 以降で判断が要るもの）

- **Gateway をバイパスできないことが、どこでも検査されていない**（architect）。ADR-004 が前提とし、ネットワーク層で担保するとしているが、その担保を確かめる手段がない。サービスが 2 → 6 に増える前に、運用側の検査として持つべき
- **荷主の編集ストーリーが計画に無い**（user-representative）。実務で最も頻度が高いのは新規登録ではなく「打ち間違いを直す」。誤りが溜まったまま予約機能に進むことになる
- **法人荷主を US03 まで登録させるか**（user-representative）。契約番号・割引率が空の法人が溜まると、US03 で全件の追加入力が発生する。営業所への案内を決める必要がある
- **モックが安全網を無効化する構造**（programmer / tester）。E2E がモック相手である限界の線引きを test_strategy に明文化しないと、「E2E が緑だから大丈夫」と読み違えられる
- **無操作タイムアウトの要否**（user-representative）。共用端末で開いたまま離席した場合の扱いが決まっていない
