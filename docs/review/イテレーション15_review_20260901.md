# イテレーション 15 マルチパースペクティブレビュー

| 項目 | 内容 |
| :--- | :--- |
| 対象 | IT15（US36 例外を含む業務シナリオ・US37 ランダム継続実行）＋ IT14 から送った負債 10 件 |
| 実施日 | 2026-09-01 |
| 範囲 | `git log b3ace1551..HEAD`（simulationms 全体・trackingms・bookingms・billingms・shared・frontend・ops・docs） |

## 実施方法について（正直に記録する）

**5 視点のうち、独立したレビューが返ってきたのは利用者代表 1 つだけである。**

programmer / tester / architect / technical-writer の 4 体は、起動から 2 時間以上
経っても結果を返さなかった（3 度の催促にも応答なし）。**待ち続けるより、担当分を
自分で実施して正直に記録する方を選んだ**——ただし、**自分が書いたコードの自己
レビューは、独立したレビューより弱い**。見落としの可能性はレビュー結果を読む人が
差し引いて読む必要がある。

実際、利用者代表が挙げた 7 件のうち **6 件は自分では見つけられていなかった**。
自己レビューの限界がそのまま表れている。

| 視点 | 実施者 | 結果 |
| :--- | :--- | :--- |
| 利用者代表 | 独立したレビュー | **高 7 件・受入基準の未達 4 件を指摘**。対応後に受け入れ判定 |
| アーキテクト | 自己レビュー（代替） | ADR-031 の決定 6 件を 1 つずつ壊して赤を確認 |
| テスター | 自己レビュー（代替） | 受入基準 12 件とテストの対応を突合 |
| プログラマー | 自己レビュー（代替） | 実装を読み直し、**US37-1 が実質成立していない**ことを発見 |
| テクニカルライター | 自己レビュー（代替） | マニュアルの表が実態と食い違っていた（利用者代表の指摘と重複） |

## 指摘と対応

### 高（利用者代表・7 件）

| # | 指摘 | 対応 |
| :--- | :--- | :--- |
| 1 | **一覧の分母が選択中シナリオ固定**（US36-4 未達）。完了した誤配が「18 / 14 工程」と出る。毎朝ありもしない障害を追う | **対応**。行ごとの実行のシナリオから取る |
| 2 | **実行間隔が効いていない**（US37-1・2 未達）。保存・表示にしか使われず、1 本終われば 1 秒で次が始まる | **対応**。前の開始からの経過を見る。進む時計のテストで固定 |
| 3 | **設定を画面から変えられない**（US37-2 未達）。「例外を多めに出して見せる」調整ができない | **対応**。間隔・同時実行数・例外の割合の入力欄 |
| 4 | **営業の予約一覧・経理の精算書一覧に混ざる**。支払期限超過に架空の未入金が積み上がり、督促の判断を誤る | **対応**。予約は SQL で（件数にも同じ条件）、精算書は `invoice.simulated`（V7） |
| 5 | **統計から次に押すものがない**（US37-8）。50 件の一覧を目で開いて回ることになる | **対応**。工程名をリンクにし、その工程で落ちた実行だけに絞る |
| 6 | **停止処理中から戻らない**。1 件詰まると停止も新規開始もできず、復旧が Pod 再起動だけ | **対応**。進行中件数を表示し 15 分で見切る。**進行中は止めない**（決定 4 維持） |
| 7 | **落ちた実行に翌朝辿り着けない**（直近 50 件） | **IT16 へ**。5 で統計からは辿れるため急ぎでないとレビュアーも同意 |

### 高（自己レビュー・3 件）

| # | 指摘 | 対応 |
| :--- | :--- | :--- |
| 8 | **生成器が選んだ入力が業務 API まで届いていない**（US37-1 が実質シナリオしか効かない）。予約登録は固定値を送っていた | **対応**。引き継ぎに載せ、`GeneratedInputReachesBusinessApiTest` で固定 |
| 9 | **貨物種別によって要る入力が変わる**。冷蔵は保管温度、危険物は危険物申告。危険物クラスはコードで送る（実環境 23 件） | **対応** |
| 10 | **航海が受け入れる貨物種別が固定**。冷蔵・危険物の実行は経路候補が 0 件（実環境 18 件） | **対応** |

### 中（利用者代表・対応方針を明記）

| 指摘 | 方針 |
| :--- | :--- |
| **停止した瞬間に種が画面から消える** | IT16。過去セッションの一覧が要る |
| **統計の「実行中」が減らない** | **対応済み**。`SimulationRun.STALE_AFTER` / `abandoned()` に判定を 1 つ置き、「中断」として分けて数える |
| キャンセル承認待ち・荷役・通関の一覧に架空の案件 | **IT16（最優先）**。それまでは**夜間の継続実行を禁じる運用**をマニュアルに明記 |
| 実行一覧にセッション・種の列がない | IT16 |
| セッションの残り進行中件数が出ない | **対応済み**（停止処理中に表示） |

### 低

- 経路設計者の航海一覧に `V-SIM-` が溜まる。**意図して見せている**（隠すと経路候補から消える）。「シミュレーション由来を隠す」切り替えは IT16 以降
- 種で再現できるのは「シナリオと入力の列」まで。**ADR-031 に「この決定の前提の外にあるもの」として記載済み**

## ADR-031 の決定と検査の実効性

**6 件すべて、実装を壊すと検査が赤になることを確認した**（Try 5「検査を書いたら、その場で壊して赤を見る」）。

| 決定 | 壊した箇所 | 結果 |
| :--- | :--- | :--- |
| 1 種から乱数器を作り直す | `Seed#newGenerator` が毎回新しい種を使う | **赤** |
| 2 スケジューラは内に置く | 上限の判定を外す | **赤** |
| 3 上限（前半） | `ContinuousRunPolicy#allows` が常に true | **赤** |
| 3 ヘルスチェック除外（後半） | `AsyncContinuousRunner#running` が常に 0 | **赤** |
| 4 停止は新規の開始だけ | 進行中があっても即 `STOPPED` | **赤** |
| 5 例外は実際の操作 | 誤配の荷降しを予定どおりの港にする | **赤** |
| 6 二重実行の拒否は手押しだけ | 手で押す実行の拒否を外す | **赤** |

| 例外シナリオ 5 種 | すべて通過（誤配は 18 工程） |

## IT16 への送り（利用者代表の提示順）

1. **キャンセル承認待ち・荷役・通関の一覧から `SIM-` を外す**（最優先）。それまでは夜間の継続実行を禁じる運用で守る
2. 落ちた実行への到達性（直近 50 件・日付での絞り込み・過去セッションの一覧と種）
3. 実行一覧にセッション・種の列
4. `SONAR_ADMIN_TOKEN` の設定と Hotspot の承認
5. 独立したレビューが返らなかった 4 視点の実施
