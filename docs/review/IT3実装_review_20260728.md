# IT3 実装 マルチパースペクティブレビュー（2026-07-28）

対象コミット範囲: `ruby/take-1/v0.1.0..HEAD`（Routing Context の US24/US25/US07/US08、Location 共有カーネル、外部経路 ACL）。5 つの XP 視点で並列レビューを実施した。

## サマリー

- **クローズ前対応済み（高）**: Schedule の時系列連続性検証、RouteCandidate の transit_days 型正規化、外部 ACL の 5xx/不正 JSON フォールバック、経路割り当て画面のオーファン導線、Location 未配線の正直な記述化、architecture_backend の ADR-0004 整合。
- **次イテレーション対応（Try に反映）**: 楽観ロック（voyages）、Location 実在検証の配線、経路候補への到着日/費用/運送会社表示、航海登録の入力補助（港サジェスト・日時ピッカー・多区間）、US25 差分確認、US08 寄港地接続評価、RouteCandidate 公開ビュー射影、命名統一（ExternalCargoRoutingService）・README 更新。

## 視点別指摘と対応方針

### プログラマー（コード品質）

| # | 深刻度 | 指摘 | 対応 |
|:--|:--|:--|:--|
| H-1 | 高 | Schedule が区間の時系列連続性を未検証（タイムトラベル可） | **対応済み**: `validate!` に時系列チェック追加 |
| H-2 | 高 | 外部の transit_days 文字列で期限判定が TypeError→500 | **対応済み**: RouteCandidate で `to_i` 正規化 |
| M-1 | 中 | voyages に楽観ロックなし（更新のロストアップデート） | 次 IT: lock_version 導入 |
| M-2 | 中 | 経路候補の期限判定が「今日」起点で航海出発日を無視 | 次 IT: 候補ごとの実出発日で判定 |
| M-3 | 中 | RegisterVoyage/UpdateSchedule の重複・register の二重責務 | 次 IT: reconstitute 分離 |
| M-4 | 中 | Location 参照整合が未担保（未登録地点で登録可） | 次 IT: LocationDirectory 検証配線 |
| L-1〜L-3 | 低 | 既定 URL の暗黙挙動・cop の Include 依存・多区間 origin | 随時 |

### テスター（テスト品質）

- **対応済み（高）**: 時系列違反・transit_days 文字列・ACL 5xx/不正 JSON のテストを追加。
- **次 IT（高）**: US25 差分表示・キャンセルの検証、US08 寄港地接続可能性評価（フォールバックが直行のみで stub がすり抜け）→ 実装とテストを次 IT。受入基準側に IT スコープを明記。

### アーキテクト（構造）

| 深刻度 | 指摘 | 対応 |
|:--|:--|:--|
| 高 | Location 共有カーネルが実消費ゼロ（LocationDirectory 未配線） | **対応済み（記述）**: 未配線を正直に明記し IT4 で配線。VO 埋め込み回避方針は妥当 |
| 中 | `calculate_route_candidates` が内部 VO を境界外へ素通し（privacy の実質漏れ） | 次 IT: RouteCandidate 公開ビュー射影 |
| 低 | architecture_backend の RouteCandidate 記述が ADR-0004 未反映 | **対応済み**: US08 行を ADR-0004 に整合 |
| 低 | 一時/永続 RouteCandidate の構造不一致・フォールバック全件走査 | IT7 着手前に統合方針を ADR 追補 |

- 良好点: ACL 層配置・Booking→Routing の公開 API 編成・privacy 実効化・カスタム cop は規律が高い。

## 結論

高優先の**正しさ（時系列検証・型正規化・ACL 堅牢化）・DoD 到達性（経路割り当て導線）・正典整合**はクローズ前に解消した。残る指摘は業務 UX 改善（候補情報・入力補助・検索体験）と設計硬化（楽観ロック・Location 配線・命名統一・RouteCandidate 射影）であり、次イテレーションの Try に反映して計画的に返済する。特に「動くが業務では回らない」UX ギャップ（到着日・費用・運送会社・導線）は IT4 の優先事項とする。
