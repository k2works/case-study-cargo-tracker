# レビュー結果: Rails 版設計ドキュメント（2026-07-07）

## レビュー対象

- `docs/design/` 配下の全 10 ドキュメント
  - architecture_backend.md / architecture_frontend.md / architecture_infrastructure.md
  - data-model.md / domain-model.md / ui_design.md
  - test_strategy.md / non_functional.md / operation.md / tech_stack.md
- レビュー方式: XP エージェント 5 名（xp-product-manager / xp-architect / xp-interaction-designer / xp-tester / xp-user-representative）による並列マルチパースペクティブレビュー

## 総合評価

DDD + ヘキサゴナル + CQRS を Rails 8 のイディオム（PORO ドメイン層 + Active Record リポジトリ + Packwerk 境界 + Hotwire SSR）へ翻案する設計思想は、全エージェントが「実現可能かつ妥当」と評価しており、OOUX に基づく UI・公開追跡ページ・全環境 PostgreSQL 統一など実務価値の高い判断も多い。一方で、**Java 版からの翻案過程で生じたドキュメント間の構造的不整合**（コンテキスト数 6/7/8 の分裂、Packwerk パス 3 通り、SQLite/Selenium/htmx/Devise の翻案漏れ、US 番号ズレ、BookingStatus の齟齬）が複数の視点から独立に指摘されており、実装着手前に SSOT を確定して解消することが最優先課題である。

### 評価サマリー

DDD + ヘキサゴナル + CQRS を Rails のエコシステムへ翻案する方針は技術的に実現可能かつ妥当。個々の技術選定は Rails 8 のイディオムに沿っている。一方で 10 ドキュメント間の整合性に構造的な破綻があり、「コンテキスト数」「Packwerk パス」「テスト DB」「E2E ドライバ」の 4 点は実装着手時に必ず手戻りを生む。設計思想レベルでは「変更を楽に安全に」を満たすが、矛盾が残ったまま実装すると境界の定義が揺れて逆に変更を危険にする。

### 良い点

- DI コンテナを使わず「コンストラクタ注入 + デフォルト引数 + 明示的組み立て」に落とした判断は Rails イディオムとの乖離を最小化する良い選択。
- `Cargo`（PORO）と `CargoRecord`（Active Record）の分離・相互変換方針が一貫している。
- CQRS Read Model を `Data.define` の不変オブジェクトで返す設計は自然。
- 同期イベントのトランザクション境界への注意喚起と Transactional Outbox への移行見通しが明記されている。
- 全環境 PostgreSQL 統一は環境差異バグの排除として正しい。
- 非機能要件が ISO/IEC 25010 準拠で SLA/SLO を階層化し測定可能な形で定義されている。

### 改善提案

- 【重要度: 高】コンテキスト数が 6・7・8 の 3 通りに分裂。Shipper と Estimation の扱いを確定し全ドキュメントを一致させる。
- 【重要度: 高】Packwerk のパック配置パスが 3 通りに矛盾（`packs/*` / `app/domains/*` / `app/packages/*`）。`packs/<context>/app/...` に統一推奨。SimpleCov のグループ正規表現も連動。
- 【重要度: 高】architecture_backend.md にテスト DB「SQLite」が残存。全環境 PostgreSQL 方針と矛盾。
- 【重要度: 高】architecture_backend.md の E2E が「Selenium」。他ドキュメントの Playwright と矛盾。
- 【重要度: 中】data-model.md に Devise が併記され Rails 8 標準認証の統一方針と矛盾。
- 【重要度: 中】test_strategy.md に「htmx の 30 秒ポーリング」という Java 版記述が残存。
- 【重要度: 中】「ドメイン層に Active Record 依存を持ち込まない」ルールは Packwerk 標準では検証できない。RuboCop カスタム cop か手動レビューでの担保を明記すべき。
- 【重要度: 低】マイグレーションのバージョン指定が `ActiveRecord::Migration[7.2]`。Rails 8.0 なら `[8.0]`。

### 懸念事項

- DomainEvents = `ActiveSupport::Notifications` は本来計装用途で、購読側例外の同期伝播・順序保証・型安全性が弱い。「なぜ専用 pub/sub gem ではないか」を ADR 化推奨。
- PORO ↔ Active Record 相互変換のボイラープレートコスト。「規律のためのコスト」受け入れを ADR に残すべき。Shipper・Estimation の切り出しが独立変更の単位に値するかは再検討の余地。
- Zeitwerk と Packwerk パスの整合。3 通りのパス表記のまま実装するとオートロードエラーが多発する。

### スコープ外の発見

- index.md が矛盾を追認しており SSOT の役割を果たせていない。
- 翻案元との差分管理の仕組みが無い。翻案チェックリスト（DB / E2E / テンプレート / 認証 / コンテキスト数）の運用ドキュメント化を推奨。
