# IT8 マルチパースペクティブレビュー（2026-06-05）

## サマリ

IT8 は計画 8/8 SP（A1 ShedLock / A2 SendGrid / A3 RestShipperInfoAcl / A4 PaymentDetailRecorded）を完全達成し、加えて ADR-0020（決済機関 webhook 受信設計）を起票した。本イテレーションの主目的「本番デプロイ可能な状態に仕上げる」は概ね達成されている。一方で、**(1) WireMock 統合テストが SendGrid SDK の host 上書き仕様の制約で trackingms / billingms 両方とも未実装になり Mockito で代替している、(2) 部分入金対応（PARTIALLY_PAID）は ADR-0020 で起票したが IT9 持ち越しのため決済機関 webhook 自動化の業務効果はまだ得られていない、(3) IT8 マーカー棚卸し追加項目（1.4-1.10）の進捗が未消化** が残課題として残る。これらは IT9 以降のフォローアップとして明示する。

## ふりかえり所感

- **集約発火型（ADR-0012）の堅実な拡張**: ApplyDiscount manualRate + PaymentDetailRecorded 補完 event の連続 apply は ADR-0012 を素直に拡張しただけで、二段イベントを再導入することなく所期の業務要件を満たした
- **adapter パターン（ADR-0015）の威力**: ShipperInfoAcl の Rest / Stub 切替が @ConditionalOnProperty + @ConditionalOnMissingBean で完結し、フィードバック「割引適用時の bookingms 障害耐性」を S23 UI 改修まで含めて 2 サブタスクで実現できた
- **WireMock 統合の知見**: SendGrid SDK の URIBuilder 仕様で host port 指定不可な制約を発見、Resilience4j + Spring AOP は `spring-boot-starter-aop` 必須、@Cacheable と @CircuitBreaker の AOP order は CacheInterceptor が外側で動く（明示的な aspect order 設定なしで意図通り）。これらは IT9 以降の WireMock テスト設計に再利用可能
