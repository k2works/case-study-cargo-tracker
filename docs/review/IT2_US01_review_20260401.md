## 総合評価

DDD・ヘキサゴナルアーキテクチャの規律は高水準。テストピラミッドも意識的に構成されている。
しかし **本番起動クラッシュ候補のバグ**・**バリデーション UX の無言の失敗**・**受入条件 AC5/AC6 の未実装**が要対応。

## 受入条件充足状況

| AC | 内容 | 状況 |
|----|------|------|
| AC1 | 5 項目入力（出発地・目的地・希望期限・貨物種別・重量） | ✅ 実装済 |
| AC2 | ルート照会・複数候補表示 | ✅ 実装済（stub） |
| AC3 | 経由港・所要日数・料金・航海番号表示 | ✅ 実装済 |
| AC4 | 見積番号発行・保存 | ✅ 実装済 |
| AC5 | 希望期限超過通知 | ⚠️ 部分的（エラーメッセージはあるが期限適合の可視化なし） |
| AC6 | 接続失敗時代替候補表示 | ❌ 障害 vs ルートなしが区別できない |

## xp-programmer レビュー（コード品質）

### 評価サマリー

DDD の集約・値オブジェクト・ドメインイベントが丁寧に実装されており、テストピラミッドも意識された構成。一方で Web 層の DRY 違反と `QuoteNumber.generate(UUID)` の設計意図の揺れが気になる。

### 良い点

- `reconstitute` と `issue` の明確な分離（再構成時にドメインイベントを発行しない設計）
- `Collections.unmodifiableList` による不変性保護（コピー → unmodifiableList の二段構え）
- `QuoteCondition` の自衛的バリデーション（`weightKg.compareTo(BigDecimal.ZERO) <= 0` まで値オブジェクト自身が守る）
- テストの充実（ドメインユニットテスト → Web レイヤー統合テストまで TDD サイクルが外から内へ正しく回っている）
- コンストラクタインジェクションの一貫した使用

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | `QuoteWebController` | `cargoTypes` の `model.addAttribute` が 3 箇所に重複 → `@ModelAttribute` メソッドに集約 |
| 高 | `Quote.issue` | `QuoteNumber.generate(UUID.randomUUID())` の UUID 生成責務が `issue()` に漏れている → 引数なし `generate()` に変更（YAGNI） |
| 中 | `RegisterQuoteCommandService` | ルート空チェックが service / domain の 2 箇所で重複 |
| 中 | `QuoteWebController.detail` | UUID パースロジックを `QuoteId.fromString()` ファクトリに閉じ込める |
| 低 | `@Profile("!product")` | `product` という命名が `prod` と混同されやすい |
| 低 | `StubQuoteRouteProviderAdapter` | condition を無視するため「ルートなし」シナリオをスタブでテストできない |

### 懸念事項

- `Quote.equals/hashCode` 未定義（参照比較になる）
- `QuoteNumber` の先頭 4 文字だけで衝突リスクあり
- Flash Attribute (`createdQuoteNumber`) のリダイレクト後検証なし

## xp-tester レビュー（テスト品質）

### 評価サマリー

テストピラミッドの各層（ユニット → `@WebMvcTest` → 統合 → E2E）が意識的に構成されており基盤設計は良好。統合テストのテスト責任混在と E2E テストのデータ汚染リスク・ログインボイラープレートの重複に改善の余地あり。

### 良い点

- `PostgreSQLIntegrationTestBase` のシングルトンコンテナパターン（テスト実行時間の大幅短縮）
- `@Transactional` による DB 状態のロールバック
- 認証フローの E2E テスト（未認証アクセスの検証）
- E2E テストの Step コメントによる可読性
- `@DisplayName` の日本語活用（テスト名が仕様として読める）

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | `QuoteWebE2ETest` | `@Transactional` なし → テスト間データ汚染リスク。`@AfterEach` でクリーンアップが必要 |
| 高 | `QuoteWebE2ETest` | `getRedirectedUrl()` の null チェックなし → NPE でテストが不明瞭に落ちる |
| 高 | `QuoteRegisterIntegrationTest` | `NoRouteAvailableException` のハンドリングが統合テストで未検証 |
| 高 | `QuoteRegisterIntegrationTest` | `QuoteNotFoundException` → 404 の統合検証が欠落 |
| 中 | `QuoteWebE2ETest` | ログインボイラープレートが 4 テストで重複 → `@BeforeEach` に集約 |
| 中 | `QuoteRegisterIntegrationTest` | `redirectedUrlPattern("/quotes/*")` が緩すぎ → UUID 形式検証に強化 |
| 中 | `QuoteWebE2ETest` | `containsString("見積")` が弱すぎ → `"見積一覧"` + `"見積番号"` で構造確認 |
| 低 | `QuoteRegisterIntegrationTest` | サービス直接呼び出し + MockMvc の混在はトランザクション境界が不明確 |

### 懸念事項

- UN/LOCODE 形式（5 文字英数字）のバリデーション・テストなし
- `requestedArrivalDate` に `@FutureOrPresent` 制約なし
- `QuoteRegisterIntegrationTest` でシードデータ無効化を宣言していない

## xp-architect レビュー（設計整合性）

### 評価サマリー

ヘキサゴナルアーキテクチャの依存方向は全体的に正しく守られており、コンテキスト間のクロスインポートも皆無という点で設計の規律は高い水準。ただし `RoutingConfig` の `@Profile("!product")` による起動クラッシュ候補のバグと `WireMockQuoteRouteProviderAdapter` という命名の意味的逆転が重大リスク。

### 良い点

- コンテキスト境界の純粋性（quote / routing 間のクロスインポートがゼロ、ACL パターン）
- 集約の factory メソッド分離（`issue()` と `reconstitute()` の明確な分離）
- 値オブジェクトの防御的コンストラクタ（全 VO で不変条件を検証）
- アウトバウンドポートの正しい配置（`application/internal/outboundservices`）
- コマンド/クエリサービスの明確な分離（CQRS の実践）
- `QuoteResponse.from()` ファクトリメソッドによる DTO 組み立て責務の分離

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | `RoutingConfig` | `@Profile("!product")` で product 起動時に `NoSuchBeanDefinitionException` クラッシュ。`RouteSearchService` に `@Service` を付与するか RoutingConfig から @Profile を除去 |
| 高 | `WireMockQuoteRouteProviderAdapter` | 命名が逆転（本番アダプターなのに WireMock）。`RestTemplate` も `new` で Spring 管理外。`RouteProviderRestAdapter` に改名し `RestClient` で実装 |
| 高 | `QuoteRepositoryImpl.findAll()` | N+1 クエリ（Quote ごとに RouteOption を個別 SELECT）。MyBatis `<collection>` マッピングで一括取得に変更 |
| 中 | `CargoType` enum | `DANGEROUS_GOODS` vs `HAZARDOUS` が不一致。明示的な変換メソッドを早めに定義 |
| 中 | `QuoteRepositoryImpl` | `ObjectMapper` がスタティックフィールドで Spring 管理外。コンストラクタインジェクションに変更 |
| 低 | `DomainEvent.java` | `quote` コンテキスト内に閉じており他コンテキストで重複定義になる可能性。`shared` への移動を検討 |
| 低 | `FindQuoteQueryService` | Write Model を Query にも流用。ADR として意思決定を記録推奨 |

### 懸念事項

- `product` プロファイルでの起動テストが CI に存在しない → 本番デプロイまで検出不能
- 外部サービス障害と「ルートなし」が `NoRouteAvailableException` で区別できない
- スタブデータが quote / routing の両コンテキストに散在（将来のシナリオテストで食い違いリスク）

## xp-technical-writer レビュー（ドキュメント品質）

### 評価サマリー

見積登録・詳細画面の UI ラベルと日本語バリデーションメッセージは全体的に明確。一方、UN/LOCODE という専門用語の説明不足と REST API の Swagger アノテーション未整備が主要課題。

### 良い点

- バリデーションメッセージが日本語で具体的（`@NotBlank`・`@DecimalMin` と連動）
- `CargoType` の `displayName` が UI・API 双方に露出（内部値と表示名の分離）
- detail.html の直行便表示（`（直行）` の分岐）
- `NoRouteAvailableException` のメッセージが出発地・目的地を含む
- `Quote.reconstitute()` の Javadoc で副作用を明示

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | `register.html` | `weightKg` に `required` 属性なし |
| 高 | フォーム全体 | UN/LOCODE の説明がプレースホルダーのみ → ヘルプテキスト＋コード検索リンク追加 |
| 高 | `QuoteRestController` | `@Operation`/`@Schema` なし → Swagger UI が空白 |
| 高 | REST API パス | `/api/quotes` だが設計図は `/api/v1/quotes` → バージョン不統一 |
| 中 | `requestedArrivalDate` | 過去日付の `min` 制限なし |
| 中 | `detail.html` | 概算料金が「円」固定（通貨前提が暗黙） |
| 低 | `OpenApiConfig` | デフォルト無効なのに README に注記なし |
| 低 | `Quote.java` | `issue()` の Javadoc に `@throws` 条件が未記述 |

### スコープ外の発見

- `CargoType` enum が `quote` と `booking` の 2 パッケージに重複定義

## xp-user-representative レビュー（ユーザー視点 / 業務適合性）

### 評価サマリー

基本的な入力フォームとルート候補表示は形になっており主要な流れは一応動く。ただし受入条件 AC5・AC6 が実質的に未実装であり、現場で使えるレベルには達していない。

### 良い点

- AC1：5 項目が揃っており、必須項目の `*` マークとバリデーション赤枠が適切
- AC3：経由港・所要日数・概算料金・航海番号がカード形式で見比べやすい
- AC4：登録直後に見積番号の成功メッセージが表示される

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | 出発地・目的地入力 | UN/LOCODE 直接入力は難易度が高い。港名検索・オートコンプリートが必要 |
| 高 | ルート候補一覧 | 希望着日に間に合うか一目でわからない。「✅ 間に合います」「⚠ 希望着日超過」表示が必要 |
| 高 | エラーメッセージ | ルート不在と外部障害を同じメッセージで返しているため対処不能 |
| 中 | 直行便の JPTYO 表示 | viaLocodes に出発地が含まれると「直行」判定が正しく動作しない可能性 |
| 中 | 見積一覧 | ルート候補数の列がない |
| 低 | 重量入力 | kg のみ。t（トン）換算の補助表示があると便利 |

### 懸念事項

- 「今日から所要日数後の日付」が自動計算されず手動暗算が必要
- 見積の有効期限・登録日時が非表示
- 同じ条件で再見積できない

### スコープ外の発見

- 「このルートで予約する」導線がない（US07 で対応予定）
- 荷主との紐付けなし
- 帳票 PDF 出力なし

## xp-interaction-designer レビュー（UI/UX デザイン品質）

### 評価サマリー

Bootstrap 5 の基本構造を踏襲し、業務フローに沿った情報設計は概ね適切。ただし、フォームバリデーション UX の実装に既存 booking 画面との重大な不整合があり、WCAG 2.1 AA に影響する複数のアクセシビリティ欠落が集中している。

### モダンデザイン準拠状況

| 観点 | 評価 | 詳細 |
|------|------|------|
| カラーシステム | ⚠️ 部分的 | Bootstrap 5 Semantic Color は適切に使用。カスタム CSS 変数未活用 |
| タイポグラフィ | ⚠️ 不整合 | h4/h5/h6 の見出しスケールが各画面で統一されていない |
| Elevation & Surface | ✅ 適切 | `card shadow-sm` の一貫した使用 |
| コンポーネント一貫性 | ❌ 重大 | booking では `is-invalid` 使用、quote では未使用 |
| スペーシング | ✅ 良好 | Bootstrap Spacing ユーティリティが一貫 |
| レスポンシブ | ⚠️ 問題 | navbar toggler ボタンが全ファイルで欠落。モバイルでナビが崩れる |
| ダークモード | ❌ 未対応 | `bg-white`/`bg-light` のハードコードがダークモード切替を阻害 |
| 状態デザイン | ⚠️ 部分的 | 空・成功・エラーは定義済み。ローディング状態未定義 |

### 改善提案

| 重要度 | 箇所 | 内容 |
|--------|------|------|
| 高 | `register.html` 全入力 | `is-invalid` クラスバインドが欠落 → バリデーションエラーが視覚的に表示されない |
| 高 | 全3ファイル | `<html lang="ja">` 欠落（WCAG 3.1.1 Level A 違反） |
| 高 | 全3ファイル | `<main>` ランドマーク欠落（WCAG 2.4.1 Level A 違反） |
| 高 | 全3ファイル | navbar モバイル toggler 欠落 → lg 未満でナビ消失 |
| 高 | `register.html` | `cargoType` select と `weightKg` input に `required` 属性欠落 |
| 中 | 全アラート | `role="alert"` / `aria-live` 欠落（動的表示時の読み上げ不可） |
| 中 | LOCODE 入力 | `pattern="[A-Z]{2}[A-Z0-9]{3}"` と `form-text` ヒント欠落 |
| 中 | `list.html` テーブル | `scope="col"` 欠落（WCAG 1.3.1） |
| 中 | `detail.html` | ルート候補 0 件時の空状態メッセージ未定義 |
| 中 | `detail.html` | ナビバーのアクティブ状態欠落（list.html には付与済み） |
| 低 | `detail.html` | ルート選択 CTA ボタン欠落（次ストーリーへの導線） |
| 低 | `list.html` | 日付・重量の表示フォーマット（ISO 8601 → `yyyy/MM/dd`、カンマ区切り）|

## 統合優先度マトリックス

### 🔴 最優先対応（即時修正）

1. `RoutingConfig @Profile` クラッシュバグ → `@Service` 付与
2. `register.html` の `is-invalid` バインド欠落（booking パターンを踏襲）
3. 全テンプレート: `lang="ja"` / `<main>` ランドマーク / navbar toggler
4. `QuoteRepositoryImpl.findAll()` N+1 クエリ
5. `QuoteWebController` の `cargoTypes` DRY 違反（`@ModelAttribute` メソッド化）
6. `QuoteWebE2ETest` データ汚染・null 参照

### 🟡 中優先対応（今イテレーション中）

7. `detail.html` 希望着日適合表示（AC5）
8. `WireMockQuoteRouteProviderAdapter` リネーム（`RouteProviderRestAdapter`）
9. `CargoType` enum 翻訳メソッド定義
10. Swagger アノテーション追加・REST パス `/v1` 統一
11. 統合テスト追加（404 / `NoRouteAvailableException` ハンドリング）
12. UN/LOCODE `pattern` 属性 + `form-text` ヘルプテキスト

### 🟢 低優先対応（次イテレーション以降）

- `QuoteNumber.generate()` 引数なしに変更
- `QuoteId.fromString()` ファクトリメソッド追加
- `DomainEvent.java` を `shared` パッケージに移動
- 見積→予約 CTA 導線（US07 で対応予定）
- 見積一覧の日付・重量フォーマット改善
- フォーム二重送信防止
