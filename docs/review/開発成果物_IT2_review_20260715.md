# 開発成果物レビュー — IT2 貨物予約（US04/US05/US06）

- レビュー日: 2026-07-15
- 対象: Booking Context 実装（ドメイン/アプリ/インフラ/Web/テスト）・ADR-0007/0008・カバレッジゲート
- 対象コミット範囲: `fa5b7a4f^..HEAD`（feat 9 件・docs 反映含む）
- レビュー方式: マルチパースペクティブ（xp-programmer / xp-tester / xp-architect / xp-technical-writer / xp-user-representative 並列）

## 総合評価

IT2 は「不正状態を型で表現不能にする」F# ドメイン設計が徹底され、値オブジェクト・スマートコンストラクタ・関数レコードポート・ROP を的確に用いた良質な実装。テストピラミッドのバランスも健全で、カバレッジ（全体 91.9%/ドメイン 85.7%）と ArchUnit の BC 分離維持も達成している。一方で、(1) 状態更新リポジトリの楽観ロック未機能と冷凍/危険物往復の検証不足、(2) 境界値テストの欠落、(3) post-commit イベント基盤のバイパス（宣言と実態の乖離）、(4) 一覧→詳細の導線欠落・荷主 Guid 剥き出しという業務 UX の欠落、が要対応。多くは IT2 スコープ判断として意図的に保留したものだが、技術的負債と業務リスクの両面で IT3 着手前の対応が望ましいものを含む。

## 補足: レビュー中に発見した実障害（対応済み）

開発サーバー（`dotnet watch`）起動時にマイグレーション失敗（`duplicate column name: shipper_uuid`）を確認。dev DB（gitignore 対象）に `shipper_uuid` 列は存在するがジャーナル（SchemaVersions）に `0005` が未記録の不整合（過去の部分適用時に SQLite の DDL が即コミットされジャーナル記録前に中断したため）。ジャーナルへ `0005_shipper_uuid.sql` を記録して解消（既存データ保持）。恒久対策は不要（正常な forward-only 適用では再発しない一過性の状態）。
