# 予約管理画面 UI/UX レビュー結果

## レビュー対象

- 予約一覧画面（`/bookings`）— `booking/index.html`
- 予約登録画面（`/bookings/new`）— `booking/new.html`
- 予約詳細画面（`/bookings/{bookingId}`）— `booking/show.html`

## レビュー実施日

2026-04-06

## 総合評価

Bootstrap 5 を活用した実装で、基本的なアクセシビリティ（`aria-describedby`、`required`）が備わっており、モーダル確認フローも搭載されている。一方、荷主 ID・予約番号が UUID のまま表示されていること、重量に単位表示がないこと、温度単位が内部コード（CELSIUS）のまま表示されることが、業務用途での実用性を損なっている。これらはユーザーが情報の意味を解釈できない「読めないデータ問題」であり、優先的に改善すべきコロ助。

### 評価サマリー

Bootstrap 5 の基本機能（グリッド、バッジ、モーダル、フォームバリデーション）を適切に活用しており、レスポンシブ対応・アクセシビリティの基礎（aria-describedby, required）も備えている。一方で、UUID の生のまま表示・単位情報の欠如・内部コードの露出（CELSIUS）が、業務システムとして最低限必要な「情報を人間が読める形で提示する」要件を満たしていない。

### 良い点

- Bootstrap 5 のセマンティックカラー（text-bg-primary, text-bg-secondary 等）がステータスバッジに適用されており、視覚的なステータス分類が機能している
- `aria-describedby` と `required` 属性が主要フォームフィールドに付与されており、アクセシビリティの基礎が確保されている
- 動的な特殊フィールド（危険物・冷凍）の表示切り替えが JavaScript で実装されており、不要フィールドの入力ストレスを軽減している
- `table-responsive` による横スクロール対応と `table-hover` による行ハイライトで操作性が向上している
- モーダルによる「確定」「キャンセル」の二段確認フローは破壊的操作のガードとして適切

### モダンデザイン準拠状況

- Bootstrap 5 はデザインシステムとして採用されており、カラートークン・スペーシング・コンポーネントの一貫性は概ね保たれている
- 8px グリッド（`g-3`=16px、`py-4`=24px）に準拠しており、スペーシングリズムは適切
- Elevation 表現は `shadow-sm` + `card` で一貫している
- ダークモード未対応は現フェーズでは許容範囲

- 【重要度: 中】`new.html` 荷主・貨物種別・重量・日付・出発地・目的地に `<span class="text-danger">*</span>` を追加（危険物セクションは実装済み）

### 評価サマリー

予約の登録から確定・キャンセルまでの業務フローが画面として一通り実装されており、貨物担当者が基本操作を実行できる状態になっている。ただし、荷主が UUID で表示される点は致命的な問題で、現場の担当者はどの予約がどの顧客のものか確認できない。重量の単位表示漏れも業務確認に支障をきたす。

### 良い点

- 貨物種別（一般・危険物・冷凍）の動的フォームは業務の複雑性を適切に処理しており、業務担当者の入力負担を下げている
- モーダルによる確定・キャンセルの確認フローは、誤操作防止に有効。「この操作は元に戻せません」という警告テキストも適切
- 荷主ドロップダウンに「荷主名 (荷主コード)」形式で表示しており、登録時の選択は問題ない
- 空状態の表示「登録済みの予約はありません。」は明確で適切

### 改善提案

- 【重要度: 高】荷主 UUID を荷主名に変更（一覧・詳細）。現場の担当者は UUID を記憶しておらず、どの顧客の予約か判断できない
- 【重要度: 高】重量の単位「kg」を表示。貨物業務では単位の確認が安全上重要。1 トンと 1kg の混同は実害になる
- 【重要度: 高】温度管理の表示を「-25 ～ -18 ℃」形式に変更。「CELSIUS」は業務文書として不適切
- 【重要度: 高】予約番号の一覧表示を見やすく改善。36 文字 UUID では予約番号として機能しない
- 【重要度: 中】予約一覧に検索・フィルタ機能を追加（ステータス・荷主・日付）。件数が増えると業務効率が著しく低下する
- 【重要度: 中】出発地・目的地に都市名を補足。「JPTYO」だけでは荷主確認の際に場所が分からない
- 【重要度: 中】予約一覧の空状態に「予約を登録」ボタンを追加。次のアクションへの導線が必要
- 【重要度: 中】モーダルに対象の予約番号（短縮版）を表示。「この予約をキャンセルしますか？」より「予約 #ABC12345 をキャンセルしますか？」の方が誤操作防止になる
- 【重要度: 低】「荷主 ID」ラベルを「荷主」に変更（H4 適用時）
- 【重要度: 低】予約キャンセル後の一覧への自動遷移（または一覧画面への明確な導線）を検討
- 【重要度: 低】貨物種別の一覧表示列を追加（現在は一覧に表示されていない）
