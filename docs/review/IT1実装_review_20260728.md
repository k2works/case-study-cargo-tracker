# IT1 実装 マルチパースペクティブレビュー（2026-07-28）

対象: `apps/cargo-tracker`（IT1: US26/US27 認証・US02/US03 荷主登録・ウォーキングスケルトン）。
コミット範囲 `f2ba95f9^..HEAD`（ブランチ `typescript/take-1`）。
前提: 全 121 テスト green・SonarQube Quality Gate PASS・lint/typecheck/arch クリーン。

XP 5 視点（programmer / tester / architect / technical-writer / user-representative）で並列レビューを実施した。

## 総評

層分離・値オブジェクト・判別可能ユニオンによる認証結果表現・ロックポリシーの純粋関数化など、テスト容易性と変更容易性は高い水準。一方で **US02 荷主登録が受入基準の入力項目（住所・連絡先）を満たしておらず**、**登録後の荷主 ID が利用者に見えない**、**Email 重複時の既存荷主提示が未実装**という受入基準ギャップが複数視点で収束して指摘された。

### 低

- SWC(dev)/tsc(build) 二本立ての tech_stack 追記（architect）→ **対応**（ADR-006 に併記）

## 良い点（維持推奨）

- 判別可能ユニオンによる認証結果表現とロックポリシーの純粋関数化（テスト容易・明快）

- 認証を BC ではなく shared に配置した判断（横断的関心事として妥当、コメントで明示）
- `skeleton-reachability.e2e.spec.ts` のマトリクス駆動テスト（理想形）
- fake リポジトリで境界を切ったサービステスト
