# イテレーション 15 完了報告書

日付: 2026-08-11
対象: Release 2.0（精算）／US30 輸送中の予約キャンセルを承認する（5SP）

## エグゼクティブサマリー

**US30 を完了し、Release 2.0 が完成した。** 輸送中の貨物は、追跡管理者が陸揚げ地を決めて承認するまでキャンセルが確定しない。承認するとキャンセル料が算定されて請求書になり、却下すると輸送中のまま維持される。

**本イテレーションの中心は「コメントが仕様を語りながら実装が守っていない」欠陥の是正である。** 遷移表のコメントは「#9 輸送開始前のキャンセル。#10 輸送中のキャンセル（承認を伴う）」と書きながら、**表の中身は #9 と #10 を同じループで登録していた**。画面は `cancellable` でボタンを出し、押せば確定する。つまり**輸送中の貨物を営業担当者がボタン 1 つで消せた**。貨物は船の上にあり、どこで降ろすかを決めないままキャンセルすると、荷役の現場は行き先の無い荷物を抱える。

あわせて、**着手前の検証で見つけた構造的な穴 3 件**（X1 / X2 / X3）を先行して直した。3 件とも「このまま作ると受入基準に到達できない」ものである。

品質ゲートはローカル・CI・SonarQube のいずれも通過している（Quality Gate PASS。Bug 0 / Vulnerability 0 / Code Smell 0）。クローズ前のレビューが高 5 件を出し、**対応可能な高・中はすべて本イテレーション内で対応した**。

## 技術的成果

### ドメイン

- `CancellationRequest`（**エンティティ**。却下後の再申請で 1 予約に複数行が並ぶ）・`Decision`・`CancellationStatus`・`CancellationFeeRate`・`DischargeCandidates` を新設
- `BookingCommandType.APPROVE_CANCEL` を追加し、**遷移表の #9 と #10 を分けた**
- **料率は状態で決まる**（0% / 20% / 50%）。**知らない状態を 0% にしない** — 黙って 0 を返すと、引き渡し済みに「キャンセル料 0 円」と答える
- **申請時点の料率を保持する。** 承認が遅れて輸送が進んでも料率は上がらない
- **陸揚げ地は候補の中からしか選べない。** 候補は現在地の港と**まだ着いていない**寄港地（船は戻らない）

### 越境

- **状態の伝播をイベントにした**（`CargoCancelledEvent`）。承認するのは追跡管理者、請求するのは経理担当者であり、**承認画面の前にいる人はキャンセル料について何もできない**
- 運ぶのは**事実と料率だけ**である。金額の正典は Billing にあり、Booking から金額を送ると基準額が 2 つ生まれる
- ACL ポートを 2 本新設（`CargoCurrentLocation` / `ShipperContactPort`）。**どちらも問い合わせであり、状態を変えない**

### 永続化

- `booking_cancellation`（申請ごとに 1 行。**決着していない申請は 1 予約 1 件まで**を部分ユニーク索引で守る）
- `invoice.invoice_type` と `(booking_id, invoice_type)` の UK（**二重請求の防止は保ったまま**対象を狭めた）
- `invoice_reminder`（督促の記録）
- **承認したなら陸揚げ地がある・却下したなら理由がある**を `CHECK` で守る

### 画面

- キャンセル承認待ち（古い順）と承認画面（陸揚げ地はプルダウン）
- 予約詳細に申請フォームと履歴（**US36 の訂正・取り消しとは別の欄**）
- ダッシュボードに「キャンセル承認待ち」「発行待ち」のカード
- 請求書詳細に荷主の連絡先と督促の記録

## レビュー結果

5 視点のレビュー（[統合レポート](../review/IT15実装_review_20260811.md)）で **高 5 / 中 8 / 低 3 件**。**対応可能な高・中はすべて本イテレーション内で対応した。**

最大の発見は **ADR-009 の規則 2（購読側は `REQUIRES_NEW`）を、コードの半分が守っていなかった**ことである。自分が足した 1 本を直そうとして検査を書いた瞬間、**既存に 5 本の違反がある**ことが分かった。ADR を書いた後も、半分は守られないまま増え続けていた。

ほかに、**C4（N+1）とまったく同じ型を、C4 を返済した同じイテレーションで作っていた**こと、**catch を広く取りすぎて復元の例外を「見つかりません」に化けさせていた**ことが出た。
