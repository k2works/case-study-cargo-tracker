## Keep（うまくいったこと）

- **IT8 の Try を繰越の連鎖にせず 1 イテレーションで完済**。T43〜T47 の 5 Try をすべて消化。特に IT8 で「業務判断保留」とした補償費用の方向を業務判断（当社負担＝減算）で確定し実装・ADR に落とした。「正直な残記録 → 次 IT で回収」のサイクルが 2 イテレーション連続で機能。
- **符号規約をドメインの単一の真実点に閉じた**。`InvoiceLineItem#normalize_sign` に符号正規化を集約し、T45 の方向転換をこの 1 箇所の変更で完結。アプリ層・コントローラに符号ロジックが漏れていない（IT8 Problem の是正）。
- **seed の privacy バイパスを正攻法で解消**。`calculate_freight(issued_at:)` の clock 注入で、生 SQL の invoices 直接更新を公開ファサード経由に置換。BC 境界を尊重した設計（T46）。
- **自らの学びを DoD に制度化した**。IT8 の OVERDUE 塩漬け・符号取り違えという実インシデントを根拠に、「状態機械のガードは現場ケース起点」「不変条件は VO/集約に閉じる」をコーディングとテストガイドの設計 DoD に明文化（T43/T44）。学びが個人知から規律へ。
- **クローズ前レビューが実バグと偽陽性テストを捕捉**。tester が `remove_adjustment` の seq_number 負値インデックスによる末尾誤削除（実バグ）と、担当者記録の偽陽性テスト（`include("billing")` がページ装飾と偶発一致）を検出。ユニット緑をすり抜ける欠陥をクローズ前に是正。

## Problem（課題・負債の発生源）

- **受入基準「担当者・日時・理由」の"日時"を実装時に落とした**。T47b の監査証跡で adjusted_by/reason は実装したが adjusted_at（日時）を欠落。受入基準の逐語対応（IT7 Try の「受入基準 1:1」）が料金調整で徹底されず、レビュー（user-representative）で初めて露見。
- **監査証跡テストが偽陽性だった**。`include("billing")` はロール名がナビ・パスに必ず現れるため、担当者記録が画面に無くても緑になる無効なアサート。「文字列 include で受入基準を検証した気になる」典型的な偽陽性。
- **意味論的変更（COMPENSATION 加算→減算）を ADR なしで実装していた**。請求総額の符号が反転する構造相当の判断を IT8→IT9 で行ったが ADR 未起票。architect レビューで指摘され ADR-0005 を追補。
- **金額の符号反転を集約の public メソッド（`negate`）で露出**。MoneyAmount の責務を Invoice に持たせカプセル化を破っていた（`subtract` へ是正）。
- **ビューで状態機械を再判定していた**。取消可否を `payment_status == "PENDING" || "OVERDUE"` と直書きし、自ら定めた DoD（T43 の述語判定）と実装が矛盾。`cancellable` フラグでドメインに一本化。
