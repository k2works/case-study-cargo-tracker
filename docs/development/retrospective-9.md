## KPT 分析

### Keep（継続すべきこと）

#### 技術的成功事項

- **IT8 申し送り事項の即時解消**: IT9 冒頭でまず H-8（route.html への estimatedCost カラム追加）・H-9（show.html への cargoItinerary legs 表示）・SonarQube Quality Gate 確認を実施した。申し送り事項を最優先タスクとして組み込む習慣が引き続き有効だった
- **例外処理ドメインの段階的拡張**: IT7-8 で構築した Tracking コンテキストに `ExceptionType` 列挙型・`TrackingExceptionEvent` エンティティ・`RegisterExceptionCommand` を TDD で追加した。既存のコマンド/クエリ分離設計に自然に馴染み、コアドメインへの影響を最小化できた
- **escalation_flag によるビジネスルール表現**: 紛失（LOST）の場合に `escalation_flag = TRUE` を設定するビジネスルールをドメインモデル内で表現し、UI とインフラに一貫して反映させた。DDDの戦術的設計原則（ビジネスルールをドメイン層に集約）を実践できた
- **SonarQube Code Smell の即時修正**: IT9-改善スキャン実行後に 4 件の Code Smell（catch 変数の unnamed pattern 置換等）を即時修正し Quality Gate を PASS させた。品質ゲートをスキップせずに修正してから次のタスクに進む規律が定着している
- **E2E テストの例外シナリオ網羅**: `exception.spec.ts` に遅延・破損・紛失・escalation フラグの各シナリオをすべてカバーした。正常系だけでなく異常系（追跡番号不在等）も含めて網羅的にテストできた

#### プロセス的成功事項

- **計画期間前の完了**: Week 17-18（2026-05-02〜2026-05-15）の計画に対して 2026-04-23 時点で全主要タスクを完了した。AI ペアプログラミングによる高速開発サイクルが継続している
- **成功基準の全チェック達成**: 8 つの成功基準をすべてチェック状態にして完了できた（テストカバレッジ 80% を含む）
- **整合性検証による計画品質向上**: イテレーション計画作成後に設計ドキュメント（ドメインモデル・データモデル）との整合性検証を実施し、ExceptionType.LOSS→LOST・RecordExceptionCommand→RegisterExceptionCommand 等の不整合を計画段階で修正できた

### Problem（問題点）

#### 未完了事項・受入条件の部分充足

- **US18 推定到着日未実装**: IT8 から持ち越した「推定到着日が表示される（US18 AC2）」が IT9 でもスコープ外となり未実装のまま。IT10 へ継続持ち越し
- **E2E タスク 1.4 の未完了**: IT8-改善の E2E テスト（H-8・H-9 の受入条件を E2E で確認する booking.spec.ts 拡張）がタスクリスト上で `[ ]` のまま残存している。実質的には US19・US20 の E2E 内で例外処理フローの一部として確認済みだが、H-8・H-9 専用の E2E シナリオは未追加
- **メール通知の未実装継続**: US19・US20 の受入条件「荷主への通知が送信される」はメールインフラ未整備のため UI 上の通知記録のみで対応。本格的な通知機能は IT10 以降の判断事項として持ち越し

#### 技術的課題

- **branch カバレッジが 74% にとどまる**: instruction カバレッジ 80% は達成したが、branch カバレッジは 74% で目標の 80% に未達。例外処理の分岐（escalation_flag true/false 等）は E2E でカバーしているが、単体テストの分岐網羅が不十分な箇所が残存
- **H2 長時間稼働問題の継続**: アプリ再起動による回避策が継続中。PostgreSQL テスト環境への移行は IT10 リリース準備時まで先送り
- **IT5 レビュー指摘事項（H-1〜H-3・H-5・H-6）の蓄積**: IT9 でもスコープ外となり、技術的負債が引き続き蓄積している
