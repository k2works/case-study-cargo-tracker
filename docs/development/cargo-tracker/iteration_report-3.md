# イテレーション 3 完了報告書

## エグゼクティブサマリー

**IT3 は計画した 9 SP をすべて完了しました（達成率 100%）。3 イテレーション連続で 9 SP・100% です。**

**IT3 の成果は 2 つ目の Event Sourcing サービス（routingms）を立ち上げ、その形を検査で固定したことです。** 「bookingms と同じ形か」を文章ではなく `EventSourcedServicesHaveTheSameShapeTest` に落としました。static でないコマンドハンドラ・Processing Group の列挙・`ReplayIT` の存在・例外の対応表を機械的に見ます。3 つ目のサービス（trackingms・IT8）で同じ失敗を繰り返さないための仕掛けです。

**IT2 の引き継ぎ 12 件のうち 9 件を返しました。** とくに 2 回繰り越した「契約テストの往復」を、ゴールデン一致ではなく**購読側の表に実際に入ること**で閉じました。落とした 3 件は理由と行き先を先に決めています。

**欠陥を 34 件見つけて直しました**（開発中 5 件・レビュー 29 件）。**うち 5 件は実欠陥で、すべて並列レビューが見つけたものです。** 最も重いのは「サーバ側にロール認可が 1 つも無く、認証さえ通れば誰でも航海を登録でき、全荷主の予約一覧を読めた」ことでした。

## 技術的成果

### 新サービス routingms

- `Voyage` 集約（`@EventSourced(tagKey = "voyageNumber")`）・投影（V002〜V005）・クエリ・REST・S32/S33
- 一意性の三段（集約の存在確認 → 投影の UNIQUE → `attention_item`）を bookingms と同じ形で実装
- 投影の「丸ごと比較」は**ヘッダだけでは足りない**（レビューで判明）。寄港地の順序と受入貨物種別まで比べる

### 検査で固定した「形」

| 検査 | 何を守るか |
| :--- | :--- |
| `EventSourcedServicesHaveTheSameShapeTest` | ES サービスの形（static でないハンドラ・Processing Group の列挙・`ReplayIT`・例外の対応表） |
| `EveryServiceEndpointIsRoutedAndProtectedTest` | 全経路がルートに載り、認証で守られ、**要求ロールが宣言されている** |
| `DomainThrowsBusinessRuleViolationTest` | ドメイン層がプログラミングエラーを業務規則違反に化けさせない |
| `navigationMatchesUiDesign.test.ts` | ナビと正典が**双方向で**一致し、表示ロールも一致する |
| `screenTextHasNoStoryIds.test.ts` | 画面の文言に内部のストーリー ID が漏れない |
| `ContractEventRoundTripIT` | 契約イベントが実際に別サービスへ届く |
| `serviceDoesNotDependOnAnotherService`（ArchUnit） | BC が別 BC のパッケージを直接見ない |

### SonarQube

初回は `new_violations: 2` で FAIL でした。内容は `ReplayIT` の `Instant.now()`（実時計を使うと「出港済みを含めるか」の判定が実行時刻で変わる）で、**実質的な指摘**だったため固定時刻に直しました。

認可の実装後にもう一度回して `new_violations: 3`（文字列の重複 2・`null` を返す 1）が出たため、定数化と `Optional` 化で解消しています。

### 実欠陥 5 件（いずれも並列レビューが発見）

1. **サーバ側にロール認可が無かった。** 認証さえ通れば誰でも航海を登録でき、全荷主の予約一覧を読めた
2. **投影の「丸ごと比較」がヘッダだけで**、同じ航海番号の 2 件目で既存の航海の受入貨物種別が黙って広がった
3. **`VoyageNumber` が本番経路に載っておらず**、20 文字超が投影で落ちて Processing Group が止まる
4. **誤配案件が経路設計作業一覧に 1 件も出なかった。** 並び順・コメント・正典の 3 つが揃って対応済みに見えていた
5. **routingms の要確認項目に読み口が無く**、弾かれた登録が誰にも見えなかった
