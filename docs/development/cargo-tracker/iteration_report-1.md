# イテレーション 1 完了報告書

## エグゼクティブサマリー

**IT1 は計画した 9 SP をすべて完了しました（達成率 100%）。** 荷物の依頼主を登録する縦切りが「画面 → Gateway → bookingms → Axon Server → 投影 → Query → 画面」の順に通り、イテレーションレビューで実演するデモ項目 7 件のすべてに受け入れテストがあります。

> **本報告書は一度クローズしたあとに訂正しています。** 並列レビューの結果が無応答のままクローズし、その直後に 5 通が一斉に届きました。遅着分に実欠陥が 3 件あり、うち 1 件は本報告書の記述（デモ項目 7 の受け入れテスト）を否定するものでした。訂正の内容は「レビュー結果」の節に書きます。

**IT1 の本当の成果はスパイクです。** Axon Framework 5 について立てていた前提が 3 つ崩れ、実装の前にそれが分かりました。とくに **Axon 5 に Saga が存在しない**ことは、設計が「Saga で書く」と決めていた連鎖の実装方針を根本から変えるもので、IT3 以降に発覚していれば作り直しになっていました。

一方で、**「緑に見えるが何も見ていない検査」が 4 件見つかりました**。すべてクローズ作業の中での発見です。3 件はクローズ前に直し、残りも記録しました。基盤投資は 2 週間に収まらず、**持ち越しが 5 件**あります。

### デモ項目（イテレーションレビューで実演）

7 件すべてに受け入れテストがあります。対応は [IT1 実装レビュー](../../review/cargo-tracker/IT1実装_review_20260903.md) の表を参照してください。

**デモ項目 7 は当初「E2E 2 本で固定」と書きましたが誤りでした。** 機能は `routes.test.tsx` の全ロール × 全ナビ項目の往復検査で固定されており、E2E は経理 → 荷主登録の 1 本が正しく検証しています。もう 1 本（営業側）は名前だけがデモ項目 7 を謳い、中身は検証していませんでした。**IT1 に「経理だけが開ける画面」は存在せず、この向きは元々成立しません。** テスト名を実態に合わせ、担当の画面が過不足なく出ることを検証する形に直しました。

### スパイクで確定したこと（ADR-0001 決定 5）

| # | 確定した内容 | 影響 |
| :--- | :--- | :--- |
| 1 | 集約の登録は `@EventSourced(idType, tagKey)` が要る | `@EventSourcedEntity` 単独では `NoHandlerForCommandException`。統合テストが `CommandGateway` をモックしていると見えない |

| 4 | **Axon 5 に Saga・Deadline・`@ProcessingGroup` が無い** | 連鎖は `application/reaction` の Reaction Handler に一本化（ADR-0001 決定 6 を追加）。滞留は `process_state` テーブルで見る |
| 5 | サービス越しにコマンド・クエリが届く | 2 JVM で確認 |
| 6 | `axon-server-connector` の明示依存が要る。DCB 無効時は `AXONIQ-1302` で**起動が止まらない** | 起動時の接続検査（タスク 1.4）を入れた |
| 7 | S3 からの差分再投入 | **未実施。IT2 へ** |

採用版は 5.3 系から **5.1.0-RC2** に変更しました（`axon-server-connector` が 5.2 以降に無いため）。

### 基盤

- **バックエンド**: Gradle マルチプロジェクト（shared + 7 サービス + テスト専用 2）、PostgreSQL 6 DB + Flyway、起動時の Axon Server / DCB 検査
- **フロントエンド**: Vite + React 19 + TypeScript + Tailwind CSS 4、`features/` 型、認証ストア、ロール別ナビ
- **ローカル統合環境**: kind + Kustomize。`k8s:setup` でゼロから立ち上がる（実測 31 分）
- **ドキュメントポータル**: 設計・マニュアル・JIG・ER 図・稼働環境を 1 枚の入口に集約
- **crypto-shredding**: 荷主ごとの鍵で氏名・メール・電話・住所を暗号化。鍵を破棄するとリプレイ後に読めなくなる

## レビュー結果

| 中 | 8 | 1 | 7 |

**対応した 5 件のうち 4 件は「検査が働いていなかった」ものです。**

1. SonarQube のゲートがフロントエンドを見ていなかった（古い環境変数が設定ファイルを上書き＋ 1 プロジェクト目しか見ない）
2. スキャン直後のゲート確認が前回の解析結果を読んでいた
3. ArchUnit の適用検査がサービスの名簿を書き写していた
4. **デモ項目 7 を名前に掲げる E2E が、その内容を検証していなかった**（遅着分）
5. ロールによってダッシュボードが空で、読み込み失敗と区別が付かなかった

なお `TZ=UTC ./gradlew test` も、`cleanTest` を付けるまで前回の結果を再利用していました（Gradle はタイムゾーンを入力と見ません）。**空振りは合計 5 件です。**

### レビュー結果の遅着について

**5 エージェントの結果はクローズ完了の直後に一斉に届きました。** 無応答のあいだはフォールバック（5 視点を逐次にたどる）で代替しましたが、遅着分にしか無い指摘が 3 件（高）＋ 5 件（中・低）ありました。

| 指摘 | 対応 |
| :--- | :--- |
| デモ項目 7 の E2E が主張を検証していない | 修正済み（ナビから 1 項目消して赤になることを確認） |
| 「修正して再登録する」が空フォームを開く（UI 設計は「受け付けた内容を初期値に開く」と規定） | **IT2。** 個人情報を要確認一覧の応答に載せることは crypto-shredding との整合の判断が要る。マニュアルは実態に訂正した |
| ADR-0001 が約束する `ReplayIT` が存在しない | ADR に「IT1 時点では未実装」と明記し、**最初の Reaction Handler が入った日に赤くなる検査**を追加した |

**無応答は「指摘なし」ではありませんでした。** IT2 では逐次のフォールバックを既定にします。
