## 満足条件の達成

リリース計画の満足条件は「**全ロールがログインでき、営業担当者が荷主と貨物予約を登録できる**」です。

| # | 満足条件の要素 | 達成 | 根拠 |
| :--- | :--- | :--: | :--- |
| 1 | 全ロールがログインできる | ○ | authms・Gateway の JWT 認証。ロック・失効・無操作タイムアウトを含む（US26・US27・US31） |
| 2 | 営業担当者が荷主を登録できる | ○ | 法人・個人の 2 形態、契約番号と割引率、重複は要確認一覧へ（US02・US03） |
| 3 | 営業担当者が貨物予約を登録できる | ○ | 一般・危険物・冷凍の 3 種別、寸法と輸送条件、経路設計への引き渡し（US04・US05・US06） |
| 4 | 経路設計者が航海を登録できる | ○ | routingms を立ち上げ、多区間の寄港地を順序つきで（US24。0.2 の前倒し分） |

**満足条件は満たしています。** 営業担当者の 1 日（荷主を登録し、予約を入れ、経路設計へ渡す）が画面から通ります。

## 学んだこと

序盤 3 イテレーションを通した学びのうち、0.2 以降に効くものを 3 つ挙げます。

1. **並列レビューはクローズの最初に起動する。** IT1・IT2 は結果を待たずにクローズし、遅着分に実欠陥がありました。IT3 で最初に起動したところ 4〜6 分で返っています
2. **緑のテストと壊れ方の設計は別物。** 実欠陥のほとんどは「全緑の状態で残っていた」ものです。書いたコメント・Javadoc ほど疑いにくく、「〜する」と書いたら**その変更の中で破って赤を見る**必要があります
3. **返済枠を「余力次第」にしない。** IT1〜IT3 で繰り越しが積み上がり、2 回繰り越した項目が 2 件出ました（IT4 で解消）
