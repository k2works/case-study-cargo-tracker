## 技術的成果

### 引き渡しが精算と予約へ伝わる（US16）

契約 `CargoDeliveredEvent` を先に置き（Phase 0）、荷受人の確認という検査を同じ変更で
入れてから引取を開けました。IT9 が「検査できない段階でその経路を開けない」として
断っていたものを、条件を満たして開いた形です。

購読側は billingms と bookingms の 2 つで、予約は「配送完了」になります
（輸送の「引取済」と呼び名を分けました——正典が「文脈語を添えて区別する」と定めています）。

### 例外の起票から解決まで（US19）

`TrackingException` を `TrackingActivity` 集約の中に置き、緊急かどうかは種別が答える形
（不変条件 7）にしました。解決すると例外前の状態へ戻りますが、**起票中の例外がすべて
解決したときだけ**です。

一覧の並び（緊急が先・以降は到着期限までの残日数が少ない順）は読み口が決め、
**対応で期限が動いたらその日付で並べます**。

### 共有カーネルへの集約（負債枠）

API のエラー対応表が 4 サービスに写されており（139 行 × 4）、文言と説明が少しずつ
食い違っていました。共有カーネルへ寄せ、規約テストも「写さないこと」を見る形に
書き直しました。

### 適用済みマイグレーションの検査（Try T6）

IT9 で、適用済みの `V004` にコメントを 3 行足しただけで trackingms が起動しなくなりました。
CI は毎回まっさらな DB に当てるので、この食い違いはどのテストにも現れません。
内容ハッシュの台帳で 41 件を固定し、**クローズの最中に実際に 1 件捕まえました**
（私が足した `V008` を台帳に載せ忘れていた）。

## 運用上の学び

実装ではなく**検証の段取り**で 1 時間以上を失いました。

- クラスタ E2E とフルビルドを同時に走らせ、CPU の奪い合いで双方を落とした（IT9 と同型）
- `gulp k8s:images` がイメージを作り直さず、**クラスタが IT9 のコードを動かしていた**。
  「作り直した」という出力を信じて E2E を回し、実装を疑った
- zsh の `:l` 修飾子でタグが化け、壊れたイメージを 3 つ作った

いずれもふりかえりの Try（T3・T4・T5）に落としています。
