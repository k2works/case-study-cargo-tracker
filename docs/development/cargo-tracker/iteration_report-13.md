## エグゼクティブサマリー

**引取済の予約から請求書が自動で組み立てられるようになりました。** 実際に通った区間・重量・貨物種別から基本料金を出し、法人荷主には契約割引を当て、輸出は免税になります。例外（遅延・破損・留置）があれば、根拠を指して調整を入れられます。

**billingms が初めて集約を持ちました。** IT2 から荷主の契約を写すだけだったサービスに `Invoice` と料金計算が入り、その瞬間に Event Sourcing のサービスとしての規約 3 つが新たに効き始めました（計画のリスク R3 が予想したとおり）。

**IT12 が「この版に手立てが無い」と記録した処理の列の分割は、誤りでした。** `@SequencingPolicy` をクラスに宣言すれば働きます（実測）。ADR-0014 には当時の記録を残したまま但し書きで改め、効かなくなれば赤になる検査を対で置きました。

**クローズのレビューで最も重かったのは「検査そのものが走っていなかった」ことです。** Try T8 で置いた規約検査 3 本が、入力宣言のパス誤りで 1 件も実行されていませんでした。しかもその赤を見ていながら、直前の作業（カバレッジ調整）と結びつけて読み違えていました。

## レビュー結果

5 視点で並列にレビューし、**64 件**（高 18・中 27・低 19）。**高はすべてクローズ前に修正**しました。

**最重の指摘は「検査そのものが走っていなかった」こと**です。Try T8 で置いた規約検査 3 本が、`shared/build.gradle.kts` の入力宣言のパス誤り（1 つ上の階層）で 1 件も実行されていませんでした。その陰で、受入基準の表が実在しないクラス名（`BillingReactionHandlerTest`）を名指ししていたのがすり抜けていました。

ほかに高として、**経理宛の要確認一覧に読み口が無い**（記録するだけで誰にも見えない・IT3 と同じ形）、**調整の根拠リンクが経理に 403**（開けない場所へ誘う・IT7 と同じ形）、**免税を税額から逆算していた**（税率 0% の期間に国内貨物が免税になる）、**ADR-0015 の理由が実装で成立していない**（billingms は営業日を読んでいない）がありました。

**恒真の検査を 3 件書いていた**ことも指摘されました（一覧の並び順・既定の除外・免税）。テスト名は正しいことを言っており、**名前と中身が食い違う検査は無いより悪い**という指摘です。

詳細は [IT13 実装レビュー](../../review/cargo-tracker/IT13実装_review_20260911.md) を参照してください。

## 次イテレーションへの引き継ぎ

IT14（US01 見積・US23 精算）へ **12 件**を引き継ぎます。重いのは上の #2〜#4 の 3 件で、いずれも**発行を足す前に**入れる必要があります——確認の跡が無いまま発行を足すと未確認の請求書をそのまま出せてしまい、算出漏れが塞がらないと発行の母集団から落ち続け、調整を取り消せないと誤った請求書が出た時点で事故になります。
