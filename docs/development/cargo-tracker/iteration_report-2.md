# イテレーション 2 完了報告書

## エグゼクティブサマリー

**IT2 は計画した 9 SP をすべて完了しました（達成率 100%）。** 貨物予約の登録が「画面 → Gateway → bookingms → Axon Server → 投影 → Query → 画面」で通り、デモ項目 8 件のすべてに受け入れテストがあります。

**IT2 の本当の成果は、状態を持つ集約を Event Sourcing で書いたことです。** IT1 の `Shipper` は登録しかせず、イベント列から復元した状態を見る判断が 1 つもありませんでした。`Cargo` を書いて初めて **`@EventTag` が要る**ことが分かりました。付け忘れると集約は毎回空のまま復元され、状態を見る守りが丸ごと素通りします。しかも `AxonTestFixture` では判別できません。

**IT1 の持ち越し 9 件のうち 8 件を返しました。** 落とした 1 件（契約テストの往復）は理由と代替を明記しています。

**欠陥を 12 件見つけて直しました**（開発中 7 件・レビュー 5 件のうち高中 4 件）。うち 5 件は IT1 の実装に由来し、IT1 のクローズ時点では緑でした。

## 技術的成果

### Axon 5 について確定したこと（ADR-0001 決定 5 に第 7〜12 項として記録）

| # | 確定した内容 | 影響 |
| :--- | :--- | :--- |
| 7 | **S3 差分再投入は成立する。ただしエクスポートがタグを落とす** | 件数も内容も一致し投影のリプレイも通るのに、集約だけが復元できない。復元演習の合格条件に「復元した集約へコマンドを 1 本送って通ること」を追加 |
| 8 | **イベント側に `@EventTag` が要る** | 付け忘れると集約が毎回空のまま復元され、状態を見る守りが丸ごと素通りする |
| 9 | static と instance のコマンドハンドラを両方置くと static が勝つ | 2 度目の受付が通る |
| 10 | インスタンスのハンドラにはコマンド側の `@TargetEntityId` が要る | 落ちるので気づける |
| 11 | **`AxonTestFixture` の `disableAxonServer()` ではタグ復元が働かない** | 復元を見る守りは集約の単体テストでは判別できない |
| 12 | サービス越しの例外は型が置き換わる | 型でアサートすると落ちる |

**8 と 11 は組み合わさると危険です。** タグを付け忘れた集約は空のまま復元され、その守りは単体テストでも判別できません。

### 構造の変更

| 変更 | 理由 |
| :--- | :--- |
| crypto の変換を `shared/infrastructure/crypto` へ | ADR-0003 が「billingms は契約イベントを購読して写す」と決めている以上、読む側も同じ変換が要る。持たないと暗号文がそのまま投影に入る |
| `shared/domain/location` を新設 | 国コードを文字列で切り出す処理が各 BC に散ると、輸出免税の判定（Billing）と食い違う |
| Axon Server コンテナの組み立てを 1 か所に | 3 か所に散り、起動猶予を片方だけ直して全体ビルドだけが落ちていた |

いずれも ArchUnit の共有カーネル名簿と ADR-0001 のコンプライアンス欄を**同じ変更で**直しています。
