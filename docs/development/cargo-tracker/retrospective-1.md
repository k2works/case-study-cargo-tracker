## Keep（続けること）

### スパイクを先に置いたこと

**IT1 の前提は 3 つ崩れました。** それが実装の前に分かったのが最大の収穫です。

| 崩れた前提 | 実際 | もし後で気づいていたら |
| :--- | :--- | :--- |
| Axon 5.3 系を使う | `axon-server-connector` が 5.2 以降に無く、5.1.0-RC2 に変更 | 全サービスが Axon Server に繋がらない状態で実装が進む |
| Saga で連鎖を書く | **Axon 5 に Saga・Deadline・`@ProcessingGroup` が無い** | 設計どおりに書けず、IT3 以降の連鎖で作り直し |
| 集約は `@EventSourcedEntity` | `@EventSourced(idType, tagKey)` が要る | 統合テストは緑のまま、bootJar で `NoHandlerForCommandException` |

**スパイクのコードを残さなかったこと**も効きました。結論だけを ADR と設計に書き、実装はゼロから書いています。

### 「拒否する側」を先に見せるデモ項目

デモ項目 4・5・6（重複の問いかけ・Axon Server 停止・鍵の破棄）を先に固めました。安全装置は働くことを見せて初めて入ったと言えます。実際、`AxonServerOutageIT` は「無音で in-memory に落ちない」ことを検査しており、これが無ければ設定の欠落に気づけません。

### 違反フィクスチャを実コードと同じ形で書いたこと

ArchUnit のルールは、実コードと同じ形の違反例で赤を確かめました（タスク 2.2）。最小の違反例だけだと、メタテストが緑でも実コードの違反を見逃します。

### クローズを機械的に踏んだこと

品質ゲート（ステップ 2.6）を飛ばさなかったことで、**誰も見ていない検査が 2 件見つかりました**（下の Problem）。「テストが緑だからクローズしてよい」で止めていたら、両方とも IT2 以降に持ち越されていました。

## Problem（うまくいかなかったこと）

### P1. 検査が空振りしていた（3 件）

いずれも**緑に見えていて、実際には何も見ていない**類です。

| # | 空振り | 見つかり方 |
| :--- | :--- | :--- |
| P1-a | SonarQube の Quality Gate がフロントエンドを見ていなかった（`.env` の古いキーが設定ファイルを上書き、かつゲートは 1 プロジェクト目だけ） | クローズのステップ 2.6。直したら実際に赤（重複 5.58%・指摘 2 件）が出た |
| P1-b | スキャン直後のゲート確認が前回の解析結果を読んでいた | 直したのに同じ数字が返ったため |
| P1-c | ArchUnit の適用検査がサービスの名簿を書き写していた | レビューの architect 視点。サービスを増やしたとき、増えた側だけ規則が当たらない |
| P1-d | `TZ=UTC ./gradlew test` が前回の結果を再利用していた（Gradle は TZ を入力と見ない） | クローズで `cleanTest` を付けて初めて再実行された |

**共通する原因は「検査を足したこと」で満足し、「検査が働くこと」を確かめていない点です。** 同シリーズの教訓（安全装置は破るテストで固定する）が、検査の配線そのものには適用されていませんでした。

### P2. 基盤投資が 2 週間に収まらず、持ち越しが 5 件出た

計画時点で 130h / 10 日と分かっていたため「落とす順序」を決めてありましたが、実際に落ちたのは順序表と一致しません。

| 持ち越し | 順序表の位置 | 実際 |
| :--- | :--- | :--- |
| S01 ポータル（`/portal`） | 表に無い | 落ちた |
| 全ルートのプレースホルダ（3.3） | 表に無い | 方針変更（中身の無い画面は置かない） |
| 無操作タイムアウト（3.5） | 表に無い | 落ちた |
| スパイク 0.7（S3 差分再投入） | **落とさない**（タスク 0） | 落ちた |
| 契約テストの往復（2.5） | 表に無い | 落ちた（2 サービス起動が要る） |
| ユーザーマニュアル（7） | 順序 1（最初に落とす） | **落ちていない**（5 章を執筆・キャプチャ自動生成まで完了） |

**落とす順序を決めてあったのに、実際は別のものが落ちました。** 順序表は「価値の低い順」で作りましたが、実際に落ちたのは「他のタスクに依存して着手できなかったもの」です。

### P3. 計画の記述が実態とずれた

タスク 3.2・3.3 の状態が `[~]` で「完了」と読める書き方になっており、S01 ポータルの未実装が読み取れませんでした。DoD の「マニュアルの 4 節」も、章が 5 つになったのに数を書き写したまま追随していません。

**受入基準を複写しない方針を取りながら、DoD では数を書き写していた**という一貫性の欠如です。

### P4. 並列レビューが結果を返さなかった

5 エージェントを起動しましたが、40 分後に idle になったきりレポートが届かず、催促にも応答がありませんでした。フォールバック（5 視点を逐次にたどる）に切り替えましたが、**視点が互いに引きずられない**という並列の利点は得られていません。

### P5. ロールによって画面が空だった

経路設計・荷役・荷主・管理でログインすると、ダッシュボードの「今日の作業」が 0 件で、読み込み失敗と区別が付きませんでした（クローズ中に修正）。**受入基準は満たしているのに、その担当から見ると壊れて見える**状態でした。
