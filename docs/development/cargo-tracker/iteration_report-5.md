## 技術的成果

### 経路探索（routingms・ドメイン）

- `RouteSearchService`：幅優先で経路を探す。乗り継ぎ上限 3、同じ港を 2 度通らない。**候補の件数では打ち切らず、並べたあとに上限 20 を効かせる**（ADR-0007。当初は逆で、受入基準を破っていた）
- `TransitPath` / `TransitEdge` / `RouteSearchSpecification`：区間と条件の値オブジェクト。**期限は日付で比べる**（時刻で比べると期限当日着を落とす）。判断のタイムゾーンは業務のものを渡す
- 貨物種別に対応しない航海・出港済みの区間・キャンセル済みの航海を候補にしない
- **知らない港は 422 で断る**（レビューで、書いてあるのに実装が無いことが分かった）

### サービス越しの問い合わせ（ACL + Axon Query Bus）

- 契約：`FindRouteCandidatesQuery` / `RouteCandidatesResponse` / `RouteCandidateDto`（文字列・数値・日時のみ）
- `RouteCandidateFinder`（bookingms の application/port。**利用側が定義**）と `QueryBusRouteCandidateFinder`（infrastructure/acl）
- `QueryDispatcher`（共有カーネル）が待ち方を 1 か所で決める（5 秒）。**落ちているときは空リストにせず 503**
- 契約テストは**ゴールデン一致と往復の両方**。往復は bookingms と routingms を同じ JVM に起動して確かめる

### 経路の確定（bookingms・集約）

- `Cargo.assignRoute`：不変条件 4（区間の連結・時刻昇順）と不変条件 5（旅程が経路仕様を満たす）を集約が検査する。**期限を修正したあとは新しい期限で判断する**
- `CargoItinerary` / `Leg` / `RouteCandidate`：BC ごとに別の型（routingms の `TransitPath` を持ち込まない）
- `cargo_leg` 投影：再設計では**行を入れ替える**（追記すると古い区間が残る）

### 画面

- **S31 経路設計ワークベンチ（新規）**：候補を推奨順に出し、1 件選んで確定する。0 件 / 0 件かつ打ち切り / 候補ありかつ打ち切りで**案内を出し分ける**
- S22 予約詳細：旅程・修正履歴・経路設定状態を追加。確定直後は反映を待って取り直す
- S34 航海詳細：キャンセル

### 引き継ぎ枠の成果

- `CancelVoyageCommand` と `Voyage.cancel`（R.1）
- `CargoSpecificationDiff` と `cargo_revision` 投影（R.2・[ADR-0008](../../adr/cargo-tracker/0008-cargo-revision-as-a-projection.md)）。**差分は項目ごとでなく丸ごと比べる**
