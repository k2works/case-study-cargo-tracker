# イテレーション 2 ふりかえり（KPT）

対象: IT2（2026-07-25 開発完了）。US05 特殊貨物予約・US13 予約ライフサイクル・貨物予約一覧・IT1 Try 返済（T1/T2/T4/T5）。実績 8 SP。Phase 1（予約・荷主管理基盤 MVP）完了・Release 0.1 MVP 到達。

## Keep（うまくいったこと）

### 技術的成功

- **アウトサイドイン TDD の徹底**: US05/US13 を E2E（Playwright）で受入を先に固定し、interfaces → application → domain → infrastructure を縦に貫通。ドメイン層カバレッジ 98.9% を達成。
- **可否判定のドメイン集約**: レビュー指摘（`CanCancel` の UI/ドメイン不整合）を機に `Cargo.CanConfirm/CanCancel/CanSendBackToRouting` をドメインへ集約し、UI 制御とドメイン規則を単一情報源化。8 状態 × 3 操作の真理値表テストで固定。
- **Try 返済を先行実施**: T1（設計是正）・T2（ShipperCode 改称）を着手初期に実施し、設計と実装の一致を先に確立してから機能実装に入れた。
- **共有カーネルの整理完遂**: `ShipperCode`（BC 間参照キー）新設で意味二重化を解消、`ShipperId`(UUID) を Shipper BC へ移設し ADR-0005 決定2 を完遂。共有カーネルが Location・ShipperCode・BusinessCode のみに純化。
- **CQRS 読み取りモデルの一貫適用**: 貨物予約一覧を荷主一覧と同じ Query サービス + DTO + adapter パターンで実装し、ナビ導線（貨物予約→一覧→登録/詳細）を接続。

### プロセス的成功

- **マルチパースペクティブレビュー（XP 5 視点）の有効性**: go-arch-lint 緑でも見えない `shared.ShipperId` の残存（Architect）、UI とドメイン規則の不整合（Programmer）、テストの層の偏り（Tester）を並列レビューで検出。高優先度をクローズ前に全対応。
- **品質ゲートの多層運用**: `make check` 緑の後、SonarQube Quality Gate で新規違反 2 件（引数過多）と新規カバレッジ不足（52%）を検出し、パラメータ構造体化・異常系テスト追加で PASS（84.2%）まで引き上げた。テスト緑で満足せず静的解析まで通した。

## Problem（課題・見積もりのズレ）

- **特殊貨物の必須検証がクライアント任せ（UX）**: サーバ側では値オブジェクト生成で空欄を弾いており申告漏れは発生しないが、フォームに `required` 属性・フィールド単位のエラー表示がなく、どの項目が原因か分かりにくい（User-rep H1）。
- **荷主選択の導線が手打ちのみ**: 予約登録で荷主コードをテキスト入力する必要があり、荷主一覧/検索からの選択導線がない。実業務フロー（荷主登録→そのまま予約）に沿っていない（User-rep H2）。
- **新規コードカバレッジがユニットのみでは 52% に低下**: infra（Repository・Query）が integration タグ配下で、`coverage.out`（unit のみ）に含まれず品質ゲートが一度 FAIL。カバレッジ生成手順に integration タグ込みの計測が必要と判明。
- **引数過多の作り込み**: Cargo 集約の生成・復元関数が 8-9 引数となり SonarQube で MAJOR 指摘。値オブジェクトが増えるドメインでは初めからパラメータ構造体を検討すべきだった。
- **見積もり**: 基本 6 SP に対し、Try 返済（T1/T2/T4）・貨物予約一覧・CSS 整備・レビュー対応・品質ゲート対応で実績 8 SP。序盤の設計是正返済を含む。

## 次イテレーション（IT3）への引き継ぎ

- **局面転換**: IT3 から中盤局面（インサイドアウト）へ。Phase 2（経路設計・貨物追跡）の複雑ドメイン（航海スケジュール検索 US07・経路候補算出 US08）を domain/data 層から堅牢に作り込む。
- **持ち越し（必須）**: T3（sqlc BC 別分割）・T4（カバレッジ計測標準化）は IT3 着手時に優先。US05/US13 の Phase 2 依存（通知基盤・経路候補フィルタ・選択ルート表示）は Phase 2 の該当 US で充足する。
- **ベロシティ**: IT1 実績 15 SP（序盤オーバーヘッド込み）・IT2 実績 8 SP。序盤（IT1-2）平均は設計是正の返済を含むため、中盤の複雑ドメインに向けて 3 IT 完了時（IT3）に再評価する。
