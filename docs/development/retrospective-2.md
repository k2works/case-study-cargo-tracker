## KPT 分析

### Keep（継続すること）

#### 技術的成功

- **ヘキサゴナルアーキテクチャの確立**: bookingms で domain / application / infrastructure / interfaces 層の分離をゼロから構築し、ArchUnit テストで依存ルールを自動検証する体制を確立した
- **MyBatis + Flyway + H2 パターンの定着**: IT1 の routingms と同じ永続化パターンを bookingms に適用し、H2 互換の DDL（`BIGINT GENERATED ALWAYS AS IDENTITY`）で統合テストが通過した
- **E2E テストの即時追加**: 新機能（予約登録・一覧・経路設計）の E2E テストを実装と同時に追加し、CI で全通過を確認した
- **CI パイプラインへの新サービス追加**: bookingms の起動ステップを `.github/workflows/ci.yml` に追加し、フルスタック E2E テストが CI で自動実行される体制を維持した
- **Codex 分業体制**: Claude（設計・受入）と Codex（実装）の分業が IT2 でも機能した。1 ファイル 1 指示の原則を守ることで効率的に実装を委譲できた

#### プロセス的成功

- **IT1 引継ぎ事項の実践**: API パスを Gateway ルートと事前照合し、E2E テストデータの命名規則（最大 30 文字）を考慮した。IT1 の Problem が IT2 で解消された
- **インサイドアウト開発の継続**: BE ドメイン → アプリケーション → インフラ → インターフェース → FE の順序を維持し、API が確定してから画面を構築できた

---

### Problem（改善が必要なこと）

#### 技術的課題

- **テストカバレッジが 80% 未達**: bookingms 76.5%、routingms 77.6%、FE 37% と、いずれも目標の 80% に届かなかった。特に FE は hooks / レイアウト / ライブラリ層のテストが薄い
- **FE カバレッジの極端な低さ**: `useBookings.ts`（11%）、`useItineraries.ts`（0%）、`AppLayout.tsx`（10%）など、実装ファイルのほとんどがテストされていない。モックを使った hooks テストが不足している
- **Playwright strict mode エラー**: 複数テストの実行順序によって DB に「仮予約」バッジが複数蓄積し、`getByText('仮予約')` が複数要素にマッチして strict mode エラーが発生した。`.first()` で回避したが根本原因（テスト間のデータ独立性）は未解決
- **RoutingControllerTest の H2 共有問題**: 同じ航海番号を複数テストで使用すると DB 制約違反（409 Conflict）が発生した。各テストで一意な識別子を使うことで回避したが、テスト間のデータ独立性設計が課題

#### プロセス的課題

- **カバレッジ計測の後回し**: カバレッジ確認を実装完了後に実施したため、成功基準（80%）を満たせないことが終盤に判明した。TDD サイクル中にカバレッジを随時確認する習慣が必要
- **FE コンポーネントのテスト粒度**: `BookingList.tsx`（Statement 63.6%）、`BookingForm.tsx`（未確認）など、コンポーネントの分岐テストが不十分

---

### Try（次のイテレーションで試すこと）

| アクション | 期待効果 | 優先度 |
|-----------|---------|--------|
| FE hooks テストを TDD で書く（useBookings / useCreateBooking / useItineraries） | FE カバレッジを 80% 以上に引き上げる | 高 |
| E2E テストで `beforeEach` に DB リセット or 一意なテストデータを使うパターンを導入 | strict mode エラーの根本解消 | 高 |
| 各 TDD サイクル後に JaCoCo / Vitest カバレッジを確認するステップを組み込む | カバレッジ未達の早期検出 | 中 |
| RoutingControllerTest に `@Sql` アノテーションで テスト前 DB 初期化を追加 | H2 共有問題の根本解消 | 中 |
| FE コンポーネントテストでエラーパス・ローディング状態を必ず確認する | コンポーネントの分岐カバレッジ向上 | 中 |
