# イテレーション 2 完了報告書

対象: US03（法人荷主）・US04（貨物予約）・US05（危険物・冷凍貨物）= 8 SP
期間: 2026-08-20（IT2）
局面: 序盤（アウトサイドイン）の最終イテレーション。ここで Release 0.1 が閉じる。

## エグゼクティブサマリー

営業担当者が**荷主の登録から貨物予約の仮受付までを 1 本で通せる**状態になりました。
危険物・冷凍貨物の特別情報も保存され、経路設計（IT3）が読める形になっています。

IT2 は「基盤が揃った状態で業務価値を積む最初のイテレーション」であり、計画 8 SP を
全量完了しました。IT1 から持ち越した返済枠 10 件もすべて片付けています。

実装の過程で、**検査が 5 件の実欠陥を捕まえました**。とくに次の 2 件は、全テストが緑の
まま本番でだけ壊れる形でした。

- 同時に届いたログイン失敗を取りこぼし、**何度間違えてもロックが成立しない**（US31 の保護が名目だけになる）
- CORS プリフライトが 401 になり、**画面と Gateway を別オリジンに置いた瞬間にログインすらできない**

### 実装の要点

- **予約番号の組み立てをマイグレーションに置いた**。アプリ側に置くと、別の経路（移行・運用スクリプト）が違う形式を発行できてしまう
- **到着期限を目的地の暦で判断する**。UTC で判断すると、時差の分だけ受付が拒否される時間帯ができる。可変 Clock で日付境界をまたぐ振る舞いまで検証した
- **付け忘れと同じく付けすぎも拒む**。一般貨物に危険物申告や温度条件を付けられない。経路設計（IT3）が扱いを判断できなくなるため
- **料金は 0 で埋めない**。未算出と無料が区別できなくなり、算出漏れが「無料の予約」として通る

## 品質ゲートを通すまでに直したこと

指摘 66 件をゼロにする過程で、**確かめる仕組みそのものの欠陥**が 6 件見つかった。
いずれも「間違っているのに成功する」「別の原因に見える」形で、放置すると次の
イテレーションでも同じ時間を失う。

| # | 欠陥 | どう見えていたか |
| :--- | :--- | :--- |
| 1 | 品質ゲートの照会先が走査時と食い違い、**一度も動いていなかった** | curl の失敗としてしか出ない |
| 2 | ゲートが 1 プロジェクトしか見ていなかった | もう一方が赤でも「通った」と記録できる |
| 3 | カバレッジ報告書の生成と走査が別々で、報告書が無いまま走査していた | **テスト不足に見える**（新規カバレッジ 0%） |
| 4 | 端末の制御文字が PATH に混ざり git を実行できない | 「解析に失敗しました」としか出ない |
| 5 | Gradle デーモンが壊れた PATH を保持する | 直したのに落ち続ける |
| 6 | 運用タスクが kubectl の接続先を明示していない | **別クラスタを操作しても正常終了する** |

### 指摘への対応で設計を良くした点

引数の多さの指摘は機械的に潰さず、**取り違えても型で気づけない**箇所をまとめた。

| 型 | 何を守るか |
| :--- | :--- |
| `CargoStatus` | 予約・輸送・経路の 3 状態。3 つとも同型の列挙で、順番が入れ替わっても型が合う |
| `CorporateContract` | 契約番号必須の不変条件を型に持たせた |
| `ShipperProfile` / `UserIdentity` | 4 つとも `String`。表示名とメールが入れ替わっても通る |
| `LoginState` | 「期限だけ残して回数を捨てる」組み合わせを作れなくする（IT2 で実際に踏んだ形） |
