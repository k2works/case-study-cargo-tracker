# イテレーション 2 完了報告書

## エグゼクティブサマリー

イテレーション 2 は**計画どおり 17 SP を完了**し、ゴールである「公開貨物追跡を US18 の受入基準まで
作り込み、アーキテクチャ規約の機械検査と CI で品質ゲートを機能させる」を達成した。

IT1 の品質判断は「ローカルのテスト結果のみ」に依存していたが、本イテレーションで
**CI が 47 秒で完走**するようになり（受入条件は 8 分以内）、緑の根拠が自動化された。

一方、本イテレーション最大の収穫は機能ではなく**品質ゲート自身の欠陥を見つけたこと**である。
自作の `arch-lint` は 1 行単位で照合していたため、本プロジェクトが実際に採っている
「SQL を `"..." +` で改行して連結する」書き方の違反を**検出できなかった**（実測で検出 0 件）。
メタテストが 17 件緑であることが検査器を信用する根拠になっていなかった。クローズ前に修正し、
複数行の負例を加えてメタテストを 21 件に拡充した。

利用者視点のレビューでは、**Bootstrap の CSS が読み込まれていない**ため「一目で状態が分かる」
という公開追跡の価値が実際には成立していないことが判明した。これは IT3 の序盤タスクへ送る。

SonarQube の品質ゲート（クローズ手順のステップ 2.6）は、計画上 IT3（TS05b）のスコープであり
本イテレーションでは実施していない。

### 言語調査時間の記録（Try T3 の部分達成）

独立タスクとして 8h（1.1 の 4h、3.1 の 4h）を計上したが、実作業では調査と実装が
分かちがたく、時間の切り分けができなかった。特に大きかったのは以下である。

- `query` が予約語であること（Datalog 構文）— パースエラーの原因特定に時間を要した
- `import java.lang.String` による標準ライブラリの遮蔽 — 型エラーの読み解きに時間を要した

**分単位の計測は断念し、「制約に遭遇した件数」（IT1: 10 件 → IT2: 2 件）を代理指標とする**。
遭遇件数が減っていることは、言語の学習曲線を登り切りつつあることを示す。
