# IT11 完了報告書（2026-08-05）

## エグゼクティブサマリー

**v1.0.0 の業務フローが端から端まで繋がった。** 予約 → 経路 → 追跡番号 → 荷役 →
引取までが画面から通り、その結果が荷主の追跡タイムラインに現れる。

計画 11 SP をすべて完了し、縮退は 0 件（IT5-IT11 で **7 イテレーション連続**）。
テストは 872 件（+33）、E2E は 2 本（シナリオ①・③）。品質ゲートの 5 検査と CI は緑。

本イテレーションの成果は、機能の追加よりも**「入っているのに回らない」形の解消**に
比重がある。IT10 のレビューが送った高 2 件（荷役の記録が荷主に出ない・履歴が
全件無制限）を最初に返し、そのうえで引取と手動更新を積んだ。

## 技術的成果

### ADR-0014 — 通関の扱いと、条件の測り方

2 つの主題を 1 本にまとめた。どちらも**書いた条件が実態を測れていなかった**ことへの是正である。

- **通関済は `CUSTOMS` 種別の荷役記録で表す**。`customs_declaration` を作って
  ゲートにすると、外部税関システム（TS07・延期中）が無い状態では
  **CLEARED にできる者が誰もいない**——引取が永久にできなくなる
- **再検討条件を「単一 BC へ向かう書き込み ACL アダプタ数」へ**。総数は
  「連携が増えた」と「単一の集約がハブ化している」を潰していた

### arch-lint 規約 12（IT4 由来・7 イテレーション未着手）

「BC の SQL に現れるテーブルは自 BC 所有か ACL 配下」を機械検査にした。
規約 4 は `use` 宣言を見るため**SQL に降りた結合を検出できない**。
規約は 12 件、メタテストは 34 件になった。

### Tracking 集約が出来事を持つようになった

IT10 は輸送状態だけを書き換え、`tracking_handling_event` には**誰も書いていなかった**。
`applyHandling` を「状態を変える」から「出来事を記録し、その結果状態が変わる」へ変え、
ポートを 1 メソッドに束ねて**片方だけ書かれた状態を呼び出し側が作れなくした**。

### 3 イテレーション未解決だった間欠失敗の解消

`localhost` の名前解決（`::1` 優先）と IPv4 束縛の食い違いで、
**別プロセスが応答していた**。接続先を `127.0.0.1` に固定した。

## 課題と残作業

### 本イテレーションで判明した主要な問題

1. **同じ穴を、同じ IT のうちに片側だけ塞いだ**。荷役登録でマスタ照合まで
   入れた直後、新設した追跡の手動更新は空文字しか見ていなかった
2. **安全装置の空振りが 3 イテレーション連続**（行ロック → UNIQUE → 時刻の逆行）。
   今回は集約にユニットテストが 1 件も無かったことが原因
3. **ADR の条件を置き換えたが、置き換えられる側を触らなかった**
4. **新しい再検討条件も、誰も数えていない**（現在ちょうど 3 本で、1 本で発火）
