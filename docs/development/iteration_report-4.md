## エグゼクティブサマリー

**予約 1 件に対して、期限内に到達できる経路の候補を自動で算出し、推奨順に提示できるようになった。**
本システムで最大の 1 件（US08 / 8SP）を単独で扱ったイテレーションである。

経路探索は**乗り通せる区間を見つけ、期限・取扱可否・経由回数で評価する**処理であり、
画面から作れば「つながっていない経路」「到着が出発より前の経路」を候補として
出していた。ドメインから固める意味が、IT3 に続いて実証された。

**実バグを 2 件見つけた。** どちらも「置いた気になっている装置」である。

### 受入基準の達成

**US08 の受入基準はすべて満たした。**

| 受入基準 | 実現 |
| :--- | :--- |
| 航海スケジュール検索結果と出発地・目的地・期限を入力として経路候補が自動算出される | `RouteSearchService` |
| 寄港地の接続可能性が評価される | 途中の港から乗る・途中の港で降りるを含む |
| 経路候補ごとに所要日数・経由港・費用・航海番号が表示される | 費用は**概算**（ADR-008） |
| 経路候補が推奨順に並べられて提示される | ①期限 ②直行 ③日数 ④費用 |
| 直行便がある場合、最優先候補として提示される | 所要日数が長くても直行が先 |
| 期限内に到達可能な経路がない場合、その旨が通知され条件調整が促される | 候補ゼロとは**別の状態**として表示 |

## 技術的成果

### 経路探索

- 探すのは**1 つの航海の中で出発地から目的地まで乗り通せる区間**である（`proposed_route` が航海番号を 1 つだけ持つことに対応する）
- **打ち切りの条件を持つ。** 経由回数の上限（既定 2）を超える候補は作らない
- **目的地に着いた後に出発地を出る航海は候補にしない。** 順序を見ないと到着が出発より前の候補が生まれる
- **期限の判定は日付単位**（`domain-model.md` ルール 2-1）。時刻付きで比べると期限当日に着く便がすべて期限超過になる
- **所要日数は切り上げる。** 12 日 20 時間を 12 日と呼ぶと、到着を 1 日早く見せる

### 概算費用（ADR-008）

運賃表も港間の距離も持たないまま、受入基準は費用の表示を求めていた。
**材料が無いことを認めた上で、重量と所要日数から概算を出す**判断を ADR として記録した。
単価と割増率は設定値であり、**ソースを変えずに調整できることが、この式が暫定である
ことの証拠**になる。画面・マニュアル・ADR の 3 か所に「概算」と明示している。

### BC の分離

経路探索には予約の内容が要る。ACL ポート `RoutableBookings` を Routing 側に定義し、
アダプタを Booking 側に実装した（IT2 の `ShipperExistenceChecker` と同じ形）。

**最初はポートの戻り値に Routing の値オブジェクトを置き、ArchUnit ルール 4 が落ちた。**
実装する側が相手のドメインを直接参照するなら、ACL を置いた動機そのものが消える。
境界は素の値にし、翻訳は Routing 側で行う形に直した。

`LocationMasterMapper` は `shared/infrastructure` へ移した。`Location` は共有カーネルの
要素であり、その実体を読む必要は Routing にも Booking にもある。

### スキーマ

| バージョン | 内容 |
| :--- | :--- |
| `common/V7` | `cargo` の発着港に `location` への外部キー |
| `common/V8` | `booking_route_proposal` に貨物種別・重量（探索条件の復元に必要だった） |
| `db/demo/V903` | 選べる候補・選べない候補・期限超過の候補が 1 件ずつ並ぶ航海 |

`booking_route_proposal` と `proposed_route` のテーブル自体は V1 で作成済みであり、
**本 IT が最初の利用者**である。

### 壊して赤を確認した安全装置（7 件）

経由回数の上限 1 件 / 期限の日付単位比較 1 件 / 逆走チェック 1 件 / 直行優先 1 件 /
所要日数の切り上げ 2 件 / 航海詳細の区間の並び 2 件 / 楽観的ロック 1 件。

**逆走チェックのテストは、最初は装置を外しても緑のままだった。** 判別する形に
差し替えている。「壊して赤」を実行しなければ、この空振りは見つからなかった。

### CI が一度赤になった経緯

Trivy が micrometer-core に HIGH を 2 件検出した（CVE-2026-40983 / CVE-2026-40984。
いずれも DoS）。Spring Boot の BOM が 1.16.5 を指しており、**修正版が公開されても
Boot が取り込むまで脆弱性が残る。** 1.16.6 に固定した。

IT3 は Checkstyle の推移的依存、IT4 は Boot の BOM が指すライブラリである。
**依存の脆弱性は毎イテレーション出るものとして扱う**（ふりかえり T4）。

[IT4 実装レビュー](../review/IT4実装_review_20260807.md)（高 2 件 / 中 4 件 / 低 3 件）。

| # | 指摘 | 対応 |
| :--- | :--- | :--- |
