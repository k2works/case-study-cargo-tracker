## Keep（継続すること）

- **Opus 分業がプロジェクト完走を支えた**。IT6 で確立した「タスクグループ + 受け入れテスト先行」の委譲単位が IT7 でも機能し、Billing の新 BC 立ち上げ（ドメイン → 料金算出 → 精算 → 設計同期 → レビュー修正）を 6 グループに分けて競合なく進められた。中断（it7-g1）が一度あったが、成果を verify で検証して回収でき、分業の頑健性が示された。
- **経路×コマンドマトリクスの状態合成列（IT6 Try T1）が効いた**。BookingStatus の IN_TRANSIT/DELIVERED/SETTLED を「並行経路の状態合成」欄付きで設計し、例外未解決中の DELIVERED・OVERDUE 中の入金確認といった合成を事前に定義できた。IT6 で露見した「復帰先の状態合成盲点」の再発を防いだ。
- **fail-closed 認証（ADR-011）で最終 IT のセキュリティ基盤が固まった**。新 Billing 経路を追加しても「デフォルト保護」で守られ、付け忘れが公開事故にならない構造になった。Release 1.0 のセキュリティチェックリスト（認可・情報露出・fail-closed）を DoD で確認できた。
- **BC 独立性の ACL パターンが 7 コンテキストで一貫**。BillingSnapshotAcl も CargoSnapshotAcl と同型の参照専用スナップショットで、7 番目の BC でも他 BC ドメイン型を import せずに実績・割引率・荷主連絡先を取得できた。

## Problem（問題点）

- **集約状態の再導出禁止をまた踏んだ**（レビューで検出）。割引率をカラム化せず discountAmount/base から逆算した結果、整数丸めで 0.3 を超え CONFIRMED 請求書が復元不能になる重大バグ。Ruby take-1 IT6 の同型教訓（[[domain-state-no-rederivation]]）がメモリにあったのに、金額の丸めが絡む逆算という別の顔で再発した。「永続化すべき状態を計算で代用しない」を集約設計のチェック項目に固定すべき。
- **非同期リスナー例外の非捕捉と AFTER_COMMIT 未強制が全 IT を通じて未返済のまま Release 1.0 に至った**（architect H1/H2）。同期 emit + async リスナーの拒否は発行側 try/catch で捕捉されず、write と emit が別 autocommit で状態デシンクの余地が残る。単一プロセス前提では機能するが、構造的整合性保証がないことを負債として明示計上した。
- **料金の距離係数が所要日数比例で業務的に倒錯**（architect M5）。遅延ほど請求が増える逆インセンティブ。港間距離マスタが設計未定義のための暫定式だが、金額を左右するロジックの根拠が弱いまま出荷した。
- **通知が記録スタブのまま Release 1.0**。本文（ADR-012）は載るが実配信手段がなく、決済機関連携（PaymentGatewayPort）も常に成功するスタブ。業務的な「一気通貫」は成立するが、外部連携は運用フェーズの実装待ち。
