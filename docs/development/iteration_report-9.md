# イテレーション 9 完了報告書

## エグゼクティブサマリー

MVP（US01-US27・Release 1.1）後のハードニング・イテレーションとして、IT8 のマルチパースペクティブレビューとふりかえりで浮かんだ料金調整（US21-6）の実運用課題を解消しました。補償費用の増減方向を業務判断（当社負担＝請求減算）で確定（T45）、料金調整の取消・監査証跡（担当者・理由・日時）・例外管理から該当請求書への導線を実装（T47a/b/c）、開発シードの BC privacy バイパスを公開 API 経由に是正（T46）、さらに IT8 の実インシデントを根拠に設計 DoD（状態機械のガードは現場ケース起点・不変条件は VO/集約に閉じる）をコーディングとテストガイドに制度化（T43/T44）しました。

計画 7 SP を 100% 消化。クローズ前のマルチパースペクティブレビュー（5 視点）で高優先 6 件を是正し、特に tester が検出した `remove_adjustment` の seq_number 負値インデックスによる末尾誤削除（実バグ）、監査証跡の偽陽性テスト、受入基準「日時」の欠落を是正しました。COMPENSATION の意味反転は ADR-0005 として記録。RSpec 429 examples 0 failures・全体カバレッジ 95.95%・新規 91.7%・SonarQube Quality Gate PASS・CI success を達成し、**Release 1.2** を発行します。

## 技術的成果

- **符号規約の単一の真実点**: `InvoiceLineItem#normalize_sign` に減算方向の正規化を集約。減額・補償費用とも請求額を減算（ADR-0005）。アプリ層・コントローラは符号を意識しない。
- **監査証跡の貫通**: `adjusted_by`/`reason`/`adjusted_at` が domain（clock 注入）→ repository（永続化/復元）→ 公開ビュー → 請求書詳細まで欠落なく通る。
- **状態機械のドメイン一本化**: 取消可否を `View#cancellable`（集約の `unsettled?` 由来）に集約し、ビューでの状態再判定を排除。
- **カプセル化の回復**: `MoneyAmount#subtract` を新設し、集約に露出していた `negate` を削除。
- **seed の正攻法化**: clock 注入で過去日発行を公開ファサード経由に。生 SQL の invoices 直接更新（Packwerk 非検知の越境）を除去。
- **設計規律の制度化**: 状態機械のガードは現場ケース起点、不変条件は VO/集約に閉じる、を設計 DoD に明文化（T43/T44）。

## レビュー結果

マルチパースペクティブレビュー（[IT9 実装レビュー](../review/IT9実装_review_20260729.md)）を 5 視点で実施。

- **高優先 6 件を是正**: 偽陽性テスト（担当者を実氏名で検証）・seq_number 境界バグ・監査日時欠落・ADR 未起票・`negate` の public 露出・T47c テスト皆無。
- **中優先 4 件を是正**: ビューの状態再判定（`cancellable` フラグ化）・デッドパラメータ除去・図の可視性記号・コメント整合。
- **高 2 件・中/低 3 件を方針明記のうえ許容/保留**: 物理削除（未精算限定のため許容・T50 で将来検討）・reason 任意（description が必須説明を兼ねる）・N+1（小規模のため保留・T51）・seq 位置ベース識別（単一リクエストで安定）。
