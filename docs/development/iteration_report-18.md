## エグゼクティブサマリー

**最後の未実装 BC（Estimation）を立ち上げ、US01 の受入基準 6 件をすべて満たした。** `package-info.java` だけのパッケージは無くなり、`release_scope.md` の「未割当」も空になった。US01〜US36 のすべてがどれかのリリースに属し、実装済みである。

**設計上の中心は ADR-023 である。** `domain-model.md` は「ルート候補はスタブ実装（固定値）」と書いていたが、ADR-006 が外部連携を採らないと決めており、その「将来」は来ない。一方 Routing には US08 で本物の探索がある。**固定値を返す見積は、画面は動くのに数字が現実と無関係**になる —— 荷主に渡る数字であり、実在しない便の所要日数と費用を「概算」として提示することになる。ACL ポートで Routing の探索に繋いだ。

**この IT の失敗は「入力させたものを捨てていた」ことに集約される。** 2 件あり、どちらも作った本人には見えなかった。

## 技術的成果

### 新規の設計判断

**ADR-023: 見積のルート候補は Routing の探索から作る**

- ポートは Estimation が所有し、アダプタは提供側（Routing）に置く（ADR-012 / `RoutableBookingsAdapter` と同じ形）
- BC 間で型を渡さない。アダプタが `ProposedRoute` を素の値へ変換する（ADR-005）
- **「便が無い」と「期限に間に合わない」を区別する** —— 営業担当者が次に取る行動が違う
- **`EXPIRED` は永続化しない。** ADR-019 との違い（状態変化自体に業務上の意味があるか）を表で記録した

### 開始準備で見つけた正典の誤り

**`route_candidate` の所有 BC が、正典と検査の名簿の両方で誤っていた**（Routing → Estimation）。IT17 で入れた「正典と検査の突合」は、**両方が同じ間違いをしているため検出できない**。気づいたのはスキーマ（外部キー）まで遡ったときである。

### 新規の安全装置（すべて破壊検証済み）

| 安全装置 | 何を止めるか |
| :--- | :--- |
| `EstimateRouteCandidateTest` | 見積の数字が固定値になる（**スタブに戻すと 4 本すべて赤**） |
| `EstimateScreenTest` | 見積へ到達できない／他ロールに入口が出る |
| `EstimateToBookingTest` | 予約へ内容が引き継がれない |
| `EstimateCreationTest` | **入力が保存されない／種別変更で他の欄が消える** |
| `CheckMessageOriginTest` | 検査の失敗から理由に辿れない |
| `DelegatingAccessorRatchetTest` | 委譲アクセサが増える（**実際に自分で踏んだ**） |
