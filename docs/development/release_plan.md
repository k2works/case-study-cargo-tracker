# リリース計画 - 国際貨物輸送管理システム（java/take-6）

## 概要

本ドキュメントは、国際貨物輸送管理システムのリリース計画を定義します。

**スコープの区切り（どの US をどのリリースに入れるか）の正典は [リリーススコープ定義](release_scope.md) です。** 本ドキュメントはそこに**ストーリーポイント・イテレーション分割・スケジュール**を与えるものです。スコープを変更する場合は先に `release_scope.md` を更新してください。

### プロジェクト情報

| 項目 | 内容 |
|------|------|
| **プロジェクト名** | 国際貨物輸送管理システム（Cargo Tracker） |
| **目的** | 国際貨物輸送の予約から追跡・精算までを一貫して管理し、予約業務の効率化・最適ルート設計・リアルタイム追跡・例外対応の迅速化を実現する |
| **対象ユーザー** | 荷主・荷受人・営業担当者・経路設計者・追跡管理者・荷役作業員・経理担当者 |
| **開発チーム** | 1 名（AI ペアプログラミング） |
| **ブランチ** | `java/take-6` |

## 満足条件

### スコープ

Release 1 で「**予約から追跡までが一本つながる**」ことを最優先とします。幅を広げるより、細くても端から端までつながっていることを優先します（ウォーキングスケルトン）。

| リリース | 内容 | US 数 | SP |
|---------|------|------|-----|
| Release 0.1 | 予約基盤（認証・荷主・予約） | 6 | 16 |
| Release 0.2 | 経路設計・予約確定 | 6 | 21 |
| Release 1.0 | 追跡（予約から追跡までの一気通貫） | 3 | 8 |
| Release 1.1 | 実運用に必要な補完 | 12 | 41 |
| Release 2.0 | 精算 | 3 | 11 |
| （うち IT1〜IT8 の対象） | Release 0.1〜1.1 | 27 | 86 |
| **合計** | | **30** | **97** |

> US02 と US24 は他ストーリーの入力データを作るため、**先行して着手しなければ後続が動作確認できません**（`release_scope.md` の依存順序）。

### スケジュール

- **開発期間**: 8 イテレーション
- **イテレーション**: 1 イテレーション = 1 サイクル
- **リリース**: イテレーション末に動作するソフトウェアをデプロイする（小さなリリース）

### リソース

- **開発者**: 1 名
- **ベロシティ（初期値）**: **12SP / イテレーション**

> **初期ベロシティの根拠**: 同一題材の他言語版の実績から推定しています。`flix/take-1` 12.3SP（12 IT）、`haskell/take-1` 10.6SP（8 IT）、`scala/take-1` 10.1SP（9 IT）。**3 イテレーション経過後に実績で再調整します。**
>
> 環境構築が完了しており（Gradle・Docker・品質ツール・CI・Heroku デプロイ）、ウォーキングスケルトンの立ち上げコストが他 take より低いことを見込んで上限側の 12SP を採りました。**これは推測であり、IT1 の実績が最初の検証になります。**

## イテレーション計画

ベロシティ 12SP を基準に配分します。

| IT | リリース | ストーリー | 計画 SP | 目的 |
|----|---------|-----------|--------|------|
| [IT1](iteration_plan-1.md) | 0.1 | US26 / US27 / US31 / US02 | 9 | **ウォーキングスケルトン**。認証と荷主登録で「画面 → ドメイン → DB」を貫通させる |
| [IT2](iteration_plan-2.md) | 0.1 | US04 / US32 | 7 | 予約登録。Booking Context の集約と状態遷移を確立する。**US32 は IT1 レビューの受け入れ条件**として追加 |
| [IT3](iteration_plan-3.md) | 0.2 | US24 / US07 / US06 | 8 | 航海スケジュールの登録と検索。経路算出の入力を用意する |
| IT4 | 0.2 | US08 | 8 | **経路候補の算出**。最大の 1 件を単独で扱う |
| IT5 | 0.2 | US09 / US11 | 5 | 経路の選択・確定と予約への紐付け |
| IT6 | 1.0 | US13 / US14 / US15 / US33 | 10 | **一気通貫の完成**。予約確定・追跡番号・荷役記録。US33 は IT1 持ち越し（C2）の期限 |
| IT7 | 1.1 | US18 / US16 / US17 / US03 / US25 | 13 | 追跡照会と引取・状態更新 |
| IT8 | 1.1 | US05 / US10 / US12 / US19 / US20 / US28 / US29 | 28 | 例外対応・誤配・通関（**要分割**） |

> **IT8 は 28SP でベロシティを大きく超えています。** IT1〜IT3 の実績が出た時点で IT8 を 2〜3 イテレーションに分割します。**今の時点で細かく割っても、根拠のない数字を精密に見せるだけです。**
>
> IT1 は 9SP、IT2 は 7SP と控えめにしています。**初回はベロシティが未検証**であり、環境構築が終わっているとはいえ実装の地ならし（`SecurityConfig`・MyBatis マッパー・Thymeleaf レイアウトの初出）が同時に発生するためです。

### ベロシティ

| IT | 計画 | 実績 | 備考 |
|----|------|------|------|
| IT1 | 9 | 9 | 対象 4 ストーリーをすべて完了 |
| IT2 | 7 | 7 | US04 / US32 を完了。**計画外の地ならしが 5 件**発生（完了報告書に記録） |

**ベロシティの初期値 12SP は据え置きます。** IT1 の実績 9SP は「計画 9SP を完了した」ことを
示すだけで、**上限を測っていません**（9SP しか積んでいないため）。IT2 の 7SP と合わせても
16SP であり、判断材料が足りません。**IT3 終了時に 3 イテレーションの実績で再調整します**
（development_strategy.md の予定どおり）。

> IT1 では計画外の作業が発生しました。マルチパースペクティブレビューで見つかった
> 高優先度 10 件の修正、SonarQube の整備、脆弱性 30 件の解消です。**これらは SP に
> 計上していません。** 見積もりの対象はユーザーストーリーであり、品質を満たすための
> 作業はストーリーの一部だからです。ただし**次の IT の計画では、この地ならしが
> 一度きりだったのか毎回起きるのかを見る必要があります**。

## リスクとバッファ

| リスク | 影響 | 対応 |
|-------|------|------|
| 初期ベロシティ 12SP が過大 | 全体スケジュールが後ろ倒しになる | IT3 終了時に実績で再計算する。**推測値を実績に置き換えるまで計画を信用しない** |
| US08（経路候補算出）が 8SP で収まらない | IT4 が破綻する | 内部シミュレーション（ADR-006）で実装する。外部連携は行わないため範囲は閉じている |
| IT8 が 28SP と過大 | 実行不能 | IT3 終了時に分割する（上記） |
| 認証（US26/US31）の実装が地ならしを兼ねる | IT1 が膨らむ | IT1 を 9SP に抑え、US04 を IT2 に分離済み |

**バッファは取っていません。** 代わりに Release 1.1 以降を優先度「中」とし、**削れる範囲を明示**しています。
