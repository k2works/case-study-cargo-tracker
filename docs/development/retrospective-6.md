## Keep（継続すること）

### 技術的成功事項

- **BC 独立の徹底（新コンテキストでも維持）**: 新設した `domain-estimation`／`app-estimation` を他 domain クレート非依存に保ち、Routing 参照を `RouteCandidateProvider` ACL（`estimation_acl.rs`）に隔離。architect が「BC 独立は Cargo.toml レベルで健全・BC 跨ぎ結線は ACL に完全に閉じ込め」と評価。ADR-0007 で方針を明文化。
- **純粋関数導出の例外拡張（ADR-0006 の予告どおり）**: `current_status()` の末尾判定に `has_active_exception()` を織り込み、例外解決後は直前イベント状態へ復帰。状態を二重管理せず、ADR-0006 の「導出ロジック差し替えで拡張」を正確に実現。
- **型による意味の表現**: `enum RouteCheck { OnRoute, OffRoute, Unknown }`（Try#5）で「判定不能＝警告しない」を型で表現。IT5 の bool 三値問題を解消。
- **アウトサイドインの一貫実施**: US01 を受入（HTTP/E2E）起点で設計し、`domain-estimation` の `Estimate` 集約・`RouteCandidate` へ落とした。貧血ドメインを回避しつつ業務シナリオ起点で束ねた。

### プロセス的成功事項

- **IT5 Try の高返済率**: #1 通知アサート DoD 化・#2 冪等再操作パス・#4 Read Model キャッシュ明記・#5 RouteCheck enum を返済。#3 は宛先解決まで前倒しで対応。
- **レビュー→改善ループの実効**: 5 視点並列レビューで重複指摘された高優先度（通知宛先ハードコード＝機能欠陥・料金テスト欠如・危険物出し分けテスト欠如・対応表不整合）をクローズ前に全対応。ADR 2 件も起票。
- **設計図の同時整備**: 計画の設計節に PlantUML（ドメインモデル・状態遷移・ER・画面遷移・シーケンス）を掲載し、構文エラーもクローズ前に修正。

## Problem（問題点）

### テスト・受入基準の課題

- **通知宛先ハードコードが機能欠陥として残存していた（Try#3 の一部先送りの帰結）**: US14 は荷受人連絡先を使うのに、状態変更・例外発生/解決・荷役反映の通知だけ `shipper@cargotracker.example` 固定で、荷主に届かない状態だった。5 視点中 4 視点が重複指摘。HTTP フローが通知「件数」しか見ていなかったため素通りしていた。「送信＝記録」系の宛先・本文まで検証する必要（IT4-6 で通知テストの穴が 3 IT 連続で形を変えて露見）。
- **危険物フォーム出し分けが全レベル未検証だった**: `data-testid="hazardous-field"` を用意済みなのに E2E で表示検証をしていなかった。受入基準「危険物フォーム出し分け」とテストの 1:1 対応が欠落。
- **推定到着日が受入基準を厳密には満たさない簡易実装**: 「最新イベント日時＋頃」は到着"予定"ではない。コメントで負債を明示しているが導出テストも無い。確定経路連携（IT7）が前提。

### 設計・実装の課題

- **概算料金のマジックナンバーがテスト非対象だった**: composition 層 private 関数で金額を検証するテストが無く、業務上重要な金額のリグレッションを検出できなかった。名前付き定数＋純粋関数化＋単体テストで解消。
- **rank 採番の二重責務**: ACL（所要日数昇順）と集約 `replace_candidates`（rank 再ソート）に責務が重複。ADR-0007 に負債として記録。
- **per-handler 認可の構造的リスク**: 公開ルート追加で「ガード引数書き忘れ＝認可漏れ」の面積が広がる。ADR-0008 で検出策（ルーター分割）を将来対策として記録。

## 次イテレーション（IT7）への引き継ぎ

- **IT7 スコープ**: 破損・紛失例外処理（US20 系）と輸送料金算出・法人割引適用。Tracking 例外種別に Damage/Lost を追加（`ExceptionType` 拡張）、Estimation の概算料金スタブを料金ポリシー確定に伴いドメインへ引き上げる（ADR-0007 の負債返済トリガー）。
- **通知の実配信**: Try#3 の繰り越し分（メール送信・通知履歴導線）を IT7 で対応。
- **推定到着日の厳密化**: 確定経路連携（Try#4）。
- **UX 改善のまとめ対応**: dashboard 拡充・見積有効期限・公開ページ再照会フォーム（Try#6）。
- **料金ロジックの配置**: 料金ポリシー確定時に `domain-estimation` へ引き上げ（ADR-0007）。
