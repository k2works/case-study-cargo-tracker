## KPT 分析

### Keep（良かったこと・継続すること）

#### 技術的成功

- **Playwright E2E テスト整備（TI03）完了**: ログイン→ダッシュボード、航海スケジュール、貨物予約→経路設計→追跡の基幹フロー 6 シナリオを整備できた。リグレッション防止基盤が確立した
- **RabbitMQ マイクロサービス間イベント連携（TI04）完成**: `TrackingNumberIssuedEvent` の publish → consume フローを実装し、bookingms の予約状態が TRACKING_ISSUED に自動遷移するようになった
- **コードレビュー指摘の迅速な解消**: TI05（H5/H7）・TI07（#1〜#5）の高優先度指摘をすべて解消できた
- **SonarQube Quality Gate PASS**: リファクタリング（ラムダ内スロー分離・Code Smell 解消）により品質基準を維持した
- **BE テストカバレッジ 80%+ 達成**: 主要 5 サービス（authms 84%・bookingms 83%・trackingms 89%・routingms 84%・gatewayms 95%）が目標を達成した
- **v0.1.0 リリースタグ作成・リモートプッシュ完了**: CHANGELOG.md 作成・package.json バージョン更新・git tag・リモートプッシュまで一貫して実施できた

#### プロセス的成功

- **Codex 分業による効率化**: BE 実装（イベントクラス・RabbitMQ パブリッシャー・リスナー）を Codex エージェントに委譲し、並列で作業を進められた
- **TDD サイクルの遵守**: TI04・TI07 の BE 実装でテストファースト（Red→Green→Refactor）を徹底できた
- **コミット粒度の適切な管理**: Conventional Commits に従い、機能・バグ修正・リファクタリングを分けてコミットできた

### Problem（課題・改善が必要なこと）

#### 未完了タスク

- **TI05 3.3（H6 FE: API エラーレスポンスのトースト通知）未着手**: BE 側（H6 バリデーション改善）は完了したが、FE 側でエラーメッセージをトースト通知に表示する実装が未着手のまま残った
- **TI04 2.4（統合テスト）未着手**: RabbitMQ イベント連携の動作検証は手動確認にとどまり、Testcontainers による自動化統合テストが未実装
- **TI03 1.7（CI パイプライン E2E 統合）未着手**: Playwright E2E テストの CI 統合が未実施のため、CI/CD 上での自動実行ができていない

#### 品質目標

- **FE テストカバレッジ 70% 未達**: DashboardPage・BookingForm テストを追加したが、最終カバレッジは約 48% にとどまった。テスト対象が少ない（主要ページのみ）ことが原因
- **FE テスト実装の困難さ**: React コンポーネントのテストでモック戦略が複雑になりやすく、テスト作成に時間を要した

#### 見積もり精度

- **TI03 E2E テストが計画より工数超過**: Playwright の既存テスト（1.1〜1.6）が IT5 で整備済みであることを考慮していなかったため、実際の追加作業は 1.5（荷役記録→追跡照会フロー追加）のみとなった
