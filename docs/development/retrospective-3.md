# イテレーション 3 ふりかえり（KPT）

対象: IT3（2026-07-25 開発完了）。中盤局面（インサイドアウト）の初回。Routing/Estimation の 2 新規 BC を立ち上げ、US24/US25/US07（航海スケジュール登録・更新・検索）・US01（輸送見積作成）・US06（予約引き渡し）を実装。基盤として CargoType の共有カーネル昇格・sqlc の BC 別分割を先行。実績 17 SP。

## Keep（うまくいったこと）

### 技術的成功

- **インサイドアウト TDD の徹底**: 新規 BC を domain（値オブジェクト・集約・不変条件）→ infrastructure（Repository）→ application → interfaces の順で作り込み、貧血ドメインモデルを回避。routing domain 100%・estimation domain 97.4% のカバレッジ。
- **基盤の先行整備が効いた**: タスク 0 で CargoType 昇格・sqlc BC 別分割を先に済ませたことで、新 BC は最初から `shared.CargoType` を参照し、`make arch` の BC 独立性検証を一度も破らずに立ち上げられた。IT2 の ShipperCode 移設パターンの再利用が奏功。
- **sqlc の BC 別分割（ADR-0005 決定3 完遂）**: 共有 sqlcgen の隠れた BC 結合を解消し、go-arch-lint に `*-sqlcgen` コンポーネントを定義して越境を構造的に検出できるようにした。
- **コンテキスト固有型の一貫適用**: `VoyageNumber` を Routing 固有型として新設し、BC 独立性を型で表現。Schedule の連結制約（空間・時刻）を集約の不変条件として担保。

### プロセス的成功

- **着手前の横断整合検証が奏功**: opening-iteration の validating-design で CargoType の BC 独立性違反リスク・US06 の状態設計揺れを事前に検出し、実装前に方針を確定できた。手戻りゼロで着手。
- **マルチパースペクティブレビューの網羅性**: Programmer が Schedule の時刻連続性欠落（宣言と実装の乖離）、Technical Writer が設計ドキュメント本体の未反映（DoD 未達）、User-rep がフォーム UX を検出。go-arch-lint 緑でも見えない不変条件・ドキュメント整合をクローズ前に潰せた。

## Problem（課題・見積もりのズレ）

- **Schedule の不変条件に抜けがあった**: 「時系列順」と宣言しながら空間連結のみ検証し、時刻連続性を検証していなかった（Programmer H-1）。ドメイン名と実装の乖離はレビューで初めて露見。
- **設計ドキュメント本体の是正が実装より遅れた**: 計画で「注」として是正対象に挙げた 3 トピック（voyage 列・CargoType 昇格・航路権限）を実装時に本体反映せず、クローズのレビューで DoD 未達を指摘された。実装と同時にドキュメントを直す規律が緩んだ。
- **フォーム UX の横展開漏れ**: IT2 の Try H1（必須検証 UI）を新フォームに一部しか展開できず、レビューで指摘（航海登録の日付・区間の必須検証）。運送区間が固定 2 段・edit は 1 区間でデータ損失リスクも残る。
- **見積ルート候補がスタブ**: 経由港が候補に含まれず、`time.Now()` 依存でテストが非決定的。US08 依存として割り切ったが、集約の期限検証もアプリ層に流出。
- **SonarQube でアクセシビリティ違反が多発**: テンプレートのラベル未関連付けで新規違反 26 件。実装時にアクセシビリティを意識できていなかった。
- **見積もり**: 17 SP は完了したが、2 新規 BC 同時立ち上げは大きく、レビュー対応・品質ゲート対応で工数が伸びた。

## 次イテレーション（IT4）への引き継ぎ

- **IT4 スコープ**: US08（経路候補を算出する・8SP）・US09（経路を選択・確定する・3SP）。中盤の複雑ドメインの核心。IT3 で作った Voyage 集約・Estimate 集約を土台に、寄港地接続グラフ探索とルート候補の精緻化を実装する。
- **持ち越し（Try 反映必須）**: T2（動的区間・edit）・T3（候補精緻化・Clock 注入）は US08 と同時に実施。T1（設計是正の同時反映）・T4（アクセシビリティ DoD）は継続方針。
- **ベロシティ**: IT1 15 SP・IT2 8 SP・IT3 17 SP。3 IT 平均 ≒ 13 SP/IT。中盤の複雑ドメイン（US08=8SP 単体）に向けて、IT4 は US08+US09=11SP を基本スコープとし、繰越 Try を加味して着手時に再見積もり。
