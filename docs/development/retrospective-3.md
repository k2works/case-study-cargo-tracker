## KPT 分析

### Keep（継続すること）

#### 技術的成功

- **Testcontainers によるリアルな RabbitMQ 連携テスト**: H2 やインメモリモックではなく、Testcontainers で RabbitMQ コンテナを起動し、CargoRoutedEvent の発行・消費をリアルな環境で検証できた。本番環境との乖離リスクを低減する効果的なアプローチ
- **ポート/アダプタパターンでの DDD 設計**: CargoRoutedEventPublisher をポートインターフェースとして定義し、RabbitMQ アダプタと NoOp フォールバックを分離した。テスト容易性と本番環境の柔軟性を両立した設計パターン
- **SonarQube Quality Gate PASS**: Bug 0・Vulnerability 0・Code Smell 0 を達成。静的解析による品質チェックが CI パイプラインに組み込まれ、品質基準を自動的に担保する体制が確立された

#### プロセス的成功

- **インサイドアウト開発の継続**: BE ドメイン → アプリケーション → インフラ → インターフェース → FE の順序を IT3 でも維持。API が安定してから画面を構築するパターンが定着した
- **E2E テストの即時追加**: 予約→経路割り当て→確定の一連フローを E2E テストで検証し、CI で自動実行される体制を維持

---

### Problem（改善が必要なこと）

#### 技術的課題

- **@ConditionalOnBean の評価順序問題**: RabbitMQ アダプタと NoOp フォールバックの切り替えに `@ConditionalOnBean` を使用したが、Bean の評価順序によっては NoOp が優先されるリスクがある。テスト環境と本番環境で異なる挙動を示す可能性があり、信頼性に懸念が残る
- **@DirtiesContext によるテスト実行時間の増加**: Testcontainers を使用するテストで `@DirtiesContext` が必要となり、Spring コンテキストの再起動によるテスト実行時間の増加が発生。テストスイート全体の実行時間が延びる傾向にある
- **テストカバレッジ 80% 未達の継続**: IT2 から引き続き、BE・FE ともにカバレッジ目標 80% に到達していない。特に FE のカバレッジ改善が進んでいない

#### プロセス的課題

- **カバレッジ改善の先送り**: IT2 の Try で掲げた FE hooks テストの TDD 実施が IT3 でも実現できなかった。機能実装を優先した結果、カバレッジ改善が 3 イテレーション連続で先送りされている

---

### Try（次のイテレーションで試すこと）

| アクション | 期待効果 | 優先度 |
|-----------|---------|--------|
| `@ConditionalOnBean` の代替手段検討（`@AutoConfiguration` への移行） | Bean 評価順序の不確実性を排除し、環境切り替えの信頼性を向上 | 高 |
| Testcontainers の shared container 活用でテスト時間短縮 | `@DirtiesContext` を不要にし、コンテキスト再起動のオーバーヘッドを削減 | 高 |
| FE hooks テストを TDD で書く（IT2 から引き続き） | FE カバレッジを 80% 以上に引き上げる | 中 |
| IT4 の計画時にカバレッジ改善タスクを SP に含める | カバレッジ改善を「機能外タスク」ではなく計画内タスクとして管理 | 中 |

## 次のイテレーション（IT4）への引継ぎ事項

### 技術的引継ぎ

- **@ConditionalOnBean の信頼性**: IT4 で `@AutoConfiguration` への移行を検討する。特に trackingms での RabbitMQ 連携時に同じパターンを適用する場合は注意が必要
- **Testcontainers の shared container**: IT4 で新規テストを追加する際に shared container パターンを導入し、テスト実行時間の増加を抑制する
- **テストカバレッジ**: IT4 の DoD にカバレッジ改善タスクを含め、機能実装と並行してテスト拡充を行う
- **Cargo 集約の状態遷移**: IT3 で PRELIMINARY → ROUTE_PROPOSED → CONFIRMED / CANCELLED の遷移を実装した。IT4 では CONFIRMED → TRACKING_ISSUED の遷移を追加する
