## エグゼクティブサマリー

**経理の月次締めが画面で完結し、荷主が自分から見に行かなくても異常に気づけるように
なった。** あわせて、IT15 が**運用（夜間の継続実行の禁止）で守っていた状態**を実装で
塞いだ。

本 IT の価値は、機能そのものより**検査が 6 回、実際に欠陥を捕まえたこと**にある
——いずれも「実装は正しいつもり」の状態からである。

一方で、**自分が入れた退行をレビューが見つけた**。US38 の絞り込みで「合計から外す」と
「一覧から消す」を取り違え、**取り消した請求書（赤伝）が検索から消えていた**。
しかも自分で書いたテストがその誤りを固定していた——テストは実装ではなく
**私の理解**を写していた。

## 技術的成果

### ADR-032（荷主への知らせ）の 7 決定

| 決定 | 内容 |
| :--- | :--- |
| 1 | **画面がポーリングする**（押し出す仕組みを持ち込まない）——ブラウザはメッセージ基盤を直接読めない |
| 2 | **既読はサーバが覚える**——ブラウザに持つと、端末を変えると同じ知らせが出る |
| 3 | 既読は**進むことしかできない**（ドメインと SQL の両方に置く） |
| 4 | **出した時点で既読**にする |
| 5 | 自社かどうかの判定は**一覧（US33）と同じ道**を通る |
| 6 | シミュレーションは**確認用の荷主を使い回す**（当初「毎回紐付け直す」は誤りだった） |
| 7 | 継続実行のスケジューラは**Pod が 1 つ**であることを前提にする |

**7 件すべて、実装を壊すと検査が赤になることを確認した。**

### 検査が 6 回、実際に働いた

| 何が捕まえたか | 何を捕まえたか |
| :--- | :--- |
| 方言スモーク | `ON CONFLICT` が H2 で構文誤り（PostgreSQL では通る） |
| `SchemaDesignConsistencyTest` | `data-model.md` に `simulated` が無い |
| JaCoCo | `CargoSnapshot` の 4 引数コンストラクタが**誰も通らない道**になっていた |
| Checkstyle（FileLength） | `BillingControllerTest` の肥大。**変わる理由が違う**テストを分ける契機 |
| oxlint | 種の受け渡しを effect で同期していた |
| E2E（CI） | 新しい区画が既存の指し方を曖昧にした（`SES-`・「種」が二重に一致） |

### 途中で見つけた、計画になかった問題

| 内容 | 影響 |
| :--- | :--- |
| **利用者を切り替えると入った直後に断られる**（利用者からの申告） | ログイン後の戻り先が「前に開こうとした人」のものだった。担当外の画面へ着地して 403 |
| **Heroku に simulationms のアプリが無い** | `deploy:dev` が 401 で停止（Heroku は未作成アプリへの push に 404 でなく 401 を返す） |
| **`deploy.js` が 3 サービスに接続先を渡していない** | **US33（荷主の自社貨物追跡）が Heroku で 500 を返し続けていた**。「実環境だけ 500」の 4 度目 |
| 検査はあったが**配り先の片方しか見ていなかった** | `ServiceEndpointConfigTest` が k8s だけを見て Heroku を見ていなかった |
| **適用済みマイグレーションの編集**（IT15 の `IF NOT EXISTS` 削除） | 既存クラスタだけが `checksum mismatch` で起動しない |
| `db:reset` が**終了中の Pod を待って必ず失敗** | `-l app=postgres` が古い Pod にも一致していた |

### Quality Gate が PASS にならない理由

未レビューの Security Hotspot 2 件（java:S2245・乱数の使用）が残る。
**中身を読んだうえで安全と判断している**（[ADR-031](../adr/031-random-continuous-simulation.md)
に根拠を記載）——`SecureRandom` に替えると「同じ種 → 同じ並び」が成立しない。

承認の記録には `SONAR_ADMIN_TOKEN` が要り、**IT14 から 3 IT 連続で未設定**である。
認証情報の問題であって、コードの問題ではない。

## レビュー結果

[マルチパースペクティブレビュー](../review/イテレーション16_review_20260902.md)——
高 5・中 5・低 4 件。**高は全件対応**、中は 4 件対応・1 件を IT17 へ、
低は 2 件対応・1 件確認済み・1 件を IT17 へ。

**5 視点のうち、独立したレビューが返ってきたのは利用者代表 1 つだけである。**
これで **3 回連続**（IT15 は 4 体、IT16 の計画時は 2 体が無応答）。今回は待ち時間の
上限を先に決めたため判断は速かったが、**上限を決めても独立したレビューが得られない
事実は変わらない**。

**利用者代表が挙げた高 5 件のうち、自分で見つけられたのは 0 件である。**
