## Keep

### 技術面

- **`BookingLeg` VO と `booking_legs` テーブルで区間情報をドメインモデルに正しく表現できた**: 経路の各区間を `BookingLeg` 値オブジェクトとして切り出したことで、予約集約が「選択済み経路の区間一覧」を明示的に保持できるようになりました。テーブル設計とドメインモデルが 1:1 対応しており、US22 の受入条件「区間詳細を `#assignModal` で確認できる」も自然な実装で満たせました。

- **候補なし時の条件調整フォームを US23 で実装し、IT7 の Problem だった AC5（候補なし）シナリオをカバーできた**: IT7 の Problem で「`StubRouteProviderAdapter` の制約上 E2E で候補なしを再現できない」という課題を認識していました。US23 では候補なし時の条件調整フォームと営業担当者リンクを実装し、候補ゼロのシナリオを UI として明示的に処理するパスを追加しました。これにより AC5 相当の UX を完結させました。

- **`BookingEventHandler` 通知ハンドラで予約イベントを疎結合に統合できた**: US24 の実装では `BookingEventHandler` を通じて経路確定後の通知処理を書くことで、booking BC と notification BC の結合度を最小化しました。TDD サイクルで実装した結果、通知ハンドラの単体テストが独立して書けており、リグレッションリスクを抑えられています。

- **SonarQube `java:S5960`（ラムダ内複数スロー）を静的定数抽出で解消できた**: ラムダ式内で複数の例外をスローする実装が SonarQube に検出されましたが、スローする例外を静的定数に抽出することでルール違反を解消しました。修正と同時に可読性も向上しており、「品質指摘がリファクタリングの機会になる」パターンを実践できました。

- **E2E テスト数を IT7 比 +9 件（51 件 → 60 件）増やしながら全件 Green を維持できた**: US22〜US24 の受入条件を E2E でカバーし、テストスイートを着実に拡充しました。IT7 から継続している「受入条件 = E2E テストケース」のパターンが IT8 でも機能しています。

### プロセス面

- **E06 リグレッションを同一イテレーション内に検出・修正できた**: IT8 で追加した `#assignModal` 内の `h5` 要素により、既存 E2E テスト `E06` の `page.locator('h5')` が複数マッチしてエラーになりました。セレクタを `h5.mb-3` に絞り込んで即時修正し、イテレーション内に解消できました。IT7 の Try「UI 変更後は即座に E2E 全件を実行して回帰確認する」を実践した成果です。

- **IT7 の Try 項目を IT8 内に消化できた**: IT7 で掲げた `StubRouteProviderAdapter` の `viaLocodes` 意味論明確化・E2E 全件実行による回帰確認・US23 での候補なしシナリオカバーの 3 点を IT8 の実装・テスト工程で対処しました。ふりかえりの Try が次イテレーションで具体的な改善につながるサイクルを維持できています。

- **Phase 3（経路設計高度化）全 18 SP を 2 イテレーション（IT7 + IT8）で完了できた**: IT7 で 10 SP、IT8 で 8 SP を計画通り消化し、Phase 3 を完結させました。AI 支援開発により計画期間（4 週間）より大幅に短い実績（2 日）で完了しており、ベロシティの高さを維持できています。

## Problem

### 設計・実装

- **計画期間と実績期間の乖離が継続している**: IT8 の計画期間は 2026-07-07〜07-20（2 週間）ですが、実績は 2026-04-05 の 1 日で完了しています。IT7 でも同様の乖離を指摘しましたが、リリース計画への反映が追いついていません。実績ベロシティに基づいた計画の見直しと `release_plan.md` の更新が必要です。

- **lint-staged のハング問題が未解消**: IT7 から持ち越された課題で、IT8 でも `git commit --no-verify` を使用しています。pre-commit の品質ゲートが機能していない状態が続いており、SonarQube や E2E に頼った品質保証になっています。

- **E2E テストのセレクタが DOM 構造に依存しやすい**: `h5`・`h5.mb-3`・`main h5` のように要素タグとクラス名を組み合わせたセレクタは、UI リファクタリングの際に壊れやすいです。`data-testid` などのテスト専用属性で E2E セレクタを安定させる方針の検討が必要です。

### 品質管理

- **IT7 中・低優先度レビュー指摘が IT8 にも持ち越し**: 経路候補画面の経由港表示スタイル統一・`DesignCondition` の `status` バッジ色・モーダルの `aria-label` など、UI/UX の改善点が引き続き未対応です。Phase 4 着手前に整理・対応を検討します。
