## Keep（うまくいったこと）

### 技術的成功

1. **強化イテレーションでの受入残の体系的消化**: IT7 レビュー（高7/中8/低5）と retro-7 Try#1-#5 を計画のエピック 1-5 に写像し、受入残を Red→Green で 1 つずつ潰した。各コミットが 1 タスク完結で緑を保ち、後戻りゼロ。
2. **既存パターンの再利用による低コスト強化**: 集約拡張（税フィールド）・DU 写像永続化・合成層 ACL（`findEmailByBooking`・`hasUnresolvedException`・`findRouteLegs`）・受け入れ縦貫通という確立済みパターンを再利用。新規概念（`ConsumptionTax`・`Charge.deriveDistance`）もドメインサービスとして純粋に追加できた。
3. **Settled 同期の集約駆動化**: 状態射影のガードなし `UPDATE`（`syncBookingStatus`）を廃止し、`RouteAssignment.settle` 経由で Delivered→Settled の遷移ガードを集約で通す方式へ移行。booking_status の実値検証で射影の検証欠落（IT7 レビュー高#1）も解消。
4. **セキュリティ優先の技術判断**: 決済契約固定で WireMock.Net が高深刻度の推移的依存（`System.Linq.Dynamic.Core`・`Scriban.Signed`・NU1903）を多数引き込むことを検出し、外部依存ゼロの `HttpListener` インプロセス契約スタブへ切り替え。ADR-0014 に逸脱理由を明記。
5. **到達不能分岐の検証可能化**: `Money.add` の異通貨拒否分岐が単一通貨（JPY のみ）で到達不能だった問題を、`CurrencyCode` に USD を追加して検証可能化（IT7 レビュー中#3 消化）。

### プロセス的成功

1. **Ralph Loop の小さな緑の連鎖**: エピックを 8 ターンに分割し、各ターンでビルド緑・全テスト緑・設計反映・コミット。`[<Literal>]` decimal 不可・Giraffe 属性ヘルパー・withServer シグネチャ変更などの躓きを都度即修正。
2. **設計ドキュメントの都度反映**: domain-model・ADR-0013/0014・data-model を実装と同時に更新し、ドキュメントドリフトを発生させなかった。
3. **不可逆アクションの確認**: DB スキーマ変更（マイグレーション 0014）とリリース出荷（バージョンバンプ・tag）でユーザーに確認を取り、Ralph Loop 内での自律実行と人間判断の境界を守った。

## Problem（課題）

1. **付加料金（`invoice_line_item`）は未実装のまま**: 消費税は実装したが、燃油サーチャージ等の付加料金明細の計上は継続扱い。金額内訳は基本料金/割引/小計/消費税/総額に留まる。
2. **距離導出が代理指標**: 地理座標を持たないため、距離を確定経路の区間数×標準区間距離（500km）で代理導出。実距離マスタ（location 間距離）は未整備。
3. **MailSender が console 実装**: 送信抽象は導入したが実 SMTP/SES 送信は未結線（`consoleMailSender` が既定）。実送信基盤の整備は運用フェーズへ。
4. **決済アダプタは合成層未結線**: 実 HTTP アダプタ（`PaymentGateway.createHttp`）と契約テストは整備したが、本番の決済 API URL・認証情報が未確定のため、Web の `paymentConfirm` は依然 `stub` を使用。
5. **リリース出荷が未完了**: バージョンバンプ・CHANGELOG・git tag はユーザー判断で保留。正式出荷は別途判断待ち。
