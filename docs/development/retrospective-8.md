## KPT 分析

### Keep（継続すべきこと）

#### 技術的成功事項

- **IT7 申し送り事項の即時対応**: IT8 冒頭でまず htmx フラグメント化（`display:none` 廃止・`th:fragment` + `d-none` パターン）を実施した。申し送り事項を最優先タスクとして組み込む習慣が定着している
- **Tracking コンテキストの段階的拡張**: IT7 で構築した Tracking コンテキストに US16（CLAIM 種別・状態遷移）・US18（TrackingQueryService・Read Model）・US17（手動状態更新コマンド）を TDD で追加した。既存設計の延長として自然に機能拡張できた
- **CQRS 原則の適用**: US18 の追跡情報照会を `TrackingQueryService`（Read Model）として分離し、コマンド側との責務を明確に分けた。`domain-model.md` の「クエリ専用履歴参照は Read Model として分離」方針に準拠できた
- **公開 API の認証分離**: US18 の公開追跡（`/public/tracking/{trackingNumber}`）を `PublicTrackingController` として認証あり側（`TrackingThymeleafController`）と分けて実装した。Spring Security の二重フィルターチェーン設計が活きた
- **ナビゲーション UX の改善**: ふりかえり後に「ナビバーから追跡照会にたどり着けない」「予約一覧から荷役作業登録できない」問題を発見・即時修正した。ユーザー視点でのフロー確認が機能改善につながった
- **E2E テストの Page Object 拡張**: `TrackingPage.ts` に `TrackingDetailPage`・`StatusUpdatePage` を追加し、追跡照会と手動状態更新画面の操作を抽象化した。既存パターンとの一貫性が維持されている

#### プロセス的成功事項

- **計画期間前の完了**: Week 15-16（2026-04-18〜2026-05-01）の計画に対して 2026-04-20 に全主要タスクを完了した。AI ペアプログラミングによる高速開発が継続している
- **成功基準の全チェック達成**: 6 つの成功基準をすべてチェック状態にして完了できた
- **バグ即時修正サイクル**: E2E テスト失敗（`StatusUpdatePage.submitButton` が 2 要素にマッチ）→ `hasText: '更新する'` でセレクタ修正→全件パス、のサイクルを素早く完了した

### Problem（問題点）

#### 未完了事項・受入条件の部分充足

- **SonarQube 未実施**: DoD のうち「SonarQube Quality Gate PASS」が未確認。IT8 実装完了後にスキャンを実施していない
- **US16/US17 メール通知未実装**: 受入条件「状態変更の種類に応じて荷主への通知が送信される（US17 AC5）」が未実装。メール送信インフラが本プロジェクトに未整備のため IT10 以降へ持ち越し
- **US18 推定到着日未表示**: 受入条件「推定到着日が表示される（US18 AC2）」が部分実装（追跡詳細には現在の状態・荷役履歴は表示されるが推定到着日フィールドが未実装）
- **H-1〜H-3, H-5〜H-9 の保留継続**: IT5 レビュー指摘（特に H-8 費用情報表示・H-9 割り当て済み経路表示）が引き続き未対応のまま蓄積している

#### 技術的課題

- **H2 データベースの長時間稼働問題**: E2E テスト実行中に `CHK_SHIPPER_TYPE` チェック制約失敗が発生した。H2 2.x の既知バグ（長時間セッション後の DB クローズ）が原因。アプリ再起動で回避できるが、根本対策（PostgreSQL への切り替えまたは H2 ファイルベース DB）が必要
- **E2E テスト構造のリファクタリング遅延**: `tracking.spec.ts` で `setupTrackingIssuedBooking` 関数が `test.describe` ブロック内に誤挿入され、構文エラーが発生した。テストファイルの全体構造を把握してから追記する習慣が必要
