## 技術的成果

### 例外の状態管理

- **発生前の状態をカラムに退避**（`V14`）。解決時の復帰先を履歴から再導出すると、
  ユニットテストが緑でもクロスリクエストで誤復帰する
- **例外中の再発生を拒む**。未解決の行が 2 つ並ぶと、解決の SQL が両方を
  同じ日時・同じ対応方針で塗り潰し、どちらの対応だったか読めなくなる
- **書き込みを和型で表す**（`ExceptionWrite`）。当初は `resolvedAt = Some("")` を
  「解決でない」の合図に使っていたが、**番兵は型でもテストでも守られない**

### arch-lint 規約 13

ADR-0014 決定 4（単一 BC へ向かう書き込みアダプタは 3 本まで）を機械が数える形にした。
**4 本目で実際に赤くなることを実測**している。規約は 13 件、メタテストは 36 件。

### `Clock.now()`

エスカレーションの判定は時間単位だが、`today() + "T00:00"` を渡していたため
**最大 24 時間ずれていた**。分精度の現在時刻を足した。

## 課題と残作業

### 本イテレーションで判明した主要な問題

1. **安全装置の空振りが 4 イテレーション連続**（行ロック → UNIQUE → 時刻の逆行 →
   `escalated`）。今回は「計算した結果を誰も受け取っていない」形だった
2. **記録と解決を別々のテストで確かめていた**ため、連鎖が切れていることに
   気付けなかった。個別はすべて緑だった
3. **追跡管理者の画面が荷主の画面より情報が少なかった**。IT10 の H8 と向きが逆の
   同じ形
4. **「この IT で塞いだ穴」の照合（IT11 Try T1）が、新しい入口で漏れた**

## v1.0.0 の総括

**全 12 イテレーション・20 ユーザーストーリー・149 SP を完了した。**

業務フローは端から端まで通る——見積 → 予約 → 経路 → 確定 → 追跡番号 → 荷役 →
通関 → 引取。乱れたとき（経路逸脱・遅延）の処理も入っている。

既知の制約は 6 件（通知・記録の取り消し・未解決例外の一覧・精算・外部連携・
間欠失敗）で、いずれも[ふりかえり](retrospective-12.md)に当座の運用とともに記録した。
