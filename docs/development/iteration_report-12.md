## エグゼクティブサマリー

**IT12 で Release 1.1（49SP）が完成した。**

US35 は IT7 の引き継ぎである。IT7 の引取記録は**提示された値をそのまま書き写すだけ**で、照合する相手がシステムの中に無かった。「記録はできるが引き渡しの証明にならない」という判定から 5 イテレーション後、**採番と照合が入り、引取が証明になった**。

US36 は IT6 のレビュー H11 が US 化を求めてから 6 イテレーション後の実装である。**誤登録をそのままにすると、貨物が届いていないのに配送完了として扱われる**という穴が塞がった。

**返済枠がストーリー本体と同じ規模（27h / 30h）だったが、8 タスク 12 件をすべて返し、1 つも落とさなかった。** 3 イテレーション繰り越していた C6 / C11 / C12 / C16 にも決着がついた。

一方で、**クローズ前の自己レビューが高優先度 3 件を見つけた**。全緑の状態からの発見は 4 イテレーション連続である。とくに「訂正を承認しても記録が直らない」は、**マニュアルが実装より多くを主張していた**形であり、IT11 の Problem がドキュメントで再発した。

## 技術的成果

### 新しい設計判断

- **ADR-015: BC 間の結合は SQL の層でも検査する。** ArchUnit は Java の依存グラフしか見ない。**検査が緑であることが、越境していないことの根拠にならない**
- **引取確認コードは追跡番号とは別の値**（形式も `CLM-` で分ける）。追跡番号は取引先へ転送される合鍵であり、それを知っているだけで引き取れてはならない
- **引取の直前の状態は Tracking が自分で持つ**（`status_before_claim`）。履歴からの再導出はしない
- **申請と承認を分け、申請者本人の承認を禁じる。** 承認の意味は別人であって初めて生まれる

### 追加した ACL ポート（3 本）

| ポート | 向き | 目的 |
| :--- | :--- | :--- |
| `CustomsStatuses` | Tracking → Handling | 追跡照会に出す通関状態 |
| `CargoExceptions` | Booking → Tracking | 予約詳細に出す例外（読み取り専用） |
| `LinkedAccounts` | Shipper → Security | 荷主に紐付いた利用者名 |

いずれも `infrastructure/acl` のアダプタが実装し、**運ぶのは素の値だけ**である（ADR-005 / ADR-012）。
