## Problem（問題点）

### P1. 「操作を終えた後の到達性」が抜けた（最も重い）

**経路を確定すると、経路割り当て画面が 404 になった。** 予約詳細には
「経路を割り当て」ボタンが出たままで、押すと 404 になる。

「読める」条件と「割り当てられる」条件を同じ SQL で兼ねていたことが原因である。
IT3 で予約詳細を経路設計者に開いたとき（GET のみ許可）に一度通った判断が、
ここでは適用されていなかった。

**到達性の抜けは 4 回連続である。**

| IT | 抜けた観点 |
| :--- | :--- |
| IT2 | ロールがその画面を**開けるか** |
| IT3 | 開いた画面から**次に何ができるか** |
| IT4 | 置いてあるボタンを**実際に押せるか** |
| IT5 | **操作を終えた後にもう一度開けるか** |

**受入基準には現れない。** 業務では当たり前の動き（確定した後にもう一度見たい）が、
ストーリーの文には書かれない。

### P2. 片方だけ直して満足した

算出（`/proposals`）には楽観的ロックの衝突処理を足したのに、**確定（`/selection`）には
足していなかった**。同じ例外を投げる経路が他にないかを見ていない。

IT3 の Try T1「修正した層の鏡像を探す」は**層をまたぐ形**では守れていたが、
**同じ層の中の別の入口**は数えていなかった。

### P3. 同じ値を 2 通りに扱っていた

`RouteProposalMapper` の UUID に型ハンドラを明示せず、実行時の設定に頼っていた。
実行時は動くが、**設定を読まない道具（Jig）からは解決できず、このマッパーだけが
読み飛ばされて CRUD 図に欠落が出ていた**。

他のマッパー（`CargoMapper`）は明示している。**書き方が 2 通りあると、
片方だけが壊れていても気づきにくい。**

### P4. `package-info` が 16 パッケージで欠けていた

Jig を実行するまで気づかなかった。IT4・IT5 で増えたパッケージが大半で、
**ACL のアダプタや共有カーネルが指す実体の読み取りなど、置いた理由が名前から
読み取れないもの**ばかりだった。
