## Keep（うまくいったこと）

### 技術的成功

1. **型駆動ドメイン設計の徹底**: 判別共用体 + スマートコンストラクタで不変条件（DiscountRate 0-30%・WeightKg 上限・出発地≠目的地）を型で保証。FsCheck のプロパティテストで網羅性を確認できた。
2. **ポート＝関数レコードのテスト容易性**: `ShipperRepository`・`ExternalRoutingServicePort` を関数レコードとし、モックライブラリなしで関数リテラルのスタブを差し込めた（tech_stack 方針の実証）。
3. **ADR-0002 コンプライアンスの実証**: UnitOfWork のロールバック時イベント非発行を統合テストで実証。self-review で見つけた集約の部分永続化も同じ原則で修正できた。
4. **Docker 不要の統合テスト**: SQLite in-memory / 一時ファイルでリポジトリ・マイグレーション・認証・受け入れテストを実行でき、CI 前でも高速に回せた。
5. **アウトサイドインの受け入れテスト**: TestServer で「ログイン → 認可 → 操作 → 一覧」を検証し、ロール認可（403）・異常系（400）まで含めて縦貫通を確認できた。

### プロセス的成功

1. **Ralph Loop による小さな増分**: レイヤー単位（ドメイン → アプリ → インフラ → Web）で 1 増分 1 コミット、各コミットで全テスト緑・警告 0・フォーマット済みを維持できた。
2. **設計ドキュメントとの整合**: 着手前の validating-iteration-plan / validating-design で ADR 番号衝突・ロールモデル・ACL 名の不整合を解消しておいたことで、実装中の手戻りがなかった。

## Problem（課題）

1. **Playwright E2E 未実施（タスク 3.4）**: ブラウザ環境依存のため繰り越し。受け入れテストは TestServer で代替できたが、htmx を含む実ブラウザ挙動は未検証。
2. **カバレッジ計測が層をまたがると過小評価**: 単体 Tests 単独では Infrastructure 層（IntegrationTests で被覆）が計上されず、ドメイン/アプリ層のみで 40% 前後に見える。統合カバレッジのマージ（ReportGenerator）と 80% ゲート化が未整備。
3. **集約永続化のトランザクション漏れ**: `EstimateRepository.Save` を当初 autocommit で実装し、self-review で原子性の欠陥を発見・修正した。着手時にトランザクション方針を先に決めておくべきだった。
4. **荷主 Email 一意性が DB 制約で担保されていない**: 設計（domain-model）どおりアプリ層チェックだが、並行登録時の TOCTOU リスクが残る。
