## KPT 分析

### Keep（継続すべきこと）

#### 技術的成功事項

- **ポートとアダプターパターンの適用**: `RouteCandidateProvider` をポートとして抽出することで、スタブ実装（`StubRouteCandidateProvider`）から実データ実装（`VoyageRouteCandidateProvider`）への差し替えを Spring の `@Primary` アノテーション一つで実現した。テストコードは一行も変更せずにプロダクション実装を切り替えられるヘキサゴナルアーキテクチャの真価を確認できた
- **DDD Routing コンテキストの独立設計**: `Voyage`（集約ルート）・`VoyageNumber`（値オブジェクト）・`Schedule`（値オブジェクト）・`CarrierMovement`（エンティティ）の階層を domain-model.md の設計に忠実に実装した。コンテキスト間の結合は `RouteCandidateProvider` ポートのみに限定できている
- **Testcontainers シングルトンパターンの活用**: `PostgreSQLIntegrationTestBase` を継承するだけで全統合テストが同一 PostgreSQL コンテナを共有するパターンが機能した。テスト間のデータ干渉問題も `@BeforeEach` での TRUNCATE + テストデータ再挿入で解決できた
- **ArchUnit によるアーキテクチャ保護**: Estimation コンテキストのレイヤー依存ルールをビルド時に自動検証するガードレールを追加した。将来のコンテキスト崩壊をコンパイル時に検知できる
- **MyBatis 動的クエリの適用**: `VoyageMapper.xml` の `<if test="...">` による optional フィルタリングで、出発地・目的地・期間の任意組み合わせ検索を単一 SQL で実現した
- **Location.displayName() による UI 改善**: IT3 での UI/UX 改善が E2E テストに影響（`'JPTYO'` → `'東京 (JPTYO)'`）したが、期待値修正で迅速に対応し、都市名 + UNLOCODE 形式の一貫した表示を確立した

#### プロセス的成功事項

- **AI ペアプログラミングによる加速継続**: IT4 の主要タスク（US07・US08）を計画 2 週間に対し 2 日で完了。IT1-3 と同様の加速が維持されている
- **コンテキスト圧縮（/compact）の活用**: セッションの文脈量が限界に近づく前に `/compact` を実施し、作業継続性を維持した
- **テスト間のデータ干渉を即座に診断・修正**: `VoyageControllerTest.setUp()` の TRUNCATE が `EstimateCommandServiceTest` に影響する問題を速やかに特定し、`@BeforeEach` でテストデータを自己充足的に管理する方式に変更した

### Problem（問題点）

#### 品質関連

- **SonarQube Quality Gate が 4 イテレーション連続で未確認**: IT1〜IT4 とスキャンを実行しておらず、静的解析による問題が蓄積している可能性がある。IT4 でも「SonarQube 実行」を Task 1.1 に計上したが、セッション時間の制約で優先度が後回しになった
- **E2E テスト件数の不整合**: IT3 から 40 件と報告（IT3: 41 件から -1 件）。`voyage.spec.ts` 追加で +4 件のはずが計数方法の差異による可能性あり。正確なテスト件数の追跡が必要
- **US07 受入条件の部分未達**: `危険物・冷凍貨物の場合、対応可能な航海のみに絞り込む`（受入条件 6）が実装されていない。実データではすべての航海が貨物種別を区別しない。IT5 以降での対応が必要

#### アーキテクチャ関連

- **IT3 申し送り中優先度が複数持ち越し**: `Cargo.requireStatus()` 抽出・`BookingThymeleafController` try-catch 共通化・ナビゲーション順序変更・テスト命名規則統一が IT4 でも未対応のまま IT5 に持ち越しとなった
- **`Voyage.getDurationDays()` をドメインモデルに追加**: テンプレート側の計算を簡略化するために `getDurationDays()` メソッドをドメインオブジェクトに追加した。純粋なドメインモデルへのプレゼンテーション関連メソッドの混入が蓄積すると設計が汚染される可能性がある

#### テスト関連

- **E2E 異常系テストの追加が未着手**: IT3 から持ち越しの「見積作成フォームのバリデーションエラー」E2E テストが IT4 でも未実施。Voyage 検索フォームの異常系も同様に未追加
