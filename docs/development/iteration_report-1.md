# イテレーション 1 完了報告書

## エグゼクティブサマリー

イテレーション 1 は**計画どおり 16 SP を完了**し、ゴールである「公開貨物追跡の 1 ユースケースを HTTP からデータベースまで縦に貫き、設計が前提とする機構が実装として成立することを証明する」を達成した。

本イテレーションの価値は機能ではなく**検証**にある。Flix の代数的効果でヘキサゴナルアーキテクチャを表現するという設計上の賭けについて、4 つの中核仮定をすべて実装で確認できた。同時に、設計時には想定していなかった**Flix の言語制約 10 件**が判明し、設計ドキュメントへ反映した。

一方で、CI と SonarQube による品質ゲートは未整備のため実施できていない（IT3 のスコープ）。現時点の「緑」はローカルのテスト結果のみに基づく。

## 課題と残作業

### 判明した Flix の制約（10 件）

設計時に「擬似コード」として書いた構文の多くが実際には動かず、実装中に判明した。

| # | 制約 | 影響 |
|:--:|------|------|
| 1 | 同名トップレベルモジュールを複数ファイルで宣言できない | モジュール命名規約を接頭辞方式へ変更（設計反映済み） |
| 2 | ドット区切り `mod A.B.C` は参照解決できない | 同上 |
| 3 | 型エイリアスがモジュール境界を越えて公開されない | `enum` で包む |
| 4 | `resources/` は fatjar には入るが `flix test` の classpath には載らない | Flyway の location を二重指定 |
| 5 | テストランナーが stderr 出力を失敗として扱う | `slf4j-nop` を追加 |
| 6 | Flyway 10 に H2 用モジュールが存在しない | 9.22.3 を採用（技術スタック反映済み） |
| 7 | `run`・`as`・`handler` が予約語 | 命名を回避 |
| 8 | `String.contains` は名前付き引数 `substr` を取る | - |
| 9 | メソッドチェーンで改行前にドットを置けない | 中間変数へ分割 |
| 10 | 仮想スレッド Executor はデーモンスレッドを生成する | `CountDownLatch` で待機。Dockerfile にも影響 |

さらにクローズ作業中、**`try/catch` を含むネストしたラムダで Flix コンパイラが不正なバイトコードを生成する不具合**（`VerifyError`）に遭遇した。`DatabaseMetaData` ベースの実装へ書き換えて回避している。
