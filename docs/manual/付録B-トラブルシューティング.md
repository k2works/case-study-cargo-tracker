# 付録 B トラブルシューティング

症状から引ける Q&A です。画面に出たメッセージがあれば、そのまま本ページ内を検索してください。

## Q1. ログインに関する症状

### Q1-1. ログインできない（「利用者 ID またはパスワードが正しくありません」）

| 確認すること | 対処 |
| :--- | :--- |
| 利用者 ID の綴りは正しいか | 管理者から通知された ID をそのまま入力します |
| キーボードの入力モードは半角か | 全角で入力すると一致しません |
| Caps Lock が有効になっていないか | パスワードは大文字と小文字を区別します |
| 5 回以上続けて失敗していないか | アカウントがロックされています。[Q1-2](#q1-2-正しいパスワードなのにログインできない) を参照してください |

**このメッセージは、ID が存在しない場合・パスワードが違う場合・ロックされている場合のすべてで同じです。仕様であり、不具合ではありません。** 区別して表示すると、その ID が実在することを第三者に教えることになります。

### Q1-2. 正しいパスワードなのにログインできない

アカウントがロックされている可能性があります。**パスワードを続けて 5 回間違えると 30 分間ロックされます。**

| 確認すること | 対処 |
| :--- | :--- |
| 直前に何度か入力を間違えたか | 30 分待ってから、正しいパスワードでログインします |
| 30 分待ってもログインできない | パスワードそのものが違う可能性があります。管理者に確認してください |
| 急いでいて待てない | **解除の手段は現在ありません。** 30 分お待ちください |

ロックの解除を待つ間に何度試しても、ロック時間は**延びません**。

> **管理者による即時解除の機能は、現在ありません。** 提供されるまでは 30 分お待ちいただく運用になります。

### Q1-3. 覚えのないログイン失敗でロックされる

第三者が ID を使ってログインを試みている可能性があります。**管理者に連絡してください。**

### Q1-4. アカウントを無効にされたと言われた

無効にされたアカウントは、パスワードが正しくてもログインできません。表示されるメッセージは Q1-1 と同じです。管理者に確認してください。

## Q2. 画面・メニューに関する症状

### Q2-1. あるはずのメニューが表示されない

**利用できる画面はロールによって変わります。** ロールに該当しない項目は、メニューそのものに表示されません。仕様であり、不具合ではありません。

| 確認すること | 対処 |
| :--- | :--- |
| 自分のロールは何か | [00. はじめに](00-はじめに.md#利用者-id-とロール) の表で確認します |
| 担当が変わったのにロールが古い | 管理者にロールの変更を依頼します |

### Q2-2. 画面を開こうとしたら「アクセスが拒否されました」と表示される

そのロールでは利用できない画面です。URL を直接入力した場合にも起こります。画面の「ダッシュボードに戻る」から作業を始めてください。

担当が変わってこの画面が必要になった場合は、[システム管理担当窓口](00-はじめに.md#システム管理担当窓口)にロールの変更を依頼してください。

### Q2-3. ログアウト後にブラウザの「戻る」で業務画面を見ようとしたが表示されない

**仕様です。** 共有端末で前の利用者の情報が見えないようにしています。

## Q3. 荷主登録に関する症状

### Q3-1. 「このメールアドレスは既に登録されています」と表示される

同じメールアドレスの荷主がすでに登録されています。**登録は行われていません。**

| 確認すること | 対処 |
| :--- | :--- |
| 提示された既存荷主が同じ取引先か | その荷主をそのまま使います。リンクから詳細を確認できます |
| 別の取引先か | 別のメールアドレスで登録し直します |

**どちらを使うかは担当者が判断します。** システムが自動でどちらかに寄せることはありません。

### Q3-2. 「登録」をクリックしても登録されず、項目が赤枠になる

必須項目が未入力か、形式が正しくありません。赤枠の項目の下に理由が表示されます。入力済みの内容は消えていないため、該当項目だけ直して再度「登録」をクリックしてください。

| 項目 | よくある原因 |
| :--- | :--- |
| メールアドレス | `@` を含まない形式になっている |
| 国 | 2 文字の国コードではない（日本は `JP`） |
| 郵便番号・都道府県・市区町村 | 未入力（**番地・建物名以外は必須です**） |

### Q3-3. 法人で登録したのに契約割引率が「-」と表示される

一覧の「契約割引率」が `-` になるのは、**個人**として登録されている場合です。荷主詳細を開いて種別を確認してください。

「個人」を選んだまま契約番号・割引率を入力して登録した場合、**契約情報は保存されません**。正しい種別で登録し直してください（[3.2](03-荷主管理.md#32-荷主を登録する)）。

### Q3-6. 「契約割引率は 30% を超えられません」と表示される

契約割引率の上限は 30.00% です。それを超える割引が必要な場合は、契約条件そのものの見直しが必要です。

### Q3-4. 登録した内容を直したい

登録内容の変更は今後の提供で対応します。管理者に連絡してください。

### Q3-5. 荷主一覧に「荷主が登録されていません」と表示される

まだ 1 件も登録されていない状態です。**エラーではありません。**「+ 新規荷主登録」から登録してください。

## Q4. 予約の確定でつまずいたとき

### Q4-1. 「経路が割り当てられていない予約は確定できません」と表示される

まだ経路が決まっていません。運ぶ道筋が決まっていない予約は確定できません。経路担当者が経路を割り当てるのを待ってください（[5.4](05-航路管理.md#54-航海の全区間を確認する)）。

### Q4-2. 「満船の便が含まれています（V0001）。経路を選び直してください」と表示される

経路候補を算出したあとに、別の貨物がその便を埋めました。**確定の瞬間に空きを数え直しているため、ここで止まります。** 経路担当者に別の便での割り当てを依頼してください。

### Q4-3. 「この状態の予約は確定できません」と表示される

すでに確定済みか、キャンセル済みです。予約詳細のステータスを確認してください。

### Q4-4. 「予約を確定」ボタンが表示されない

経路が割り当てられていないか、すでに確定済みです。**押せないボタンは表示しない方針**のため、ボタンが無いことがそのまま「今はできない」という意味です。

### Q4-4. 「経路が確定していないため通知できません」と表示される

**原因**: 経路が割り当てられていない予約に通知しようとしています。送る中身がまだありません。

**対処**: 経路設計者が経路を割り当てると通知できるようになります（[5.5](05-航路管理.md#55-経路候補を算出して確定する)）。**中身の無い通知を「送信済み」として記録すると、通知履歴そのものが信用できなくなる**ため、あえて塞いでいます。

**関連**: [4.6](04-貨物予約.md#46-確定経路を荷主に通知する)

## Q5. 追跡番号・経路の再算出でつまずいたとき

### Q5-1. 「確定していない予約には追跡番号を発行できません」と表示される

営業担当者が予約を確定するのを待ってください。確定された予約は「追跡管理」の一覧に現れます（[7.1](07-追跡管理.md#71-発行待ちの予約を確認する)）。

### Q5-2. 「この予約にはすでに追跡番号 TRK-… が発行されています」と表示される

発行済みです。**表示された番号をそのまま荷主に連絡してください。** 番号は予約詳細でいつでも確認できます。

### Q5-3. 発行した追跡番号が分からなくなった

予約詳細の「追跡番号」欄で確認できます。予約が分からない場合は、荷主名・出発地・目的地から貨物予約一覧で探してください。

### Q5-3. 「条件に合う航路が見つかりませんでした」と表示される

**原因**: 現在の条件（期限・経由回数の上限）で運べる航海がありません。**候補ゼロは異常ではなく日常的に起きます。**

**対処**: 2 つの道があります。

1. **条件を緩めて探し直す**（[5.6](05-航路管理.md#56-条件を緩めて経路を探し直す)）。「+3 日」「+7 日」「経由 +1」を押すとその場で探し直します
2. **航海スケジュールを登録する**（[5.3](05-航路管理.md#53-航海スケジュールを登録する)）。出発地・目的地の両方に寄港する便が無い場合はこちらです

**関連**: [5.5](05-航路管理.md#55-経路候補を算出して確定する)

### Q5-4. 「延長できる日数の上限は 30 日です」と表示される

**原因**: 一度に延ばせる日数の上限を超えています。**条件は変わっていません**（切り詰めて探し直したりはしません）。

**対処**: 30 日を超える変更は輸送計画の引き直しです。荷主と合意のうえ、予約を取り直してください。

**関連**: [5.6](05-航路管理.md#56-条件を緩めて経路を探し直す)

## Q6. 荷役の登録でつまずいたとき

### Q6-1. 「追跡番号の形式が正しくありません」と表示される

`TRK-20260401-0001` の形式で入力してください。このメッセージは**入力欄のすぐ下**に出ます。

### Q6-2. 「追跡番号 TRK-… の貨物が見つかりません」と表示される

番号の写し間違いか、追跡番号がまだ発行されていません。**このメッセージはフォームの上**に出ます。番号を確認しても見つからない場合は追跡担当者に問い合わせてください。

### Q6-3. 「積込 には航海番号が必要です」と表示される

積込・荷降しは、どの便に対する作業かが必要です。貨物の予定ルートの航海番号を入力してください。

### Q6-4. 「予定ルートに無い積込です」と警告が出た

**登録は済んでいます。** ただし予定と違う便・港に積み込まれており、誤配として記録されました。**追跡担当者に連絡してください。**

### Q6-5. 「他の操作が先に行われました」と表示される

他の担当者が同時に同じ貨物を操作しました。**このとき作業は記録されていません。** 一覧で状態を確かめてから登録し直してください。

### Q6-6. 登録したのに追跡の状態が変わらない

**すぐには変わりません。** 荷役の記録と追跡への反映は別々に行われるため、登録の直後は前の状態が見えることがあります。少し待ってから開き直してください。

それでも変わらない場合は、システム管理担当窓口に連絡してください（反映が失敗した記録がログに残っています）。**荷役の記録そのものは残っています。**

### Q6-7. 登録した作業を間違えた

荷役記録の訂正・取り消しは今後の提供で対応します。追跡担当者に連絡してください。

## Q7. 引取の登録でつまずいたとき

### Q7-1. 「引取 には荷受人確認が必要です」と表示される

引取だけは、確認コードと荷受人氏名の**両方**が必要です。引き渡しの証明が無いまま「引き渡し済み」として記録が残ると、「渡した」「受け取っていない」の争いになったときに会社が不利になるためです。

荷受人から確認コードを聞き取り、実際に受け取った方の氏名とあわせて入力してください（[8.2](08-荷役管理.md#82-荷役作業を記録する)）。

### Q7-2. 「予約の荷受人（○○）と違う方が受け取っています」と警告が出た

**登録は成功しています。** 代理の方が受け取ることは実務では珍しくないため、拒否はしません。

**担当者メモに理由を記入してください。** 後から「なぜ別の方が受け取ったのか」を確認できるのは、このメモだけです。

### Q7-3. 「作業日時が追跡番号の発行日（2026-09-03）より前です」と表示される

追跡番号が発行される前に荷役は起こりえないため、登録できません。**年や月の打ち間違い**がないか確認してください。発行日当日は登録できます。

### Q7-4. 誰が受け取ったかを後から確認したい

荷役作業一覧の「受取人 / メモ」欄で確認できます（[8.1](08-荷役管理.md#81-記録した作業を確認する)）。引取以外の作業では空欄です。

### Q7-5. 引取を間違えて登録した

**登録後の訂正・取り消しはできません。** 追跡担当者にご連絡ください。訂正の手段は今後の提供で対応します。

## Q8. 貨物追跡でつまずいたとき

### Q8-1. 「該当する貨物が見つかりません」と表示される

追跡番号の写し間違いがないか確認してください。**番号が存在しない場合と形式が違う場合を区別せず、同じメッセージを表示します**（他社の貨物の有無を番号の総当たりで探られないようにするためです）。

追跡番号が分からない場合は、担当営業にお問い合わせください。

### Q8-2. 現在地が「受領前のため未確定」と表示される

まだ貨物を受領していない状態です。**出発地を推測して表示することはしません**（受領していない貨物を「出発地にある」と表示すると、集荷が済んだと誤解されるためです）。

### Q8-3. 推定到着日が「未確定」と表示される

経路がまだ確定していない状態です。経路の確定後に表示されます。

### Q8-4. 荷役を登録したのに追跡に反映されていない

反映まで最大 30 秒ほどかかることがあります。**荷役の記録そのものは確実に残っています。** しばらく待ってから開き直してください。

### Q8-5. 「アクセスが集中しています」と表示される（公開追跡）

短時間に何度も照会した場合に表示されます。画面に表示された秒数だけ待ってから、もう一度お試しください。

### Q8-6. ログインしていないが追跡したい

ログイン画面の「追跡番号をお持ちの方はこちら（ログイン不要）」から照会できます（[9.2](09-貨物追跡.md#92-ログインせずに照会する)）。

## Q9. 貨物状態の手動更新でつまずいたとき

### Q9-1. 「現在の状態より前の状態には戻せません」と表示される

**原因**: 進んだ状態より前へ戻す更新を送っています。

**対処**: そのままでは戻せません。**誤って登録した場合は取り消しの申請が必要です**（今後の提供）。手動更新で戻せると、引き渡し済みの貨物を輸送中に戻せてしまうため、あえて塞いでいます。

**関連**: [7.4](07-追跡管理.md#74-貨物の状態を手動で更新する)

### Q9-2. 「登録されていない港です」と表示される

**原因**: 入力した UN/LOCODE がマスタにありません。打ち間違いか、扱っていない港です。

**対処**: 港のコードを確認して入力し直します。存在しない場所の記録は追跡の役に立たないため受け付けていません。

**関連**: [7.4](07-追跡管理.md#74-貨物の状態を手動で更新する)

### Q9-3. 手動更新の欄が表示されない

**原因**: 追跡担当者以外のロールでログインしています。手動更新は追跡担当者のみが行えます。

**対処**: 荷主・荷受人は照会のみです。状態の更新が必要な場合は追跡担当者に依頼してください。

**関連**: [7.4](07-追跡管理.md#74-貨物の状態を手動で更新する)

### Q9-4. 入港を登録したのに状態が変わらない

**原因**: **これは正常です。** 入港は船が着いただけであり、貨物の状態を変えるのは荷降ろしです。入港は位置の記録に留まります。

**対処**: 荷降ろしは荷役作業員が[荷役管理](08-荷役管理.md)で登録します。

**関連**: [7.4](07-追跡管理.md#74-貨物の状態を手動で更新する)
