# ユーザーマニュアル

国際貨物輸送管理システム（Cargo Tracker）の操作マニュアルです。読者は業務担当者であり、開発者ではありません。

このマニュアルの価値は網羅性ではなく、**画面の前に座った担当者がその場で手を動かせること**にあります。

## 章構成

| 章 | ドキュメント | 内容 |
| :--- | :--- | :--- |
| — | [00. はじめに](00-はじめに.md) | 読み方・表記規約・動作環境 |
| — | [01. 業務フロー](01-業務フロー.md) | 業務の流れと各章への入口 |
| 2 | [02. ログイン](02-ログイン.md) | ログイン・ログアウト・アカウントロック |
| 3 | [03. 荷主管理](03-荷主管理.md) | 荷主の登録・一覧・詳細 |
| 付録 A | [用語集](用語集.md) | 業務用語・画面用語 |
| 付録 B | [トラブルシューティング](付録B-トラブルシューティング.md) | 症状から引く Q&A |

章はアプリケーションのメニュー構成に沿って並べています。**章番号は画面の並び順であり、業務の順序ではありません。** 業務の順序は [01. 業務フロー](01-業務フロー.md) が担い、各章はそこから参照されます。

> 本マニュアルは実装済みの画面のみを扱います。貨物予約・経路設計・追跡・精算はイテレーションの進行にあわせて章を追加します。

## 執筆テンプレート

画面・タブごとに 1 節を立て、次の構成で書きます。**この順序は読者が実際に迷う順序**であり、崩すと読者は自分の状況に対応する記述を探せなくなります。

```markdown
## <章.節> <画面・機能名>

### この画面でできること
### 画面の開き方
### 画面の説明
### 操作手順
### 注意・補足
```

## 画面キャプチャの方針

**キャプチャは Playwright で自動生成します。手作業で PNG を置いてはいけません。** 次回の再生成で上書きされ、UI 変更のたびに撮り漏れが出ます。

| 項目 | 内容 |
| :--- | :--- |
| 生成 spec | `e2e/manual/manual-screenshots.spec.js` |
| 設定 | `playwright.manual.config.js` |
| 実行コマンド | `npm run screenshots:manual` |
| 出力先 | `docs/manual/assets/` |
| 配信 | `local` プロファイル（H2）で起動したアプリを Playwright の `webServer` が立ち上げる |
| データ | Flyway のシードユーザーと、spec 内で登録するダミー荷主のみ |
| 命名 | `<章番号>-<英字スラッグ>.png`（例: `02-login.png`） |

実在の顧客名・住所・電話番号・メールアドレスはキャプチャにも本文にも載せません。マニュアルは Git 管理下で公開されるためです。

> **キャプチャ spec は通常のテスト実行（`./gradlew check`）の対象外です。** ドキュメント生成であり検証ではありません。

## 公開

```bash
npx gulp manual:build   # docs/manual → apps/manual へ HTML 出力
npx gulp deploy:docs    # ドキュメントサイトへ配信（/manual/ で閲覧できる）
```

章を追加・削除したら、`index.md`（本ファイル）・[00-はじめに.md](00-はじめに.md) の全体構成表・`mkdocs.yml` の nav の **3 箇所を必ず揃えます**。索引が古いと、読者はそのページに辿り着けません。
