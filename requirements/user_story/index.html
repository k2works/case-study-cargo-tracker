    ユーザーストーリー - 国際貨物輸送管理システム¶

    システムユースケースから開発可能な粒度のユーザーストーリーを導出する。 「〜として、〜したい。なぜなら〜だからだ」の形式で記述し、各ストーリーに受入条件を定義する。

    受入条件は人と AI の契約として、Given/When/Then で一意に判定できる形で書き、AC-01 から番号を振る。元の基準に無い振る舞いを補った条件には「（AI の仮定）」と印を付ける。各ストーリーの「参照する成果物」は生成時に AI に渡すコンテキスト、「確認ポイント」は承認ゲートで人が判断する点、「AI の仮定」は未確認の前提を示す。用語は用語集、AI に任せる範囲とリスク ID はリスク台帳に従う。

    US01: 輸送見積を作成する¶

    として: 営業担当者

    したい: 荷主の輸送要件（出発地・目的地・希望期限・貨物種別・重量）を入力し、輸送料金と所要日数の見積を作成したい

    なぜなら: 荷主が予算と納期を事前に把握でき、予約決定を迅速に行えるからだ

    対応 UC: UC01

    Unit: U-02 貨物予約

    受入条件:

    • AC-01 Given 営業担当者が見積作成画面を開いている / When 出発地・目的地・希望期限・貨物種別・重量を入力して検索する / Then 航海スケジュールをもとにした経路の概算候補が表示される
    • AC-02 Given 経路の概算候補が表示されている / When 候補一覧を見る / Then 候補ごとに経由港・所要日数・概算料金・航海番号が表示される
    • AC-03 Given 経路の概算候補が表示されている / When 見積を保存する / Then 見積が保存され、見積番号が発行される
    • AC-04 Given 希望期限までに目的地へ到達できる航海が無い / When 見積の条件で検索する / Then 期限に間に合う経路が無いことが通知される
    • AC-05 Given 見積作成画面を開いている / When 貨物種別に「危険物」を選ぶ / Then 危険物申告情報の入力フォームが表示される

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC01 輸送見積を作成する
    • 制約条件: 要件定義書「経路設計の制約条件」

    確認ポイント: 概算料金の算出方法が未定義（US21 の輸送料金算出と同じ計算かどうか）。危険物申告情報の項目は要件に無い（R-05）

    AI の仮定: 概算候補の抽出には US08 の経路候補算出と同じ制約条件を使う（要確認）

    US02: 荷主を登録する¶

    として: 営業担当者

    したい: 新規荷主の氏名/社名・住所・連絡先・メールアドレスをシステムに登録したい

    なぜなら: 次回以降の予約で荷主情報の再入力を省略でき、顧客情報を一元管理できるからだ

    対応 UC: UC02

    Unit: U-02 貨物予約

    受入条件:

    • AC-01 Given 入力するメールアドレスの荷主が登録されていない / When 氏名または社名・住所・連絡先・メールアドレス・荷主種別「個人」を入力して登録する / Then 荷主が登録され、荷主 ID が発行される
    • AC-02 Given 同じメールアドレスの荷主が登録済みである / When そのメールアドレスで登録しようとする / Then 既存の荷主が表示され、既存の荷主を使うか登録を続けるかを選べる

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC02 荷主を登録する

    確認ポイント: 必須項目が未入力のときの振る舞いは受入条件に無い

    AI の仮定: 「どちらを使用するか選択できる」を、既存の荷主を使うか新規登録を続けるかの選択と解釈した（要確認）

    US03: 法人荷主を登録する¶

    として: 営業担当者

    したい: 法人荷主の契約番号と割引率を含めて登録したい

    なぜなら: 法人契約条件（割引率）を精算時に自動適用できるからだ

    対応 UC: UC02

    Unit: U-02 貨物予約

    受入条件:

    • AC-01 Given 荷主登録画面を開いている / When 荷主種別「法人」を選ぶ / Then 契約番号と割引率の入力欄が表示される
    • AC-02 Given 荷主種別「法人」を選んでいる / When 割引率 0%〜30%（境界値 0% と 30% を含む）で登録する / Then 法人荷主が登録され、荷主 ID が発行される
    • AC-03 Given 荷主種別「法人」を選んでいる / When 割引率に 30% を超える値または負の値を入力して登録する / Then 登録できず、範囲外であることが示される（AI の仮定）
    • AC-04 Given 割引率を登録した法人荷主がいる / When その荷主の輸送料金に法人割引を適用する（US22） / Then 登録した割引率が使われる

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC02 荷主を登録する
    • 関連ストーリー: US22 法人割引を適用する

    確認ポイント: AC-03 は元の基準「0〜30% の範囲で設定できる」から導いた範囲外の振る舞い

    AI の仮定: 範囲外の割引率は登録を拒否する（警告に留めない）（要確認）

    US04: 貨物予約を登録する¶

    として: 営業担当者

    したい: 荷主 ID・貨物仕様（種別・重量・寸法・個数・品名）・輸送条件（出発地・目的地・希望日）を入力して予約を登録したい

    なぜなら: 荷主の見積承認後に正式な予約を受け付け、経路設計フェーズに引き継げるからだ

    対応 UC: UC03

    Unit: U-02 貨物予約

    受入条件:

    • AC-01 Given 荷主が登録済みである / When 荷主 ID を入力する / Then その荷主が選択される
    • AC-02 Given 荷主を選択している / When 貨物種別・重量・寸法・個数・品名と、出発地・目的地・希望引渡日・希望着日を入力して登録する / Then 予約番号が発行され、予約状態が「仮受付」になる
    • AC-03 Given 予約の登録が完了した / When 完了を確認する / Then 経路設計者に予約登録が通知される
    • AC-04 Given 見積のある荷主の予約を登録する / When 登録する / Then 見積の内容との整合性が確認される

    • ユースケース: UC20 ユーザーを認証する（システムユースケース）

    確認ポイント: ロック解除までの「一定時間」が未定義。AC-05 の案内と AC-03 の同一メッセージの方針が衝突しないか（無効化アカウントの存在を知らせることになる）。認証・認可の実装は確認必須（R-02）

    AI の仮定: AC-02 は元の基準「認証成功時に失敗回数がリセットされる」の境界値として補った。ロック解除までの時間は 30 分とする（要確認）

    US27: システムからログアウトする¶

    として: システム利用者

    したい: 業務終了時にログアウトしてセッションを終了したい

    なぜなら: 共用端末・モバイル端末での第三者による不正操作を防げるからだ

    対応 UC: UC20

    Unit: U-01 認証

    受入条件:

    • AC-01 Given ログインしている / When ログアウトする / Then セッションが破棄されてログイン画面に戻り、ログアウト日時がログに記録される
    • AC-02 Given ログアウトした / When ブラウザの戻る操作などで業務画面を開こうとする / Then 業務画面は表示されない

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC20 ユーザーを認証する（システムユースケース）

    確認ポイント: セッションの破棄方式は US26 の認証方式の決定に従う（R-02）

    AI の仮定: 業務画面はキャッシュさせず、戻る操作ではログイン画面に誘導する（要確認）

    US28: 誤配を検知して経路を再設計する¶

    として: 追跡管理者（検知は荷役作業員）

    したい: 予定経路と異なる場所で荷役が行われたことを検知し、貨物の現在地から目的地までの経路を組み直したい

    なぜなら: 誤配は発見が遅れるほど納期遅延と輸送コストが膨らむため、その場で気づいて組み直せることが被害を最小にするからだ

    対応 UC: UC16（例外を処理する）、UC08（経路条件を調整する）

    Unit: U-04 荷役・追跡

    受入条件:

    • AC-01 Given 作業場所が予約の予定経路に含まれない / When 荷役作業を登録しようとする / Then 登録前に警告が表示される
    • AC-02 Given 誤配の警告が表示されている / When 警告を承認して登録する / Then 経路の状態が「誤配」になり、例外種別「誤配」の追跡イベント（例外）が自動で起票される
    • AC-03 Given 誤配が起票された予約がある / When 予約詳細を開く / Then 誤配の警告バナーと、検知した追跡イベント（荷役。場所・日時）、貨物の現在地が表示される
    • AC-04 Given 誤配が起票された予約がある / When 経路設計者が [経路を再設計] を選ぶ / Then 現在地を出発地とし、元の予約の目的地と希望期限を引き継いだ経路割り当て画面に遷移する
    • AC-05 Given 再設計した経路の到着予定が当初の希望期限を超える / When 再設計を確定する / Then 希望期限との差分が表示され、荷主への通知内容に含まれる
    • AC-06 Given 誤配の追跡イベント（例外）がある / When 追跡管理者が例外一覧を開き、解決フォームで対応内容を記録する / Then 対応内容が記録され、解決後も誤配の記録が残り、料金調整の根拠として参照できる

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC16 例外を処理する、UC08 経路条件を調整する（システムユースケース）
    • 状態: 要件定義書「追跡情報（貨物状態）の状態遷移」

    確認ポイント: 「経路の状態」（誤配）は用語集と状態モデルに無い（US09 と同じ）。誤配の起票で貨物状態を「例外発生」にするか。経路設計と荷役・追跡の両方にまたがるため、Unit 分解（ステップ 6）で置き場所を判断する

    AI の仮定: 誤配の起票でも貨物状態は「例外発生」になる（要確認）

    US29: 通関申告を登録・管理する¶

    として: 荷役作業員（申告の登録）、追跡管理者（状態の管理）

    したい: 輸入港での税関申告を登録し、通関状態を管理したい

    なぜなら: 通関が下りないと荷受人に引き渡せないため、どの貨物がどの段階にあるかが分からないと引取作業の計画が立たず、留置が長引けば保管料が発生するからだ

    対応 UC: UC21

    Unit: U-04 荷役・追跡

    受入条件:

    • AC-01 Given 輸入港で荷降しが記録された貨物がある / When 荷役作業員が追跡番号・申告番号・申告日時を入力して通関申告を登録する / Then 通関申告が登録され、通関状態が「審査中」になる
    • AC-02 Given 通関申告が登録されている / When 追跡管理者が理由を入力して通関状態を「通関済」「留置」「不可」のいずれかに更新する / Then 通関状態が更新され、監査ログに記録される
    • AC-03 Given 通関申告が登録されている / When 理由を入力せずに通関状態を更新しようとする / Then 更新できない
    • AC-04 Given 通関状態が「通関済」でない貨物がある / When 引取荷役を記録しようとする / Then 拒否され、現在の通関状態が表示される
    • AC-05 Given 通関状態を「通関済」に更新する / When 更新する / Then 荷主と荷受人に通関完了が通知される
    • AC-06 Given 通関状態を「留置」に更新する / When 更新する / Then 例外種別「税関保留」の追跡イベント（例外）が自動で起票される
    • AC-07 Given 「留置」のまま 3 日を超えた申告がある / When 通関申告の一覧と追跡管理者のダッシュボードを開く / Then 一覧で警告が表示され、ダッシュボードに件数が表示される
    • AC-08 Given 通関申告が複数ある / When 貨物 ID・追跡番号・通関状態で検索する / Then 条件に合う申告が表示される
    • AC-09 Given 通関状態が変更された申告がある / When 申告詳細を開く / Then 変更履歴（日時・変更者・理由）が表示される

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC21 通関申告を管理する（システムユースケース）
    • 状態: 要件定義書「追跡情報（貨物状態）の状態遷移」

    確認ポイント: インセプションデッキは「税関申告システム（連携は行うが、申告業務自体は対象外）」をスコープ外としている。本ストーリーは税関とは連携せず申告結果を手入力で記録するもので、スコープ外の申告業務そのものではないと読めるか。税関と電子連携しない判断は ADR が未記録。「貨物 ID」は用語集に無い。UC21 の「不可」時の返送・廃棄の判断と「3 日超の督促通知」が受入条件に無い

    AI の仮定: 申告業務のうち記録だけをスコープ内とする。「貨物 ID」は予約番号を指す（要確認）

    US30: 輸送中の予約キャンセルを承認する¶

    として: 追跡管理者

    したい: 輸送中の貨物に対するキャンセル申請について、陸揚げ地を指定したうえで承認または却下したい

    なぜなら: 輸送開始後のキャンセルは貨物が船の上にあるため「どこで降ろすか」の判断が必要であり、営業担当者の操作だけで完結させると貨物が宙に浮くからだ

    対応 UC: UC22

    Unit: U-02 貨物予約

    受入条件:

    • AC-01 Given 予約状態が輸送開始前（仮受付・経路提案中・予約確定・追跡番号発行済）の予約がある / When 営業担当者がキャンセルする / Then 承認なしで即座にキャンセルされる
    • AC-02 Given 予約状態が「輸送中」の予約がある / When 営業担当者が予約詳細を開く / Then [キャンセル（要承認）] の申請ボタンだけが表示される
    • AC-03 Given 「輸送中」の予約でキャンセルを申請する / When 理由を入力せずに申請する / Then 申請できない
    • AC-04 Given 「輸送中」の予約で理由を入力して申請した / When 申請が完了する / Then 追跡管理者に通知され、承認待ちの一覧に表示される
    • AC-05 Given 承認待ちの申請がある / When 追跡管理者が陸揚げ地（現在地の港または次の寄港地）を指定して承認する / Then キャンセルが確定し、陸揚げ地への荷降しが手配され、荷主に通知される
    • AC-06 Given 承認待ちの申請がある / When 追跡管理者が却下する / Then 予約は「輸送中」のまま維持され、却下理由が申請者と荷主に通知される
    • AC-07 Given 予約状態が「配送完了」以降の予約がある / When キャンセルしようとする / Then キャンセルできない
    • AC-08 Given キャンセル料が発生する状態の予約をキャンセルする / When キャンセルが確定する / Then 状態に応じた料率でキャンセル料が算定され、精算に引き渡される
    • AC-09 Given キャンセルの申請・承認・却下があった / When 予約詳細を開く / Then 履歴（日時・実行者・理由）が表示される

    参照する成果物:

    • ドメイン用語: 用語集
    • ユースケース: UC22 予約をキャンセルする（システムユースケース）
    • 状態: 要件定義書「貨物予約の状態遷移」

    確認ポイント: キャンセル料の料率が未定義で AC-08 を判定できない。AC-01 は営業担当者の振る舞いで、ストーリーの主語（追跡管理者）と異なるため分割の候補。US13 AC-04 と重複。予約状態に「キャンセル承認待ち」を持つか（R-06）

    AI の仮定: 承認待ちの間も予約状態は「輸送中」のままとし、申請は別に記録する（要確認）
