# developing-review — 本プロジェクトでの設定

SKILL.md の汎用手順に対する、国際貨物輸送管理システム固有のレビュー観点です。食い違う場合は本ファイルを正とします。

## レビューの前提

| 項目 | 値 |
| :--- | :--- |
| 契約（受入条件） | `docs/requirements/user_story.md` の `AC-01` など |
| Bolt 計画 | `docs/development/bolt_plan-N.md` |
| 用語・状態 | `docs/design/glossary.md`、要件定義書の状態モデル |
| AI に任せる範囲・確認必須の操作 | `docs/requirements/risk_register.md` |
| レビュー結果の置き場所 | `docs/review/` |

## AI 生成コードに固有の観点

各エージェントのレビューに次の観点を加える。AI は人と違う壊れ方をするため、人向けのチェックリストだけでは見落とす。

| 観点 | 何を見るか |
| :--- | :--- |
| 先回り実装 | テストの無い分岐・将来用のオプション引数・使われない汎用化が無いか。受入条件に無い振る舞いや「（AI の仮定）」「要確認」の振る舞いが実装されていないか |
| 同型テスト | 期待値が受入条件から来ているか。実装の出力をコピーしただけのテストになっていないか。各テストがどの AC を検証するか説明できるか |
| 過剰なモック | 検証対象までモックにしていないか。モックは外部システム・DB などの境界だけか |
| 既存の無視 | 既存の値オブジェクト・ユーティリティ・フィクスチャ（各開発スキルの `PROJECT.md` に記載）を使わず、似たものを新しく作っていないか |
| 幻覚 API | 存在しないライブラリのメソッドや設定を使っていないか（ビルド・型チェックの結果を確認する） |
| 未申告の変更 | 完了報告のファイル一覧と `git diff --stat` が一致するか |

## 本プロジェクトのドメインの観点

既存レビュー（`docs/review/ドメインモデル分析_review_20260331.md`）で見つかった誤りの型を、実装のレビューでも確かめる。

- 状態の列挙値が要件定義書の状態モデル（予約状態 8・貨物状態 9・通関状態 4）と一致しているか。参照実装やオリジナルの Cargo Tracker の列挙値を持ち込んでいないか（R-06）
- 識別子が値オブジェクトになっていて、識別子のための集約ルート・リポジトリが無いか
- Unit（コンテキスト）の境界を越えて相手の型を直接参照していないか。依存の向きが `units.md` の依存 DAG と一致しているか
- 集約と値オブジェクトの間に循環依存が無いか
- 経路算出の制約条件が要件定義書の 5 つと一致しているか（R-04）
- 金額計算の期待値が受入条件に定義された式から来ているか（U-05）
- 語が用語集の表記と一致しているか（クラス名・メソッド名の英語名は用語集に追加された対応表に従う）

## 確認必須の操作の見落とし

スキーマ変更（R-03）、認証・認可（R-02）、外部連携と依存ライブラリの追加（R-01）、環境変数（R-10）を含む変更が、承認ゲートを通らずに入っていないかを確かめる。
