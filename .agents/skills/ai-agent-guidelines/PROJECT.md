# ai-agent-guidelines — 本プロジェクトでの設定

SKILL.md の汎用の実行ガイドラインに対する、国際貨物輸送管理システム固有の規律です。本プロジェクトは AI-DLC を採用しています（`CLAUDE.md`）。食い違う場合は本ファイルを正とします。

## 作業の前に読むもの

| 何をするか | 読むもの |
| :--- | :--- |
| すべての作業 | `docs/requirements/risk_register.md`（AI に任せる範囲・確認必須の操作） |
| 文書を書く | `docs/design/glossary.md`（用語と状態名） |
| 実装する | 対象ストーリーの受入条件（`user_story.md`）、`bolt_plan-N.md`、各開発スキルの `PROJECT.md` |
| 計画する | `docs/requirements/units.md`、`docs/development/release_plan.md` |

## コードは全行理解できる形で出す

AI-DLC では、人は AI が書いたコードでも理解していない行をマージしない。人が承認ゲートで全行を読めるように、次を守る。

- 1 ステップの変更は、そのステップのゴールに必要な範囲に留める。ついでのリファクタリングや整形を混ぜない
- 完了報告に、作成・変更・削除したファイルの一覧と、各ファイルで何をしたかを書く
- 生成したテストが、どの受入条件（`AC-01` など）を検証するかを示す

## 仮の実装を明示する

Green で最小限にするための仮の実装（定数を返す、分岐を 1 つだけ書くなど）は、次のテストで一般化する前提のものだと報告に書く。人が本実装と取り違えないようにするためである。受入条件に「（AI の仮定）」「要確認」がある振る舞いは、仮の値でも実装しない。

## 仮定で埋めない

情報が足りないときは推測で埋めずに質問する。本プロジェクトで未定義のまま残っているもの（基本料金の計算式、キャンセル料率、危険物申告の項目、ロック解除までの時間、推奨順の基準など）は、`release_plan.md` の「着手前に解消する要確認」とストーリーの「確認ポイント」に載っている。

## 修正をガードレールにする

人に修正された振る舞いは、同じ修正を繰り返さないよう次に反映する。

| 修正の種類 | 反映先 |
| :--- | :--- |
| 全プロジェクト共通の規律 | `CLAUDE.md` |
| 本プロジェクトの開発・計画・分析の規約 | 該当スキルの `PROJECT.md` |
| 特定の Unit・ストーリーの判断 | `bolt_plan-N.md` の「AI の仮定」、`docs/journal/` |
| 用語・状態名 | `docs/design/glossary.md`（承認を得てから） |
| AI に任せる範囲・リスク | `docs/requirements/risk_register.md`（承認を得てから） |

SKILL.md は booster の更新で上書きされるため、プロジェクト固有の規律は SKILL.md ではなく `PROJECT.md` に書く。

## 移行時に分かった注意点

- 検査スクリプト `migrating-ai-dlc/scripts/aidlc_check.py` は、本プロジェクトのストーリー ID（`US01` 形式）に合わせて `--story-id 'US\d+'` を付けて実行する
- 同スクリプトは `apps/.gitkeep` をコードとして数え、「ブラウンフィールド」と誤判定する。`apps/` に実装が入るまでは静的・動的モデルの WARN を無視してよい
- `apply-okf` の `okf_apply.py apply` は索引の表の外（ファイル末尾）に登録行を足す。各 `index.md` の表に移す
