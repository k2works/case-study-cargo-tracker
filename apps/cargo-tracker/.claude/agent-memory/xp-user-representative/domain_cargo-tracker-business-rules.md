国際貨物輸送管理システム（apps/cargo-tracker）の業務ユーザー観点で繰り返し確認すべき点。

**見積（US01・営業担当者）**
- 見積は顧客への提示物。有効期限・作成日・料金内訳（基本運賃/危険物割増/燃油）が業務上必須。
- 危険物クラスは IMDG コード（クラス1〜9）で構造化すべき。フリーテキスト不可。cargo_type=HAZARDOUS 時はクラス必須。
- 港は UN/LOCODE 手打ちだと誤入力事故。営業は港名で思考する→港名サジェスト/併記が要る。
- 候補無し時は「最短到着可能日」を出すと即交渉できて価値が高い。

**公開追跡（US18・荷主/荷受人）**
- 荷主は港コードを知らない→公開ページの場所は必ず港名ラベル化。
- 現在地/推定到着日が空のときは「出港前」等の明示が要る（不具合と誤解される）。
- 追跡番号入力フォームのある入口ページと URL コピー機能が共有に必要。

**遅延例外（US19・追跡管理者）**
- US19 の眼目は「荷主への通知」。対応報告に荷主通知（要否/文面/控え）の要素があるか毎回確認。
- 荷主が最も知りたいのは新到着予定日→対応報告で新到着予定日は原則必須。
- 発生日時は「現在以前」に制限すべき（記録なので未来日は入力ミス）。

**Why:** 機能が動いても業務では使えない典型（見積有効期限なし・荷主通知フロー欠落）を IT6 レビューで検出。
**How to apply:** cargo-tracker の見積/追跡/例外 UI をレビューする際、上記を最初にチェックする。
