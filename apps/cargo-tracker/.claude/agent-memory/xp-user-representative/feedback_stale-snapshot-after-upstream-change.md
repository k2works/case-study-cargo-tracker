上流のマスタ（航海スケジュール）を更新できるようにしたら、その値を**写して保存している下流**（`leg.load_time` / `unload_time`）が古いままにならないか必ず確かめる。

**Why:** IT9 の US25 で航海の発着時刻を更新できるようにしたが、確定済み経路の `leg` は割り当て時の写しであり更新されない。同じ IT の US34 で予約詳細を荷主に開放したため、**荷主が古い ETA を正しい日程だと信じる**形になった。「確定経路は自動で作り直さない」という設計判断は妥当だが、**古いと分かる印**が画面に無いのが問題。

**How to apply:** 上流更新の機能をレビューするとき、(1) 下流に写しがあるか、(2) 写しが古くなったことを画面で見分けられるか、(3) 誰がいつ気づくか、の 3 点を聞く。件数を確認画面に出すだけでは、確定した瞬間に情報が消える。
